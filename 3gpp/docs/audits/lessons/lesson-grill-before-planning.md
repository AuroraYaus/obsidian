# 写作计划与决策问题先拷问

**根因**：2026-08-11 协议栈与 OSI 知识点入库任务——按 brainstorming → writing-plans 标准流程推进，用户连续批准设计（"批准"→"再详细点"→"批准"），Agent 未停下来确认是否要加 grill-me 拷问环节。用户追问"为什么不拷问我"，并明确要求固化为全局规则。

**How to apply**：
1. 任何写作计划（讲义/教材/笔记/文档内容）、设计方案、需要用户决策的问题——动手前先拷问（grill-me：一次一个问题、附推荐答案、能自查先自查），收敛写入 PLAN.md 后再执行。
2. 拷问不是审批流程的替代，是审批之前的设计压力测试。用户连续批准 ≠ 不需要拷问——批准的是"理解"，拷问检验的是"设计"。
3. 本次拷问实际发现 5 处计划漏洞：MAC 中文名与全库标准不一致（介质访问控制 vs 媒体接入控制层）、概念笔记索引区格式错误（3 列 vs 实际 2 列 + 分区）、LTE/NR 双侧缺失（NR 图未注 LTE 无 SDAP）、译码主线桥接缺失、术语审计工具 TECH_TERMS 扩展决策——证明拷问在动手前的价值。
4. 豁免：纯信息性问答、已获批准的执行步骤（无新决策点）、单一机械性修改。

**固化**：`3gpp/CLAUDE.md` 第 14 条（项目硬性规则）+ auto-memory `grill-before-planning`（全局会话生效）。
