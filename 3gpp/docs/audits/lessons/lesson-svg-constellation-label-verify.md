# svg-constellation-label-verify

> 星座图的比特标签必须用协议映射式**反推核对**，不能用目查验；「抄成了邻点的标签」这类错误在几何审计与肉眼检查下都完全隐形

2026-11-10 修正 16QAM 映射符号（38.211 §5.1.4 是减号 $2-(1-2b_2)$）时，连带发现基准资产 `docs/L1_基础/assets/T2.1_16qam_constellation_carrier.svg` 的 4 个带标签星座点里有 3 个标签是错的：`1011`、`0100`、`1110` 分别被标在 $(-3,+1)$、$(+3,-3)$、$(-1,-1)$ 上，而按规范应为 `1010`、`0111`、`1100`。

## 根因

1. **错误形态是「抄邻点」**：三个错标恰好都是相邻点的正确标签（`1011` 属 $(-3,+3)$、`0100` 属 $(+1,-1)$、`1110` 属 $(-3,-1)$）。不是符号约定分歧，是搬运时错位。
2. **两道现有防线都不覆盖它**：`audit_svg_layout.py` 只查几何（文字是否越界/重叠/贴边），不查语义；人工目检能看出"文字压线"，看不出"标签与坐标不匹配"——除非当场心算映射式。
3. **基准资产被引用而已**：该图被 `T2.9` 引用，正文只描述"4 个彩色圈"，从未复述标签，所以错误可以长期存活而无人发现。

## How to apply

1. **任何带比特标签的星座图**（SVG 或 Mermaid），生成后必须用脚本做一次 **round-trip 核对**：按协议映射式由坐标反推标签、与图内标签逐点比对，输出 16（或 64/1024）行对照表。脚本可临时写，不必入库，但对照表要贴进交付报告。
2. **正向与反向都要算**：正向（比特串 → 坐标）验证映射式抄写正确；反向（坐标 → 标签）验证图上标签没抄错位。只做正向会漏掉本教训这类错误。
3. **同一张图多处出现标签时要全改**：本次该 SVG 的星座面板与波形面板各有一份标签，只改一处会造成面板间自相矛盾。
4. **改完必须重新渲染 PNG 并目检**：确认两处面板一致、标签与圈/坐标轴不重叠。
5. **交叉锚点**：以 `docs/concepts/Modulation_Constellations_调制星座.md` 与其配图的 16 点标签为权威参照（该图已程序化解析坐标比对，16/16 一致），新图与之对齐即可。
