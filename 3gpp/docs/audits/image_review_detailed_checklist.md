# 图片逐图审核详细清单

审查时间：2026-06-20  
适用范围：`docs/L1/assets/*.png`、`docs/L2_协议算法/assets/*.png`、`docs/L3/assets/*.png`、`tools/figures/*.py`，以及后续新增的 Python/PIL/Matplotlib/Mermaid 转图片资产。

## 审核目标

图片审核不是确认“脚本能运行”或“PNG 没有贴外边界”。每张图必须同时满足：

- **能读懂**：主体文字、表格、标签、图例和说明区在讲义缩放后仍清晰。
- **看起来专业**：标题、表头、关键状态和正文有清楚字重层级，不能整图正文默认加粗。
- **结构清晰**：箭头、节点、表格、说明框、图例和底部区域之间有明确间距。
- **证据完整**：能追溯脚本、输出路径、尺寸、审计命令、目视结论和修复记录。

以下四项必须作为逐图独立结论记录，不能合并成“无遮挡”“目检正常”：

- 字体与上下边框的距离。
- 相邻边框之间的距离。
- 箭头是否正常。
- 连线起始位置是否合理。

箭头项必须进一步看头部是否由实际连线向量或折线最后一段向量生成。水平/垂直专用箭头也不能使用固定方向三角形 helper 后假定永远不会换方向；脚本应能从 start/end 计算线身截断点、箭头尖端和两侧翼点。线身截断点必须沿同一单位向量回退，不能只对 x 方向或 y 方向固定偏移；两侧翼点必须围绕同一个回退点，用最终线段单位向量的法向量对称展开，不能用固定 `±x/±y` 偏移或角度模板让人工无法确认头线一致。目检时要确认线身轴线、箭头头部中轴线、箭头尖端和两侧翼点在同一条直线或同一折线最后一段的几何体系内。

## 审核范围

必须纳入逐图审核：

- 正文已经引用的所有 PNG。
- 后续新增或重生成的所有 PNG。
- 协议表格复现图、协议原图教学重建图、论文结构图、算法流程图。
- 长表图、矩阵图、缓存/ring buffer 图、RTL/ASIC 架构图、测试流程图。
- 用户指出过问题的同类图，不限于原图本身。

不允许只审核用户指出的一张图。修复一个局部后，必须重新审核整张图。

## 自动审核

单图脚本至少执行：

```bash
python3 tools/figures/<script>.py
python3 tools/audit_figure_readability.py tools/figures/<script>.py
python3 tools/audit_figure_geometry.py tools/figures/<script>.py
python3 -m py_compile tools/figures/<script>.py
```

全项目阶段至少执行：

```bash
python3 tools/audit_figure_readability.py tools/figures
python3 tools/audit_figure_geometry.py --focus-only tools/figures
python3 tools/audit_figure_geometry.py tools/figures
python3 -m py_compile tools/figures/*.py
```

自动审核只作为最低门槛。工具输出 `OK` 后仍必须逐图目视审核。

## 目视审核方法

每张图至少检查三种视角：

| 视角 | 怎么看 | 目的 |
|:---|:---|:---|
| 整体缩放 | 打开完整图片，看全局布局。 | 检查读图顺序、区块比例、是否拥挤。 |
| 原始尺寸 | 接近 100% 查看。 | 检查文字贴框、表格单元格、箭头端点。 |
| 风险区域放大 | 对长表、底部说明、密集节点、箭头交汇处单独看。 | 检查自动工具无法发现的局部问题。 |

长图必须看顶部、中部和底部。复杂图必须逐区块看，不允许只看标题区。

## 字号标准

| 对象 | 标准 |
|:---|:---|
| 主体教学文字 | 原则上不低于 `24px`。 |
| 表格正文、表头、首列 | 原则上不低于 `24px`。 |
| 表格行高 | 原则上不低于 `56px`。 |
| 图例正文、说明框正文 | 原则上不低于 `24px`。 |
| 坐标轴刻度、短索引、小地址标签 | 可低于 `24px`，但只能作为辅助信息，并必须有大字号解释区补偿。 |

失败判据：

- 主体文字低于 `24px`。
- 表格为了塞内容压小字。
- 表格行高不足，文字上下拥挤。
- 长表只看顶部，没有复核底部。
- 辅助小字没有说明原因和补偿解释区。

## 字重标准

允许加粗：

- 图片主标题。
- 区块标题。
- 表头。
- 编号、路径名、节点名。
- `selected`、`pass`、`fail`、`pruned`、`kept` 等关键状态。
- 少量需要强调的关键词。

不允许加粗：

- 普通正文。
- 长说明段落。
- 表格正文整列或整表。
- 卡片正文整段。
- 工程检测点正文整段。
- 节点正文默认全加粗。

失败判据：

- 整张图看起来所有文字都很重。
- 表格正文和表头没有层级。
- 正文加粗后贴边或拥挤。
- 绘图函数默认 `bold=True` 用于普通正文。

正确做法：

- 标题、表头、关键状态使用 bold。
- 普通正文、说明段落、表格正文默认 regular。
- 关键状态可以在单元格内单独加粗，不扩大到整行正文。

## 文本框内边距

必须检查：

- 文字到左、右、上、下边界有可见留白。
- **字体到上边框距离**：标题或正文第一行不能贴近上边框；上边距必须明显大于笔画高度造成的视觉误差。
- **字体到下边框距离**：正文最后一行、表格单元格文字、底部说明最后一行不能贴近下边框。
- **字体与上下边框的距离必须单独记录**：每类节点、卡片、说明框、表格单元格、底部说明区都要分别看第一行和最后一行，不能只看图片外边界。
- 第一行不能贴近上边框。
- 最后一行不能贴近下边框。
- 多行正文行距足够。
- 中文、英文、数字混排不贴边。
- 加粗后仍不拥挤。

失败判据：

- 标题或正文靠边框太近。
- 底部说明框最后一行压框底。
- 表格单元格文字上下不居中。
- 圆框、胶囊框、节点框中文字撑满框。

## 边框间距

必须检查所有相邻图元的边框间距：

- **边框间的距离必须单独记录**：节点、卡片、表格、说明框、图例、底部框之间的外边框距离都要检查，尤其是“表格贴近上方框图”和“底部说明贴近表格”。
- 流程节点与流程节点之间有明显空隙。
- 卡片与卡片之间有明显空隙。
- 表格外框与上方框图之间有明显空隙。
- 表格外框与下方说明框之间有明显空隙。
- 图例框、说明框、底部框不接触其他边框。
- 长图中每个大区块之间的边框距离一致或符合读图层级。

失败判据：

- 两个边框视觉上几乎贴在一起。
- 表格顶边离上方流程框太近。
- 底部说明框顶边离表格太近。
- 多个卡片边框间距不均，导致读图顺序混乱。
- 为了塞内容把区块压得过密。

## 居中与对齐

默认必须居中：

- 流程节点。
- 短标签。
- 表格单元格。
- 图例短文本。
- 圆形节点和胶囊标签。
- 状态标签。
- 地址块和候选路径块。

允许左对齐：

- 长段落说明。
- 多条工程检测点。
- 备注区。
- 参考说明。

左对齐区域必须有足够内边距、行距和下边距。

## 箭头和连线

必须检查：

- **箭头是否正常**：箭头头部方向正确、大小适中、没有变形、没有过长或过短、没有压字、没有被框线吞掉。
- **箭头正常性必须单独记录**：不能只写“连线无重叠”，必须确认箭头方向、头部大小、线宽、终止位置和避让文字都正常。
- **箭头头部与线段匹配**：箭头头部中轴线必须沿实际连线方向，斜线箭头不能使用水平/垂直箭头头部，线段应在箭头头部前停止；禁止线段画到箭头尖端后再用三角头覆盖。线身停止点必须沿实际连线单位向量或折线最后一段单位向量计算，不能使用固定水平/垂直偏移造成头部方向与线身方向不共线。
- **箭头形状与路径一致**：直线箭头必须视觉上保持直线；折线/避让线必须由清晰直线段组成，箭头头部只跟最后一段方向一致。不得把普通流程线画成圆滑折线、Bezier、弧线或 `joint="curve"` 风格的似直非直路径；确需曲线时必须说明教学含义或避让理由。
- **箭头路径静态审计**：普通 `arrow()`、`connect_arrow()`、`arrow_between()` helper 内不得混入曲线、弧线、Bezier 或未标注多段路径，也不得用命名变量间接传入三点及以上路径。普通箭头 helper 只能绘制两点直线 shaft；需要折线避让时，必须使用 `polyline_arrow`、`elbow_arrow`、`route_arrow` 等明确命名的避让 helper，且函数名、调用点或审计记录必须说明这是避让路径，并配合穿框断言或等价检查。
- 箭头从源节点真实边界出发。
- 箭头尖端停在目标节点真实边界。
- 线身不进入节点框。
- 箭头不穿过文字。
- 箭头不压住表格、图例或说明框。
- 多条箭头不互相遮挡。
- 连线路径符合读图顺序。
- 跨层线、斜线、折线和反馈线不穿过任何无关节点、卡片、表格或说明框；有 bbox 条件时脚本应加入 segment-rectangle 相交断言，不能只靠人工目检声称“避开”。
- 修改节点尺寸后，箭头端点同步更新。
- **连线起始位置是否合理**：连线应从最符合读图方向的边界出发，例如左右相邻节点优先左右边界，上下相邻节点优先上下边界，斜向节点使用最近边界点；不能机械地全从右侧或中心出线。
- **连线起始位置必须单独记录**：每条关键流程线都要检查源节点出线边界是否符合相对位置和读图方向，不能默认所有线从右侧出发。
- **连线终止位置是否合理**：终点应落在目标框真实边界附近，不能停在框内、框外很远或文字中间。
- **文本框中点锚点规则**：单条箭头连接两个文本框时，起点和终点优先落在对应边中点；左右相邻用右边中点到左边中点，上下相邻用下边中点到上边中点。若必须斜向连接，也应从最接近读图方向的边中点或对称锚点出发，不能使用角点或任意偏移点。
- **多入多出对称规则**：同一文本框同一边有多条入线或出线时，锚点应围绕该边中点等距对称分布；若分布在不同边，也应使用上/下/左/右边中点或对称位置，避免所有线挤在一个非中点位置。
- **直线优先规则**：普通流程箭头应使用直线连接。只有直线会穿过无关文本框、表格、图例或关键文字时，才允许使用折线/曲线避让；避让不能替代端点中点和对称锚点要求。
- **宽聚合框规则**：横向很宽的聚合框、总线框、fanout/fanin 框和 evidence/archive 类宽框，不能用跨越大半张图的长斜线硬连到框边中点。若长斜线穿过视觉中心、压近正文或使箭头形状难以判断，应优先重排布局，让源框与聚合框中心线对齐，使用上下边中点竖直直连或短距离直连。修改布局后必须同步更新全部连线调用并重新目视整图。

推荐实现：

- 使用 `boundary_point()`、bbox helper 或等价计算。
- 使用 `edge_midpoint()`、`symmetric_edge_points()` 或等价 helper 生成中点/对称锚点。
- 对宽聚合框使用中心线对齐或短直连布局，避免远距离长斜线连接宽框中点。
- 使用向量单位方向和法向量生成箭头头部，不能只按水平/垂直分支画斜线箭头；两个翼点必须由同一回退点加减法向量得到，不能混用固定偏移。
- 对已知 bbox 的节点、卡片、表格和说明框，加入 `segment_intersects_rect()`、`assert_no_unrelated_crossing()` 或等价检查；折线/曲线路径应逐段检查。
- 避免纯手工固定坐标。
- 避免把普通流程线改成折线；需要折线时记录原因，并确认使用的是命名避让 helper 而不是普通 `arrow()` helper 内部的多点路径。
- 不靠白色遮罩隐藏穿框线。

失败判据：

- 箭头进入框内。
- 箭头压字。
- 箭头方向与读图方向相反。
- 箭头头部方向与斜直线不匹配。
- 箭头头部过大压到节点或过小看不清。
- 箭头形状与实际路径类型不匹配，例如线身看起来是曲线而审计记录写直线，或折线头部没有沿最后一段方向。
- 普通 `arrow()` helper 内部用三点及以上 list/tuple 或命名变量画多段路径，导致审计记录写“直线”但视觉上不是直线。
- 连线穿过无关模块。
- 折线/曲线某一段穿过无关模块，或避让原因未记录。
- 箭头端点离目标边界过远。
- 所有箭头机械地从同一侧出线，导致路线不自然。
- 单条连线没有落在文本框对应边中点。
- 多条入线/出线没有围绕边中点对称分布。
- 文本框尺寸变化后沿用旧锚点，导致端点偏离中点或对称位置。
- 普通流程箭头被不必要地画成折线或曲线。

## 表格块

表格必须单独审核：

- 表头、首列和正文有清楚层级。
- 字号满足 24px+。
- 行高满足 56px+。
- 列宽足够。
- 单元格文字水平和垂直居中。
- 长字段不硬拆。
- 表格与上方框图之间有明显间距。
- 表格与下方说明之间有明显间距。
- 表格底部不贴图片底边。

失败判据：

- 表格字明显小于图中其他正文。
- 表格密度太高。
- 单元格文字上下不居中。
- 英文 token 被硬拆，例如 `process` 拆成 `proc` 和 `ess`。
- 表格和上方图块接触或距离过近。

## 底部区域

底部区域必须单独审核：

- 底部说明框离图片底边足够远。
- 框内最后一行不压底。
- 说明区和上方表格/图块有明显间隔。
- 脚注不贴边。
- “读图顺序”“工程检测点”“风险”不能拥挤。
- 底部说明正文不能全文加粗。

失败判据：

- 底部说明框贴边。
- 最后一行接近框线。
- 说明区和上方图表接触。
- 说明区比例失衡。
- 说明区太小导致内容拥挤。

## 长图和协议表

长图、协议复现表、完整序列表要额外检查：

- 顶部、中部、底部均已目视。
- 图片宽度足够，不能挤窄列。
- 行高不低于标准。
- 表头清楚。
- 必要时分组、分段或拆图。
- 底部有证据说明。
- Markdown 插入后仍可阅读。

失败判据：

- 为了完整复现协议表而压小字。
- 只贴长表，没有解释列含义。
- 表格底部证据文字太小或贴边。
- 只审核顶部，没有看底部。

## 协议图表复现

若图片复现协议或论文内容，额外检查：

- 正文说明 TS 编号、Release、章节、图表号。
- 本地证据路径明确。
- 教学重绘必须说明“教学重建”或“本地复现”。
- 图中字段与正文协议解释一致。
- 若只复现子集，必须说明子集范围和原因。
- 图下方或正文说明读图顺序、每列含义、每块含义。

失败判据：

- 只给链接，不复现本节依赖的图表内容。
- 表格列名没有解释。
- 协议图重绘没有证据路径。
- 教学图和协议原图边界不清。
- 图中字段与正文不一致。

## 颜色和视觉层级

必须检查：

- 同类对象颜色一致。
- 颜色有语义，不作纯装饰。
- pass/fail/selected/pruned 清楚区分。
- 背景色不影响文字对比度。
- 红色用于失败、风险、剪枝等语义。
- 绿色用于通过、保留、有效等语义。
- 蓝色可用于流程、表头、协议对象。
- 图例颜色和图中颜色一致。

失败判据：

- 颜色太花但没有语义。
- 低对比度导致文字不清楚。
- 同一含义使用多种颜色。
- 不同含义使用同一颜色且无说明。

## 内容完整性

图片必须支持正文教学目标：

- 覆盖本节 prompt 点名的图形要求。
- 图中对象与正文解释一致。
- 图中缩写在正文有解释。
- 图中关键变量在正文有定义。
- 图能帮助零基础读者理解，不只是协议索引。
- 有读图顺序或工程检测点。
- 有协议证据或边界说明。

失败判据：

- 图只是协议索引，没有教学解释。
- 图中出现关键对象但正文没有解释。
- 图中流程和正文接收端流程不一致。
- prompt 要求的图形内容没有覆盖。

## 审核结论分级

| 结论 | 含义 |
|:---|:---|
| `PASS` | 自动审计通过，目视审核通过，无明显风险。 |
| `PASS_WITH_NOTE` | 可接受，但有明确说明的辅助例外。 |
| `FIX_REQUIRED` | 存在可局部修复的问题，例如贴框、全加粗、箭头进框、表格太近。 |
| `REDRAW_REQUIRED` | 结构性问题，局部修不动，需要重画或重排。 |

必须修复：

- 主体字小于 24px。
- 表格行高不足。
- 正文全加粗。
- 文字贴边。
- 表格文字不居中。
- 箭头进入框内或压字。
- 图块互相遮挡。
- 底部说明贴边。
- prompt 图形内容未覆盖。
- 协议图表缺证据路径。

## 全项目执行顺序

1. 列出全项目 PNG 清单。
2. 建立图片到脚本的映射。
3. 全量运行自动审计。
4. 逐张打开原图目视审核。
5. 对 `FIX_REQUIRED` 和 `REDRAW_REQUIRED` 逐张修复。
6. 修复后重生成图片。
7. 重新运行自动审计。
8. 重新目视审核修复图。
9. 生成最终逐图审核报告。
10. 更新 `docs/audits/image_asset_inventory.md`、`docs/audits/lte_nr_decoding_remaining_work_register.md` 和相关讲义证据记录。
