# L0 深度提问指导

把一次普通概念问答升级为"协议全景 + 分层职责 + 联系链"的深度问答。来源：2026-08-25 用户以「导频是什么」为例提出的问题——「你会列出所有涉及它的 3GPP 资料吗？每个协议讲了哪一部分？它们之间的联系是什么？」——被证实能一次性带出完整协议地图，固化为本模板。

## 提问模板（四步）

对任意协议概念 $X$（导频、交织器、HARQ、速率匹配……），按以下四步提问：

1. **概念是什么**：$X$ 是什么？它解决什么问题？
2. **协议分布**：列出 3GPP 协议族中**所有涉及 $X$ 的资料**（TS 编号 + 章节），每个协议讲了 $X$ 的哪一部分？
3. **分层职责**：这些协议之间按什么逻辑分工？（生成 → 配置 → 调度/触发 → 测量 → 验收）
4. **联系链**：它们之间的联系是什么？从定义到工程验收的完整链条如何串起来？

### 四步提问的通用措辞

> 如果我问"$X$ 是什么"，你能列出所有涉及 $X$ 的 3GPP 资料吗？每个协议讲了 $X$ 的哪一部分？它们之间的联系是什么？

## 完整示例：导频（pilot）

> 如果我问"导频是什么"，你能列出所有涉及导频的 3GPP 资料吗？每个协议讲了导频的哪一部分？它们之间的联系是什么？

### 回答骨架（对应四步）

| 步骤 | 内容 | 落点 |
|:---|:---|:---|
| 1 概念 | 导频 = 收发双方都已知的参考符号，接收端用它反推信道；NR 中正式名称为参考信号（Reference Signal, RS） | [[Pilot_导频]] |
| 2 协议分布 | TS 38.211（序列/映射）、TS 38.213/214（触发/接收过程）、TS 38.215（RSRP/RSRQ/SINR）、TS 38.331（配置 IE）、TS 38.101/104/133（功率/精度）；LTE 侧 TS 36.211/213/214/331 对应 | 各协议本地 `3GPP_Rel19/processed/` 目录 |
| 3 分层职责 | 物理信道层讲"是什么、放哪"；过程层讲"何时用哪个"；测量层讲"怎么量化"；RRC 讲"具体参数"；性能规范讲"要多准" | [[Pilot_导频]] 的"导频在协议族中的分布（五层职责）"小节 |
| 4 联系链 | 生成 → 配置 → 调度/触发 → 测量 → 验收；LTE 广播式 CRS vs NR 按需式 DM-RS/CSI-RS/PTRS/TRS/SRS 两代哲学 | [[CRS_小区特定参考信号]]、[[DMRS_解调参考信号]]、[[CSI_RS_信道状态信息参考信号]] |

## 适用范围与边界

- **适用**：跨协议层的协议概念（物理信号/信道/编码步骤/过程机制）——它们天然分布在多个 TS 中，四步模板能还原完整协议地图。
- **不适用**：纯数学概念（如 LLR 定义、贝叶斯公式）、纯工程概念（定点位宽）——它们没有"协议分布"维度，强行套模板反而啰嗦。
- **与 Q&A 流水线的关系**：本模板是**提问侧**的升级（用户怎么问）；Q&A 流水线（CLAUDE.md 第 15 条）是**回答侧**的沉淀机制（命中计数、扩充/新建、排名表）。两者配合：按本模板提问 → 按流水线处理命中 → 若概念笔记缺"协议分布"维度则按导频先例扩充。
- **复用先例**：交织器家族问题（2026-08-25）按同构方式沉淀为 [[Interleaver_交织器]] 全景笔记——四步模板同样适用于"一个主题家族"的提问（把 $X$ 换成"交织算法"）。
