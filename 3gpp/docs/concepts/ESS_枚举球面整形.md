# ESS 枚举球面整形

## 符号与记号约定

| 符号 | 含义与取值 | 协议锚点 |
|:---|:---|:---|
| $n$ | 序列长度，即一个整形块内的幅度符号个数；取正整数，量纲一 | 由 TS 38.212 §5.2.2 导出（块分段给出的块粒度） |
| $i$ | 幅度符号在序列中的序号，取 $1$ 到 $n$ 的整数，量纲一 | 非 3GPP 标准（序列下标） |
| $a$ | 单个幅度符号的取值，属于幅度字母表；取奇数电平，量纲一 | 非 3GPP 标准（ESS 的幅度字母表） |
| $\mathcal{A}$ | 幅度字母表，即全部允许幅度取值的集合，元素个数有限、每个元素取奇数电平，量纲一 | 非 3GPP 标准（ESS 的幅度字母表） |
| $a_i$ | 序列中第 $i$ 个幅度符号，取值来自 $\mathcal{A}$，量纲一 | 非 3GPP 标准（ESS 的序列记号） |
| $a_i^2$ | 第 $i$ 个幅度符号的平方，即该符号贡献的能量；取非负整数，量纲一 | 非 3GPP 标准（能量口径） |
| $E_{\max}$ | 一个整形块允许的总能量上限，以整数能量单位计；取正整数，量纲一 | 非 3GPP 标准（ESS 的能量约束） |
| $\text{count}(n,e)$ | 动态规划计数表的表项，表示长度为 $n$、已用能量索引为 $e$ 的序列个数；取非负整数，量纲一 | 非 3GPP 标准（ESS 的计数表） |
| $\mathcal{S}(n,E_{\max})$ | 能量球约束下的可用序列集合，即长度为 $n$、总能量不超过 $E_{\max}$ 的全部幅度序列，元素个数有限，量纲一 | 非 3GPP 标准（ESS 的序列集合） |
| $O(\cdot)$ | 算法复杂度记号，$O(n)$ 表示运算量随 $n$ 线性增长，$O(1)$ 表示与 $n$ 无关；量纲一 | 非 3GPP 标准（复杂度记号） |

计数表的两个自变量 $n$ 与 $e$ 分别对应"还剩几个符号"与"还剩多少能量"，表中的每个数字都是这两种剩余状态的组合数；$e$ 是整数能量索引而非自然常数。各行来源统一写在第三列：协议量给 TS 条款号，派生量给「由 TS … §… 导出」，非协议量给「非 3GPP 标准」或「实现域」。

ESS（Enumerative Sphere Shaping）是概率整形采用的 DM 实现：在"总能量不超过上限"的能量球约束下，用 DP 计数表把均匀 bit（转成 rank）可逆地映射为非均匀幅度序列。一句话本质：**ESS 是"按编号查目录"——DP 计数表是目录索引，均匀 bit 组成大编号（rank），编码时逐位按编号翻目录选幅度、解码时沿原路累加翻回编号；能量球约束像"购书预算"，预算内组合比固定页数（CCDM）多得多，浪费的编号（rate loss）更小**。

## 解释目标与范围

本节目标：解释 ESS 如何在能量球约束下用 DP 计数表把均匀 bit 可逆映射为非均匀幅度序列，以及它相对 CCDM 的 rate loss 优势与硬件可实现性。

## 前置概念

**概率整形**（Probabilistic Shaping）指在不改变星座点位置的前提下，通过改变各星座点被选中的概率来逼近高斯分布、从而获得成形增益的技术。它作用在符号出现的频率上，而不是符号的几何位置上；因此它可以与任何调制阶数、任何纠错码组合使用，代价是发送端需要一个把均匀比特映射为非均匀符号的装置。

**分布匹配**（Distribution Matching, DM）指把均匀分布的输入比特可逆地映射为具有目标概率分布的符号序列的装置。它要求映射可逆、可硬件实现、且引入的冗余尽量小；不同的分布匹配方案在这三条上各有取舍，枚举类方案把"可逆"落在编号与序列的一一对应上。

**能量球约束**（Energy Sphere Constraint）指只允许总能量不超过上限的序列参与映射，全部合格序列构成一个高维球内的整数点集合。与固定每个幅度出现次数的组成约束相比，能量球约束只限制总和、不限制各幅度的配额，因此合格序列更多、同样长度下能承载的编号更多。

**枚举编码**（Enumerative Coding）指用序号与序列的一一对应完成编解码的方法：编码时按序号逐位决定每个位置取哪个幅度，解码时沿序列逐位累加还原序号。枚举编码不需要查找表保存全部序列，只需要一张记录"剩余位置与剩余能量下有多少种组合"的计数表，因此存储量随长度与能量线性增长。

**速率损失**（Rate Loss）指分布匹配引入的冗余，等于理论上可承载的比特数与实际可区分编号数之差。合格序列集合越大，可用的编号越多，浪费的编号比例越小；这就是能量球约束相对固定组成约束的优势所在，也是 ESS 在同样块长下效率更高的原因。

## 起源与演进

(1) **起点：DM 的实现选择。** DM 需要可逆映射 + 可硬件实现——CCDM（固定组成）rate loss 偏大，需要一个更优实现。

(2) **能量球约束。** 总能量 ≤ E_max 的序列都可入选——集合比 CCDM 固定组成大得多 → 同样长度可区分序列更多 → rate loss 更小。

(3) **DP 计数表引擎。** $\text{count}(n,e) = \sum_a \text{count}(n-1, e-e(a))$——避免枚举全部序列；整数能量映射（$(a^2-1)/8$）供索引；表 ~129×256 约 264 KB 定点存储。

(4) **rank 编解码。** 编码：逐符号沿 DP 表选路径（比较 rank 与分支计数、扣减）$O(n)$；解码：逆路径累加 $O(1)$ 查表——解码比编码轻。

(5) **边界。** 无纠错 → inverse ESS 必须在 LDPC/CRC 之后；按 nMax 分块（300 → 128+128+44）、残差块按偶数化规则——ESS block ≠ 标准 CB。

## 科学定义

能量球约束定义可用的幅度序列集合：总能量不超过上限 $E_{\max}$ 的序列都可以入选——

$$\mathcal{S}(n, E_{\max}) = \left\{ \mathbf{a} \in \mathcal{A}^n : \sum_{i=1}^n a_i^2 \le E_{\max} \right\}$$

集合大小决定每块能编码的 bit 数。与固定组成的 CCDM 相比，能量球约束的序列集合大得多——同样长度，可区分序列更多 → rate loss 更小；且 DP 表可定点化、硬件可实现——rate loss 与可实现性的综合最优，这就是选 ESS 而不选 CCDM 的原因。

实现要点：

- **整数能量**：幅度 {1,3,5,7} 映射到整数能量 $(a^2-1)/8 \to \{0,1,3,6\}$——DP 表需要整数索引。
- **DP 计数表**：$\text{count}(n,e) = \sum_a \text{count}(n-1, e-e(a))$——避免枚举所有序列；表大小 ~129×256，实测约 264 KB（mantissa/exponent 定点存储）。
- **编码（rank → 序列）**：逐符号沿 DP 表选路径（比较 rank 与候选分支计数、扣减）——O(n) 每块；**解码（序列 → rank）**：逆路径累加——$O(1)$ 查表，解码比编码轻。
- **分块与残差**：标准 CB 可能很长，按 nMax 分块（如 300 → 128+128+44），残差块按偶数化规则处理——ESS block ≠ 标准 CB。
- **错误传播**：ESS 无纠错；幅度错一位 → rank 累加分支改变 → 恢复 bit 可能大面积错——所以 inverse ESS 必须在 LDPC/CRC 之后。

## 直观模型

ESS 像"按编号查目录"：DP 计数表是目录索引，均匀 bit 组成一个大编号（rank），编码时逐位按编号翻到对应分支选出幅度符号，解码时沿原路累加把序列翻回编号。能量球约束像"购书预算"——只收录总价不超预算的组合；预算内的组合比固定页数（CCDM）多得多，编号空间更大，浪费的编号（rate loss）更小。

## 常见误解

| 误解 | 正确理解 |
|:---|:---|
| ESS 的"球"和 MIMO 球面检测的"球"是一回事 | ESS 的球是发射端幅度序列的能量约束（$\sum a_i^2 \le E_{\max}$）；MIMO sphere detector 的球是接收端检测的搜索空间——两个完全不同的东西 |
| ESS 有纠错能力 | ESS 无纠错，幅度错一位会导致恢复 bit 大面积错——inverse ESS 必须放在 LDPC/CRC 之后 |
| ESS 块就是标准 CB | 标准 CB 很长时按 nMax 分块（如 300 → 128+128+44），残差块按偶数化规则处理——ESS block ≠ 标准 CB |
| ESS 是 3GPP 标准流程 | ESS 是非 3GPP 标准（6G 候选），协议只提供 TB/CB 粒度接口锚点 |

## 协议锚点

- TB/CB 粒度：TS 38.212 §5.2.2（接口锚）。
- **ESS 本身：非 3GPP 标准，无标准小节**。
- 仿真器实现：`+ProbShaping/+ess/`（ess.m、encode/decode.m、generateEnergyTable.m、dec2binFloat.m）。

## 协议分布与边界（ESS 的协议族位置）

ESS 本身是 6G 候选技术，**不落入任何 TS 小节**——它只在块粒度上贴靠标准接口：

| 协议 | 讲了 ESS 的哪个方面 |
|:---|:---|
| TS 38.212 §5.2.2 | TB→CB 分段粒度——ESS block 按 nMax 分块、残差块按偶数化规则处理，贴此接口对齐；inverse ESS 必须位于 LDPC/CRC 之后的顺序纪律也由此节锚定 |

**联系链**：212 固定"块粒度与顺序"（ESS 必须贴的部分）→ ESS 的全部自由度（能量球约束/DP 计数表/rank 映射/定点存储）都在标准之外实现——与 PS 同一条边界纪律：**接口贴标准、算法在标准外**。

## 关键要点

1. ESS = DM 的能量球实现：Σa_i² ≤ E_max 的序列集合。
2. 集合比 CCDM 大 → rate loss 更小——选 ESS 不选 CCDM 的原因。
3. DP 计数表避免枚举：表 ~129×256 约 264 KB 定点存储。
4. 编码 $O(n)$ 选路径、解码 $O(1)$ 查表——解码比编码轻。
5. ESS 无纠错——inverse 必须在 LDPC/CRC 之后。
6. ESS 的"球"与 MIMO 球面检测的"球"完全不同。
