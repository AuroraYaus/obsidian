# Power Control 上行功率控制

## 符号与记号约定
| 符号 | 含义与取值 | 协议锚点 |
|:---|:---|:---|
| $P_0$ | 目标接收功率基准，即开环工作点，由小区级标称功率与 UE 级偏移两部分相加构成，取实数、单位为 dBm，由 RRC 的 p0-PUSCH-AlphaSet 配置 | TS 38.213 §7.1.1 |
| $\alpha$ | 路损补偿系数，取 0 至 1 的无量纲实数，取 1 为全补偿、小于 1 为部分补偿，由 RRC 的 p0-PUSCH-AlphaSet 配置 | TS 38.213 §7.1.1 |
| $PL$ | 下行路径损耗估计，取正实数、单位为 dB，由 UE 用参考信号的发射功率与实测参考信号接收功率之差推算 | TS 38.213 §7.1.1 |
| $\Delta_{\mathrm{TF}}$ | 传输格式补偿项，按调制编码方案与码块参数算出的功率修正量，取实数、单位为 dB | 由 TS 38.213 §7.1.1 导出 |
| $TPC$ | 发射功率控制命令，即下行控制信息中 2 bit 字段所载的功率调整量，取 -1、0、+1、+3 dB 等离散值，单位为 dB | TS 38.212 §7.3.1.1.1 |
| $f$ | 闭环功率调整状态，即 TPC 命令的累计项，取实数、单位为 dB，累加后在协议规定的上下限内饱和 | 由 TS 38.213 §7.1.1 导出 |
| $P$ | 一条上行信道发射功率的简记，取实数、单位为 dBm，为 $P_0 + \alpha\cdot PL + \Delta_{\mathrm{TF}} + f(\mathrm{TPC})$ 各项之和并受终端最大发射功率限制 | 非 3GPP 标准 |
| $P_{\mathrm{PUSCH}}$ | 一个 PUSCH 传输时机上的发射功率，取实数、单位为 dBm，由功率控制公式按开环项、路损项、格式项与闭环项逐项合成 | TS 38.213 §7.1.1 |

运算符与记号惯例：$\cdot$ 表示乘法，$+$ 在功率域表示 dB 值相加（等价于线性功率相乘）；下标 PUSCH 表示该量属于物理上行共享信道，不是变量相乘，$P_{\mathrm{PUSCH}}$ 读作「PUSCH 的发射功率」；$P_0$ 的下标 0 是参数集编号的固定写法，与时刻无关；公式中各量一律以 dB 或 dBm 为单位相加，因此公式本身就是一条「对数域求和」的算式。

上行功率控制（Power Control）决定 UE 用多大功率发射：既不能太小（基站收不到），也不能太大（干扰邻区、浪费电池）。它分两层——开环（open-loop）按路损补偿粗略定功率，闭环（closed-loop）用 TPC（发射功率控制命令，Transmit Power Control Command）逐次微调；PHR（功率余量报告，Power Headroom Report）把 UE 的功率余量反馈给调度器。功控是上行链路与下行最大的机制差异之一（下行固定功率、上行闭环调节）。一句话本质：**上行功控由三条机制合成——开环按路损估算基准，闭环按网络测量修正基准，功率余量报告把剩余可提升空间上报给网络**。

## 解释目标与范围

本节目标：讲清开环/闭环两层功控机制、功控公式的组成项（P0/α/PL/ΔTF/f）、TPC 命令的累计与 DCI 携带方式、PHR 的作用，以及功控与调度（Scheduler）的联动。

## 前置概念

上行共享信道（Physical Uplink Shared Channel, PUSCH）。承载上行用户数据的物理信道，它与下行共享信道最大的差别在于上行由 UE 自主发射，功率必须按 UE 逐个调节；上行控制信息走物理上行控制信道，两者的功控参数集各自独立，见 [[PUCCH_上行控制信道与UCI]]。

路径损耗（Path Loss, PL）。发射功率与接收功率之间因传播距离、阴影衰落与穿透损耗产生的衰减量，单位 dB。UE 在下行测量参考信号的接收功率，再与该参考信号的标称发射功率相减得到路损估计，开环功控就按这个估计做补偿；路损估得准不准，直接决定开环工作点偏高还是偏低。

下行控制信息（Downlink Control Information, DCI）。物理下行控制信道承载的控制信令，闭环功控的执行通道是其中一个 2 bit 的发射功率控制命令字段。UE 每个监测时机盲检 DCI，取出该字段后按累计或绝对方式更新功率调整状态，见 [[DCI_下行控制信息]]。

功率余量（Power Headroom, PH）。终端当前可用于提升发射功率的余量，即最大发射功率与当前发射功率之差，单位 dB。它由 MAC 层的功率余量报告上报给基站，基站据此判断还能否加大调制编码方案或带宽，见 [[Scheduler_MAC调度器与资源分配]]。

链路自适应（Link Adaptation）。按信道质量调整调制编码方案与资源分配的过程。上行链路自适应有两个可调维度：资源维度由调度器决定，功率维度由功控决定，两者共同决定基站侧的接收信噪比，见 [[Link_Adaptation_链路自适应与CQI]]。

## 起源与演进

(1) **起点：上行与下行的不对称。** 下行功率由基站统一管理，多用户共享、干扰可控；上行每个 UE 独立发射——近处 UE 功率过大会淹没远处 UE（远近效应，见 [[Multiple_Access_多址接入]]），过小则基站收不到。于是上行必须逐 UE 调节功率，这是上下行之间最大的机制差异之一。

(2) **开环：按路损粗略对齐。** UE 测量下行路损（PL，从参考信号功率与实测接收功率推算），按 `P0 + α·PL` 补偿——没有反馈的粗调，先把功率放到"差不多"的起点。

(3) **闭环：TPC 逐次微调。** 基站根据实际接收 SINR 在 DCI 里发 2-bit TPC 命令（-1/0/+1/+3 dB 等），UE 累计到 f 项——精细校正。TPC 就是闭环的执行通道，经 [[DCI_下行控制信息]] 下发。

(4) **公式与参数：四项一价。** $P = P_0 + \alpha\cdot PL + \Delta_{TF} + f(TPC)$：P0 是目标接收功率基准、α 是路损补偿系数（α<1 部分补偿在干扰受限场景反而更优）、ΔTF 按 MCS 补偿传输格式、f 是 TPC 累计项；PUCCH/SRS/PRACH 各有独立参数集（TS 38.213 §7.2/§7.3/§7.4）。

(5) **PHR 收口：把余量告诉调度器。** UE 周期性或触发式上报"最大功率 − 当前发射功率"的余量（MAC 层，TS 38.321 §5.4.6）——调度器据此决定能否加大 MCS/带宽。功控由此与调度闭环衔接：功率维度是链路自适应的上行镜像。

## 科学定义

### 上行功控的必要性

下行功率由基站统一管理（多用户共享、干扰可控）；上行每个 UE 独立发射——近处 UE 功率过大淹没远处 UE（远近效应，见 [[Multiple_Access_多址接入]]），功率过小基站收不到。功控让每个 UE 的到达功率恰到好处。

### 开环与闭环

- 开环（open-loop）：UE 测量下行路损（PL，路径损耗，Path Loss，从 RS 功率与实测接收功率推算），按 `P0 + α·PL` 补偿——粗略对齐，无反馈。
- 闭环（closed-loop）：基站根据实际接收 SINR（信干噪比，Signal-to-Interference-plus-Noise Ratio）发 TPC 命令（+1/-1 dB 等），UE 累计调整（f 累计项）——精细校正。

### 功控公式（PUSCH 为例，TS 38.213 §7.1 简化式——省略带宽/子载波间隔项与闭环进程索引）

$$
P_{\mathrm{PUSCH}} = P_0 + \alpha \cdot PL + \Delta_{\mathrm{TF}} + f(\mathrm{TPC})
$$

| 项 | 含义 | 来源 |
|:---|:---|:---|
| P0 | 目标接收功率基准 | RRC 配置（开环偏置） |
| α | 路损补偿系数（0-1，部分补偿省干扰） | RRC 配置 |
| PL | 下行路径损耗估计 | UE 测量 |
| ΔTF | 传输格式补偿（MCS（调制与编码方案，Modulation and Coding Scheme）相关） | 按 MCS 查表 |
| $f(TPC)$ | 闭环累计项（TPC 命令累加，含饱和） | DCI 的 TPC 字段（见 [[DCI_下行控制信息]]） |

PUCCH（物理上行控制信道，Physical Uplink Control Channel）/SRS（探测参考信号，Sounding Reference Signal）/PRACH（物理随机接入信道，Physical Random Access Channel）各有独立功控参数集（TS 38.213 §7.2/§7.3/§7.4）。

### TPC 与 PHR

- TPC：DCI 里的 2-bit 字段（见 [[DCI_下行控制信息]] 字段表），发 TPC 命令（-1/0/+1/+3 dB 等），UE 按累积项 f 调整——这就是「闭环」的执行通道。
- PHR（功率余量报告，Power Headroom Report）：UE 周期性/触发式上报「最大功率 - 当前发射功率」的余量（MAC 层，TS 38.321 §5.4.6）——调度器据此决定是否给 UE 分配更多资源（余量足=可加大 MCS/带宽）。

## 直观模型

三条机制解决同一问题的三个侧面：开环按目标接收功率与路损估算基准发射功率，闭环依据网络的上行测量结果对基准做累积或绝对修正，功率余量报告把终端剩余的可提升空间上报给网络。三者配合使接收功率贴近目标值，既满足解调所需信噪比，也不把发射功率推高到对邻区造成额外干扰的程度。

## 常见误解

| 误解 | 正确理解 |
|:---|:---|
| 上行功控和下行一样 | 下行固定功率+调度控制，上行闭环功控（开环+闭环两层） |
| 功控只在物理层 | TPC 在 DCI（物理层），PHR 在 MAC 层（TS 38.321）——跨层机制 |
| α=1 一定最好 | 部分补偿（α<1）在干扰受限场景反而更优（减少对邻区干扰） |
| PHR 越大越好 | PHR 大说明有功率余量，调度器可加大资源；但长期满功率说明覆盖边缘 |

## 关键要点

1. 上行功控分两层：开环（P0+α·PL 粗对齐）+ 闭环（TPC 微调）。
2. 公式 $P=P_{0}+\alpha\cdot PL+\Delta_{TF}+f(TPC)$；$\alpha<1$ 部分补偿在干扰受限场景更优。
3. TPC 是 DCI 的 2-bit 字段，UE 累计到 f 项——闭环的执行通道。
4. PHR 在 MAC 层（TS 38.321 §5.4.6），把功率余量反馈给调度器决定资源。
5. 下行固定功率、上行闭环调节——上下行最大机制差异之一。
6. PUCCH/SRS/PRACH 各有独立功控参数集（TS 38.213 §7.2/§7.3/§7.4）。
