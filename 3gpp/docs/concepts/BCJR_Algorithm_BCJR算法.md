# BCJR / MAP 译码算法

## 符号与记号约定

| 符号 | 含义与取值 | 协议锚点 |
|:---|:---|:---|
| $k$ | 时间步序号，即网格的深度下标，取整数、无量纲 | 非 3GPP 标准（网格时间下标） |
| $s$ | 网格状态，取状态集中的一个元素，无量纲；带撇的 $s'$ 表示同一状态集里的另一个状态 | 由 TS 36.212 §5.1.3.2.1 的卷积码网格结构导出 |
| $\gamma_k$ | 第 $k$ 步的分支度量，即从状态 $s'$ 转移到状态 $s$ 的证据；概率域取 $[0,1]$ 的实数，对数域取实数，量纲一 | 实现域（接收机算法，TS 36.212 不规定度量定义） |
| $\gamma_{k+1}$ | 第 $k+1$ 步的分支度量，与 $\gamma_k$ 同一定义换到下一步；量纲一 | 实现域（接收机算法） |
| $\alpha_{k-1}$ | 第 $k-1$ 时刻的前向度量，累积从起点到该时刻的全部路径证据；非负实数（概率域）或实数（对数域），量纲一 | 实现域（接收机算法） |
| $\alpha_k$ | 第 $k$ 时刻、状态 $s$ 的前向度量，递推式为 $\alpha_k(s)=\sum_{s'}\alpha_{k-1}(s')\gamma_k(s'\to s)$；量纲一 | 实现域（接收机算法） |
| $\beta_{k+1}$ | 第 $k+1$ 时刻的后向度量，累积从终点回退到该时刻的全部路径证据；非负实数（概率域）或实数（对数域），量纲一 | 实现域（接收机算法） |
| $\beta_k$ | 第 $k$ 时刻、状态 $s$ 的后向度量，递推式为 $\beta_k(s)=\sum_{s'}\beta_{k+1}(s')\gamma_{k+1}(s\to s')$；量纲一 | 实现域（接收机算法） |
| $u_k$ | 第 $k$ 个信息比特，取 0 或 1，单位 bit | 由 TS 36.212 §5.1.3.2.1 的信息比特定义导出 |
| $L$ | 后验对数似然比，即 $L(u_k)$；实数，取值 $(-\infty,+\infty)$，量纲一，符号给判决方向、绝对值给可靠度 | 实现域（接收机算法，TS 36.212 不规定输出形式） |
| $a$ | $\max^*$ 修正项的第一个实数操作数，量纲一 | 非 3GPP 标准（对数域运算记号） |
| $b$ | $\max^*$ 修正项的第二个实数操作数，量纲一 | 非 3GPP 标准（对数域运算记号） |
| $e^{-\lvert a-b\rvert}$ | 修正项的指数因子，取值 $(0,1]$，量纲一；差值越大取值越接近 0 | 非 3GPP 标准（对数域运算记号） |

修正项中的绝对值有两种等价写法，$\lvert a-b\rvert$ 与 $|a-b|$，因而修正项既可写作 $\ln(1+e^{-\lvert a-b\rvert})$，也可写作 $\ln(1+e^{-|a-b|})$，两种写法逐项相同。递推式中的 $\sum_{s'}$ 表示对状态 $s'$ 求和，$\to$ 表示状态转移方向。各行来源统一写在第三列：协议量给 TS 条款号，派生量给「由 TS … §… 导出」，非协议量给「非 3GPP 标准」或「实现域」。

BCJR 是最优逐比特 MAP（最大后验概率，Maximum A Posteriori）译码算法，在网格图上运行前向 α 和后向 β 递归，输出每个信息比特的后验对数似然比（Log-Likelihood Ratio, LLR）。一句话本质：**BCJR 是"双向路网巡游"——α 从起点向终点累积证据、β 从终点向起点累积证据，两条证据在每条边上会合，才得到该比特的可靠度**。

## 解释目标与范围

本节目标：解释 BCJR 为什么能给出最优逐比特判决，以及 Log-MAP 与 Max-Log-MAP 两种工程实现之间的精度与复杂度取舍。

## 前置概念

**网格图**（Trellis）是把编码器的状态按时间步展开后得到的图：每一列对应一个时间步，列中的节点是该步可能的编码器状态，相邻两列之间的边表示一次状态转移并携带该步的输出。网格把"序列的枚举"压缩成"路径的枚举"，一条从起点到终点的路径就是一个合法码字，这一表示是前向与后向递推能够成立的结构前提。

**状态**（State）指编码器在当前时刻携带的历史信息，对递归系统卷积码而言是移位寄存器中残存的比特。状态数是有限的，因此网格每一列的节点数固定；状态转移只依赖当前状态与当前输入比特，这一马尔可夫性使"路径证据"可以按步累乘而不必回看整条路径。

**分支度量**（Branch Metric）是单步转移的证据，把该步收到的信道观测与该步应有的输出相比较，输出越吻合度量越大。前向度量把从起点到某状态的所有路径的分支度量累乘（对数域累加），后向度量把从终点回退到该状态的所有路径的分支度量累乘；两者在同一条边上会合，才构成该边的完整证据。

**对数域与 log-sum-exp**（Log Domain）指用度量对数代替度量本身做运算，乘法变加法、连乘变连加，数值范围也从指数级压低到线性级。多个分支求和在对数域变成 log-sum-exp，其精确形式由一个修正项给出；丢掉落这个修正项就是 Max-Log-MAP，保留它就是 Log-MAP，两者的差别只在求和近似精度。

**后验概率与逐比特 MAP**（A Posteriori Probability）指在收到整段观测之后，某信息比特取 0 或取 1 的概率。逐比特 MAP 译码取两个后验概率之比的对数作为软输出：比值为正判 0、为负判 1，比值绝对值反映可靠度。BCJR 用前向与后向度量求出这个比值，因此输出的是逐比特软信息，可直接进入 Turbo 迭代。

## 起源与演进

(1) **起点：Viterbi 的局限。** 序列级硬判决译码（Viterbi）找最可能的整条路径，但 Turbo 迭代需要逐比特的软可靠度。1974 年 Bahl、Cocke、Jelinek、Raviv 四人提出逐比特 MAP 算法（BCJR），输出每个信息比特的后验 LLR——Turbo 迭代的软信息引擎由此而来。

(2) **机制：双向路网。** 网格图上 α 前向递归累积"至此路径的证据"，β 后向递归累积"此后路径的证据"；一条边的总证据 = 两段证据 × 边自身权重。逐比特判决取"该比特为 1 的所有边"与"为 0 的所有边"两类度量之和的对数比。

(3) **工程实现：log 域两档。** Log-MAP 用 $\max^*$（修正项 $\ln(1+e^{-|a-b|})$）精确实现；Max-Log-MAP 丢弃修正项，损失约 0.5 dB，但只需比较与加法——精度与复杂度的经典取舍。

(4) **边界：不止 Turbo。** 任何可用网格描述的码（卷积码、Turbo 分量码）与 ISI 信道均衡都能用 BCJR；TS 36.212 不规定译码器必须采用哪一种公式——算法选择属接收机实现域。

(5) **数值指向。** 某状态两条入边 γ=0.4/0.6、前向 α=0.3/0.2 → α(s)=0.24（未归一化）——多条路径到达同一状态的证据相加（逐拍推演见直观模型）。

## 科学定义

BCJR 在码的网格图上计算三类度量：

- **γ 分支度量**：由信道 LLR 与先验信息给出的状态转移概率。
- **α 前向递归**：

$$\alpha_k(s) = \sum_{s'} \alpha_{k-1}(s') \cdot \gamma_k(s' \to s)$$

- **β 后向递归**：

$$\beta_k(s) = \sum_{s'} \beta_{k+1}(s') \cdot \gamma_{k+1}(s \to s')$$

其中 $k$ 为时间步，$s, s'$ 为网格状态，$s' \to s$ 表示从状态 $s'$ 到 $s$ 的转移边。逐比特判决取"该比特为 1 的所有边"与"该比特为 0 的所有边"两类度量之和的对数比：

$$L(u_k) = \ln \frac{\sum_{(s',s):\, u_k=1} \alpha_{k-1}(s')\, \gamma_k(s' \to s)\, \beta_k(s)}{\sum_{(s',s):\, u_k=0} \alpha_{k-1}(s')\, \gamma_k(s' \to s)\, \beta_k(s)}$$

实际实现全部在 log 域进行：

- **Log-MAP**：$\max^*(a,b) = \max(a,b) + \ln(1+e^{-|a-b|})$，精确实现 BCJR。
- **Max-Log-MAP**：取 $\max^* \approx \max$，丢弃修正项，性能损失约 0.5 dB，但只需比较和加法。

## 直观模型

把网格图看成双向路网：α 递推从起点向终点累积"至此路径的证据"，β 递推从终点向起点累积"此后路径的证据"，一条边被采用的总证据等于两段证据与该边自身权重的乘积。数值例子：某状态有两条入边，边权 γ 分别为 0.4 与 0.6，对应前一状态的 α 为 0.3 与 0.2，则 α(s)=0.4×0.3+0.6×0.2=0.24（未归一化）——多条路径到达同一状态的证据相加。

## 常见误解

| 误解 | 正确理解 |
|:---|:---|
| BCJR 只用于 Turbo 译码 | 任何可用网格描述的码（卷积码、Turbo 分量码）与符号间干扰（Inter-Symbol Interference, ISI）信道均衡都能用 BCJR。 |
| Max-Log-MAP 与 Log-MAP 等价 | Max-Log-MAP 丢弃修正项 $\ln(1+e^{-\lvert a-b\rvert})$，约损失 0.5 dB 增益。 |
| BCJR 输出硬判决比特 | BCJR 输出逐比特后验 LLR，软信息才能支撑迭代译码。 |
| α、β 各自独立就能给出判决 | 每比特判决需要 α 与 β 在同一条边上会合，二者缺一不可。 |

## 关键要点

1. BCJR 是逐比特最优 MAP 译码，输出后验 LLR——Turbo 迭代的软信息来源。
2. 双向递归：α 前向 + β 后向，判决需要二者在同一条边上会合。
3. Log-MAP 精确（max* + 修正项）；Max-Log-MAP 省修正项、损失约 0.5 dB。
4. 1974 年 BCJR 四人提出；任何网格码/ISI 均衡都可用。
5. TS 36.212 不规定译码器必须用哪种公式——接收机实现域。
6. BCJR 不输出硬判决——软 LLR 才能支撑迭代。
