# MCS Table & Effective Code Rate MCS表与有效码率

调制与编码方案表（Modulation and Coding Scheme Table, MCS Table）是调度器与终端共同查阅的一张对照表：一侧是从 0 到 31 的调度索引，另一侧是该索引对应的调制阶数与目标码率，空中接口只传索引这 5 bit，两端按同一张表还原出参数。有效码率（Effective Code Rate）是另一个方向的量，它由本次实际交付的传输块大小与本次实际占用的编码比特资源相除得到，描述这次传输真正落在什么码率上，而不是调度表标称了什么。一句话本质：**MCS 表用 5 bit 索引替代参数枚举，把调制阶数与目标码率压进控制信令；有效码率则从实际传输块大小反算本次传输的编码码率，两者在传输块量化与整形压缩之处分岔，因此跨配置比较只能在有效码率上对齐。**

三处容易混淆的口径在此一并区分。其一是目标码率与有效码率：前者是表里查出的设计值，后者是本次传输的实际值，多层传输时分母必须含层数，否则有效码率会被高估层数倍。其二是频谱效率与有效码率：前者是单位带宽的吞吐，含调制与编码两层增益；后者只描述编码层，二者不能互相替代。其三是标准表与整形表：前者的频谱效率列由调制阶数与码率相乘得到，后者由整形后的互信息给出，两张表的同一列不是同一个算法。

## 独立解释任务

任务目标：解释标准侧四张表（表 5.1.3.1-1 至表 5.1.3.1-4）与仿真器自带两张概率整形表在列结构、索引范围与表值口径上的差异，说明标准表内频谱效率为何等于调制阶数与目标码率之积而整形表不成立，给出有效码率的定义并说明它与目标码率脱钩的原因，最后用一次具体调度把候选信息比特数、传输块大小、编码比特预算与有效码率逐项算出并核对。

要完成这一解释，先把后文反复出现的三类对象与两个码率口径交代清楚。

## 前置概念

后文反复出现的第一个对象是调制与编码方案（Modulation and Coding Scheme, MCS）：它是调度器为一次传输选定的一对参数——星座规模与编码码率——的编号，编号只有 5 bit，因此必须靠一张双方共有的表把编号翻译成参数，这张表就是本笔记的主题，承载编号的字段见 [[DCI_下行控制信息]]。与它配套的两个量是调制阶数与目标码率：调制阶数决定一个调制符号携带几个编码比特，目标码率决定这些编码比特里有几分之几是信息比特，二者相乘得到单位符号的信息量，再乘上带宽与层数才是吞吐。

第二个对象是传输块（Transport Block, TB）与它的尺寸：传输块是媒体接入控制层在一次调度中交付给物理层的数据单元，其比特数称为传输块大小（Transport Block Size, TBS）；物理层先按资源与码率算出一个候选信息比特数，再按协议的量化表把它圆整成合法值，圆整带来的偏差正是有效码率偏离目标码率的第一个来源，传输块的切分与编码见 [[TB_传输块]]。与传输块大小相对的是编码比特预算：本次调度可用的资源元素数、调制阶数与层数三者相乘，就是编码之后可用的比特总数，这个量在 [[E_Value_G_Value_E值与G值]] 中记作 $G$，本笔记沿用同一记法，并在那里进一步分配到各个码块。

第三个对象是概率整形（Probabilistic Shaping, PS）：它让星座点以非均匀的概率出现，靠近原点的点出现得更频繁，从而在同等发射功率下更接近高斯输入的可达速率；刻画这种非均匀程度的分布是麦克斯韦–玻尔兹曼分布（Maxwell-Boltzmann Distribution, MB 分布），其整形强度就是整形表的第五列，整形原理与分布参数见 [[Probabilistic_Shaping_概率整形]] 与 [[MB_Distribution_MB分布]]。整形表通常把星座扩大到 1024 阶正交幅度调制（1024-Quadrature Amplitude Modulation, 1024QAM），这个星座本身在 Rel-17 已成为标准表的一档，见 [[QAM1024_1024QAM]]。三类对象建立之后，下面的演进顺序按「信令约束—标准扩容—整形入表—比较口径」四步展开。

## 起源与演进

(1) **起点：控制信令容不下参数枚举。** 调制阶数与码率的组合在原理上连续，在实现上却必须离散成有限张表，原因是下行控制信息的调制编码字段只有 5 bit：链路自适应每毫秒都要重新选一次参数，若把调制阶数与码率原样编码，字段长度会随可用组合数膨胀。LTE 的解法是两级查表，调制编码索引先查调制阶数与传输块大小索引，再由传输块大小索引与资源块数查传输块大小表，规则见 TS 36.213 §7.1.7.1 与 §7.1.7.2；NR 把两级合并成一级，索引直接给出调制阶数与目标码率，传输块大小另由公式与量化表算出，规则见 TS 38.214 §5.1.3.1 与 §5.1.3.2。

(2) **标准表的扩容：从 64 阶到 1024 阶。** Rel-15 的默认表是表 5.1.3.1-1，覆盖正交相移键控、16 阶与 64 阶正交幅度调制，索引 0 至 28 用于初传；高阶表 5.1.3.1-2 把最高档换成 256 阶，索引 0 至 27 用于初传；低码率表 5.1.3.1-3 面向高可靠场景，索引范围与表 1 相同；Rel-17 增加表 5.1.3.1-4，把最高档扩到 1024 阶，由高层参数 mcs-Table-r17 配置为 qam1024 后启用，索引 0 至 26 用于初传。四张表由同一个 5 bit 字段索引，接收端必须先按配置确定用的是哪一张，再解读索引，这就是「同一个数字在两套配置下含义不同」的来源。

(3) **整形表：多一列，表值改由互信息给出。** 概率整形把星座点分布压偏，单位符号携带的信息量不再等于调制阶数乘码率：编码比特数仍是调制阶数乘码率，但其中一部分被整形带来的分布约束消耗掉，实际可达速率要按互信息重新计算。仿真器为此在标准表结构上增加第五列整形强度，并在同一行直接给出整形后的频谱效率，于是标准表的乘积关系在这张表里失效。以整形表的一行为例，索引 10 的表值为 2.5704，按同一行的调制阶数与目标码率相乘却得 4.5，两者相差 1.93 bit/s/Hz，这部分差额就是整形把可达速率压低的结果，而不是表值抄错。

(4) **有效码率的由来：比较必须同码率。** 概率整形与均匀分布的比较若直接看频谱效率，会把整形的功率增益与编码增益混在一起；把两者放到同一目标码率上、再按实际传输块大小折算，才能只比较能量效率。有效码率因此成为链路级评估的公共横轴：它等于实际传输块大小除以实际编码比特预算，与调度器选定的目标码率可以不同。传输块大小的量化、资源元素口径的差异、整形是否进入可达速率，这三件事都会让两个码率分开，分开多少要按具体配置算。

(5) **边界：表是配置的函数，不是索引的函数。** 表的选择由高层参数决定，调度器与终端必须配置一致；同一个索引在表 1 与表 2 下可能给出不同的调制阶数与码率组合，误用表号会让整条链路的参数错位。索引中还有一部分不携带参数，用于重传指示或保留，此时传输块大小沿用同一传输块最近一次下行控制信息里的值。演进的终点是一组可运算的映射与一个可比的口径，下一节把它们写成公式。

## 科学定义

本节沿用文首的符号记法，三个小节依次说明查表映射与频谱效率恒等式、从候选信息比特数到有效码率的换算链、以及整形表的口径差异；每小节给出数值，最后用一次完整调度把三段串起来。

### 查表映射与频谱效率恒等式

选定表之后，索引到参数的映射是逐行查表，标准表内频谱效率与两个参数满足乘积关系：

$$SE=Q_mR \tag{1}$$

式 (1) 的两侧是同一个量的两种算法：表中以 1024 为分母的整数先除以 1024 换成比值 $R$，再与调制阶数相乘。数值核对取表 5.1.3.1-1 的一行，调制阶数 4、表值 490，则目标码率为 490/1024 约 0.4785，频谱效率为 4 乘 0.4785 等于 1.9141，与表内四位小数一致；再取调制阶数 6、表值 616，目标码率约 0.6016，频谱效率为 3.6094。两行说明乘积关系不是近似：标准表的频谱效率列就是按这两个参数算出来的，保留小数只是书写精度。

表的选择与索引范围需要一起记。表 5.1.3.1-1 的初传索引为 0 至 28，表 5.1.3.1-2 为 0 至 27，表 5.1.3.1-3 与表 1 相同，表 5.1.3.1-4 为 0 至 26；其余索引在传输块大小确定中不作新的参数解读，用于重传指示或保留，接收端遇到时按同一传输块最近一次携带参数的调度解读。上行方向的选择规则在 TS 38.214 §6.1.4.1：关闭变换预编码时复用表 5.1.3.1-1 至表 5.1.3.1-3，开启变换预编码时改用表 6.1.4.1-1 与表 6.1.4.1-2，两张表的索引范围与表值结构又不同，因此上行不能照搬下行的表号。

查表只给出两个参数，真正决定吞吐的是它们如何与资源相乘，下面转入这一层换算。

### 从候选信息比特数到有效码率

传输块大小不是参数的连续函数，而是先算候选值再量化，编码比特预算则由资源、调制与层数三者相乘：

$$N_{info}=N_{RE}Q_mR\nu,\qquad G=N_{RE}Q_m\nu,\qquad R_{eff}=\frac{N_{TBS}}{G} \tag{2}$$

式 (2) 的第一个等号说明候选信息比特数已经是「资源乘每符号信息量再乘层数」的三重积，第二个等号说明编码比特预算是同一资源乘每符号编码比特数再乘层数，二者相除恰好把资源与层数约掉，只剩下码率与量化带来的偏差。取 $N_{RE}=1200$、$Q_m=4$、$R=490/1024$、$\nu=2$，候选信息比特数为 1200 乘 4 乘 0.4785 乘 2 约 4594 bit，编码比特预算为 9600 bit；假设量化后的传输块大小为 4000 bit，则有效码率为 4000 除以 9600 约 0.4167，比目标码率 0.4785 低约 13%。这 13% 就是量化与资源口径带来的系统性偏差，它在不同配置下不同，因此不能当作常数补偿。

资源元素的口径是另一个偏差来源，也解释了为什么同一传输在不同仿真器里会得到不同的有效码率。协议第 1 步先扣除解调参考信号与配置开销，只把净资源元素计入 $N_{RE}$；若评估脚本改用整个分配的时频网格（把解调参考信号占用的资源元素也算进分母），分母从 1200 变成 1400，有效码率降为 4000 除以 11200 约 0.357。两种算法都自洽，差的只是分母是否扣除开销，因此比较不同来源的有效码率时必须先对齐这一条，否则会把口径差异误读为编码增益。

标准表的乘积关系在整形表里失效，这是下一小节的口径问题。

### 整形表的表值口径与比较基准

整形表的频谱效率不再是调制阶数与码率的乘积，同一行的两个数给出的差额就是整形压缩：

$$SE\neq Q_mR \tag{3}$$

仍以索引 10 为例，表值为 2.5704，而按同一行的调制阶数与目标码率相乘得 4.5，二者相差 1.93；这个差额不是表值误差，而是整形把星座点概率压偏后可达速率下降的部分。机理可以这样读：编码比特数仍由调制阶数与码率决定，但整形要求星座点按特定概率出现，等概率的编码比特经过分布匹配后能承载的信息量小于编码比特数本身，两者之差由整形强度 $\nu_{MB}$ 刻画。整形强度越大，分布越偏离均匀，频谱效率相对乘积的压缩越明显，这一列的读取方式与标准表完全不同。

有效码率在整形表下仍按式 (2) 计算，因为它是编码层的比值，与可达速率的口径无关；这恰好是它适合做比较基准的原因：整形与均匀分布在同一次调度下可以有不同的频谱效率，却可以有相同的有效码率，此时两者的差别只剩能量效率。反过来，若用频谱效率做比较基准，整形带来的功率增益与编码增益混在一起，无法分离。数值上，把同一次 1200 个资源元素、4 阶调制、2 层、传输块 4000 bit 的调度分别配到标准表与整形表，前者的目标码率 0.4785、后者按整形表读出的可达频谱效率 2.5704，两者的有效码率都回到 0.4167 附近，比较才落在同一口径上。

三小节分别给出映射、换算与口径，下面把这些规则的适用前提逐条划清。

## 边界情形

前述换算依赖四个未言明的前提，每个前提失效时都对应一类边界。第一个前提是表号已知：表由高层参数 mcs-Table、mcs-TableDCI-1-2 或 mcs-Table-r17 选定，索引本身不含表号，两端配置不一致时同一个 5 bit 数字会被解成两组不同参数，因此配置一致性是解读索引的前置条件。第二个前提是索引携带参数：表 5.1.3.1-1 与表 5.1.3.1-3 的 29 至 31、表 5.1.3.1-2 的 28 至 31、表 5.1.3.1-4 的 27 至 31 不给出新的调制阶数与码率，用于重传指示或保留，此时传输块大小取自同一传输块最近一次携带参数的调度，不能按当前索引重新查表。

第三个前提是分母口径一致：有效码率的分母是编码比特预算，若把层数漏掉，多层传输的有效码率会被高估层数倍；若把解调参考信号与开销算进资源元素数，有效码率会被低估，数值例中 0.4167 与 0.357 的差别全部来自这一条。第四个前提是整形参数已知：整形表的第五列决定分布，缺失该列时无法复现表值，也无法判断频谱效率的压缩量，评估脚本必须连同整形强度一起记录，否则表值不可复现。

以上四条边界说明公式只在明确口径下成立，把这些口径画成一条从索引到码率的换算链，就是下一节的直观模型。

## 直观模型

本节按结构而不是按比喻描述这条换算链，给出三级映射与两个守恒关系。

第一级是索引空间到表行的映射：5 bit 给出 32 个编号，表把其中一部分编号解释为参数对，另一部分编号解释为重传或保留；表号由配置给出，因此完整的映射是「配置选表、索引选行」的二元映射，不是单变量函数。第二级是表行到资源的映射：调制阶数决定每符号的编码比特数，目标码率决定其中信息比特的占比，二者与层数、资源元素数相乘得到编码比特预算与候选信息比特数；这一级是可乘的，四个因子中任意一个变化都线性地改变结果。第三级是候选值到合法传输块大小的量化：量化把连续候选值折到离散格点上，折点由协议的量化表规定，折后值只能取不小于候选值的最近合法值，因此量化是单向的、不可逆的。

两个守恒关系界定了这条链的边界。其一是比特总量守恒：编码比特预算等于资源元素数、调制阶数与层数之积，与传输块大小无关；传输块大小变大时预算不变，变的是码率。其二是层数的双向作用：层数同时出现在候选信息比特数与编码比特预算的分子与分母里，因此在目标码率不变时，增加层数不改变有效码率，只按层数比例放大吞吐；而在传输块大小固定时，增加层数会降低有效码率，等于为同一份信息配置了更多编码比特。

结构关系确认之后，几处容易混淆的口径可以逐条对照。

## 常见误解

| 误解 | 正确理解 |
|:---|:---|
| 整形表的频谱效率就是调制阶数乘目标码率 | 整形表的频谱效率由整形后的可达速率给出，索引 10 的表值 2.5704 与乘积 4.5 的差额 1.93 就是整形压缩。 |
| 有效码率等于目标码率 | 传输块量化与资源元素口径都会让两者分开，数值例中 0.4167 与 0.4785 相差约 13%。 |
| 有效码率的分母是资源元素数乘调制阶数 | 分母还须乘层数，否则多层传输的有效码率被高估层数倍。 |
| 1024 阶正交幅度调制不是 3GPP 标准能力 | Rel-17 起表 5.1.3.1-4 与高层参数 mcs-Table-r17 已把 1024 阶列为标准档；仿真器的整形表是另一件事，它与标准表的区别在整形而不在星座阶数。 |
| MCS 索引本身携带调制阶数与码率 | 索引只是行号，参数由配置选定的表决定，同一个索引在不同表下含义不同。 |
| 目标码率决定重传的冗余版本 | 冗余版本由下行控制信息中单独的冗余版本字段给出，与索引、码率都无关。 |

这些误解多半源于把「表」「索引」「码率」三个层次混为一谈，下面按条款给出各自的锚点。

## 协议族中的分工

MCS 表横跨四层规范，每层回答不同问题。理解它们联系的关键是分清职责：谁配置表号、谁携带索引、谁定义表与传输块公式、谁在接收端还原参数。

| 协议层 | 回答的问题 | 代表 TS（本地 Rel-19 资料） |
|:---|:---|:---|
| RRC 信令 | 用哪一张表（mcs-Table、mcs-TableDCI-1-2、mcs-Table-r17 的取值） | TS 38.331 §6.3.2 |
| 物理层控制 | 索引怎么传（下行控制信息格式 1_1 的 5 bit 字段） | TS 38.212 §7.3.1.2.2 |
| 物理层过程 | 表怎么定义、传输块大小怎么算（表 5.1.3.1-1 至 -4、资源元素数与量化表） | TS 38.214 §5.1.3.1 与 §5.1.3.2 |
| 信道编码 | 编码比特预算 $G$ 怎么定义，与速率匹配如何衔接 | TS 38.212 §5.4.2.1 |

**联系链**：331 选定表号并回答「用哪张表」→ 212 在控制信息里留出 5 bit 并回答「索引怎么传」→ 214 把索引翻成调制阶数与目标码率、连同资源与层数算出传输块大小与编码比特预算，回答「参数是多少、信息比特多少」→ 212 §5.4.2.1 把编码比特预算分配到各码块，回答「编码之后每块多少 bit」→ 有效码率取传输块大小与预算之比，回答「这次传输实际落在什么码率」。整条链围绕同一个目标：让收发两端对「这次用哪组参数、传多少信息比特、占多少编码比特」达成一致。

分工与联系链合起来，就是前面各节结论的收束。

## 关键要点

1. MCS 表把 5 bit 索引映射为调制阶数与目标码率，表号由高层配置决定，索引只是行号。
2. 标准侧四张表覆盖 64 阶、256 阶、低码率与 1024 阶；前三张与 1024 阶表分别对应不同的初传索引范围。
3. 标准表的频谱效率恒等于调制阶数与目标码率之积，表中以 1024 为分母书写码率时须先换算成比值。
4. 整形表多出整形强度一列，频谱效率改由整形后的可达速率给出，索引 10 的表值 2.5704 与乘积 4.5 的差额即整形压缩。
5. 有效码率等于传输块大小除以编码比特预算，预算的分母含资源元素数、调制阶数与层数三个因子。
6. 传输块量化使有效码率低于目标码率约一成，资源元素是否扣除解调参考信号开销会再引入一成量级的差异。
7. 概率整形与均匀分布的比较必须在有效码率上对齐，频谱效率不能跨口径直接比较。
