# Multi-TRP 多点协作传输

## 符号与记号约定

本笔记不引入新的数学符号。涉及的量——时隙、资源块、层、天线端口、传输配置指示（Transmission Configuration Indication, TCI）状态——沿用既有概念笔记的定义：子载波与资源块见 [[Resource_Units_资源单位体系]]，层与端口见 [[Layer_Mapping_层映射]]，TCI 与波束见 [[Beam_Management_波束管理]]。下文只用文字与表格描述方案与流程。

## 定位

发送接收点（Transmission and Reception Point, TRP）是网络侧的一个无线收发单元——一套基带、射频与天线阵列，通常对应一个物理站点或一个分布式天线头。**TRP 并发**指多个 TRP 在**同一时隙内**同时向同一个终端传输，与「多个 TRP 在不同时隙轮流传输」相对。前者靠空间或频率维度复用，后者靠时间维度重复。

## 解释目标与范围

本节目标：说清 TRP 在协议里如何被识别与被指示；说清「并发」与「交替」两类多 TRP 传输的区别与各自的协议落地方式；说清终端如何知道某个传输来自哪个 TRP。不展开 CSI 测量与码本细节。

## 前置概念

传输配置指示状态。协议不让终端直接知道「这个信号来自哪个 TRP」，而是用传输配置指示状态来间接表达：一个 TCI 状态里包含准共址关系（如多普勒、时延、空间接收参数），终端据此知道该用哪组接收参数去接收。**一个 TCI 状态对应一个 TRP 的波束条件**，这是多点传输在空口上的表达方式。

准共址。两个参考信号如果共享某些大尺度参数（时延、多普勒、平均增益、空间参数），就称它们准共址。终端把在参考信号上估计出的这些参数复用到数据信道上，前提是两者准共址。

控制信道的资源集池索引。为了让终端区分来自不同 TRP 的控制信道，协议给控制资源集配置一个池索引；不同池索引的控制信道可以来自不同 TRP，终端据此并行监听。

多输入多输出与层。多个 TRP 同时传输时，每个 TRP 贡献若干层，接收端用多天线把各层分开——这与单站多天线的空间复用是同一套物理机制，只是发射点分散在不同位置。

## 起源与演进

多点协作最初以「协调调度」的形式出现：多个小区在时频资源上互相避让，减少相互干扰，但每个终端仍只被一个小区服务。这一阶段不要求终端知道有几个传输点。

Rel-16 起，多 TRP 传输进入终端可见的范围：下行控制信息的一个码点可以携带**两个** TCI 状态，表示本次传输来自两个 TRP。协议同时给出若干重复方案，让两路传输可以按时隙交替、按频率分段或按空间叠加。

Rel-17 继续扩展：上行多 TRP（终端向两个 TRP 发送）、单频网方案（多个 TRP 在同一时频上发送相同信号，接收端等效为一个更强的信道）以及更细的频率分段方案。

## 科学定义

### TRP 在协议里如何被表达

协议不定义 TRP 这个实体本身，而是用 TCI 状态的数量与配对来表达「有几个传输点」。终端在控制信息里看到两个 TCI 状态，就知道本次传输涉及两个传输点；看到两个控制资源集池索引，就知道控制信道来自两个传输点、需要分别用各自的接收波束（TS 38.214 §5.1.2.1 中提到的 coresetPoolIndex 与乱序操作能力）。

这一表达方式有一个直接后果：**终端不需要知道 TRP 的物理位置**，只需要知道「用哪组接收参数」。多点的增益在空口上表现为「两套不同的空间参数被同时使用」，而不是「两个站点的坐标」。

### 并发与交替：两类多 TRP 方案

多 TRP 传输按两路信号的时间关系分为两类。

**交替式（时分）**：两路传输在不同的时隙（或同一次调度内的不同传输机会）上先后到达，同一时刻只有一路在传。典型实现是重复方案 tdmSchemeA：一次调度给出两个传输机会，各自用不同的 TCI 状态（TS 38.214 §5.1.2.1）。它的收益来自时间分集与软合并——两路内容相同、信道不同，接收端合并后等效信噪比提高。

**并发式（同隙）**：两路传输在同一时隙内同时到达，靠空间或频率维度分开。协议给出三种具体形式：

| 方案 | 分开方式 | 协议表达 |
|:---|:---|:---|
| 空分（SDM） | 两路的解调参考信号落在不同的码分复用组，层在空间上分开 | 指示两个 TCI 状态 + 天线端口字段给出两个 CDM 组（TS 38.214 §5.1.2.1、§5.1.6.2） |
| 频分 A/B（FDM） | 两路占用同一时隙内的不同频率资源（A 为不重叠分段，B 为部分重叠） | repetitionScheme 取 fdmSchemeA 或 fdmSchemeB（TS 38.214 §5.1.2.1） |
| 单频网（SFN） | 两路在同一时频资源上发送相同信号，空口上叠加成一个等效信道 | sfnSchemePDSCH 配置（TS 38.214 §5.1.2.1 相关条款） |

三者的差别在于「接收端怎么分」：SDM 靠空间可分性、FDM 靠频率不重叠、SFN 不需要分（两路相加当作一个信道）。因此「TRP 并发」不是一个单一特性，而是一组方案的统称——**并发意味着同一时隙内有多个传输点在活动**，具体如何共存由方案决定。

### 并发的代价与前提

并发不是无代价的。空分要求两个 TRP 到终端的信道足够不同，否则两层之间产生流间干扰，需要接收端检测与预编码抑制；频分要求终端在更窄的带宽上分别接收，等效降低每路的频率分集；单频网要求两路严格同步（时频对齐），否则叠加不成相干信号，反而互相干扰。

交替式的代价则是时间：两路在不同时隙，端到端时延增加、且要求终端在更长时间内保持接收状态。选择并发还是交替，本质是在「时延与分集」和「干扰与同步」之间权衡。

## 直观模型

把一次下行传输看成「一份数据经过几条发射路径到达终端」。单 TRP 只有一条路径：所有层都从一个点发出。交替式多 TRP 让两条路径在不同时隙上先后使用——前一批时隙走第一条、后一批走第二条，内容相同，接收端把两次收到的合并。并发式多 TRP 让两条路径在同一时隙内同时使用：数据被拆成两路，一路走空间上不同的层（SDM）、一路走不同的频率段（FDM）、或者两路发送相同内容在空口相干叠加（SFN）。

判断某个配置属于哪一类，看三件事：这次调度给了几个 TCI 状态（一个还是两个）、两个传输机会占不占同一个时隙、以及参考信号落在同一个还是不同的码分复用组。

## 常见误解

| 误解 | 正确理解 |
|:---|:---|
| TRP 就是小区 | TRP 是无线收发单元，一个小区的数据可以由多个 TRP 发送；小区是逻辑覆盖单位，二者层次不同 |
| 多 TRP 就是多天线 | 多天线是单点内的空间维度；多 TRP 是多个站点协同，站点间需要回传与同步 |
| TRP 并发就是两路内容一定相同 | 交替式与单频网两路内容相同；空分方案两路承载不同的层、内容不同 |
| 终端知道自己在接收哪个 TRP 的信号 | 终端只看到 TCI 状态与控制资源集池索引，不需要也不知道 TRP 的物理位置 |
| 并发的吞吐一定更高 | 空分需要空间可分，否则流间干扰反而降低性能；频分与单频网各有带宽与同步代价 |

## 关键要点

1. TRP 是网络侧的无线收发单元；协议不定义其实体，而用 TCI 状态数量表达「有几个传输点」。
2. 「TRP 并发」指多个 TRP 在**同一时隙**内同时传输；与之相对的是跨时隙交替。
3. 并发的三种实现：空分（不同 CDM 组的层）、频分（同隙不同频段）、单频网（同频同内容叠加）。
4. 交替式的收益来自时间分集与软合并，代价是时延；并发的收益来自同一时隙内的并行，代价是干扰与同步要求。
5. 终端只看到 TCI 状态与池索引，不需要知道 TRP 的物理位置。
6. 空分要求两路信道足够不同；信道高度相关时强行并发会引入流间干扰。
7. 判断方案类型看三件事：几个 TCI 状态、是否同一时隙、DM-RS 是否在不同 CDM 组。
