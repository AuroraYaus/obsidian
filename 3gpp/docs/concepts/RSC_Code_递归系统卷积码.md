# RSC 递归系统卷积码

## 符号与记号约定
| 符号 | 含义与取值 | 协议锚点 |
|:---|:---|:---|
| $D$ | 延迟算子，在生成多项式的记法中表示把序列延迟一个时刻，取形式变量、无量纲，是多项式记法而不是可传输的比特量 | 非 3GPP 标准 |
| $g_f(D)$ | 反馈多项式，决定编码器的递归回路，LTE 组成编码器取 $1+D^2+D^3$、八进制写作 15，单位为无量纲的二进制系数多项式 | 由 TS 36.212 §5.1.3.2.1 导出 |
| $g_p(D)$ | 前馈多项式，决定校验位对输入与各寄存器抽头的组合，LTE 组成编码器取 $1+D+D^3$、八进制写作 13，单位为无量纲的二进制系数多项式 | 由 TS 36.212 §5.1.3.2.1 导出 |
| $G(D)$ | 生成多项式，写成两项的矩阵形式，第一项 1 表示系统位直通、第二项为前馈多项式与反馈多项式之比，单位为无量纲 | 由 TS 36.212 §5.1.3.2.1 导出 |
| $m$ | 编码器的寄存器个数，即记忆阶数，决定状态数为 2 的 m 次方；LTE 取 3，单位为个，对应 8 个状态 | 由 TS 36.212 §5.1.3.2.1 导出 |
| $k$ | 时刻序号，从 0 起逐拍递增的非负整数，无量纲，用于标记第 k 拍的输入、输出与寄存器状态 | 非 3GPP 标准 |
| $u_k$ | 第 k 拍送入编码器的输入比特，取 0 或 1，单位为 bit | 非 3GPP 标准 |
| $x_k$ | 第 k 拍的系统位输出，等于该拍的输入比特本身，取 0 或 1，单位为 bit | 非 3GPP 标准 |
| $p_k$ | 第 k 拍的校验位输出，由当前输入与寄存器状态共同决定，取 0 或 1，单位为 bit，逐拍记作 $p_0$、$p_1$、$p_2$、$p_3$ | 非 3GPP 标准 |
| $v_k$ | 反馈回路的内部比特，等于当前输入与末级寄存器状态的模 2 和，取 0 或 1，单位为 bit，逐拍记作 $v_0$、$v_1$、$v_2$、$v_3$ | 非 3GPP 标准 |
| $s_{1,k}$ | 第 k 拍第一级寄存器的状态，取 0 或 1、无量纲，次一拍的状态记作 $s_{1,k+1}$ | 非 3GPP 标准 |
| $s_{2,k}$ | 第 k 拍第二级寄存器的状态，取 0 或 1、无量纲，次一拍的状态记作 $s_{2,k+1}$ | 非 3GPP 标准 |
| $\mathbf{u}$ | 一次输入比特序列，元素取 0 或 1、单位为 bit，以粗体字母表示整条序列（例如四位序列 1011）而不表示单个比特 | 非 3GPP 标准 |
| $\mathbf{x}$ | 系统位输出序列，元素取 0 或 1、单位为 bit，由输入序列逐位直通得到 | 非 3GPP 标准 |
| $\mathbf{p}$ | 校验位输出序列，元素取 0 或 1、单位为 bit，由反馈回路与寄存器状态逐拍算出 | 非 3GPP 标准 |

运算符与记号惯例：$\oplus$ 表示模 2 加（异或），$\frac{g_p(D)}{g_f(D)}$ 中的分式不是数值除法而是二进制多项式的除法（以反馈多项式为模的递归滤波）；下标 k 表示第 k 拍而不是乘法，$s_{1,k}$ 读作「第 k 拍第一级寄存器的状态」；下标 1 与 2 是寄存器编号；$2^m$ 表示状态个数，其中的 2 是二进制基数、$m$ 是记忆阶数，二者都不参与编码运算。

RSC（递归系统卷积码，Recursive Systematic Convolutional Code）是 LTE Turbo 编码器的基本组成单元：两个 8 状态 RSC 并行级联，译码端由 BCJR 算法沿对应网格译码。一句话本质：**RSC 是"带记忆回路的抄写员"——系统位直通留底、校验位带历史记忆，反馈回路把短记忆变成无限记忆**。

## 解释目标与范围

本节目标：解释递归系统卷积码（Recursive Systematic Convolutional Code, RSC）的"递归"与"系统"两重结构，说明它为什么是 Turbo 码组成编码器的必然选择。在 LTE/NR 译码链路中的位置：RSC 是 LTE Turbo 编码器的基本组成单元——两个 8 状态 RSC 并行级联，译码端由 BCJR 算法沿对应网格（Trellis）译码。

## 前置概念

卷积码（Convolutional Code）。一类输出不仅取决于当前输入、还取决于此前若干拍输入的编码。编码器内部用寄存器保存最近若干拍的历史，寄存器取值的组合称为状态；记忆阶数为 m 时状态共有 2 的 m 次方个，编码过程因此可以画成在状态之间逐拍转移的网格，见 [[TBCC_咬尾卷积码]]。

生成多项式与寄存器。生成多项式是描述「哪些寄存器抽头参与某个输出」的二进制系数多项式，系数为 1 表示该抽头接入、为 0 表示不接入。同一组寄存器按不同的抽头组合分别接到系统位输出与校验位输出，就得到一路直通、一路带记忆的两路输出；系数在协议中以八进制书写，本笔记用多项式书写以便看出抽头位置。

网格（Trellis）与状态转移。网格把每个时刻的状态排成一列，把合法的状态迁移画成连边，边上的标注是该迁移对应的输入比特与输出比特。递归结构使同一输入比特对后继状态的影响不会在有限拍后消失，网格因此不再是有限记忆的滑动窗口，这正是递归码距离谱更优的原因。

交织器与并行级联。交织器按固定置换把同一段信息比特打乱次序，并行级联则让原序与交织序分别送入两个组成编码器。两路编码器看到的是同一批比特的不同排列，各自的校验位提供近似独立的约束；迭代译码的增益正来自这两路约束的相互印证，见 [[Turbo_码]]。

软输入软输出译码与 BCJR 算法。软输入软输出译码器接收每个比特的先验可靠度，输出更新后的后验可靠度；BCJR 算法沿网格做前向与后向递推，逐比特给出后验与外部信息。外部信息是扣除了本次输入先验之后的新证据，两个组成译码器只交换这部分信息，见 [[BCJR_Algorithm_BCJR算法]]、[[Iterative_Decoding_迭代译码]]。

## 起源与演进

(1) **起点：为什么卷积码要"递归"。** 普通非递归卷积码（有限冲激响应）的距离谱受限；把输出反馈回输入（无限冲激响应化）后，距离谱显著优于非递归码——这是 Turbo 组成码采用递归结构的根本原因。

(2) **"系统"与"递归"两重结构。** "系统"指系统位直通输出（$x_k=u_k$），保证原始比特在码字中；"递归"指编码器含反馈回路。生成多项式统一写成 $G(D)=[1,\ g_p(D)/g_f(D)]$——分式表示二进制多项式意义下的递归滤波。

(3) **LTE 规格。** 8 状态（$m=3$ 个寄存器），生成多项式 $G(D)=\left[1,(1+D+D^3)/(1+D^2+D^3)\right]$——协议写死，译码器必须与之匹配。

(4) **为什么是 Turbo 的必然选择。** 单独 RSC 纠错能力有限，必须与交织器加第二个 RSC 并行级联成 Turbo 码；交织后两个 RSC 看到的输入近似独立，各自贡献一路冗余——递归结构 × 交织 = 迭代增益的来源。

(5) **数值手算。** 2 寄存器玩具例（非 LTE 结构）输入 $\mathbf{u}=[1,0,1,1]$ → 系统输出 $\mathbf{x}=[1,0,1,1]$、校验输出 $\mathbf{p}=[1,1,1,1]$：$k=1$ 时输入为 0 但 $p_1=1$——历史状态参与了校验，这正是"递归记忆"的体现（逐拍推演见直观模型）。

## 科学定义

卷积码（Convolutional Code）的输出不仅由当前输入决定，还由过去 $m$ 个输入决定；$m$ 个寄存器产生 $2^m$ 个状态。"系统"指系统位直通输出（$x_k=u_k$），保证原始比特在码字中；"递归"指编码器含反馈回路。生成多项式统一写成：

$$
G(D)=\left[1,\ \frac{g_p(D)}{g_f(D)}\right]
$$

其中 $D$ 表示延迟一拍，$g_p(D)$ 为前馈多项式，$g_f(D)$ 为反馈多项式，分式表示二进制多项式意义下的递归滤波。LTE 组成编码器为 8 状态（$m=3$ 个寄存器），生成多项式 $G(D)=\left[1,(1+D+D^3)/(1+D^2+D^3)\right]$。反馈结构使有限冲激响应变为无限冲激响应，距离谱显著优于非递归码；交织后两个 RSC 看到的输入近似独立，这是 Turbo 迭代增益的来源。

## 直观模型

用 2 寄存器玩具 RSC（非 LTE 结构）手算。定义反馈内部比特 $v_k=u_k\oplus s_{2,k}$、校验 $p_k=v_k\oplus s_{1,k}\oplus s_{2,k}$、状态更新 $s_{1,k+1}=v_k$、$s_{2,k+1}=s_{1,k}$。初始状态 $(0,0)$，输入 $\mathbf{u}=[1,0,1,1]$，逐拍计算：(1) $k=0$：状态 $(0,0)$、$v_0=1$、$p_0=1$、下一状态 $(1,0)$；(2) $k=1$：状态 $(1,0)$、$v_1=0$、$p_1=1$、下一状态 $(0,1)$；(3) $k=2$：状态 $(0,1)$、$v_2=0$、$p_2=1$、下一状态 $(0,0)$；(4) $k=3$：状态 $(0,0)$、$v_3=1$、$p_3=1$、下一状态 $(1,0)$。系统输出 $\mathbf{x}=[1,0,1,1]$，校验输出 $\mathbf{p}=[1,1,1,1]$。注意 $k=1$ 时输入为 0 但 $p_1=1$——历史状态参与了校验，这正是"递归记忆"的体现。

## 常见误解

| 误解 | 正确理解 |
|:---|:---|
| 系统位与输入相同所以冗余无用 | 校验位提供跨时间约束；系统位让网格结构与译码初始化更简单。 |
| 递归只是把输入循环一遍 | 反馈把有限冲激响应变成无限冲激响应，显著改善距离谱。 |
| RSC 可以单独作为完整码 | 单独 RSC 纠错能力有限，必须与交织器加第二个 RSC 并行级联成 Turbo 码。 |
| 8 状态指 8 个寄存器 | 状态数 $2^m$；8 状态对应 $m=3$ 个寄存器。 |
| 生成多项式可以自行设计 | LTE 固定 $G(D)=\left[1,(1+D+D^3)/(1+D^2+D^3)\right]$，译码器必须与之匹配。 |

## 关键要点

1. RSC = 递归 + 系统：系统位直通、校验位带反馈记忆。
2. 递归（无限冲激响应化）显著改善距离谱——这是选它的根本原因。
3. LTE 规格：8 状态、$G(D)=\left[1,\ (1+D+D^{3})/(1+D^{2}+D^{3})\right]$，协议写死。
4. 单独 RSC 纠错有限，必须 +交织器 +第二 RSC 级联成 Turbo。
5. 8 状态 = m=3 寄存器（2^m 个状态，不是 8 个寄存器）。
6. 译码端由 BCJR 沿网格进行（T6.2/T6.3）。
