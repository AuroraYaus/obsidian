# Fixed-Point Numbers 定点数表示

## 符号与记号约定
| 符号 | 含义与取值 | 协议锚点 |
|:---|:---|:---|
| $W$ | 定点数的总位数，含 1 位符号位；本文 `Q4.4` 例取 $W=8$，LLR 例同样取 $W=8$ | 非 3GPP 标准（数学定义） |
| $n$ | 小数部分的位数，步长由它单独决定 | 非 3GPP 标准（数学定义） |
| $L$ | 浮点对数似然比的取值，无量纲实数；符号定判决方向，绝对值定可靠度 | 非 3GPP 标准（接收机实现域） |
| $C$ | LLR 允许的最大绝对值，超出部分饱和到端点；本文例取 $C=32$ | 非 3GPP 标准（接收机实现域） |
| $\sigma_q^2$ | 均匀量化误差的方差，$\sigma_q^2=\Delta^2/12$；步长 0.25 时约为 0.0052 | 非 3GPP 标准（数学定义） |
| $m$ | 整数部分的位数，含 1 位符号位；与小数位满足 $W=m+n$ | 非 3GPP 标准（数学定义） |
| $\Delta$ | 相邻可表示值之间的间距，$\Delta=2^{-n}$；量化误差的量级由它决定 | 非 3GPP 标准（数学定义） |
| $q_{\min}$ | 有符号码字下界，$q_{\min}=-2^{W-1}$；8 位时为 $-128$ | 非 3GPP 标准（数学定义） |
| $q_{\max}$ | 有符号码字上界，$q_{\max}=2^{W-1}-1$；8 位时为 127 | 非 3GPP 标准（数学定义） |
| $Q_{m.n}$ | Q 格式记号：m 位整数（含符号位）加 n 位小数，总位宽 $W=m+n$；同一位串可对应多个 Q 格式，取哪个由解释方约定 | 非 3GPP 标准（数学定义） |
| $q$ | 硬件实际存储的 W 位整数码，取值在 $[q_{\min},q_{\max}]$ 内；小数点不存储在硬件中 | 非 3GPP 标准（数学定义） |
| $u$ | 同一串 W 位比特按无符号整数读出的值，取值 $[0,2^W-1]$；最高位为 1 时，有符号读数 $q=u-2^W$ | 非 3GPP 标准（数学定义） |
| $s$ | 定标因子，即对数似然比（Log-Likelihood Ratio, LLR）场景中每个码字代表的实数值；与 $\Delta$ 数值相同，只是换了一个名字 | 非 3GPP 标准（接收机实现域） |
| $x$ | 码字按给定 Q 格式解释出的实数，$x=q/2^n$；在 LLR 路径上同一关系写成 $x=s q$ | 非 3GPP 标准（数学定义） |
| $L_q$ | 定点化后的 LLR 值，满足 $L_q=s q$，落在可表示区间 $[x_{\min},x_{\max}]$ 内 | 非 3GPP 标准（接收机实现域） |
| $x_{\min}$ | 可表示下界，$x_{\min}=s q_{\min}$；步长 0.25 时为 $-32$ | 非 3GPP 标准（数学定义） |
| $x_{\max}$ | 可表示上界，$x_{\max}=s q_{\max}$；步长 0.25 时为 31.75 | 非 3GPP 标准（数学定义） |
| $\varepsilon$ | 量化误差，定义为真值减量化值，$\varepsilon=x-s q$；按最近舍入时绝对值不超过 $\Delta/2$ | 非 3GPP 标准（数学定义） |

运算符与记号惯例需要一并说明。$\lfloor\cdot\rfloor$ 表示向下取整，因此 $\lfloor x/\Delta+0.5\rfloor$ 是对 $x/\Delta$ 作最近舍入；$\min$ 与 $\max$ 取两数中的较小者与较大者，用来表达饱和；$\bmod$ 表示按位宽取余，用来表达回绕。$q$ 与 $x$ 之间的斜线是实数除法，只在由实数求码字时出现；相邻两个符号（如 $s q$）表示相乘，省略乘号。上下标有两种语义：$q_{\min}$ 与 $q_{\max}$ 的下标是边界标记，不是相乘；$2^{W-1}$ 的上标是幂次。同一量在两处使用两套记号时以本表为准：Q 格式路径写 $\Delta=2^{-n}$，LLR 路径写 $s$，二者数值相同。

定点数（Fixed-Point Number）用固定位宽的整数码表示实数：Q 格式固定小数点位置，补码固定负数表示，饱和固定溢出行为。一句话本质：**定点数是实数在一个有限、等间距、位置固定的有理数格点集合上的表示——步长 $\Delta$ 决定分辨率，位宽 $W$ 决定格点总数，可表示范围与分辨率之比由 $W$ 单独锁定，超出上界的值必须饱和到端点而不是按位回绕。**

这套表示在 LTE/NR 译码链路里出现在三个位置：软解调输出的 LLR 要在存储阵列中按整数保存，混合自动重传请求（Hybrid Automatic Repeat Request, HARQ）的软合并要把多次重传的 LLR 逐比特相加，迭代译码要在变量节点与校验节点之间反复搬运消息。三处都要求同一位串在任意时刻被解释成同一个数，否则浮点仿真与硬件实现无法比特精确对齐（见 [[Bit_Exact_Regression_比特精确回归]]）。下文先补齐七个前置对象，再给出定标代数与两组可手算的数值例，最后把表示问题与 LLR 量化损失接起来。
## 解释目标与范围

本节目标：解释定点数如何用固定位宽整数表示实数，说明 Q 格式、二进制补码、定标因子与饱和策略如何共同决定可表示范围与分辨率；用 `Q4.4` 表示 3.6875 的二进制码与量化误差、以及 8 位 LLR 在步长 0.25 与 0.5 下的范围/分辨率两组手算数值例，把「位宽、步长、动态范围」三者的约束关系算实；并说明 LLR 从浮点到定点的三类损失来源。

## 前置概念

本节把后文反复使用的七个对象一次交代清楚，按从底层表示到上层误差的顺序排列：整数表示与补码决定位串如何读成数，定标与 Q 格式决定小数点放在哪里，动态范围、量化噪声、饱和与回绕决定这套表示在边界上的行为。若已熟悉，可直接跳到「起源与演进」。

整数表示（integer representation）把实数映射为有限位宽的整数码：位宽 $W$ 的位串有 $2^W$ 种取值，最高位通常取作符号位，其余位按二进制权值展开。位宽一旦确定，可表示的数就固定为一个有限集合，运算结果超出这个集合时必然发生溢出，这是所有定点问题的起点。

二进制补码（Two's Complement）是负数在硬件中的统一表示：正数的码字就是其二进制值，最高位为 1 时按 $q=u-2^W$ 读出负值，其中 $u$ 是同一串比特的无符号读数。补码让加法与减法共用同一套加法器，符号位与数值位一起参与运算，溢出表现为按 $2^W$ 取模的折返。它不区分正负号的处理方式，是定点硬件能把面积压下来的直接原因。

定标（scaling）在整数码与实数之间建立线性关系：选一个正实数 $s$，令实数等于码字乘 $s$。同一串码字配不同的 $s$ 就得到不同的实数集合，因此定标不是数据的属性，而是解释方与数据之间的约定；约定一旦丢失，位串就退化为无意义的整数。LLR 的定点化本质上就是替所有 LLR 选定同一个 $s$。

Q 格式（Q-format）把定标固定为 2 的负幂：`Qm.n` 表示 m 位整数（含 1 位符号位）加 n 位小数，总位宽 $W=m+n$，步长 $\Delta=2^{-n}$。本笔记采用「m 含符号位」的约定，因此 `Q4.4` 是 8 位而不是 9 位；不同工具与厂商存在「m 不含符号位」的写法，交接时必须显式声明，否则同一位串会被解释成相差一倍的数。

动态范围（dynamic range）在本笔记中定义为最大可表示幅度与步长之比，它衡量这套格式能同时容纳多大的数与多细的差。位宽固定时该比值约为 $2^{W-1}$：每增加 1 位，该比值翻倍（约 6 dB），这一位可以用于扩大范围、提高分辨率，或按需要分摊；减少 1 位则必须从两者之一扣回。把位宽理解成「范围与分辨率的总预算」，比把它当成单纯的精度指标更接近工程实际。

量化噪声（quantization noise）是实数落到最近格点时产生的误差：按最近舍入，$\varepsilon$ 的绝对值不超过 $\Delta/2$；在误差均匀分布、码字密集的假设下，其方差为 $\Delta^2/12$，即表中的 $\sigma_q^2$。它的大小只由步长决定，与信号幅度无关，这一点与浮点表示相反——浮点的绝对误差随数值增大而增大，相对误差大致恒定。量化口径与裁剪的工程细节见 [[LLR_Quantization_LLR量化]]。

饱和（saturation）与回绕（wrap-around）是溢出后的两种处理：饱和把结果钳在 $q_{\min}$ 或 $q_{\max}$，误差有界且符号不变；回绕让结果按 $2^W$ 取模折返，可能把正的大数变成负的大数。对 LLR 这类以符号承载判决方向的量，回绕会直接翻转硬判决，因此译码链路一律采用饱和。

## 起源与演进

表示方式的演进由硬件成本与误差可控性两条线索推动，下面四步按因果顺序排列，末一步落到 LLR。

(1) **从浮点仿真到整数硬件。** 通用处理器上的浮点运算需要专门的浮点单元与较长的流水线，而基带与译码器要求每个时钟周期完成大量乘加。定点运算的加法与乘法都由整数单元完成，面积与功耗远低于浮点，这使定点成为专用集成电路（Application-Specific Integrated Circuit, ASIC）的默认选择。

(2) **Q 格式成为接口约定。** 为了在整数硬件上表达小数，工程界把小数点位置固定为 2 的负幂，形成 Q 格式；同一条乘法指令配合不同的移位量就能服务不同量纲的信号，格式因此从内部实现细节上升为模块之间的接口约定。约定不一致时，两个模块各自都能工作，连起来却差一个 2 的幂次。

(3) **补码统一负数表示。** 补码成为主流的原因是加减法共用一套电路、符号位无需单独处理；定点硬件的溢出检测也建立在补码的模运算之上。原码与反码需要两套运算逻辑，在面积敏感的基带芯片里没有竞争力。

(4) **LLR 的定点化。** 软输入软输出译码要求 LLR 在存储与迭代中反复读写，浮点表示无法承受其面积；工程上把 LLR 裁剪到 ±31 附近、用 6 位有符号数保存，使 48 位存储字可以打包 8 个 LLR。位宽每增加 1 位只带来约 0.1-0.2 dB 的误块率（Block Error Rate, BLER）改善，而 ±31 处的裁剪损失已低于 0.02 dB，收益在此封顶；这组数字是本库的工程预算口径，不是协议规定。

## 科学定义

上一节的口头定义可以压缩成三条可运算的关系：定标给出码字与实数的换算，手算数值例把换算走一遍并量化误差，LLR 定标则把同一套换算用在软信息上并暴露范围与分辨率的交换关系。三节按「一般关系、具体算例、工程用法」递进。

### 定标关系、Q 格式与可表示集合

设总位宽为 $W$、整数位为 $m$、小数位为 $n$，三者满足 $W=m+n$。硬件保存码字 $q$，解释方按

$$x=\frac{q}{2^n},\qquad \Delta=2^{-n}$$

把码字还原成实数：分母 $2^n$ 就是小数点向左移动的位数，步长 $\Delta$ 是相邻码字对应的实数差。反过来，给定实数 $x$ 求码字需要舍入，

$$q=\left\lfloor \frac{x}{\Delta}+0.5\right\rfloor$$

向下取整后再加 0.5 实现最近舍入，正好落在两个格点中间时统一向上取。若改用直接截断，误差会偏向一个方向，并在多次累加后形成直流偏置。

有符号码字的取值范围由补码给出：$q_{\min}=-2^{W-1}$，$q_{\max}=2^{W-1}-1$，负数与无符号读数 $u$ 的关系是最高位为 1 时 $q=u-2^W$。对应到实数，

$$x_{\min}=s\,q_{\min}=-2^{m-1},\qquad x_{\max}=s\,q_{\max}=2^{m-1}-2^{-n}$$

其中 $s=\Delta$。负半轴比正半轴多一个格点，这是补码不对称的直接结果：`Q4.4` 的可表示区间是 $[-8,\,7.9375]$，下界可达 $-8$，上界到不了 $8$。

可表示集合的规模与间距一起决定了格式的能力。格点总数为 $2^W$，最大幅度与步长之比为 $x_{\max}/\Delta=2^{W-1}-1$，折合 $20\log_{10}(2^{W-1}-1)\approx6(W-1)$ dB；这个比值只由 $W$ 决定，与 $m$、$n$ 如何分配无关。把 $m$ 调大、$n$ 调小，等于把同一组格点整体移向大数方向：范围变大、分辨率变粗；反过来则范围变小、分辨率变细。位宽不变时，范围与分辨率是同一个自由度的两端，不能同时改善。

同一 Q 格式的数在加法下封闭：不溢出时码字直接相加，小数位不变，因此定点累加不需要重新定标。乘法不封闭：两个 n 位小数的码字相乘会得到 2n 位小数，需要右移 n 位并舍入才能回到原格式，位宽也要按 $2W$ 预留。这一条决定了定点实现的乘法器后必须跟一个定标移位级，也是定点与浮点在运算结构上最实际的差别。

### 手算数值例：Q4.4 表示 3.6875

取 `Q4.4`：$W=8$、$m=4$、$n=4$，步长 $\Delta=2^{-4}=0.0625$，可表示区间为 $[-8,\,7.9375]$。要表示的实数是 $3.6875$，先做缩放：

$$3.6875\times16=59.0$$

缩放结果恰为整数，说明该数正好落在格点上。码字 $q=59$，8 位补码二进制为 `0011 1011`；把小数点放在第 4 位之后读作 `0011.1011`，逐位权值为 $2+1+0.5+0.125+0.0625=3.6875$，与输入一致。解码按 $q/2^n$ 计算，$59/16=3.6875$，量化误差为

$$\varepsilon=3.6875-\frac{59}{16}=0$$

之所以恰好为零，是因为 $3.6875=59/16$ 的分母就是 $2^4$；任何分母为 $2^n$ 且落在区间内的实数都能被 `Qm.n` 精确表示。

把输入换成 $3.7$，缩放得 $3.7\times16=59.2$，最近码字仍是 $59$，量化值为 $3.6875$，误差 $\varepsilon=+0.0125$，小于半步长 $0.03125$。相邻格点 $58$ 与 $60$ 分别对应 $3.625$ 与 $3.75$，$3.7$ 离 $3.6875$ 更近，舍入方向正确。若输入为 $3.72$，缩放值 $59.52$ 越过中点，最近码字变为 $60$，量化值 $3.75$，误差 $-0.03$；误差的绝对值始终压在半个步长之内，这是最近舍入的定义所保证的。

负数走同一条路径：$-3.6875$ 的缩放值为 $-59$，8 位补码是 `1100 0101`；按无符号读得 $197$，$197-256=-59$，再除以 $16$ 还原 $-3.6875$。补码的全部意义在这里体现：同一串比特按无符号读与按有符号读只差一个 $2^W$ 的偏移，硬件不需要为负数准备第二套编码。

### LLR 定标：步长、范围与分辨率

LLR 是软解调输出、译码器输入的实数，其符号给出比特判决方向、绝对值给出可靠度。定点实现用一个 8 位有符号码字保存它，定标关系为

$$L_q=s\,q,\qquad q\in[-128,\,127]$$

$s$ 的选择同时决定可表示范围与分辨率。取 $s=0.25$ 时，$L_q$ 落在 $[-32,\,31.75]$，相邻可表示值相差 $0.25$，最大量化误差 $0.125$；取 $s=0.5$ 时范围扩大到 $[-64,\,63.5]$，但分辨率退化为 $0.5$，最大误差翻倍到 $0.25$。两组的格点总数都是 256，最大幅度与步长之比都是 127——改变 $s$ 只是把同一组 256 个格点整体缩放，不能在不增加位宽的前提下同时保住大范围与细分辨率。

| 定标因子 $s$ | 可表示范围 | 分辨率 | 最大量化误差 | 量化噪声方差 $\sigma_q^2$ |
|:---|:---|:---|:---|:---|
| 0.25 | $[-32,\,31.75]$ | 0.25 | 0.125 | 0.0052 |
| 0.50 | $[-64,\,63.50]$ | 0.50 | 0.25 | 0.0208 |

饱和与回绕在这组参数上的差别可以直接算出来。设某个 LLR 的真值为 $100$，$s=0.25$ 时理想码字为 $400$，远超 $q_{\max}=127$。若按饱和处理，码字钳到 127，$L_q=31.75$，幅度被压缩但符号为正；若按 8 位回绕处理，$400\bmod 256=144$，有符号读数为 $144-256=-112$，$L_q=-112\times0.25=-28$，一个强正的可靠度被折成中等强度的负值，硬判决方向直接翻转。饱和的误差虽然可以很大（此例为 68.25），但它是单调的——所有超过阈值的输入映射到同一个端点，可靠度的排序不被破坏；回绕则破坏排序并翻转符号，对迭代译码是灾难性错误。

把量化误差折算成噪声，步长 $s$ 的均匀量化器误差方差为 $\sigma_q^2=\Delta^2/12$（$s=\Delta$），$s=0.25$ 时约为 0.0052，标准差约 0.072。这个量在译码器输入端等效为一份额外噪声：步长加倍，量化噪声功率变为四倍，弱信号（绝对值小于一个步长的 LLR）的方向信息最先被淹没。

把这条定标关系放回译码链路，浮点 LLR 到定点 LLR 的损失有三个来源，且三者共用位宽这一个预算。第一是量化噪声：真值被舍入到最近的格点，误差不超过 $\Delta/2$、方差为 $\Delta^2/12$，它主要损伤判决边界附近的小幅 LLR，等效于在原有噪声之外再叠加一份与步长平方成正比的噪声。第二是饱和裁剪：绝对值超过 $C$ 的 LLR 一律映射到端点，端点以内的相对顺序保留、端点以外的相对顺序丢失；若 $C$ 取得过小，高信噪比下最可靠的那部分比特反而被压成同一个值，迭代译码的外信息不再增长，表现为高信噪比段的误差平台。第三是动态范围与位宽的绑定：$W$ 固定时范围与分辨率只能此消彼长，而 HARQ 软合并要把多次重传的 LLR 逐比特相加，累加结果的幅度上界随合并次数线性增长——4 次合并需要 2 位额外裕量，8 次需要 3 位；实现通常在累加器里多留几位保护位，写回存储时再饱和到 $W$ 位，否则中间和先溢出，前面的量化精度全部作废（合并机制见 [[Chase_Combining_Chase合并]]）。

## 直观模型

定标关系给出的是代数式；换到实数轴上，同一组关系就是一组等间距的点。可表示集合是一组格点：原点在 0，间距为 $s$，最左点是 $s q_{\min}$，最右点是 $s q_{\max}$，点的总数是 $2^W$。每个点负责一段长度为 $s$ 的区间，量化就是把落在这段区间里的实数映射到该点；区间在内部以格点为中心取 $[s q-s/2,\,s q+s/2)$，在两端的区间只保留半个，超出最外侧区间的值由饱和钳到端点。用集合写出来就是

$$\{s q\mid q=q_{\min},\ldots,q_{\max}\}$$

定点数的全部性质都从这个集合的结构读出：它是有限的、等间距的、关于原点近似对称但负端多一个点；它的每个元素都是分母整除 $2^n$ 的有理数，不含无理数。浮点数的集合则不是等间距的——它的间距随指数增大，因而绝对误差随数值增大、相对误差大致恒定；定点选择的是相反的取舍，绝对误差恒定、相对误差随数值增大而减小。
同一结构还决定三条运算事实。加法：两个格点相加仍是格点（不溢出时），小数位不变，因此定点累加不需要重新定标。乘法：两个 n 位小数的格点相乘得到 2n 位小数，结果一般不在原集合内，必须右移并舍入。比较：格点上的数可以直接按整数码比较大小，补码的顺序与实数顺序一致，这一点让饱和、取最大值、符号判决都能用整数比较器完成。回绕则是把码字当成 W 位地址空间做模 $2^W$ 运算：$q_{\max}$ 加一回到 $q_{\min}$，符号位随之翻转；这正是饱和必须替代回绕的原因。

## 常见误解

以上定义、算例与工程用法各自成立，但若把其中一条抽出来单独记忆，容易在边界上读错。下面把七处最常见的误读集中对照，每行给出误解与对应的正确理解。

| 误解 | 正确理解 |
|:---|:---|
| 位宽越大越好 | 每加 1 位只换来范围与分辨率之比扩大一倍（约 6 dB），且这一位只能用于扩范围或提分辨率之一；存储、布线、功耗与每周期吞吐成本同步上升。LLR 在 6 位、裁剪到 ±31 后损失已低于 0.02 dB，继续加位宽的收益封顶，位宽应按动态范围与合并裕量确定。 |
| 溢出用回绕和用饱和差不多 | 回绕按 $2^W$ 取模，会把 $+100$ 折成 $-28$ 并翻转符号；饱和钳在端点，符号与单调性都保留。LLR 的符号就是判决方向，回绕属于灾难性错误。 |
| `Qm.n` 的 m 含符号位是唯一定义 | 本笔记约定 $W=m+n$、m 含符号位，`Q4.4` 是 8 位；另一些工具让 m 不含符号位，同一记号会多出一位。交接时必须写明约定。 |
| 定点数就是精度较低的浮点数 | 定点是等间距格点上的有理数子集，绝对分辨率恒定、范围有限；浮点是相对精度恒定、范围随指数扩展。两者误差结构与溢出行为都不同。 |
| 小数点保存在硬件里 | 硬件只保存整数码 $q$，小数点位置是编译期或接口约定，由解释方按 $2^{-n}$ 移位还原；同一串比特换一个 Q 格式就是另一个数。 |
| 量化误差可以忽略 | 误差上界为 $\Delta/2$、方差为 $\Delta^2/12$；步长加倍则噪声功率变四倍，弱 LLR 的方向信息先被淹没，迭代译码的收敛速度与误差平台都会受影响。 |
| 饱和阈值越大越好 | 位宽固定时阈值与分辨率共用同一个自由度：阈值放大一倍，步长也放大一倍，小 LLR 的分辨率随之退化；阈值应按 LLR 动态范围与可接受损失确定。 |

## 协议锚点

把前文的表示与算例对照协议文本，可以划出四条边界：协议规定到哪一级、哪些量留给实现、本笔记的示例数字属于哪一类、哪些内容根本不属于 3GPP。

- **协议规定的部分**：TS 38.212 Rel-19 §5.4.2.1 定义 LDPC 码的比特选择（bit selection），TS 36.212 Rel-19 §5.1.4.1.2 定义 Turbo 码的比特收集、选择与传输；两者确定速率匹配后进入译码器的编码比特序列及其顺序。LLR 序列的每一个分量对应其中一个编码比特，这是定点 LLR 与协议之间唯一确定的对应关系（本地抽取件：`3GPP_Rel19/processed/TS_38.212_38212-j30/full.md`、`3GPP_Rel19/processed/TS_36.212_36212-j30/full.md`）。
- **协议不规定的部分**：LLR 的数值标度、位宽、Q 格式、舍入方式、饱和函数与裁剪阈值都不在 TS 36.212 与 TS 38.212 的文本内，属于接收机实现域；协议只保证比特级语义，接收机可以用浮点、定点或对数域近似实现，只要输出比特与协议一致。
- **本笔记的取值边界**：文中 `Q4.4`、8 位 LLR、步长 0.25、阈值 $C=32$、±31/6 位等数字都是教学与工程示例，不是协议常量；±31/6 位的损失数据来自本库工程预算口径（见 [[T21.1_engineering_budget_overview]] 与 [[T21.3_llr_dynamic_range_clipping_tradeoff]]），使用时应按具体译码器重新测量。
- **非 3GPP 标准项**：整数表示、补码、定标、Q 格式、量化噪声方差、饱和与回绕均为数字信号处理与计算机算术的标准内容，不来自任何 TS/TR 条款。

## 关键要点

1. `Qm.n` 的代数关系是 $W=m+n$（m 含符号位）、$\Delta=2^{-n}$、$x=q/2^n$；硬件只存整数码，小数点位置由解释方约定。
2. 可表示区间为 $[s q_{\min},s q_{\max}]$；`Q4.4` 是 8 位，区间 $[-8,\,7.9375]$，步长 0.0625。
3. `Q4.4` 表示 3.6875：$3.6875\times16=59$，码字 `0011 1011`，量化误差为 0；3.7 的误差为 $+0.0125$，小于半步长 $0.03125$。
4. 位宽锁定范围与分辨率之比：8 位时最大幅度与步长之比为 127（约 42 dB），$s=0.25$ 给 $[-32,\,31.75]$，$s=0.5$ 给 $[-64,\,63.5]$，不能同时扩大范围与细化分辨率。
5. 饱和保留符号与单调性，回绕按 $2^W$ 折返并翻转符号：真值 $+100$ 在 $s=0.25$ 下饱和为 31.75，回绕为 $-28$。
6. 量化噪声的误差上界为 $\Delta/2$、方差为 $\Delta^2/12$；步长加倍，量化噪声功率变四倍。
7. LLR 定点化的损失有三个来源：量化噪声损伤小 LLR、饱和裁剪丢失高可靠端的排序、位宽约束范围与分辨率；HARQ 合并还要为累加器预留保护位。
8. 「6 位 LLR」不是完整规格：必须同时写明符号约定、Q 格式、裁剪阈值与舍入方式，才能比特精确复现。
