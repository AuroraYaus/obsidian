# Bit-Exact 回归验证

## 符号与记号约定

| 符号 | 含义与取值 | 协议锚点 |
|:---|:---|:---|
| $v$ | 回归套件中的单条协议向量，含输入比特串与期望输出比特串；量纲一 | 由 TS 36.212 §5.1.3.2.1 导出（LTE Turbo 向量语义） |
| $V$ | 全部协议向量的集合，$v$ 是它的元素；覆盖正常、边界、异常、重传四类，量纲一 | 由 TS 36.212 §5.1.3.2.1 导出（向量语义，向量本身由实现构造） |
| $A$ | 第一个实现层级对一条向量给出的输出比特串，长度等于该向量的信息比特数，量纲一 | 实现域（实现层级的输出） |
| $B$ | 第二个实现层级对同一条向量给出的输出比特串，与 $A$ 同口径、同长度，量纲一 | 实现域（实现层级的输出） |
| $\overset{\text{bit-exact}}{=}$ | 比特精确相等关系，表示两侧逐比特完全一致、容差为零，量纲一 | 非 3GPP 标准（等号上标注的排版记号） |
| $\Longleftrightarrow$ | 逻辑等价算子，表示左右两个命题互为充要条件，量纲一 | 非 3GPP 标准（逻辑记号） |

等号上方的 `bit-exact` 只是关系标注，不是变量名。各行来源统一写在第三列：协议量给 TS 条款号，派生量给「由 TS … §… 导出」，非协议量给「非 3GPP 标准」或「实现域」。

Bit-Exact 回归验证要求同一输入在所有实现层级（Python ↔ C/C++ ↔ RTL（寄存器传输级，Register Transfer Level））产生逐比特一致的输出。一句话本质：**bit-exact 回归是"三方对账"——手算、Excel、银行流水分毫不差才算平账，差一分钱都说明某处进位或舍入不一致；差异点直接指向溢出、舍入或状态机错误，而不是笼统的"结果不对"**。

## 解释目标与范围

本节目标：解释分层比对框架中各层级的误差容限为何不同，以及 bit-exact 与功能正确之间的区别。

## 前置概念

**实现层级**（Implementation Tier）指同一算法在不同抽象层次上的落地形态，本笔记涉及浮点参考实现、定点模型与寄存器传输级实现三层。层级越靠下，可用的数值精度越低、时序约束越硬，因此三层对"一致"的要求并不相同：浮点层负责定义正确性，定点层负责逼近，硬件层负责与定点层逐比特对齐。

**量化误差**（Quantization Error）指用有限位宽表示实数时产生的舍入偏差，其大小由位宽与舍入规则共同决定。量化误差会在运算链上累积，同一算法在浮点与定点两层给出不同判决是正常现象；回归验证要做的不是消除这种差别，而是把差别限制在预先声明的容限之内，并在超出时定位到具体的运算步骤。

**定点数**（Fixed-Point Number）指小数点在位宽内位置固定的数值表示，由总位宽、小数位宽与符号位共同描述。定点运算的加法可能溢出、乘法需要舍入，两者都会破坏与浮点结果的等价性；因此定点模型的位宽选择本身就是设计决策，回归失败时首先怀疑位宽不足或舍入方式不一致。

**回归测试**（Regression Test）指用一组固定输入反复运行、把每次输出与基线比对的验证方式，目的是发现"改动一处、破坏另一处"的退化。回归测试的有效性取决于向量集的覆盖面：只覆盖正常流程的向量集无法暴露边界条件与异常路径的退化，因此向量集要显式包含正常、边界、异常与重传四类。

**黄金模型**（Golden Model）指被公认为正确性基准的参考实现，通常是浮点、无量化、可读性优先的版本。黄金模型只定义"应该是什么"，不规定"怎么实现"；下游实现与黄金模型的差距用容限描述，而下游实现之间的一致性用逐比特相等描述，两种判据不可互换。

## 起源与演进

(1) **起点：多层实现的正确性怎么保证。** Python/C/C++/RTL 三层实现同一算法——必须逐比特一致才能互相替换。

(2) **三级误差容限。** Golden Reference（浮点基准、无量化误差）；定点比对（量化误差在容许范围内）；RTL 比对（必须 bit-exact、容差为零）。

(3) **对账纪律。** 不只比对最终 CRC——中途 checkpoint（各译码器内部状态）也要比对，才能定位首个发散点。

(4) **两条边界。** bit-exact 保证一致性、不保证正确性（两个实现可能一致地错——正确性靠 Golden 与协议向量）；单条向量通过不构成回归证据（正常/边界/异常/重传都要覆盖）。

(5) **协议边界。** TS 不规定回归框架——bit-exact 验证属工程方法论，非 3GPP 标准。

## 科学定义

设 $V$ 为协议向量集合，$A, B$ 为两个实现层级，bit-exact 定义为对每条向量输出比特串完全相等：

$$A \overset{\text{bit-exact}}{=} B \quad\Longleftrightarrow\quad \forall v \in V:\; A(v) = B(v)$$

分层框架的三级误差容限依次收紧：

- **Golden Reference**：Python 浮点实现，作为正确性基准，无量化误差。
- **定点比对**：C/C++ 定点模型 vs Golden，量化误差在容许范围内。
- **RTL 比对**：RTL vs 定点模型，必须 bit-exact，容差为零。
- **回归套件**：覆盖正常/边界/异常/重传 case。

## 直观模型

同一笔账由手算、Excel、银行流水三方对账：分毫不差才算平账，差一分钱都说明某处进位或舍入不一致。数值例子：某译码器对同一码块输入 16 bit LLR 向量，Golden 浮点与定点模型各自给出判决比特串，若第 17 位由 0 变 1，回归即失败——差异点直接指向溢出、舍入或状态机错误，而不是笼统的"结果不对"。

## 常见误解

| 误解 | 正确理解 |
|:---|:---|
| bit-exact 要求所有层级与浮点 Golden 完全一致 | 浮点 Golden 是正确性基准；定点与 RTL 只需互相 bit-exact，与 Golden 的差距在量化容限内。 |
| 只比对最终 CRC 就足够 | 中途 checkpoint（各译码器内部状态）也要比对，才能定位首个发散点。 |
| bit-exact 等于功能正确 | 两个实现可能一致地错；bit-exact 保证一致性，正确性靠 Golden 基准与协议向量保证。 |
| 一条向量通过即宣告回归通过 | 正常/边界/异常/重传向量都要覆盖，单条通过不构成回归证据。 |

## 协议锚点

- 协议向量来源：TS 36.212 Rel-19 `36212-j30`（LTE Turbo 语义）、TS 38.212 Rel-19 `38212-j30`（NR Polar/LDPC 语义）。
- 本地锚点：`3GPP_Rel19/processed/TS_36.212_36212-j30`；`3GPP_Rel19/processed/TS_38.212_38212-j30`。
- 协议边界：TS 不规定回归框架、文件命名、CI 命令或 RTL 端口；协议只规定每串逻辑比特和校验语义应是什么。bit-exact 验证属工程方法论，非 3GPP 标准。

## 关键要点

1. bit-exact：$\forall v\in V:\ A(v)=B(v)$——所有层级必须一致。
2. 三级容限：Golden 基准/定点容限内/RTL 零容差。
3. 不只比 CRC——中途 checkpoint 定位首个发散点。
4. bit-exact ≠ 功能正确——两个实现可能一致地错。
5. 回归套件要覆盖正常/边界/异常/重传四类。
6. 回归框架是工程方法论，非 3GPP 标准。
