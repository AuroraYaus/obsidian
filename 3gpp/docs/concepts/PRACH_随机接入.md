运算符与记号惯例：$\lfloor\cdot\rfloor$ 为向下取整，$\lceil\cdot\rceil$ 为向上取整，$\min\{\cdot\}$ 取较小值，$\times$ 与 $\cdot$ 都表示乘法，$\bmod$ 表示取余（余数落在 0 至 $L_{RA}-1$）。下标起限定作用：$L_{RA}$ 的 RA 指随机接入，$N_{CS}$ 的 CS 指循环移位，$P_{tgt}$ 的 tgt 指目标取值，$s_{id}$、$t_{id}$、$f_{id}$ 的 id 指索引。上标表示所属对象或量名：$N_{preamble}^{total}$ 的 total 指总数，$n_{shift}^{RA}$ 的 RA 指该量属于随机接入前导。$\Delta$ 不与别的字母分离使用，只连写成 $\Delta f_{RA}$（子载波间隔）与 $\Delta_{F}$（格式相关功率偏移）。

三个容易混淆的量在此一并区分：$L_{RA}$ 是序列的元素个数（839、139、571、1151），直接决定占用的子载波个数；$N_{CS}$ 是相邻前导之间的移位步长，$n_{shift}^{RA}$ 是一根根序列能容纳的移位数，两者满足 $n_{shift}^{RA}=\lfloor L_{RA}/N_{CS}\rfloor$；$p$ 是前导在一个 occasion 内的索引（0 至 63），$i$ 是逻辑根序列索引，$u$ 是 $i$ 经查表得到的物理根序列号。三套编号的维度不同，混用会把前导集合算错。

记号确定后，先把前导放回随机接入链路的位置。用户设备（User Equipment, UE）开机后先做小区搜索取得下行同步，此后仍缺两样东西：上行定时与小区内唯一标识；前导就是在这两样都缺的时候唯一能主动发送的上行信号。前导的波形在物理层生成与发送，资源配置与过程控制由媒体接入控制（Medium Access Control, MAC）层承担，因此同一个对象在三份规范中各有一半定义：TS 38.211 管序列长什么样，TS 38.213 管在哪个时频位置发、用多大功率发、响应窗口多长，TS 38.321 管发几次、失败后怎么办、竞争如何解决。

随机接入（Random Access, RA）过程本身分四步（Msg1 至 Msg4，即消息 1 至消息 4，依次为前导、随机接入响应、连接请求与竞争解决）或两步（MsgA 与 MsgB），前导是它的第一步，也是 UE 在未被调度的情况下唯一可以主动发送的上行信号；此后的上行传输都要等网络给出授权。一句话本质：**PRACH 前导是 UE 在上行未同步、小区内尚无唯一标识时发出的确定性序列；基站在相关域里从它读出两个整数——前导索引与时间偏移，前者说明"发了哪一个前导"，后者换算成定时提前量说明"要提前多少"，而"到底是谁"留给随后的 Msg3 与 Msg4 回答。**
## 解释目标与范围

本节目标：讲清 PRACH 前导的生成规则与编号方式（ZC 序列、循环移位、64 个前导如何由根序列与移位拼出）、$L_{RA}$、$\Delta f_{RA}$、$N_{CS}$ 三个参数如何共同决定前导集合与小区半径、四步与两步随机接入各步的分工，以及 RA-RNTI 与功率爬坡在其中的作用。

阅读前应能说明小区搜索如何让 UE 获得下行同步、系统信息块 1（System Information Block 1, SIB1）如何携带随机接入配置；读完之后应能仅凭 $L_{RA}$ 与 $N_{CS}$ 算出每根序列的移位数与前导总数，由零相关区长度估算小区半径上限，并说明 Msg2 的 RA-RNTI 为什么由 occasion 的时频位置算出而不是由 UE 身份算出。后文反复使用的对象有七个，先补齐它们的定义。

## 前置概念

第一个对象是随机接入（Random Access, RA）。它是 UE 与网络建立上行同步、取得首个上行授权并完成初始接入或重建、切换、恢复的 MAC 过程，触发场景包括初始接入、无线资源控制（Radio Resource Control, RRC）重建立、切换、连接恢复、上行失步后的数据到达与波束失败恢复；在本笔记中它是外层的流程框架，讲义版见 [[T15.2_PRACH_random_access]]。

第二个对象是前导（preamble）。它是在 PRACH 上发送的、由一条根序列的循环移位得到的确定性序列，长度记为 $L_{RA}$，一个 PRACH occasion 内共 64 个；前导本身不携带比特信息，它的"内容"就是自己的索引 $p$，基站检测到哪个索引，就等于知道 UE 选了哪一个前导。

第三个对象是 Zadoff-Chu 序列（Zadoff-Chu sequence, ZC）。它是单位幅度的复指数序列，相位随元素序号按二次函数变化，有两条性质：周期自相关在零时延处出现单峰，不同根序列之间的互相关很低。前导取的是 ZC 序列的循环移位，因此"检测"与"测时"可以由同一个相关器一次完成；本笔记中 $x_u$ 指第 $u$ 号根序列。

第四个对象是循环移位（cyclic shift）。它把长度为 $L_{RA}$ 的序列首尾相接后整体平移若干个元素，平移量记为 $C_v$；同一个根序列的不同循环移位在相关域上互不重叠，前提是时延造成的峰位移动小于移位步长 $N_{CS}$。前导集合的大小与小区半径都由这个步长决定。

第五个对象是前导格式（preamble format）。它是一组预先规定的参数组合——序列长度 $L_{RA}$、子载波间隔 $\Delta f_{RA}$、循环前缀时长与序列时长，用编号 $F$ 区分：长格式 0 至 3，短格式 A1 至 A3、B1 至 B4、C0 与 C2。格式决定前导占用的带宽与时长，也决定它能支持多大的小区。

第六个对象是随机接入响应（Random Access Response, RAR）窗口。UE 发完前导后在长度 $T_{RAR}$ 的窗口内监视物理下行控制信道（Physical Downlink Control Channel, PDCCH），等待用 RA-RNTI 加扰的下行控制信息；窗口内没有收到与本次前导对应的响应，UE 就判定这次尝试失败并重发前导，窗口长度与起点由 TS 38.213 §8.2 与 TS 38.321 §5.1.4 共同规定。

第七个对象是竞争与非竞争（contention-based / contention-free random access, CBRA/CFRA）。竞争接入由 UE 从可用前导中随机选一个，多个 UE 可能选中同一个，冲突要靠 Msg3 与 Msg4 的身份交换解决；非竞争接入由网络在 PDCCH order 或切换命令中指定前导索引与 occasion，不会发生冲突，代价是资源必须预留，流程见 [[T16.6_random_access_rrc_connection_setup]]。

七个对象就位后，可以看这套前导集合是如何从 LTE 一路演进到 NR 的。

## 起源与演进

(1) **起点是没有上行同步。** UE 刚开机或失步时，基站既不知道它存在，也不知道它的传播时延，因此需要一个 UE 能在未被调度时主动发送、基站又能同时完成检测与测时的信号。等幅的 ZC 序列同时满足这两条：相关峰的位置给出时延，峰的编号给出是哪一个前导。

(2) **LTE 把参数定型。** TS 36.211 §5.7.2 规定每个小区 64 个前导，由一条或数条根序列的循环移位拼出，序列长度 839（格式 0 至 3）或 139（格式 4），移位步长 $N_{CS}$ 由 zeroCorrelationZoneConfig 查表给出；格式 0 的循环前缀为 3168 个基本采样、序列为 24576 个基本采样，折合 103.1 µs 与 800 µs。

(3) **NR 保留长格式并加入短格式。** TS 38.211 §6.3.3.1 沿用 839 与 1.25 kHz、5 kHz 的组合（格式 0 至 3），并新增 $L_{RA}=139$ 的短格式 A、B、C 三系，子载波间隔为 $15\cdot 2^{\mu}$ kHz；短格式的序列时长只有 66.7 µs（$\mu=0$），一个时隙内可以放多个 occasion，适配高频段与波束扫描。Rel-19 的格式表还列出 571 与 1151 两种长度，在同一子载波间隔下占用更宽的带宽。

(4) **流程从四步压到两步。** 四步流程需要两次往返（前导与响应、Msg3 与竞争解决），两步流程把前导与物理上行共享信道（Physical Uplink Shared Channel, PUSCH）载荷合成 MsgA、把响应与竞争解决合成 MsgB，省掉一次往返；代价是前导与 PUSCH 资源的关联配置更复杂，失败时还要回退到四步流程。

(5) **边界在于触发场景与层次分工。** 随机接入不只服务于初始接入，切换、重建立、连接恢复、上行失步后的数据到达与波束失败恢复都要走这条流程；分工上前导的波形与序列在物理层，occasion 的选择、重发与竞争解决在 MAC 层，功率与窗口在物理层规范中给出。三层各管一段，任何一段读错都会表现为"前导发得出去、响应收不回来"。

上述五步给出的是设计脉络，下面把前导集合固定成可引用的定义与算式。

## 科学定义

### 前导序列的生成与前导索引的编号

TS 38.211 §6.3.3.1 规定，一个 PRACH occasion 上的 64 个前导由根序列的循环移位给出。每个前导对应一对编号：逻辑根序列索引 $i$ 与移位序号 $v$。枚举时先固定 $i$、把 $v$ 从 0 递增，用完一根序列的全部移位后再把 $i$ 加 1 继续，直到凑满 64 个——这就是条文里"先按循环移位递增、再按逻辑根序列索引递增"的顺序。无约束集合下移位量为 $C_v=v\cdot N_{CS}$，相邻前导之间固定隔 $N_{CS}$ 个元素；逻辑根序列索引本身循环排列，索引 0 与 $L_{RA}-2$ 相邻，$i$ 经表 6.3.3.1-3 至表 6.3.3.1-4B 映射为物理根序列号 $u$。

$N_{CS}$ 不是自由参数，它由配置项 zeroCorrelationZoneConfig 查表得到（表 6.3.3.1-5 至表 6.3.3.1-7 按子载波间隔与序列长度分表），并且还要选择无约束集合、受限集合 A 或受限集合 B。表 6.3.3.1-5 在 1.25 kHz 下给出的取值从 0、13、15、18 一直到 419；同一行在受限集合下有另一组更大的数，因为受限集合要额外容纳多普勒造成的峰位偏移。

手算一例可以看清这几个量的关系。取 $L_{RA}=839$、$N_{CS}=13$：一根根序列可生成的循环移位数为 $n_{shift}^{RA}=\lfloor839/13\rfloor=64$，余下 $839-13\times64=7$ 个元素不参与划分；64 个前导的移位量依次为 $C_v=0,13,26,\ldots,819$，恰好填满一个 occasion 的 64 个索引，于是所需根序列数 $K=\lceil64/64\rceil=1$，可用前导总数（按根序列数计）为 $K\,n_{shift}^{RA}=64$。若把步长改成 $N_{CS}=15$，则 $n_{shift}^{RA}=\lfloor839/15\rfloor=55$，$K=\lceil64/55\rceil=2$，第二根根序列只用前 9 个移位，可用前导总数变成 $2\times55=110$，本 occasion 只取前 64 个，其余不进入本 occasion 的前导集合。

$N_{CS}$ 决定小区半径的原因在时延轴上。第 $v$ 个前导的移位量使它的相关峰比根序列的峰晚 $C_v$ 个元素，往返时延再把这个峰往后推；只要时延折算出的元素数小于 $N_{CS}$，峰就落在本前导独占的区间内，不会被读成相邻的前导。以 $L_{RA}=839$、$\Delta f_{RA}=1.25$ kHz 为例，序列时长等于 $1/\Delta f_{RA}=800$ µs，平均到 839 个元素上每个元素约 0.954 µs；$N_{CS}=13$ 给出约 12.4 µs 的时延窗口（按 $N_{CS}-1$ 个元素计的零相关区为 11.4 µs），对应 $d=c_{0}T_{RTT}/2=1.86\times10^{3}$ m 的理想上限。工程上还要给时延扩展留余量，并按 $N_{CS}-1$ 个元素计算保护区，实际规划半径按 1 km 至 2 km 量级取。

覆盖上限并不只由 $N_{CS}$ 决定，循环前缀的长度同样约束时延：格式 0 的循环前缀为 103.1 µs，可吸收约 15.5 km 的往返时延，此时半径受 $N_{CS}=13$ 的 12.4 µs 限制；短格式 B1 的循环前缀只有 7.0 µs（$\mu=0$），可吸收约 1.05 km，与 $N_{CS}$ 给出的上限同量级，二者取较小者。这条约束也说明"前导越长覆盖越大"只在循环前缀同时放大的前提下成立。

半径与容量之间存在直接的折中。$N_{CS}$ 增大使零相关区变宽、可支持的小区变大，但每根序列可用的移位数 $\lfloor L_{RA}/N_{CS}\rfloor$ 变少，64 个前导需要更多根序列，前导之间的互相关性能与规划自由度随之下降；$N_{CS}=15$ 时的 2 根根序列就是这种折中的最小例子。序列与移位确定之后，下一个问题是这些序列以什么格式、在什么位置被发送。

### 前导格式与时频资源

前导格式决定四个量：序列长度 $L_{RA}$、子载波间隔 $\Delta f_{RA}$、循环前缀时长与序列时长。长格式 0 至 3 取 $L_{RA}=839$，格式 0 至 2 的子载波间隔为 1.25 kHz、格式 3 为 5 kHz；格式 0 的循环前缀折合 103.1 µs、序列 800 µs，占用约 1.05 MHz 带宽，频域上约 6 个物理资源块（Physical Resource Block, PRB）。短格式以 $L_{RA}=139$ 为主，子载波间隔 $15\cdot2^{\mu}$ kHz，$\mu$ 取 0、1、2、3、5、6；序列时长等于 $1/\Delta f_{RA}$，$\mu=0$ 时为 66.7 µs，格式 B1 的循环前缀 7.0 µs、序列占 2 个符号共 133.3 µs，频域上 139 个子载波约 2.09 MHz，折合 12 个 PRB。

时域资源由配置项 prach-ConfigurationIndex 查表给出（按双工方式与频率范围分别查表 6.3.3.2-2、表 6.3.3.2-3 与表 6.3.3.2-4），频域资源由 msg1-FrequencyStart 给出起点、msg1-FDM 给出同一时刻频分复用的 occasion 个数 $M$（取 1、2、4、8）。频域 occasion 从上行带宽的最低频起编号为 $n_{RA}$，$0\le n_{RA}<M$；每个 occasion 上有 64 个前导（小区实际可用的前导数由 totalNumberOfRA-Preambles 配置，取 1 至 64），因此一个小区在一个时刻能容纳的前导总数不超过 $64M$，再按 SSB 分组分配。

同步信号块（Synchronization Signal Block, SSB）与 occasion 的关联在 TS 38.213 §8.1 中给出：配置项 ssb-perRACH-OccasionAndCB-PreamblesPerSSB 规定一个 occasion 关联几个 SSB、每个 SSB 分到几个竞争前导，映射顺序是先按 occasion 内的前导索引递增、再按频域 occasion 索引递增、再按时域 occasion 索引递增、最后按 PRACH 时隙索引递增。UE 选定某个 SSB 之后只能在该 SSB 对应的前导子集里选，基站从"哪个前导"就能反推出 UE 选的是哪个下行波束。

格式的选择由覆盖与部署场景共同决定。长格式的序列时长在 0.8 至 3.2 ms 之间（格式 0 为 800 µs、格式 2 为 3200 µs），能量集中、子载波间隔窄，适合低频大区与需要大覆盖的部署；短格式的序列时长只有几微秒至几十微秒，一个时隙内可以排多个 occasion，适合高频段、波束扫描与低时延场景。长度 571 与 1151 的格式在 Rel-19 中与 139 并列给出，同一子载波间隔下占用更宽的带宽，用于需要更高相关处理增益的部署。格式与资源位置确定之后，剩下的问题是这个过程由谁发起、失败后如何重试、以多大功率重发。

### 随机接入过程、RA-RNTI 与功率爬坡

四步流程的第一步由 MAC 层选资源：TS 38.321 §5.1.2 规定 UE 依据 SIB1 中的 RACH-ConfigCommon 选出 PRACH occasion、与之关联的 SSB 以及前导索引 $p$，再把 occasion、索引与目标接收功率交给物理层发送。竞争接入时 $p$ 从该 SSB 的竞争前导子集里随机选；非竞争接入时 $p$ 由 PDCCH order 或 RRC 配置直接指定。

第二步是随机接入响应。UE 在长度 $T_{RAR}$ 的窗口内监视 Type1-PDCCH 公共搜索空间，等待用 RA-RNTI 加扰的下行控制信息（Downlink Control Information, DCI）格式 1_0。RA-RNTI 由 occasion 的时频位置算出，TS 38.321 §5.1.3 给出的算式为 $1+s_{id}+14\cdot t_{id}+14\cdot80\cdot f_{id}+14\cdot80\cdot8\cdot c_{UL}$，其中 $s_{id}$ 是 occasion 首个正交频分复用（Orthogonal Frequency Division Multiplexing, OFDM）符号的序号（0 至 13）、$t_{id}$ 是首个时隙在系统帧内的序号（0 至 79）、$f_{id}$ 是频域 occasion 索引（0 至 7）、$c_{UL}$ 区分 NUL 与 SUL。取 $s_{id}=0$、$t_{id}=10$、$f_{id}=0$、$c_{UL}=0$ 时 RA-RNTI 为 141；四个字段都取最大值时 RA-RNTI 为 17920，两步流程的 MSGB-RNTI 在此之上再加 $14\cdot80\cdot8\cdot2=17920$。

响应消息携带定时提前命令、临时 C-RNTI（Temporary C-RNTI）与一个上行授权。UE 用这个授权在 Msg3 中发送 RRC 连接请求，Msg3 由临时 C-RNTI 加扰并携带 UE 身份，身份可以是公共控制信道（Common Control Channel, CCCH）的服务数据单元，也可以是小区无线网络临时标识（Cell Radio Network Temporary Identifier, C-RNTI）的 MAC 控制单元（MAC Control Element, MAC CE）；第四步的竞争解决消息用临时 C-RNTI 调度，其中的 UE Contention Resolution Identity MAC CE 回显 Msg3 的身份，比对一致才判定竞争成功，比对失败则重发 Msg3 或重新发起整个流程。定时器 $T_{CR}$ 从 Msg3 传输结束后的第一个符号起计，超时同样判为失败。

定时提前量把相关峰的位置换算成发射时刻。基站从峰位读出往返时延，在响应中给出定时提前命令索引 $T_A$（0 至 3846），UE 按 $N_{TA}=T_A\cdot16\cdot64/2^{\mu}$ 换算成基本时间单位 $T_c$ 的个数，并把上行发射整体提前 $N_{TA}T_c$。$\mu=1$ 时每加 1 对应 512 个 $T_c$，即约 260 ns 的往返时延、约 39 m 的单程距离；定时提前的分辨率与前导的时延分辨率是两套不同的量，前者由命令字段的位宽决定，后者由 $N_{CS}$ 与采样率决定。

功率爬坡决定重发时用多大功率。物理层按 $P_{PRACH}=\min\{P_{CMAX},P_{tgt}+P_{loss}\}$ 发射，其中 $P_{tgt}$ 是前导目标接收功率、$P_{loss}$ 是下行路损估计、$P_{CMAX}$ 是配置的最大输出功率；MAC 层给出的目标值是 $P_{tgt}+\Delta_{F}+(N_{ramp}-1)S_{step}$，$\Delta_{F}$ 是与格式相关的偏移（长格式取 0、−3、−6 dB，短格式是 $\mu$ 的一次式）、$S_{step}$ 是爬坡步长、$N_{ramp}$ 从 1 起。取 $P_{tgt}=-100$ dBm、$\Delta_{F}=0$ dB、$S_{step}=2$ dB、$N_{ramp}=3$，目标值为 −96 dBm；再取 $P_{loss}=110$ dB，则发射功率为 14 dBm，未触及 $P_{CMAX}=23$ dBm 的上界。

爬坡计数器并非每次重发都递增。TS 38.321 §5.1.3 规定，只有上一次发送之后没有收到物理层"暂停爬坡计数"的指示、没有收到先听后说（Listen Before Talk, LBT）失败指示、且本次选中的 SSB 与上次相同，$N_{ramp}$ 才加 1；换波束、信道接入失败或功率受限都会让重发沿用原功率。前导发送计数器 $N_{tx}$ 在每次判定本次尝试失败时累加（未收到匹配响应，或收到 LBT 失败指示），达到 `preambleTransMax` 加 1 时 MAC 层向 RRC 上报随机接入问题，由高层决定重建或切换。

两步流程把前导与 PUSCH 载荷合成 MsgA、把响应与竞争解决合成 MsgB：UE 在同一 occasion 上发前导，并用与该前导关联的 PUSCH 资源发送载荷；网络用 MSGB-RNTI 调度 MsgB，其中既可以是对前导的 fallbackRAR（退回四步流程继续），也可以是直接携带竞争解决信息的 successRAR。省下的是一次往返，代价是前导与 PUSCH 的关联必须配置正确，否则载荷落不到对应资源上。过程中的每一步都压在序列与资源这两组关系上，把它们压缩成结构化描述，就是下一节的内容。

## 直观模型

先看相关域上的坐标。接收端对每个候选根序列做循环互相关，输出是一条长度 $L_{RA}$ 的峰位序列：发出去的是第 $u$ 号根序列的第 $v$ 个循环移位时，与 $u$ 相关得到的峰出现在 $C_v$ 处，传播时延再把它往后推 $T_{RTT}$ 折算出的元素数。只要这个推移量小于 $N_{CS}$，各前导的峰就互不进入对方的区间，检测与测时同时成立；$N_{CS}$ 因此可以读成每个前导在时延轴上占用的宽度、也就是零相关区的宽度，它的一端连着小区半径，另一端连着每根序列能分出多少个前导。多普勒频偏会让相位随时间旋转、峰被削低并向邻近区间泄漏，超过门限时只能改用受限集合重排移位，代价是 $n_{shift}^{RA}$ 变小、需要更多根序列。

再看前导索引的二维编号。一个 occasion 内的 64 个前导排成"根序列 × 移位"的二维表：第二维长度是 $n_{shift}^{RA}=\lfloor L_{RA}/N_{CS}\rfloor$，第一维长度是 $K=\lceil64/n_{shift}^{RA}\rceil$，索引 $p$ 沿第二维先递增、再换到第一维的下一行。$L_{RA}=839$、$N_{CS}=13$ 时这张表是 1 行 64 列；$N_{CS}=15$ 时是 2 行 55 列，第二行只用前 9 格。这个地址空间有三个要素：起点由 prach-RootSequenceIndex 给出，步长是 $N_{CS}$，上界与回绕由 $L_{RA}$ 决定——$C_v$ 对 $L_{RA}$ 取模，逻辑根索引 0 接在 $L_{RA}-2$ 之后。这两组关系在几种常见说法上容易被读反，下面逐条对照。

## 常见误解

| 误解 | 正确理解 |
|:---|:---|
| 前导越长，覆盖半径越大 | 半径由零相关区 $N_{CS}$ 与循环前缀长度共同决定、取较小者；$L_{RA}$ 决定占用带宽与相关处理增益。格式 0 的循环前缀有 103.1 µs，半径受 $N_{CS}=13$ 的 12.4 µs 限制；格式 B1 的循环前缀只有 7.0 µs（约 1.05 km），两个上限都落在 1 km 至 2 km 量级。 |
| 64 个前导就是 64 根根序列 | 64 是「根序列 × 循环移位」的结果。$L_{RA}=839$、$N_{CS}=13$ 时一根根序列就给出 64 个前导，$N_{CS}$ 越大所需根序列越多。 |
| 前导是随机数，所以叫随机接入 | 前导是确定的 ZC 循环移位，随机性只体现在 UE 选哪一个索引；非竞争接入时索引由网络直接指定。 |
| 竞争解决靠前导区分 UE | 前导只区分"哪个前导被发过"，多个 UE 可以发同一个前导；竞争解决靠 Msg3 携带的 UE 身份与 Msg4 的回显比对，Msg3 由临时 C-RNTI 加扰。 |
| $N_{CS}$ 越大越好 | $N_{CS}$ 越大零相关区越宽、支持半径越大，但每根序列可用的移位数 $\lfloor L_{RA}/N_{CS}\rfloor$ 越少，需要更多根序列，前导之间的互相关性能与规划自由度随之下降。 |
| RA-RNTI 标识 UE | RA-RNTI 由 PRACH occasion 的时频位置算出，标识"哪个 occasion"，同一 occasion 上的多个 UE 共用一个 RA-RNTI；UE 身份要到 Msg3 才出现。 |
| 功率爬坡每次重发都加一步 | 换 SSB、LBT 失败或物理层指示暂停时爬坡计数器不递增；只有同一 SSB、且前一次未被指示暂停时才加 1。 |
| 随机接入只用于初始接入 | 还用于 RRC 重建立、切换、连接恢复、上行失步后的数据到达、波束失败恢复、系统信息请求与 PDCCH order。 |
| 两步接入总是比四步快 | 只有前导与 MsgA 的 PUSCH 都被正确接收才省一次往返；否则回退到四步流程，前导重发还要多花时间。 |

误解多集中在参数之间的大小关系与职责归属上；把等号与上限的归属单独列出，可以避免把折中当成单调关系。

## 边界情形

第一处边界是 $N_{CS}=0$。表 6.3.3.1-5 与表 6.3.3.1-7 的配置索引 0 给出 0，此时一根根序列只有 $v=0$ 一个前导，64 个前导需要 64 根根序列；逻辑根索引对 839 只有 0 至 837 共 838 个、对 139 只有 0 至 137 共 138 个（表 6.3.3.1-4 在 137 之后标 N/A），因此 0 只适用于半径极小、同时要求前导容量足够的场景。

第二处边界是逻辑索引的回绕。prach-RootSequenceIndex 给出的起点可以靠近序列末端，凑满 64 个前导时索引要绕回 0；绕回发生在 $L_{RA}-2$ 之后，而不是按物理根序列号从 0 重新递增。把逻辑索引与物理根序列号混为一谈，会在起点接近末端时算出错误的 $u$。

第三处边界是半径的两个约束取较小者。格式 0 的循环前缀 103.1 µs 对应约 15.5 km，$N_{CS}=13$ 只给出 12.4 µs，半径由后者限制；格式 B1 的循环前缀 7.0 µs 对应约 1.05 km，与 $N_{CS}$ 的上限同量级。只调大 $N_{CS}$ 而不换格式，半径不会超过循环前缀允许的上限。

第四处边界是功率上界与失败判定。$P_{tgt}+P_{loss}$ 超过 $P_{CMAX}$ 时发射功率被封顶，继续重发只增加 $N_{ramp}$ 而不增加实际功率；$N_{tx}$ 达到 `preambleTransMax` 加 1 时上报随机接入问题。窗口与定时器也各有边界：$T_{RAR}$ 内没有匹配的 RA-RNTI 就重发前导，$T_{CR}$ 内没有匹配的竞争解决身份就重发 Msg3，两者都不会无限重试。边界条件明确后，协议条款与关键要点可作为复核清单。

## 关键要点

1. 一个 PRACH occasion 上有 64 个前导，由根序列的循环移位给出，枚举顺序是先按循环移位递增、再按逻辑根序列索引递增。
2. 无约束集合下 $C_v=v\cdot N_{CS}$，每根序列的移位数为 $n_{shift}^{RA}=\lfloor L_{RA}/N_{CS}\rfloor$，所需根序列数 $K=\lceil64/n_{shift}^{RA}\rceil$。
3. $L_{RA}=839$、$N_{CS}=13$ 时 $n_{shift}^{RA}=64$、$K=1$，一个 occasion 的 64 个前导由一根根序列全部给出；$N_{CS}=15$ 时 $n_{shift}^{RA}=55$、$K=2$。
4. $N_{CS}$ 决定零相关区宽度，从而决定小区半径上限；839 与 1.25 kHz 下一个元素约 0.954 µs，$N_{CS}=13$ 对应约 12.4 µs、理想半径约 1.86 km。
5. 覆盖上限取零相关区与循环前缀的较小者：格式 0 的循环前缀 103.1 µs 不构成约束，格式 B1 的 7.0 µs 只允许约 1.05 km，会更早成为约束。
6. 前导格式由 $L_{RA}$、$\Delta f_{RA}$、循环前缀与序列时长四元组确定，长格式 0 至 3 用 839，短格式 A/B/C 用 139，Rel-19 另列 571 与 1151。
7. RA-RNTI 由 occasion 的时频位置算出（$s_{id}$、$t_{id}$、$f_{id}$、$c_{UL}$），标识的是 occasion 而不是 UE；MSGB-RNTI 在 RA-RNTI 之上加 17920。
8. 前导重发功率按 $P_{tgt}+\Delta_{F}+(N_{ramp}-1)S_{step}$ 爬坡，最终发射功率受 $P_{CMAX}$ 封顶；换 SSB、LBT 失败或收到暂停指示时爬坡计数器不递增。
9. 竞争解决不靠前导，而靠 Msg3 的 UE 身份与 Msg4 的回显比对；两步流程只有在前导与 MsgA 的 PUSCH 都成功时才省下一次往返。
