# TB 传输块

## 符号与记号约定

本笔记的数学片段只涉及传输块的长度接口与分段判据：载荷比特数、循环冗余校验（Cyclic Redundancy Check, CRC）位数、附加 CRC 后的比特数、码块数与最大码块长度。表中「读法」一列给出符号的口述读法，「含义与取值」一列按含义、取值或范围、单位、来源四项写成一句连贯书面语，「协议锚点」一列说明出处。

| 符号 | 读法 | 含义与取值 | 协议锚点 |
|:---|:---|:---|:---|
| $A$ | 大写 A | 一个传输块的载荷比特数，即介质访问控制（Medium Access Control, MAC）交给物理层的数据量，等于调度器选定的传输块大小；取正整数，单位为 bit；由 TS 38.212 §7.2.1 与 §6.2.1 定义为传输块的比特数。 | TS 38.212 §7.2.1 |
| $L$ | 大写 L | 附加在传输块上的 CRC 校验位数；NR 在 $A>3824$ 时取 24、否则取 16，LTE 固定取 24，单位为 bit；由 TS 38.212 §7.2.1 与 TS 36.212 §5.3.2.1 规定。 | TS 38.212 §7.2.1 |
| $B$ | 大写 B | 附加传输块 CRC 之后进入分段模块的比特数；取 $B=A+L$，单位为 bit；由 TS 38.212 §7.2.1 的等式导出。 | 由 TS 38.212 §7.2.1 导出 |
| $C$ | 大写 C | 一个传输块分段得到的码块数，决定后续逐块编码与软缓存的份数；$B\le K_{cb}$ 时取 1，否则取 $\lceil B/(K_{cb}-24)\rceil$，单位为个；由 TS 38.212 §5.2.2 的判定给出。 | TS 38.212 §5.2.2 |
| $K_{cb}$ | K 下标 cb | 低密度奇偶校验码（Low-Density Parity-Check code, LDPC）码块的最大长度，是是否需要分段的门槛；基图（Base Graph, BG）1 取 8448、基图 2 取 3840，单位为 bit；由 TS 38.212 §5.2.2 规定。 | TS 38.212 §5.2.2 |

运算符与记号惯例：$\lceil\cdot\rceil$ 表示向上取整，$\le$ 与 $>$ 表示不超过与超过，$/$ 表示除法并在分段判据中保留有理数形式。$A$、$B$、$L$、$C$ 都是协议原文的大写写法，不作缩写展开；$K_{cb}$ 的下标 cb 是限定词，不表示相乘。

记号既已统一，下面先给出传输块的定位，再交代本笔记要回答的问题与展开顺序。

传输块（Transport Block, TB）是介质访问控制（MAC）层在一次调度中交给物理层、由物理层信道编码链路整体处理的数据单元。一次调度可以不发数据，也可以发一个或两个传输块。一句话本质：**TB 是 MAC 与物理层（Physical Layer, PHY）之间的交付单位——它先附加传输块级 CRC，再按编码器长度上限分段为码块（Code Block, CB）并逐块编码，接收端重组之后以传输块级 CRC 作为交付与否的最终判据**。

## 独立解释任务

任务目标：解释传输块为什么是交付与混合自动重传请求（Hybrid Automatic Repeat Request, HARQ）成败判断的主对象，传输块级 CRC 的位数如何按载荷大小选定，以及分段得到的码块数与编码器上限之间的关系。

阅读本笔记前应知道物理层按码块而不是按整块数据做信道编码，并了解 CRC 的基本作用；读完之后应能由载荷比特数算出附加 CRC 后的长度与码块数，说明所有码块校验通过为什么仍不等于传输块交付成功，并把这一判据与 HARQ 的确认反馈对应起来。完成这一解释需要先建立 MAC、码块与分段、CRC、填充位四个基础对象，下一节先行交代。

## 前置概念

第一个对象是介质访问控制（Medium Access Control, MAC）层。它负责调度、复用与 HARQ 进程管理，把上层的数据组织成一次调度可以发送的单元再交给物理层。它在本笔记中是传输块的来源：传输块的大小与发送时机都由 MAC 侧的调度决定，进程与重传状态见 [[HARQ_Process_HARQ进程管理]]。

第二个对象是码块（Code Block, CB）与码块分段（Code Block Segmentation）。码块是信道编码器一次处理的比特块；当传输块超过编码器允许的最大码块长度时，按固定规则切分为多个码块，每块独立附加码块级 CRC、独立编码与速率匹配。它在本笔记中承担执行层的角色：传输块决定交付边界，码块决定编码与译码的工作粒度，切分规则见 [[Segmentation_码块分段]] 与 [[CB_码块]]。

第三个对象是循环冗余校验（Cyclic Redundancy Check, CRC）。CRC 把一段比特视为 GF(2) 上的多项式，除以生成多项式后取余数作为校验位附在数据之后，接收端重做除法并以余数为零判断是否出错。它在本笔记中出现两次：一次作用于整个传输块，一次作用于每个码块，两级校验的对象与判据不同，原理见 [[CRC_循环冗余校验]]。

第四个对象是填充位（Filler Bits）。它是分段时为对齐码块长度而插入的已知比特，在编码前固定为已知值、译码后按位置删除，不承载信息，也不参与传输块级 CRC 的计算。它在本笔记中说明重组的边界条件：填充位的位置与数量由分段规则唯一确定，删除顺序错误会直接导致传输块级 CRC 失败，细则见 [[Filler_Bits_填充位]]。

四个对象就位后，可以看这套「先加 CRC、再分段、最后整块复核」的结构是怎样从两代调度需求中形成的。

## 起源与演进

(1) **起点：MAC 与 PHY 之间的数据单元。** MAC 把一次调度的数据以传输块的形式交给物理层，物理层编码链路的全部工作——CRC 附加、分段、编码、速率匹配——都围绕这一个对象展开。传输块是这条链路的输入边界，它的比特数就是调度器选定的传输块大小。

(2) **打包：附加传输块级 CRC 与可能的分段。** 发送端先对整个传输块附加 CRC：NR 在载荷超过 3824 bit 时用 24 bit 的 gCRC24A，否则用 16 bit 的 gCRC16；LTE 固定用 24 bit 的 gCRC24A。附加 CRC 后的比特流在超过编码器最大码块长度时切分为码块，切分只改变编码的执行粒度，交付对象仍是整块。

(3) **验收：重组与传输块级 CRC 才是最终判据。** 接收端把所有码块译完、按顺序重组、删除填充位，再对整个传输块做一次 CRC。所有码块校验通过只是必要条件而不是充分条件——拼接顺序、填充位删除、码块数量任一环节出错，都只能由整块复核发现。

(4) **影响面：传输块大小决定多项资源。** 传输块大小同时决定码块数、单次译码的计算量、软缓存占用量与 HARQ 的重传行为，因此它是调度器与译码器之间必须对齐的第一个参数。码块数由分段判据给出，传输块级 CRC 的结果则直接驱动 HARQ 的确认反馈。

演进的终点是三条可运算的规则，下一节把它们写成公式与判据。

## 科学定义

本节公式沿用文首符号表的记法：$A$ 是载荷比特数，$L$ 是传输块级 CRC 位数，$B$ 是附加 CRC 后的比特数，$C$ 是码块数，$K_{cb}$ 是最大码块长度。

### 传输块的边界与长度关系

传输块级 CRC 附加之后，比特数由一条加法关系确定：

$$B=A+L$$

其中 $A$ 由调度给出，$L$ 按载荷大小选定：NR 的上下行共享信道在 $A>3824$ 时取 24、否则取 16，LTE 的共享信道不论载荷大小都取 24。$B$ 是分段模块的输入长度，也是码块级 CRC 计算的起点，因此它同时出现在两个相邻环节的接口上。这条关系只描述长度，不描述内容：CRC 的生成多项式与零余数判据见 [[CRC_Polynomials_CRC生成多项式]]。

### 分段与码块数

分段判据把长度关系接到编码器约束上：

$$C=1\ (B\le K_{cb}),\qquad C=\left\lceil\frac{B}{K_{cb}-24}\right\rceil\ (B>K_{cb})$$

最大码块长度 $K_{cb}$ 由基图决定：基图 1 取 8448、基图 2 取 3840。分段发生时每个码块再附加 24 bit 码块级 CRC，故分母取 $K_{cb}-24$，保证附加 CRC 后的码块仍不超过编码器上限；分段不发生时码块级 CRC 也不附加，$C$ 恒为 1。用两组参数可以校验上式（设基图为 1）：载荷 10000 bit 超过 3824，故 $L=24$、$B=10024$，超过 8448，$C=\lceil 10024/8424\rceil=2$；载荷 3000 bit 不超过 3824，故 $L=16$、$B=3016$，不超过 8448，$C=1$。

### 接收侧的验收顺序

接收端按与发送端相反的顺序处理：先对每个码块做译码与码块级 CRC 校验，再按码块编号顺序把译码输出拼接起来，删除分段时插入的填充位，得到传输块候选，最后对整个候选计算传输块级 CRC。只有最后一步的余数为零，传输块才被判定为交付成功并向 MAC 报告确认；任一步失败都报告否认，由 HARQ 触发重传。两级校验的分工由此确定：码块级 CRC 定位出错的码块并支撑部分重传，传输块级 CRC 判定整块能否交付。

三条规则给出传输块在链路中的位置，下一节用结构化描述把它压缩成可复核的层次与顺序。

## 直观模型

传输块在链路上占两个层次。上层是交付层，对象是整块传输块，长度为 $A$ 加 $L$，判据是传输块级 CRC；下层是执行层，对象是 $C$ 个码块，每个码块有自己的码块级 CRC 与编码长度，判据是各块的校验结果。两层的编号与边界由分段规则唯一确定：码块按传输块内的比特顺序连续切分，切分点由 $K_{cb}$ 与码块级 CRC 长度共同决定，层次之间不重叠也不留空隙。

三个接口量把两层连起来。第一个是 $A\to B$ 的加法接口，附加 CRC 只增加长度、不改变比特顺序；第二个是 $B\to C$ 的取整接口，分段数由向上取整给出，余数部分由最后一个码块承载；第三个是码块结果到交付判定的判据接口，码块级结果只能说明各块自身的对错，整块对错必须由传输块级 CRC 重新计算。以载荷 10000 bit 为例，$B=10024$、$C=2$，两个码块各自附加 24 bit 码块级 CRC 后分别编码；接收端两块都通过校验、按序拼接并删除填充位之后，整块 CRC 仍可能因拼接错误而失败，这正是判据接口必须独立存在的原因。

层次与接口既已明确，几处容易混淆的口径可以逐条对照。

## 常见误解

| 误解 | 正确理解 |
|:---|:---|
| 传输块与码块是同一层对象 | 传输块是交付与 HARQ 判断对象，码块是编码与译码的工作单元，二者由分段规则联系。 |
| 传输块级 CRC 一律 24 bit | NR 按载荷是否超过 3824 bit 在 24 bit 与 16 bit 之间二选一，LTE 固定 24 bit；位数由协议按载荷选定。 |
| 所有码块通过校验就一定交付成功 | 拼接顺序、填充位删除与码块数量仍可能出错，只有传输块级 CRC 能发现这类错误。 |
| 传输块大小只是一个数组长度 | 它同时决定码块数、译码计算量、软缓存占用与 HARQ 重传行为，是跨层对齐的参数。 |

这些误解多半源于把交付判据与编码判据混为一谈，下面按条款给出可核实的锚点。

## 协议锚点

- LTE：TS 36.212 Rel-19 §5.3.2.1 下行共享信道、寻呼信道与多播信道的传输块 CRC 附加，固定 $L=24$ 且使用 gCRC24A；§5.2.2.1 上行共享信道的传输块 CRC 附加；§5.1.2 码块分段与码块级 CRC 附加，最大码块长度 6144。
- NR：TS 38.212 Rel-19 §7.2.1 下行共享信道的传输块 CRC 附加与 $L$ 的取值规则；§6.2.1 上行共享信道的同名规则；§5.2.2 码块分段、$K_{cb}$ 取值与码块数 $C$ 的判定；§7.2.3 与 §6.2.3 分别为下行与上行的分段流程入口。
- 本地锚点：`3GPP_Rel19/processed/TS_36.212_36212-j30/content.md`；`3GPP_Rel19/processed/TS_38.212_38212-j30/content.md`。

锚点列到条款一级之后，本笔记的结论可以收成下面几条可复核的要点。

## 关键要点

1. 传输块是 MAC 与 PHY 之间的交付单位，一次调度可以发一个或两个；码块是编码与译码的工作单元。
2. 传输块级 CRC 位数按载荷选定：NR 在载荷超过 3824 bit 时取 24、否则取 16，LTE 固定取 24。
3. 附加 CRC 后的长度为 $B=A+L$，它同时是分段模块的输入长度。
4. 码块数由分段判据给出：$B$ 不超过 $K_{cb}$ 时为 1，否则为 $\lceil B/(K_{cb}-24)\rceil$，$K_{cb}$ 取 8448 或 3840。
5. 所有码块通过校验不等于交付成功，拼接顺序、填充位删除与码块数量只有传输块级 CRC 能校验。
6. 传输块级 CRC 的结果直接驱动 HARQ 的确认与否认，也决定软缓存与译码预算的占用。
