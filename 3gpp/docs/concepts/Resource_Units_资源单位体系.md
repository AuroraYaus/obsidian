# Resource Units 资源单位体系

## 符号与记号约定

本笔记用到的每个数学符号都在此给出读法、含义与取值来源，以及它在协议中的位置；下文出现这些符号时不再重复定义。

| 符号 | 读法 | 含义与取值 | 协议锚点 |
|:---|:---|:---|:---|
| $k$ | 小写 k | 频域子载波索引；取 $0$ 至载波内最大子载波号，单位为子载波；以 Point A 为原点 | TS 38.211 §4.4.4.3 |
| $l$ | 小写 l | 时域符号位置索引；取 $0$ 至时隙内符号数减一，单位为符号；相对某参考点计数 | TS 38.211 §4.4.3 |
| $p$ | 小写 p | 天线端口号；取天线端口集合中的编号，无量纲；由 DCI 与高层配置给出 | TS 38.211 §4.4.1 |
| $\mu$ | 小写 mu | 子载波间隔配置；取整数，对应 15、30、60、120、240 kHz 等子载波间隔，与频段配套 | TS 38.211 §4.2 |
| $a_{k,l}^{(p,\mu)}$ | a 下标 kl 上标 p,mu | 资源元素 $(k,l)$ 上的复数值；取任意复数，单位为调制符号；由调制映射按 §5.1 生成 | TS 38.211 §4.4.3 |

| $N_{symb}^{sh}$ | N 上标 sh，下标 symb | 一次调度实际占用的符号数；取 1 至 $N_{symb}$，单位为符号；由时域资源分配给出 | TS 38.214 §5.1.2.1 |

| $N_{RE}$ | N 下标 RE | 一次传输可用的 RE 总数；取非负整数，单位为 RE；由 $\min(156,N_{RE}')\cdot n_{PRB}$ 算出，156 是协议上限 | TS 38.214 §5.1.3.2 |

| $n_{CRB}^{\mu}$ | n 上标 CRB,mu | 公共资源块编号；取非负整数，单位为组（每组 12 个子载波）；由 $\lfloor k/12\rfloor$ 算出，原点为 Point A | TS 38.211 §4.4.4.3 |

| $N_{BWP,i}^{size,\mu}$ | N 上标 BWP,i,size,mu | 第 $i$ 个 BWP 的频域大小；取正整数，单位为组（PRB 数）；由 BWP 配置给出 | TS 38.211 §4.4.5 |
| $P$ | 大写 P | RBG 的标称大小，即每个资源块组含几个连续 VRB；取集合中的整数，单位为组；取值由 BWP 大小按 TS 38.214 Table 5.1.2.2.1-1 决定 | TS 38.214 §5.1.2.2.1 |
| $N_{RBG}$ | N 下标 RBG | 一个 BWP 内的 RBG 总数；取正整数，单位为组；由 $\lceil(N_{BWP,i}^{size,\mu}+(N_{BWP,i}^{start,\mu}\bmod P))/P\rceil$ 算出 | 由 TS 38.214 §5.1.2.2.1 导出 |

| $\Delta f$ | Delta f | 子载波间隔；取 15、30、60、120、240 kHz 等值，单位为 kHz；由 $\mu$ 按 $15\cdot2^{\mu}$ 决定 | TS 38.211 §4.2 |

运算符与记号惯例：$\lfloor x\rfloor$ 表示向下取整，$x\bmod y$ 表示取余，$\lceil x\rceil$ 表示向上取整；上标用于区分限定条件而非乘方，例如 $N_{BWP,i}^{start,\mu}$ 中的 $start$ 指起点、$\mu$ 指子载波间隔配置；下标中的逗号表示多个限定条件并列；资源块编号一律以「组」为单位，而资源元素以「个」为单位，两者不可直接相加。

## 定位

这套单位解决的是同一个网格上「用哪把尺子量」的问题：资源元素量的是最小可调制单元，资源块量的是频域宽度，公共资源块、物理资源块、虚拟资源块是同一宽度的三种编号方式，资源块组与资源元素组则是调度与控制信道各自的分组单位。七个名字看起来像七种资源，实际上是两层结构——一层是「格点与宽度」，另一层是「编号与分组」。

## 解释目标与范围

读完本笔记应能回答四类问题：一个资源元素由哪些坐标唯一确定；为什么同一个物理位置在不同带宽部分里的物理资源块编号不同；虚拟资源块与物理资源块之间差哪一步映射；资源块组与资源元素组分别服务于哪类信道。这些问题的答案都在 TS 38.211 §4.4 与 TS 38.214 §5.1.2.2 的原文里，本笔记只做组织与数值化。

## 前置概念

资源单位建立在正交频分复用（Orthogonal Frequency Division Multiplexing, OFDM）的时频网格上。一个载波在给定子载波间隔配置 $\mu$ 下被划分成若干子载波，时间方向被划分成若干 OFDM 符号，二者的交叉点就是一个可承载复数值的最小格点。子载波间隔取 15 kHz 的整数倍（$15\cdot2^{\mu}$ kHz），它同时决定符号长度与资源块的频域宽度，因此换子载波间隔就是换整套几何。

带宽部分（Bandwidth Part, BWP）是载波内一段连续的资源块集合，终端只在激活的 BWP 内收发。这一概念让「载波带宽」与「终端实际使用的带宽」解耦：载波可以很宽，而终端一次只用其中一段。它同时是物理资源块编号的参照系——同一个绝对位置，在不同 BWP 里编号不同。

Point A 是全载波资源块网格的公共原点，由高层参数 offsetToPointA 以「相对最低 SS/PBCH 块最低资源块的偏移」的形式给出，FR1 按 15 kHz、FR2 按 60 kHz 的资源块单位表示。有了这个公共原点，不同 BWP、不同终端之间才能用同一套公共资源块编号描述同一个频域位置。

天线端口（antenna port）是资源元素的第三个坐标：同一个 $(k,l)$ 在不同端口上是不同的资源元素，对应不同的复数值。资源网格按端口分别定义，这也是参考信号能与数据共址而不互相污染的原因。

## 起源与演进

LTE 的资源块是时频二维块。TS 36.211 §6.2.3 与 Table 6.2.3-1 规定常规循环前缀下一个物理资源块包含 7 个 OFDM 符号与 12 个子载波，合计 84 个资源元素，时域恰为一个 0.5 ms 时隙、频域 180 kHz。资源块与调度时隙绑定，符号数不可变。

NR 把时域那一半从资源块的定义里拿掉了。TS 38.211 §4.4.4.1 只说资源块是频域上 12 个连续子载波，不再规定符号数；时域长度由每次调度的符号数 $N_{symb}^{sh}$ 单独给出。这一改动让 NR 可以在同一套资源块几何上支持多种符号长度（2 至 14 个符号的短调度）与多种子载波间隔。

编号体系随之复杂化。NR 引入公共资源块作为公共参照、物理资源块作为 BWP 内参照、虚拟资源块作为分配字段内的参照，并用交织资源块支持非授权频谱上的等间隔分配。控制信道也从 LTE 的资源元素组沿用下来，但分组大小与映射规则按 NR 重新定义。

## 科学定义

### 最小单位：资源元素

资源元素是资源网格上的一个格点，由四元组 $(k,l)_{p,\mu}$ 唯一确定：$k$ 是频域子载波索引、$l$ 是时域符号位置、$p$ 是天线端口、$\mu$ 是子载波间隔配置，对应复数值 $a_{k,l}^{(p,\mu)}$（TS 38.211 §4.4.3）。它是三种计数的最小单位——调制与解调在此进行（一个资源元素出一个复符号，对应一个或多个比特的对数似然比）、参考信号在此占位、发送功率在此定义。

数据在网格上的填充顺序是「先频后时」：先填满一个符号内的全部子载波，再推进到下一个符号（TS 38.211 §7.3.1.1）。接收端按同一顺序提取软信息，因此发送端映射顺序与接收端解映射顺序必须是同一套约定。

一个物理资源块在一个时隙内覆盖的资源元素数可以直接算出：常规循环前缀下 $N_{symb}=14$，故 $12\times14=168$ 个。扣除解调参考信号占用的 6 个后为 162 个；再受 TS 38.214 §5.1.3.2 的 156 上限截断，即

$$N_{RE}'=12N_{symb}^{sh}-N_{DMRS}^{PRB}-N_{oh}^{PRB},\qquad N_{RE}=\min(156,N_{RE}')\cdot n_{PRB}$$

其中 $N_{DMRS}^{PRB}$ 是每物理资源块内解调参考信号占用的资源元素数（含无数据的码分复用组开销），$N_{oh}^{PRB}$ 是高层参数 xOverhead 配置的额外开销（0、6、12、18）。这三个数字（168、162、156）在传输块大小计算中反复出现，来源都是这条链。

### 频域宽度与三套编号

资源块的定义只有一句：频域上 $N_{sc}^{RB}=12$ 个连续子载波（TS 38.211 §4.4.4.1）。它只定义宽度，不带编号，也不含时域含义，因此「资源块」与「物理资源块」不是同义词——前者是宽度，后者是编号结果。

公共资源块以 Point A 为原点、在全载波范围内从 0 向上编号，其中心与 Point A 的关系是「公共资源块 0 的子载波 0 的中心对准 Point A」，编号与子载波索引的换算为 $n_{CRB}^{\mu}=\lfloor k/12\rfloor$（TS 38.211 §4.4.4.3）。物理资源块则在带宽部分内从 0 编号到 $N_{BWP,i}^{size,\mu}-1$，与公共资源块之间只差一个偏移：

$$n_{CRB}^{\mu}=n_{PRB}^{\mu}+N_{BWP,i}^{start,\mu}$$

（TS 38.211 §4.4.4.4）。虚拟资源块同样在带宽部分内编号，但它只是资源分配字段里的数字，必须经过 VRB-to-PRB 映射（TS 38.214 §5.1.2.3）才落到物理位置；映射可以是非交织的（虚拟到物理一对一平移）或交织的（按行写按列读）。

资源块组是「分组」而非「宽度」：下行分配类型 0 把 $P$ 个连续虚拟资源块合成一组，用位图指示哪几组被调度（TS 38.214 §5.1.2.2.1）。组数由带宽部分大小与起点共同决定，

$$N_{RBG}=\left\lceil\frac{N_{BWP,i}^{size,\mu}+\left(N_{BWP,i}^{start,\mu}\bmod P\right)}{P}\right\rceil$$

第一个组的组大小为 $P-(N_{BWP,i}^{start,\mu}\bmod P)$、最后一个组为 $(N_{BWP,i}^{start,\mu}+N_{BWP,i}^{size,\mu})\bmod P$（为 0 时取 $P$）、其余各组均为 $P$。这条计算说明一个常被忽略的事实：因为带宽部分的起点未必对齐到 $P$ 的整数倍，首组会被截短。

频域宽度与载波容量可以直接算出量级。一个资源块的宽度等于 12 乘以子载波间隔：15 kHz 时 180 kHz，30 kHz 时 360 kHz，60 kHz 时 720 kHz，120 kHz 时 1.44 MHz。载波内可用的资源块总数不是带宽除以资源块宽度，而是规范表格给出的、扣除两侧最小保护带后的整数（TS 38.101-1 Table 5.3.2-1）：20 MHz 配 15 kHz 为 106 个，50 MHz 配 30 kHz 为 133 个，100 MHz 配 30 kHz 为 273 个，100 MHz 配 60 kHz 为 135 个。

其中 273 这个数值得单独算一遍，因为它是 FR1 的上限，也决定了 DCI 里频域字段的位宽。100 MHz 配 30 kHz 时，最小保护带每侧 845 kHz（Table 5.3.3-1），可用带宽为 $100-2\times0.845=98.31$ MHz，除以一个资源块的 360 kHz 得 273.08，下取整即 273。反证同样直接：取 274 个时占用 98.64 MHz、单边只剩 680 kHz，低于 845 kHz 的下限；取 275 个时单边只剩 500 kHz，更不成立。所以 273 是这条约束下的最大整数，与「2 的幂」或任何取整习惯无关——它的质因数分解是 $3\times7\times13$，本身没有算术特殊性。

这个上限的连带影响落在两处。频域分配类型 1 需要在 $N(N+1)/2$ 个起点长度组合里编号，$N=273$ 时组合数为 37401，向上取整到 $2^{16}$，故位宽 16 bit；类型 0 的位图由资源块组数决定，$N=273$ 落在「145 至 275」档、组大小 $P=16$、组数为 $\lceil273/16\rceil=18$，故位图 18 bit。100 MHz 载波之所以在控制信息里要占 16 或 18 个比特，根源就是这个由保护带算出来的 273。

交织资源块服务于非授权频谱上的等间隔分配：交织 $m$ 由公共资源块集合 $\{m,\,M+m,\,2M+m,\dots\}$ 构成，其编号与公共资源块的换算为

$$n_{CRB}^{\mu}=M\,n_{IRB,m}^{\mu}+N_{BWP,i}^{start,\mu}+\left(\left(m-N_{BWP,i}^{start,\mu}\right)\bmod M\right)$$

（TS 38.211 §4.4.4.6）。它的用途是让一次传输在频域上分散到足够多的资源块，以满足非授权频谱的占用带宽要求。

### 控制信道的另一套分组

控制信道不使用资源块组，而用资源元素组与控制信道单元。资源元素组是「1 个物理资源块 × 1 个 OFDM 符号」，控制信道单元由 6 个资源元素组构成（TS 38.211 §7.3.2.2）。二者与数据信道的资源块计数不通用：一个控制信道单元在单符号配置下占 6 个物理资源块，在双符号配置下占 3 个物理资源块 × 2 个符号，但两种情形都记作 6 个资源元素组。

聚合等级就是控制信道单元的个数：聚合等级 4 表示一条控制信息占用 4 个控制信道单元、即 24 个资源元素组。这一层分组的存在使得控制信道的容量与可靠性可以用「用几个单元」这一整数直接表达，而不必逐个资源元素规划。

## 直观模型

把时频网格想成一张坐标纸：纸上的每个交叉点是一个资源元素，一列 12 个交叉点构成一个资源块的宽度。编号则像在纸上画三套坐标：以整张纸左下角（Point A）为原点的叫公共资源块坐标，以某个方框（带宽部分）左下角为原点的叫物理资源块坐标，而资源分配字段里写的是虚拟坐标，需要先按规则平移或交织才对应到纸上的实际位置。

分组单位是另一层：资源块组把 12 列宽的若干列捆成一组，用于位图式的粗粒度分配；资源元素组则只取一列中的一行（一个符号），用于控制信道的细粒度组织。同一张纸上同时运行着「格点—宽度—编号—分组」四层，每层服务不同的协议过程，这正是七个名字容易混淆的根源。

## 常见误解

| 误解 | 正确理解 |
|:---|:---|
| 资源块就是物理资源块 | 资源块是「12 个子载波」的宽度定义，不带编号；物理资源块是某个带宽部分内从 0 编号的结果，二者是宽度与编号的关系 |
| 同一位置在不同带宽部分里物理资源块编号相同 | 不同；物理资源块编号相对各自带宽部分起点，同一位置在载波上的公共资源块编号才唯一 |
| 一个资源块等于 84 个资源元素 | 那是 LTE 的二维块（7 符号 × 12 子载波，TS 36.211 Table 6.2.3-1）；NR 的一个物理资源块在一个时隙内是 168 个，且受 156 上限截断 |
| 虚拟资源块是另一种物理资源 | 虚拟资源块只是编号方式，经 VRB-to-PRB 映射后落到物理资源块上，没有独立的物理位置 |
| 资源块组与资源元素组是同一类分组 | 前者服务于下行分配类型 0 的位图，按 $P$ 个虚拟资源块成组；后者服务于控制信道，按「1 个物理资源块 × 1 个符号」成组，6 个构成一个控制信道单元 |
| 载波内资源块数等于带宽除以资源块宽度 | 不是除法；载波内资源块数由规范表格给出，已扣除保护带（TS 38.101-1 Table 5.3.2-1），例如 20 MHz 配 15 kHz 为 106 个而非 111 个 |

## 边界情形

第一类是起点不对齐。带宽部分的起点不必是 $P$ 的整数倍，因此第一个资源块组会被截短为 $P-(N_{BWP,i}^{start,\mu}\bmod P)$ 个资源块。忽略这一点会让位图与 RBG 序号的对应关系整体错位一格，调度解析随之失败。

第二类是切换带宽部分带来的编号跳变。终端激活的带宽部分改变后，同一频域位置的物理资源块编号随之改变，而公共资源块编号不变。跨带宽部分的测量上报与调度必须在公共资源块坐标下对齐，否则会出现「同一个位置被描述成两个不同编号」的现象。

第三类是控制信道与数据信道的计数不通用。控制信道单元与聚合等级的计数以资源元素组为单位，数据信道的传输块大小计算以资源元素为单位，两者之间没有直接换算关系；把聚合等级当成资源块数使用，会在容量估算上出现数倍偏差。

## 关键要点

1. 资源元素由 $(k,l)_{p,\mu}$ 四元组唯一确定，是调制、软信息、参考信号占位与功率定义的最小单位。
2. 资源块只定义频域宽度（12 个子载波），不含编号与时域长度；把资源块等同于物理资源块是最常见的错误。
3. 公共资源块以 Point A 为原点全载波编号，物理资源块在带宽部分内编号，二者差一个起点偏移 $N_{BWP,i}^{start,\mu}$。
4. 虚拟资源块只是分配字段里的编号，必须经 VRB-to-PRB 映射才落到物理位置；映射有非交织与交织两种。
5. 资源块组按 $P$ 个连续虚拟资源块成组，用于下行分配类型 0 的位图；首组因起点不对齐会被截短。
6. 资源元素组是「1 个物理资源块 × 1 个符号」，6 个构成 1 个控制信道单元，聚合等级即控制信道单元的个数。
7. 一个物理资源块在一个时隙内是 168 个资源元素，扣除解调参考信号 6 个为 162 个，再受 156 上限截断。
8. 载波内资源块数由规范表格给出而非除法，20 MHz 配 15 kHz 为 106 个；LTE 的资源块是 7×12=84 个资源元素的二维块，两代不可互换。
