# Soft Buffer 软缓存

## 符号与记号约定

阅读本笔记的公式前先明确记法。下表登记全文使用的每一个数学符号，并按行给出它可追溯的协议出处；后文出现时不再重复定义。运算符与下标语义见表后的约定。

| 符号 | 读法 | 含义与取值 | 协议锚点 |
|:---|:---|:---|:---|
| $N_{soft}$ | N 下标 soft | 终端的总软缓存单元数，按 UE 类别给出，覆盖该终端全部下行 HARQ 进程与码字 | TS 36.212 §5.1.4.1.2；TS 36.306 §4.2.1.3、Table 4.1-1 |
| $N_{IR}$ | N 下标 IR | 单个传输块可用的软缓存单元数，是总缓存按码字数与进程数均分后的份额 | TS 36.212 §5.1.4.1.2 |
| $N_{cb}$ | N 下标 cb | 每个码块的缓存长度，即该码块在软缓存中可寻址的地址数 | TS 38.212 §5.4.2.1；TS 36.212 §5.1.4.1.2 |
| $N_{ref}$ | N 下标 ref | 有限缓存速率匹配给出的每码块缓存上限 | TS 38.212 §5.4.2.1 |
| $K_{MIMO}$ | K 下标 MIMO | 码字数因子：单码字取 1，双码字取 2 | TS 36.212 §5.1.4.1.2 |
| $N_{HARQ}$ | N 下标 HARQ | 参与均分的下行 HARQ 进程数，取实际配置进程数与常数 8 的较小值 | TS 36.212 §5.1.4.1.2 |
| $C$ | C | 一个传输块内的码块数 | TS 38.212 §5.2.2；TS 36.212 §5.1.2 |
| $b_{LLR}$ | b 下标 LLR | 每个软信息单元的量化位宽（比特），常见取 6 至 8 bit | 非 3GPP 标准（实现域） |
| $R_{LBRM}$ | R 下标 LBRM | 有限缓存速率匹配的参考码率，协议固定为 2/3 | TS 38.212 §5.4.2.1 |
| $N$ | N | NR 母码长度：基图 1 为 $66Z_c$，基图 2 为 $50Z_c$，已扣除不写入缓存的 $2Z_c$ 个系统位 | TS 38.212 §5.3.2 |
| $Z_c$ | Z 下标 c | NR LDPC 提升因子，基图矩阵按该值扩展为校验矩阵 | TS 38.212 §5.2.2、§5.3.2 |
| $TBS_{LBRM}$ | TBS 下标 LBRM | 有限缓存速率匹配假设下按最大配置算出的参考传输块大小 | TS 38.212 §5.4.2.1；TS 38.214 §5.1.3.2 |
| $K_w$ | K 下标 w | LTE 母码长度，由系统位与两路校验位拼接而成，$K_w=3K_{\Pi}$ | TS 36.212 §5.1.4.1.2 |
| $K_{\Pi}$ | K 下标 Π | LTE 单个码块的长度，含 24 bit 码块 CRC | TS 36.212 §5.2.2 |
| $E_r$ | E 下标 r | 第 r 个码块本次速率匹配的输出比特数，决定 LLR 写回的地址段长度 | TS 38.212 §5.4.2.1 |
| $p$ | p | HARQ 进程序号，取值 0 到 $N_{HARQ}-1$ | 非 3GPP 标准（本笔记的进程编号） |
| $r$ | r | 码块序号，取值 0 到 $C-1$ | TS 38.212 §5.4.2.1（比特选择以 r 标记码块） |

运算符与下标语义如下，它们与符号同等重要：

1. 下标语义：$N_{IR}$ 的 IR 指增量冗余（Incremental Redundancy），$N_{cb}$ 的 cb 指循环缓存（Circular Buffer），$E_r$ 的 r 指第 r 个码块；这些都是标识，不是乘法因子。
2. 取整：$\lfloor\cdot\rfloor$ 为向下取整，$\lceil\cdot\rceil$ 为向上取整；本笔记的配额计算一律向下取整，除不尽的余数直接丢弃，不结转给其他码块或进程。
3. 取小：$\min(\cdot)$ 取括号内各项的最小值，用于把母码长度截到缓存上限；只有量纲一致的长度才能放进同一个取小式。
4. 上下标：$b_{LLR}$ 的 LLR 是量名标识而非变量；$R_{LBRM}=2/3$ 中的 2/3 是协议常数，不是两个符号的商。
5. 五套长度口径不可混用：$N_{soft}$ 以整机软比特计，$N_{IR}$ 以每传输块计，$N$ 与 $K_w$ 是母码长度，$N_{ref}$ 与 $N_{cb}$ 是每码块地址数；跨口径直接比较是下文多数错误的来源。

记法既已确定，下面先给出软缓存的定位与本质，再说明本笔记要解释的问题及其前置对象。

软缓存（Soft Buffer）是 HARQ 接收端为尚未译码成功的传输块保存软信息的存储区。它的每个地址对应循环缓存中的一个编码比特位置，而不是空口 LLR 流的到达顺序；同一地址在多次传输中被再次写入时，新旧 LLR 按可靠度合并，此前未被覆盖的地址保持未知状态。缓存长度记为 $N_{cb}$，其取值不是母码长度，而是母码长度、有限缓存速率匹配上限与每进程配额三者取小后的可寻址范围。

一句话本质：**软缓存把译码前的可靠度信息按母码地址保存下来，使跨重传的 LLR 合并、打孔位补证与进程间配额分配落在同一段地址空间上；软缓存的大小问题，最终都化为 $N_{cb}$ 由哪一个上限截断的问题。**

## 独立解释任务

任务目标：解释软缓存为什么保存量化后的 LLR 而不是硬判决比特，说明总软缓存 $N_{soft}$、每进程配额 $N_{IR}$、每码块缓存长度 $N_{cb}$ 与 LBRM 上限 $N_{ref}$ 四者的换算关系，给出可直接核算的数值例，并讲清 $N_{cb}<N$ 与 $N_{IR}$ 不足这两种溢出方向各自发生在哪一级、造成什么后果。

要完成这一解释，需要先把后文反复使用的六个对象交代清楚，它们分属解调侧、合并侧、调度侧与编码侧。

## 前置概念

解调侧的第一个对象是软判决（Soft Decision）。解调器对每个接收比特不只给出 0 或 1，而是给出该比特取 0 与取 1 的相对可能性；这种带可靠度的判决称为软判决，其数值形式为对数似然比（Log-Likelihood Ratio, LLR），符号表示倾向哪一比特，绝对值表示该倾向的可信程度。软缓存的存储单元保存的正是这种量，而不是最终比特，参见 [[Soft_Demodulation_软解调]]、[[LLR_对数似然比]]。在本笔记中，LLR 是缓存的内容，$b_{LLR}$ 是每个内容的量化宽度。

合并侧的对象是软合并（Soft Combining）。同一编码位置被多次观测时，接收端把各次 LLR 相加，使可靠度随观测次数增长；相加前若不做限幅，量化器会溢出，因此工程上采用饱和加法。按重传是否更换冗余版本（Redundancy Version, RV），软合并分为每次发送相同比特的 Chase 合并与每次发送不同校验位的增量冗余（Incremental Redundancy, IR）。软缓存是这两类合并共同的存储载体：合并发生在缓存地址上，而不是发生在空口比特流上，参见 [[Chase_Combining_Chase合并]]、[[Incremental_Redundancy_增量冗余]]。

调度侧的对象是 HARQ 进程（HARQ Process）。混合自动重传请求（Hybrid Automatic Repeat Request, HARQ）把一条“传输—反馈—重传”链组织为一个进程，进程号、新数据指示（New Data Indicator, NDI）与冗余版本共同决定本次传输写入哪一个缓存区间、是覆盖写还是累加写。软缓存按进程切分，一个进程占用一段连续区间，因此进程数是缓存配额公式里的分母，参见 [[HARQ_Process_HARQ进程管理]]、[[HARQ_混合自动重传请求]]、[[RV_冗余版本]]。

编码侧的对象是有限缓存速率匹配（Limited Buffer Rate Matching, LBRM）。循环缓存（Circular Buffer）的长度本来可以取整个母码，但终端不必为每个码块保留全部母码；LBRM 以参考传输块大小与参考码率算出一个上限 $N_{ref}$，把循环缓存截短，从而在几乎不损失性能的前提下降低存储量。$N_{ref}$ 是 NR 唯一写进协议的软缓存上限，参见 [[Circular_Buffer_循环缓存]]、[[Rate_Matching_速率匹配]]。

最后一个对象是码块级 CRC（Code Block CRC）。一个传输块被切分为 $C$ 个码块，每个码块带 24 bit 循环冗余校验（Cyclic Redundancy Check, CRC）；译码后逐码块校验，通过者其 LLR 区间可以提前释放，未通过者保留等待重传。码块级 CRC 因此是软缓存区间的释放判据之一，传输块级 CRC 则决定整个进程区间是否释放，参见 [[CRC_循环冗余校验]]、[[CB_码块]]。

六个对象既已就位，下面按演进顺序说明软缓存的大小口径如何从“按终端类别固定分配”走到“按参考码率截断”。

## 起源与演进

(1) **起点：硬判决丢失可靠度。** 若接收端只保存硬判决比特，则同一比特两次观测中一次接近门限、一次远离门限，合并时无法区分二者的可信程度；保存 LLR 才能让合并按可靠度加权。这是软缓存存在的最初理由，也是“软”字的全部含义。

(2) **从保存 LLR 到按地址保存。** 仅有 LLR 还不够，重传必须写回同一编码位置才能合并。发射端的循环缓存以母码坐标编号，接收端于是采用同一套坐标：地址由码块序号、冗余版本起点与本次输出长度共同确定。地址规则一旦与发射端不一致，合并就会把不同编码位置的 LLR 加在一起，表现为码块 CRC 全部失败。

(3) **LTE：按 UE 类别分配总缓存。** LTE 用终端能力给出总软缓存 $N_{soft}$，再按码字数 $K_{MIMO}$ 与下行 HARQ 进程数 $N_{HARQ}$ 均分，得到每传输块配额 $N_{IR}=\lfloor N_{soft}/(K_{MIMO}N_{HARQ})\rfloor$；每个码块再取 $\lfloor N_{IR}/C\rfloor$，与母码长度 $K_w$ 取小得到 $N_{cb}$。这套做法的特点是总量由终端类别固定，进程越多每进程越少。

(4) **NR：改按参考码率截断。** NR 不在 38.212 中定义 $N_{soft}$ 与 $N_{IR}$，只给出 LBRM 上限 $N_{ref}=\lfloor TBS_{LBRM}/(C\cdot R_{LBRM})\rfloor$（$R_{LBRM}=2/3$），并规定 LBRM 开启时 $N_{cb}=\min(N,N_{ref})$、关闭时 $N_{cb}=N$。实际存储器规模与是否额外按进程限幅属于实现域；协议保证的是收发两端对 $N_{cb}$ 的理解一致。

(5) **两代口径的收束。** LTE 的上限来自“终端能存多少”，NR 的上限来自“参考码率需要多少”；前者随终端类别变化，后者对所有终端一致。把两代写法放进同一个取小式，就得到 $N_{cb}=\min(N,N_{ref},\lfloor N_{IR}/C\rfloor)$ 的一般形式，但任一代只让其中两项生效，第三项在另一代不存在。

## 科学定义

本节给出配额换算、缓存长度与数值例；符号读法见文首「符号与记号约定」，本节不再重复定义。

### 从总缓存到每进程配额

LTE 的总软缓存 $N_{soft}$ 是终端能力量，由 UE 类别查表得到，单位是软比特（一个软比特对应一个 LLR 存储单元），实际存储器容量还要乘以量化位宽 $b_{LLR}$。总缓存先按码字数与进程数均分，得到每传输块配额：

$$N_{IR}=\left\lfloor\frac{N_{soft}}{K_{MIMO}\cdot N_{HARQ}}\right\rfloor$$

其中 $K_{MIMO}$ 在双码字传输时取 2、单码字时取 1；$N_{HARQ}$ 等于实际配置的下行 HARQ 进程数与常数 8 的较小值，协议里的两个量分别记作 `M_DL_HARQ` 与 `M_limit`。这个上限常数的作用是阻止分母随进程数无限增大：若终端配置的进程数超过 8，协议仍按 8 份计算每进程配额，多出来的进程在配额上并不额外获得存储。

配额落到码块一级还要再除一次码块数。第 r 个码块可分到的单元数是 $\lfloor N_{IR}/C\rfloor$，除不尽的余数丢弃。这个量是 LTE 缓存长度的第二项上限，与母码长度 $K_w$ 取小后写入循环缓存。量化位宽 $b_{LLR}$ 不进入配额公式，它只决定每个单元占多少物理比特。$N_{soft}$ 计的是软比特个数，不是物理比特数；物理存储量为 $N_{soft}\cdot b_{LLR}$ 位，把 $N_{soft}$ 直接当作物理比特数会漏乘位宽，把 $N_{soft}$ 当作字节数则会低估 8 倍。

### 每码块缓存长度的三种上限

把两代协议的上限写在一起，缓存长度的一般形式是

$$N_{cb}=\min\left(N,\;N_{ref},\;\left\lfloor\frac{N_{IR}}{C}\right\rfloor\right)$$

三项分别代表母码长度、LBRM 上限与每进程配额分到码块后的份额。这个式子是概念上的合并写法，具体到某一代只有两项有效，见下表。

| 制式与配置 | 生效的上限 | 协议写法 | 哪一项实际取到 |
|:---|:---|:---|:---|
| NR，LBRM 关闭 | 母码长度 | $N_{cb}=N$ | 母码长度 |
| NR，LBRM 开启 | 母码长度、LBRM 上限 | $N_{cb}=\min(N,N_{ref})$ | 通常为 $N_{ref}$，因为参考码率 2/3 高于母码码率 |
| LTE 下行共享信道与寻呼信道 | 母码长度、每码块份额 | $N_{cb}=\min(K_w,\lfloor N_{IR}/C\rfloor)$ | 由终端类别与码块数决定 |

三者的量纲必须一致才能同表取小。NR 的 $N$ 与 $N_{ref}$ 都以每码块比特地址计，可以直接比较；LTE 的 $\lfloor N_{IR}/C\rfloor$ 虽然也以每码块单元计，但它来自“每传输块配额除以码块数”，与 $N_{ref}$ 的来源不同，两代的项不能互相代入。另一点容易忽略：$N_{IR}$ 是每传输块的量，进入每码块取小式前必须先除以 $C$；直接写 $\min(N,N_{ref},N_{IR})$ 会把上限高估 $C$ 倍，这是把三个符号并列时最常见的口径错误。

### 手算数值例与两种溢出方向

先算 LTE 的每进程配额。取 UE 类别 5 的总缓存 $N_{soft}=3667200$、双码字 $K_{MIMO}=2$、配置进程数 16（NR 可取 16；LTE TDD 实际最大 15，此处只作算术示例）。协议上限把参与均分的进程数截到 8：

| 步骤 | 计算式 | 结果 |
|:---|:---|:---|
| 总缓存 | $N_{soft}=3667200$ | $3667200$ 个软比特 |
| 码字数因子 | $K_{MIMO}=2$ | $2$ |
| 参与均分的进程数 | $N_{HARQ}=\min(16,8)$ | $8$ |
| 每进程配额 | $N_{IR}=\lfloor3667200/(2\times8)\rfloor$ | $229200$ 个软比特 |
| 若不计上限直接除以 16 | $\lfloor3667200/(2\times16)\rfloor$ | $114600$ 个软比特（非协议值） |

两行结果的差别全部来自上限 8：按 16 份均分得到 114600，按协议截到 8 份得到 229200。后者是协议值，前者只在把 `M_limit` 误当作“建议值”时才会出现；由于 229200 正好是 114600 的两倍，这类错误会让实现把每个进程的缓存低估一半，重传合并的次数随之减少。

再算 NR 的 LBRM 上限。取基图 1、提升因子 384，则母码长度 $N=66\times384=25344$；取参考传输块大小 $TBS_{LBRM}=16896$、码块数 $C=2$、参考码率 $R_{LBRM}=2/3$：

| 步骤 | 计算式 | 结果 |
|:---|:---|:---|
| 母码长度 | $N=66\times384$ | $25344$ |
| LBRM 上限 | $N_{ref}=\lfloor16896/(2\times2/3)\rfloor$ | $12672$ |
| 每码块配额份额（沿用上例） | $\lfloor N_{IR}/C\rfloor=\lfloor229200/2\rfloor$ | $114600$ |
| 三者取小 | $N_{cb}=\min(25344,12672,114600)$ | $12672$ |

在本例中 LBRM 上限 12672 最小，因此 $N_{cb}=12672$，等于 $33Z_c$；母码的地址 12672 至 25343 不进入缓存。注意这里的第三项 114600 来自 LTE 配额，NR 的 38.212 正文只写 $N_{cb}=\min(N,N_{ref})$，第三项只在实现了额外进程限幅时才出现。若把第三项误写成 $N_{IR}$ 而不除以 $C$，会得到 229200，取小结果不变，但一旦换成小缓存终端就会得出错误的上限。

把第三项换成真正会取到的情况，需要一个小缓存、多码块的 LTE 例子。取 UE 类别 3 的 $N_{soft}=1237248$、$K_{MIMO}=2$、$N_{HARQ}=8$、码块数 $C=8$、单码块长度 $K_{\Pi}=6144$：

| 步骤 | 计算式 | 结果 |
|:---|:---|:---|
| 每进程配额 | $N_{IR}=\lfloor1237248/(2\times8)\rfloor$ | $77328$ |
| 每码块份额 | $\lfloor N_{IR}/C\rfloor=\lfloor77328/8\rfloor$ | $9666$ |
| LTE 母码长度 | $K_w=3\times6144$ | $18432$ |
| 缓存长度 | $N_{cb}=\min(18432,9666)$ | $9666$ |

此时最小项是每码块份额 9666，缓存只覆盖母码的前 9666 个地址，后 8766 个地址不存。这个例子说明 $N_{IR}$ 不足并不需要 LBRM 参与，仅凭“总缓存除以进程数与码块数”就足以把母码截短。

两种溢出方向的后果不同，必须分开说。第一种方向是 $N_{cb}<N$，即缓存装不下母码：地址空间从 $N$ 缩到 $N_{cb}$，母码尾部的校验位永远没有地址可写，也永远不会被任何冗余版本选中，接收端在这些位置没有 LLR，只能按擦除处理（LLR 取 0）。在译码器看来，这类取值未知的未发送位置属于打孔；若未写入的是编码前已知取零的填充位，则属于缩短。由于 LBRM 的 $N_{ref}$ 由参考码率 2/3 算出，示例中 $N_{cb}=33Z_c$ 仍覆盖 $22Z_c$ 个系统位，被截掉的是尾部校验位，存储下来的码等效码率为 $22/33=2/3$；这正是 $R_{LBRM}=2/3$ 的来历。若 LTE 的配额小到 $\lfloor N_{IR}/C\rfloor<K_{\Pi}$，连系统位都会被截掉，该码块在本进程内无法可靠译码，调度器必须用 UE 类别与最大传输块大小的配套假设避免这种配置。

第二种方向是 $N_{IR}$ 不足引起的跨进程挤占，发生在进程之间而不是码块之内。总缓存 $N_{soft}$ 是一个固定池，$N_{IR}$ 是按 $K_{MIMO}\cdot N_{HARQ}$ 预先切好的份额；每个进程只能写自己的份额，不能借用其他进程的区间。上限 8 限制的是“码字数与进程数之积” $K_{MIMO}\cdot N_{HARQ}$，因此是否超配要看实际需要缓存的传输块份数：以 15 个进程都按双码字工作为例，每个进程需要 $K_{MIMO}N_{IR}=2N_{IR}$，所需总量为 $15\times2N_{IR}=30N_{IR}$，而总池只按 $2\times8=16$ 份切分，前者是后者的 $30/16=15/8$ 倍。协议不规定超配时丢弃哪一段，这一部分属于实现域；后果是部分进程的旧 LLR 被压缩、截断或提前释放，重传只能获得较少的合并增益，严重时等效退化为不合并的单次译码。双码字传输把 $K_{MIMO}$ 取 2，等于在同一进程内再分两半，会加重这种挤占。

## 直观模型

软缓存可以按“进程区间—码块子区间—地址”三级来读。整机共有 $N_{soft}$ 个存储单元，每个单元保存一个 $b_{LLR}$ 位的量化 LLR 和一个有效标志；第 $p$ 个进程占用从 $p\cdot N_{IR}$ 起、长度为 $N_{IR}$ 的连续区间；进程内第 $r$ 个码块再占用从 $r\cdot\lfloor N_{IR}/C\rfloor$ 起、长度为 $\lfloor N_{IR}/C\rfloor$ 的子区间；这个子区间实际可寻址的长度被截到 $N_{cb}$。子区间内的地址仍按循环缓存的坐标编号为 0 到 $N_{cb}-1$，写回时先算进程基址与码块基址，再加上循环缓存地址，三级基址任何一级算错都会让 LLR 落到别的码块或别的进程。

写入与清空遵循同一套地址规则。某个地址第一次被本次传输覆盖时，有效标志置 1，LLR 取本次解调值；同一地址被后续传输再次覆盖时，新旧 LLR 相加并按 $b_{LLR}$ 饱和，有效标志保持 1；本次没有覆盖的地址不改动，其旧值继续参与译码。清空分两个粒度：码块 CRC 通过时释放该码块的子区间，传输块 CRC 通过或 NDI 翻转时释放整个进程区间；释放只把有效标志置 0，不改变区间划分，也不把区间转交给其他进程。地址从未被覆盖的位置与已被清空的位置在数值上都表现为 0，区别只在有效标志，因此实现必须同时维护标志位，不能只用 LLR 是否为零来判断有无观测。

## 常见误解

| 误解 | 正确理解 |
|:---|:---|
| 软缓存越大越好 | 缓存超过 LBRM 上限不会带来增益，因为发送端不会产生对应的校验位；超出部分只增加功耗与面积。 |
| 软合并就是把新旧 LLR 直接相加 | 相加必须按位宽饱和，否则量化溢出会翻转符号；合并前还要确认两个 LLR 指向同一编码地址。 |
| $N_{cb}$ 等于母码长度 | LBRM 或每进程配额生效时 $N_{cb}<N$；NR 的 $N_{cb}$ 取 $\min(N,N_{ref})$，LTE 取 $\min(K_w,\lfloor N_{IR}/C\rfloor)$。 |
| $N_{IR}$ 是每个码块的缓存 | $N_{IR}$ 是每个传输块的配额，每码块还要除以码块数 $C$；直接把 $N_{IR}$ 当码块上限会高估 $C$ 倍。 |
| 软缓存按传输块编号定位 | 定位需要进程号、码块号与循环缓存地址三级信息；只用传输块编号无法区分并行进程。 |
| LLR 的量化位宽由 3GPP 规定 | 38.212 只规定地址与长度，位宽、饱和门限与溢出策略均属实现域。 |
| 打孔位在接收端被丢弃 | 打孔位不发送，接收端在该地址保留无效标志，译码时按 LLR 为 0 的擦除参与，而不是把该比特删掉。 |
| LBRM 只影响发送端 | 收发两端必须用同一 $N_{ref}$ 计算 $N_{cb}$；接收端算错会让 LLR 写回地址整体错位。 |
| 清空缓存等于把 LLR 写成 0 | 清空是把有效标志置 0 并允许重新初始化；只写 0 而不清标志会把旧观测误当成新观测。 |

这些误解的共同根源是把不同口径的长度当成同一个量，下面按条款给出可核对的锚点。

## 协议锚点

- LTE 缓存配额：TS 36.212 Rel-19 §5.1.4.1.2 给出 $N_{IR}$ 的定义式、$K_{MIMO}$ 的取值条件、`M_DL_HARQ` 与 `M_limit=8`，以及 $N_{cb}=\min(\lfloor N_{IR}/C\rfloor,K_w)$；本地抽取件 `3GPP_Rel19/processed/TS_36.212_36212-j30/content.md:827-841`（软缓存与 $N_{IR}$）、`:917`（$K_{MIMO}$）、`:919-921`（进程数与上限 8）。
- LTE 终端能力：TS 36.306 Rel-19 §4.2.1.3 定义总软缓存参数，Table 4.1-1 给出各 UE 类别的取值，类别 5 为 3667200、类别 3 为 1237248；本地 `TS_36.306_36306-j20/full.md:3251`（条款）、`:2742-2752`（表）。
- NR 缓存长度：TS 38.212 Rel-19 §5.4.2.1 规定 LBRM 关闭时 $N_{cb}=N$、开启时 $N_{cb}=\min(N,N_{ref})$，并给出 $N_{ref}=\lfloor TBS_{LBRM}/(C\cdot R_{LBRM})\rfloor$ 与 $R_{LBRM}=2/3$；本地 `TS_38.212_38212-j30/full.md:1752-1756`。
- NR 母码长度：TS 38.212 Rel-19 §5.3.2 给出基图 1 的 $N=66Z_c$、基图 2 的 $N=50Z_c$，并说明前 $2Z_c$ 个系统位不写入缓存序列；本地 `full.md:1178-1184`。
- NR 参考传输块大小：TS 38.212 Rel-19 §5.4.2.1 规定 $TBS_{LBRM}$ 按 TS 38.214 的 §5.1.3.2（下行共享信道与寻呼信道）确定；本地 `TS_38.214_38214-j30/full.md:1766`（§5.1.3.2）。
- NR 码块数：TS 38.212 Rel-19 §5.2.2 给出码块分段与码块 CRC，传输块内的码块数 $C$ 由此确定；本地 `TS_38.212_38212-j30/full.md:765`。
- 非标准项：LLR 量化位宽 $b_{LLR}$、饱和加法门限、进程超配时的丢弃策略，以及 NR 侧实际的软缓存存储器规模，均不在 38.212/38.214 的正文中，属于实现域；NR 的 38.212 与 38.306 都没有给出 $N_{soft}$ 与 $N_{IR}$，本笔记出现的这两个量只在 LTE 语境下是协议量。
- 口径冲突的处理：与本篇相关的循环缓存长度以 TS 38.212 §5.4.2.1（本地 `full.md:1756`）为准；若其他笔记把 $N_{cb}$ 写成等于 $N$，应检查该处是否假定了 LBRM 关闭。

## 关键要点

1. 软缓存保存的是按母码地址组织的量化 LLR，不是硬判决比特；地址规则必须与发射端循环缓存一致。
2. LTE 的每进程配额为 $N_{IR}=\lfloor N_{soft}/(K_{MIMO}N_{HARQ})\rfloor$，其中 $N_{HARQ}$ 取配置进程数与 8 的较小值，上限 8 不能省略。
3. 每码块配额是 $\lfloor N_{IR}/C\rfloor$，除不尽的余数丢弃；把 $N_{IR}$ 直接当码块上限会高估 $C$ 倍。
4. NR 的缓存长度为 LBRM 关闭时 $N_{cb}=N$、开启时 $N_{cb}=\min(N,N_{ref})$，$N_{ref}$ 由参考传输块大小与参考码率 2/3 算出。
5. 一般形式 $N_{cb}=\min(N,N_{ref},\lfloor N_{IR}/C\rfloor)$ 是概念合并式，任一代只让其中两项生效，三项量纲必须一致。
6. $N_{cb}<N$ 时母码尾部不进入缓存，尾校验位永远不发送，接收端按擦除处理；这是“不存全部母码”的方向。
7. $N_{IR}$ 不足时发生跨进程挤占：总池固定、份额预先切分，实际需要的传输块份数超过 $K_{MIMO}\cdot8$ 后，各进程所需之和大于池，部分进程的 LLR 被压缩或释放。
8. 释放以有效标志为准，不以 LLR 是否为零为准；码块 CRC 释放子区间，传输块 CRC 通过或 NDI 翻转释放整个进程区间。
