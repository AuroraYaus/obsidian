# Segmentation 码块分段

## 符号与记号约定

本笔记以文字描述机制，符号表中列出正文用到的量；表中按「先定义后使用」排列，正文不再重复解释。

| 符号 | 含义与取值 | 协议锚点 |
|:---|:---|:---|
| $B$ | 传输块大小（含传输块 CRC 之前的载荷长度）；取正整数，单位为 bit；由调度给出的传输块大小字段确定 | TS 36.212 §5.1.2 |
| $B'$ | 计入每码块 CRC 之后的总比特数；取正整数，单位为 bit；等于 $B$ 加上码块数与每块 CRC 长度之积 | 由 TS 36.212 §5.1.2 导出 |
| $C$ | 码块数；取正整数，单位为个；等于 $B'$ 除以最大码块长度向上取整，且不超过协议上限 | TS 36.212 §5.1.2 |
| $K_+$ | 合法码块长度表中不小于均分长度 $B'/C$ 的最小值；取正整数，单位为 bit；由协议表查出 | TS 36.212 §5.1.2 |
| $K_-$ | 合法码块长度表中不大于均分长度的最大值；取正整数，单位为 bit；由协议表查出 | TS 36.212 §5.1.2 |
| $C_+$ | 取 $K_+$ 的码块个数；取 0 至 $C$ 的整数，单位为个；由均分长度与 $K_+$、$K_-$ 的关系确定 | 由 TS 36.212 §5.1.2 导出 |
| $F$ | 填充位数；取非负整数，单位为 bit；由较短码块补足到相同长度所需的比特数给出 | 由 TS 36.212 §5.1.2 导出 |
| $Z_c$ | LDPC 基图提升因子，决定母码长度；取协议允许的整数集合中的值，无量纲；由传输块大小与基图查表确定 | TS 38.212 §5.2.2 |
| $K_{cb}$ | 单个码块的最大编码块长度；取正整数，单位为 bit；由基图类型决定 | TS 38.212 §5.2.2 |


码块分段（Segmentation）把一个 TB 拆成一个或多个 CB，使每个译码核心处理的块长满足协议和编码器约束。一句话本质：**切割分两层——第一层 TB→CB 是编码器约束下的必做动作，第二层 CB→CBG 是为部分重传而设的可选动作**，且每一刀的规则都写在协议里，收发双方按同一套公式切。分段还会引入 CB CRC、filler bit 和 CB 顺序重组问题。

## 解释目标与范围

本节目标：解释 segmentation 如何把 TB 变成可译码的 CB 集合。

## 前置概念

传输块与 CRC 校验。传输块是 MAC 交给物理层的数据单元，其末尾附加循环冗余校验供整块验收，见 [[TB_传输块]] 与 [[CRC_循环冗余校验]]。分段发生在这层验收之后，目的是把长块切成编码器能处理的长度。

编码器的最大块长。卷积码、Turbo 码与 LDPC 码各自有最大输入长度限制，Turbo 码还受内部交织器合法长度的约束，LDPC 则受基图与提升因子约束，见 [[Turbo_码]]、[[LDPC_低密度奇偶校验码]] 与 [[Base_Graph_基图]]。分段数由传输块长度与编码器上限共同决定。

码块与填充位。每个码块附加自己的 CRC 后独立编码，码块长度必须落在编码器支持的取值集合内，不足部分用填充位占位，见 [[CB_码块]] 与 [[Filler_Bits_填充位]]。填充位不携带信息、接收端译码后丢弃，但会影响速率匹配与资源映射的比特预算。

## 起源与演进

(1) **加 TB CRC**。先给整个 TB 加 24 比特 CRC，作为整块验收的凭证。以下手算示例取 LTE、B=10001 比特（数据 9977 + CRC 24）。

(2) **算要切几块**。Turbo 编码器最大块长 6144，每个 CB 还要再挂 24 比特 CB CRC，因此每块净容量 6120：C = ⌈10001/6120⌉ = 2 块；切完预留 CRC 后 B' = 10001 + 2×24 = 10049。

(3) **选块长——不能取任意整数**。Turbo 内部交织器只认 188 个合法长度（40~6144）。取表内最小满足 C·K ≥ B' 的长度作长块 K+ = 5056（2×5056 = 10112 ≥ 10049），低一档作短块 K- = 4992（K+ − K- = 24，恰为一个 CB CRC 的长度）；短块数 C- = ⌊(10112−10049)/64⌋ = 0——本例两块均用 K+ = 5056。

(4) **补 filler**。多出的空间 F = 10112 − 10049 = 63 比特，以 `<NULL>` 占位填在第一个码块开头；filler 不是数据，接收端译完即弃，不交付上层。

(5) **顺序规矩**。协议规定短块在前、长块在后（本例等长）。每块再挂 CB CRC 后独立编码，译码器的"CB 级流水"就绪。

(6) **NR 差异与第二层切割**。NR 换 LDPC 后上限放宽：先选基图（BG1 上限 8448 / BG2 上限 3840），TB 很大时再挂 16 比特 CRC，随后选提升值 Zc 使 22×Zc 覆盖块长、差补 filler（例：B=10000、BG1 → C=2）；Polar 路径只有 C=1 特例。第一层切完，NR 还可按 CBG 再切一层（M=min(N,C)，见 [[CBG_码块组]]）。

## 科学定义

码块分段是信道编码前的结构化切分。发送端先处理 TB CRC，再根据最大码块大小、编码家族和协议表决定 CB 数量、每个 CB 的长度、filler 数量以及是否附加 CB CRC。接收端必须按同一结构反向重组。

## 直观模型

segmentation 像把一段长数据装进多个固定规格的盒子。盒子太大或太小时都不符合协议；为了对齐盒子大小，可能要在第一个盒子前面加入 filler 占位。

## 常见误解

| 误解 | 正确理解 |
|:---|:---|
| filler 是业务 0 | filler 是占位，不能交付为 TB 数据。 |
| 分段只是数组切片 | 分段还决定 CRC、filler、CB 长度和重组顺序。 |
| 接收端可以自行猜 CB 边界 | CB 边界必须由协议规则和 descriptor 确定。 |

## 协议锚点

- LTE：TS 36.212 Rel-19 §5.1.2 Code block segmentation and code block CRC attachment。
- NR：TS 38.212 Rel-19 §5.2.1 Polar coding；§5.2.2 LDPC coding。

## 码块分段在协议族中的分布（五层职责）

| 协议层 | 回答的问题 | 代表 TS（本地 Rel-19 资料） |
|:---|:---|:---|
| 信道编码 | **分段算法本体**（C/K+/K-/filler/CB CRC 计算） | TS 36.212 §5.1.2（LTE Turbo）/TS 38.212 §5.2.2（NR LDPC）/§5.2.1（NR Polar，C=1 特例） |
| 物理层过程 | **要切的 B 从哪来**（调度结果 → TBS） | TS 38.214 §5.1.3（NR TBS）/TS 36.213 §7.1.7（LTE TBS） |
| 物理层控制 | MCS/资源分配指示（决定 TBS 的 DCI 字段） | TS 38.212 §7.3（NR）/TS 36.212 §5.3.3（LTE） |
| RRC 信令 | 编码相关配置（NR 基图选择依赖的 mcs-Table 等） | TS 38.331（泛提） |
| MAC | TB 大小与码块交付（传输块组装） | TS 38.321 §5.3.2.2 |

**联系链**：MAC/调度定 TB 大小 → 213/214 定 TBS → 212 按编码器约束切出 C 个 CB（合法块长 + filler + CB CRC）→ 331 提供编码配置 → 接收端按同一规则重组。CBG 分组是在分段结果之上的第二次"切"（见 [[CBG_码块组]]）。

## 关键要点

1. 切两次：先切 CB（编码器约束，必做），再切 CBG（重传粒度，可选）。
2. CB 长度必须落在合法表：LTE Turbo 188 个值（40~6144），NR 是 22×Zc 的倍数。
3. K+ − K- = 24 = 一个 CB CRC 的长度；短块在前、长块在后。
4. filler 是 `<NULL>` 占位，填在首块开头，不是业务数据。
5. 接收端的边界完全由协议公式与 descriptor 决定，不靠猜。
6. B=10001 是边角练习：C-=0 两块等长、63 比特 filler 全在首块（T3.3 主场）。
