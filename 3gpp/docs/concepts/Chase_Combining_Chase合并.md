# Chase Combining (CC)

## 符号与记号约定

| 符号 | 含义与取值 | 协议锚点 |
|:---|:---|:---|
| $p$ | 解速率匹配后的编码比特位置，即软缓存中的地址；取整数，量纲一 | 由 TS 38.212 §5.4.2.1 导出（速率匹配后的编码位置） |
| $LLR_{\mathrm{old}}(p)$ | 本次重传之前，软缓存中第 $p$ 个位置已存的 LLR；实数，取值 $(-\infty,+\infty)$，量纲一 | 实现域（软缓存内容，TS 不规定缓存格式） |
| $LLR_{\mathrm{retx}}(p)$ | 本次重传解速率匹配后落在同一位置 $p$ 的 LLR；实数，量纲一 | 实现域（接收机软解调输出） |
| $LLR_{\mathrm{combined}}(p)$ | 合并后写回软缓存的 LLR，等于前两者之和，即 $LLR_{\mathrm{combined}}(p)=LLR_{\mathrm{old}}(p)+LLR_{\mathrm{retx}}(p)$；实数，量纲一 | 实现域（接收机软合并，非 3GPP 原文公式） |

括号中的 $p$ 是位置自变量而非乘法；$LLR$ 作为整体是一个量名，其下标表示该 LLR 所属的处理阶段。各行来源统一写在第三列：协议量给 TS 条款号，派生量给「由 TS … §… 导出」，非协议量给「非 3GPP 标准」或「实现域」。

Chase 合并（Chase Combining，CC）是 HARQ（混合自动重传请求，Hybrid Automatic Repeat reQuest）中最简单的软合并方式：每次重传发送相同编码比特，接收端把同一编码位置的多份 LLR（对数似然比，Log-Likelihood Ratio）相加后送译码。一句话本质：**CC 是"两位证人独立作证"——说法一致信心倍增（能量翻倍、等效信噪比约 +3 dB），说法矛盾置信度反而下降**。

## 解释目标与范围

本节目标：解释混合自动重传请求（Hybrid Automatic Repeat reQuest, HARQ）中最简单的软合并方式——Chase 合并（Chase Combining, CC）：重传相同编码比特、接收端按编码位置累加 LLR 的原理、增益来源与适用边界。

CC 位于接收端解速率匹配之后、信道译码之前：把多次传输的对数似然比（Log-Likelihood Ratio, LLR）在软缓存（Soft Buffer）中按编码位置合并后送入译码器。

## 前置概念

**对数似然比**（Log-Likelihood Ratio, LLR）是两种假设下观测概率之比的对数，正负号给出判决方向、绝对值给出可靠度。LLR 的核心性质是可加：两个独立观测对同一比特的证据，其 LLR 可以直接相加，相加后的符号仍指向更可能的假设，绝对值随证据一致程度增大或减小。软合并之所以成立，完全依赖这一条性质。

**软合并**（Soft Combining）指在译码之前把多次传输的软信息按编码位置合并、再统一译码的方式，合并对象是 LLR 而不是判决比特。先合并、后译码与先译码、后合并相比，前者保留了每次传输的可靠度信息，因此增益更高；代价是接收端必须为每个编码位置保留一份可累加的软缓存。

**冗余版本**（Redundancy Version, RV）指一次 HARQ 传输在循环缓存中的起始位置与读取顺序，它决定本次传输送出的是哪些编码比特。合并前必须按 RV 把每个 LLR 还原到它在编码比特串中的位置；位置对不上，相加就变成把不同比特的证据混在一起，合并结果反而更差。

**软缓存**（Soft Buffer）是接收端为每个 HARQ 进程保留的一块存储，按编码位置存放当前累积的 LLR。软缓存的容量决定能保留多少编码比特，容量不足时只能保留一部分位置，其余位置每传一次都从头累积；缓存位宽则决定 LLR 的量化精度，位宽不够会在多次累加后饱和。

**能量增益与编码增益**（Energy Gain and Coding Gain）是 HARQ 重传带来的两类不同收益。能量增益来自同一比特被重复接收、信噪比按重传次数线性提高，任何重复发送都能获得；编码增益来自新增的校验比特降低了有效码率，只有增量冗余才提供。Chase 合并只取前者，这也是它与增量冗余的分界。

## 起源与演进

(1) **起点：重传发什么的第一问。** HARQ 机制面临的第一个问题是：重传时发什么？Chase 的回答最简单——把同样的编码比特再发一遍，接收端按编码位置把新旧 LLR 相加。

(2) **原理：对数似然可加性。** 独立观测的证据按 LLR 可加性合并：同号证据相加增强、异号证据相加抵消（绝对值变小）——不是"取更相信的那位"，而是全部计入。

(3) **增益来源：纯能量增益。** 每次重传使同一位置的接收能量翻倍，等效信噪比提升约 3 dB（$10\cdot\log_{10}2\approx 3.01$ dB）；硬件上用饱和加法防止多次合并溢出。

(4) **与 IR 的边界。** CC 只叠加能量、不引入新校验比特——没有编码增益；IR 重传新增校验比特，有效码率随重传降低。真实 LTE/NR rate matching 常两者并存：重复位置相加、新增位置写入空位。

(5) **数值推演。** 同号合并增强、异号合并动摇——两种走向都源于对数似然可加性，具体数值推演见直观模型的 +0.8/+1.5/−1.5 例。

## 科学定义

Chase 合并假设每次重传发送相同（或高度相同）的编码比特，同一编码位置的 LLR 直接相加：

$$LLR_{\mathrm{combined}}(p) = LLR_{\mathrm{old}}(p) + LLR_{\mathrm{retx}}(p)$$

$p$ 是解速率匹配后得到的编码位置。物理含义：独立观测的证据按对数似然的可加性合并，同号证据相加增强、异号证据相加抵消（绝对值变小）。每次重传使同一位置的接收能量翻倍，等效信噪比提升约 3 dB（$10\cdot\log_{10} 2\approx 3.01$ dB）——这是纯能量增益。硬件上用饱和加法防止多次合并溢出。CC 与增量冗余（Incremental Redundancy, IR）的本质区别：CC 只叠加能量、不引入新校验比特，因此没有编码增益。

## 直观模型

第一次接收某编码位置 LLR=+0.8（略偏向 0），译码后 TB CRC 失败；重传同一位置得到 LLR=+1.5。合并后 +2.3，判决明显更可信。若重传给出 −1.5，合并后 −0.7——原判决反而被动摇。类比：两位证人独立描述同一事件，说法一致时信心倍增，说法矛盾时整体置信度下降，而不是"取更相信的那位"。

## 常见误解

| 误解 | 正确理解 |
|:---|:---|
| CC 是重发整包并替换旧数据 | 接收端必须保留旧 LLR 并逐位置相加，而不是覆盖。 |
| CC 能带来编码增益 | CC 只有能量增益（约 3 dB/次），编码增益来自 IR 的新增校验比特。 |
| 合并后 LLR 幅度一定变大 | 符号冲突的证据相加后绝对值可能变小。 |
| 接收端可以随意决定怎么加 | 必须先按协议 RV（冗余版本，Redundancy Version）规则确定每个 LLR 的编码位置，否则合并错位。 |
| CC 与 IR 是互斥的两条路 | 真实 LTE/NR rate matching 常同时出现重复位置（相加）与新增位置（写入空位）。 |

## 关键要点

1. CC 假设重传发送相同编码比特，同位置 LLR 直接相加。
2. 公式 LLR_combined(p) = LLR_old(p) + LLR_retx(p)，物理基础是对数似然可加性。
3. 增益是纯能量增益：每次重传等效信噪比约 +3 dB，无编码增益。
4. 符号冲突的证据相加后绝对值变小——置信度下降，而非"取更可信的"。
5. 必须按 RV 规则定位编码位置再合并，否则合并错位。
6. CC 是 IR 的退化情况，实现最简单，是软合并机制的教学入口。
