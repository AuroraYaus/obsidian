# SIB1 System Information Block Type 1

## 符号与记号约定

本笔记出现的数学符号在此给出读法、含义与取值来源；后文不再重复定义。

| 符号 | 读法 | 含义与取值 | 协议锚点 |
|:---|:---|:---|:---|
| $T_{SIB1}$ | T 下标 SIB1 | 系统信息块 1 的发送周期；协议固定为 160 ms，单位为毫秒 | TS 38.331 §5.2.2.1 |
| $T_{rep}$ | T 下标 rep | 周期内的重复发送间隔；缺省 20 ms，实际取值由网络实现，单位为毫秒 | 由 TS 38.331 §5.2.2.1 导出 |
| $k_{SSB}$ | k 下标 SSB | 同步信号块与公共资源块网格之间的子载波偏移；取 0 至 23（FR1）或 0 至 11（FR2），单位为子载波 | TS 38.211 §7.4.3.1 |
| $N_{RB}^{CORESET}$ | N 上标 CORESET，下标 RB | 控制资源集 0 的频域大小；取 24、48 或 96，单位为资源块 | TS 38.213 §13 |
| $T_{SI}$ | T 下标 SI | 系统信息消息的调度周期；取 8、16、32、64、128、256、512 帧之一，单位为无线帧 | TS 38.331 §5.2.2.1 |

运算符与记号惯例：$T_{SIB1}$ 与 $T_{rep}$ 都是绝对时长，不随子载波间隔变化；$k_{SSB}$ 的下标 SSB 表示它描述的是同步信号块的位置而非数据；$N_{RB}^{CORESET}$ 的上标表示「属于控制资源集 0」，不是乘方。

## 定位

系统信息块 1（System Information Block Type 1, SIB1）是终端在接入小区后读到的第一份完整配置：它给出这个小区的身份、能不能驻留、以及其他系统信息块到哪里去找。它由网络周期广播、内容小区专属，是终端从「搜到小区」走到「能发起接入」的必经一站。

## 解释目标与范围

本节目标：说清 SIB1 在系统信息体系中的位置与它和 MIB 的分工；说清它的承载方式与 160 ms 周期、重复发送规则；说清它的内容骨架与「如何调度其他系统信息块」这一核心职能。不展开各字段的取值含义与 RRC 过程细节。

## 前置概念

系统信息体系。3GPP 把小区级的公共配置分成三类承载：主信息块（Master Information Block, MIB）在广播信道上发送，内容极少且固定；系统信息块 1（SIB1）在共享信道上发送，是接入的门槛；系统信息块 2 及其后（SIB2、SIB3……）按需调度，内容多且可分窗发送。三者的关系是逐级展开：MIB 告诉终端去哪里读 SIB1，SIB1 告诉终端其余系统信息去哪里读。

搜索空间与无线网络临时标识。终端读 SIB1 用的是控制信道，监听位置由「类型 0 公共搜索空间」规定，CRC 由系统信息无线网络临时标识（System Information Radio Network Temporary Identifier, SI-RNTI）加扰。终端不需要预先知道自己被调度，只要按固定位置盲检、用固定标识解扰，就能认出这一份承载的是系统信息。

下行共享信道。SIB1 不是独立信道，而是作为下行共享信道上的一个传输块发送的：先经传输块 CRC 与信道编码，再映射到资源上。这意味着它的接收过程与普通数据相同，区别只在调度方式与标识。

驻留判据。终端搜到小区后并不立即驻留，而要先判断这个小区的信号质量是否达到门限、PLMN 是否在允许列表内。这些参数正写在 SIB1 里——它既是配置来源，也是驻留决策的依据。

## 起源与演进

LTE 时代已有 SIB1 与 MIB 的两级结构：MIB 用固定格式给带宽与 PHICH 配置，SIB1 给调度信息与小区身份。两级分工的基本原则是「把最必要的、终端在解码第一步就要用的信息放在最容易读的承载上」。

NR 沿用了两级结构，但把 MIB 的内容压缩到更小（24 bit 载荷），并让它携带「去哪里找 SIB1」的索引——即控制资源集 0 与公共搜索空间 0 的配置。这一步替代了 LTE 里靠固定位置盲搜的做法，使 SIB1 的位置可以按小区灵活配置。

Rel-17 起为卫星场景引入了按需 SIB1（on-demand SIB1）的概念：终端可以在没有广播 SIB1 的情况下主动请求，网络再单独发送。这让 SIB1 从「必然广播」变成「默认广播、特定场景可按需获取」。

## 科学定义

### 位置与承载：从 MIB 到 SIB1 的两跳

终端读到 MIB 之后，从中取出控制资源集 0 与公共搜索空间 0 的配置（字段 pdcch-ConfigSIB1）。这两个参数告诉终端：在哪些资源块、哪些符号上监听控制信道，以及在哪个搜索空间里盲检。随后终端在「类型 0 公共搜索空间」上盲检 CRC 由 SI-RNTI 加扰的 DCI format 1\_0，解出这一份 SIB1 传输占用的时频资源，再到下行共享信道上接收（TS 38.213 §13）。

这里有一个判据值得记住：MIB 里若 $k_{SSB}<24$（FR1）或 $k_{SSB}<12$（FR2），说明本小区存在类型 0 公共搜索空间；若 $k_{SSB}>23$（FR1）或 $>11$（FR2），则该资源集不在广播里给出，需由公共控制信道配置另行提供。也就是说，MIB 用一个偏移量的取值范围同时表达了「有没有 SIB1 可读」这一信息。

### 周期与重复：160 ms 与周期内重复

SIB1 在下行共享信道上以 $T_{SIB1}=160$ ms 为周期发送，并在周期内多次重复，缺省重复间隔 $T_{rep}=20$ ms，实际间隔由网络实现决定（TS 38.331 §5.2.2.1）。重复间隔还与同步信号块和控制资源集的复用图样有关：图样 1 下重复周期固定为 20 ms；图样 2 与图样 3 下重复周期与同步信号块的周期相同。

周期与重复的设计目标不同：160 ms 的周期决定「内容多久更新一次」，重复间隔决定「终端最坏要等多久才能收到」。一个刚上电的终端可能在任意时刻开始监听，重复发送保证它在最长一个重复间隔内就能读到 SIB1，而不必等满 160 ms。

### 内容骨架与调度职能

SIB1 的字段可归为四组（TS 38.331 §6.2.2 的 SIB1 定义）。第一组是小区身份与归属：PLMN 列表、跟踪区码、小区标识，决定终端是否可以在此驻留。第二组是接入相关配置：小区选择门限、初始上行配置（含随机接入的公共配置）、定时器与常量、接入控制信息。第三组是能力与业务指示：是否支持紧急呼叫、是否支持某种接入控制、是否使用完整恢复标识。第四组是调度信息（si-SchedulingInfo）：它把 SIB2 及其后的各个系统信息映射到若干条系统信息消息上，并为每条消息给出周期 $T_{SI}$ 与系统信息窗口长度。

第四组是 SIB1 最关键的职能。终端读完 SIB1 之后并不立即去读其他系统信息，而是先按调度信息算出「哪条消息在哪个窗口里发」，再按需去收。这也解释了系统信息体系的分层动机：把「什么时候发什么」与「内容是什么」分开，前者固定在 SIB1 里且周期广播，后者按需调度、可分窗、可按需请求。

## 直观模型

把系统信息看成两级目录。MIB 是贴在门口的索引卡，只写「本小区有没有 SIB1、SIB1 在哪几个资源块上听」，内容少到可以在最差的信道条件下也能解出。SIB1 是进门后的总目录，写清三件事：这里是不是你能待的小区、接入要用的参数是什么、其余目录（SIB2 及以后）分别放在哪一期、多长时间出一期。

两级目录的分工由「读取顺序」决定：终端必须先解 MIB 才知道去哪找 SIB1，必须先解 SIB1 才知道去哪找其余系统信息。任何一级缺失，后面全部读不到——所以这两级的编码与重复都比普通数据更保守。

## 常见误解

| 误解 | 正确理解 |
|:---|:---|
| SIB1 通过广播信道发送 | SIB1 在下行共享信道上以传输块形式发送，广播信道只承载 MIB |
| SIB1 是主信息块 | 主信息块是 MIB；SIB1 是系统信息块 1，两者承载不同、位置不同、内容量差一个量级 |
| SIB1 只在 160 ms 时发一次 | 160 ms 是周期，周期内还有多次重复（缺省 20 ms 一次），保证终端最坏只等一个重复间隔 |
| SIB1 里包含所有系统信息的内容 | SIB1 只给调度信息（哪个 SIB 映射到哪条消息、周期与窗口），内容在对应窗口里单独发 |
| SIB1 一定靠广播获得 | 默认广播；Rel-17 起卫星场景支持按需请求 SIB1，终端可主动请求后获取 |

## 关键要点

1. SIB1 是系统信息块 1，在下行共享信道上以传输块形式发送，由网络周期广播、内容小区专属。
2. 两级结构：MIB 给「去哪里找 SIB1」，SIB1 给「去哪里找其余系统信息」。
3. 读 SIB1 用类型 0 公共搜索空间 + SI-RNTI 加扰的 DCI format 1\_0，位置由 MIB 的 pdcch-ConfigSIB1 间接给出。
4. 周期固定 160 ms，周期内多次重复（缺省 20 ms），最坏等待不超过一个重复间隔。
5. 内容四组：小区身份与归属、接入配置、能力与业务指示、其他系统信息的调度信息。
6. 调度信息（si-SchedulingInfo）是 SIB1 的核心职能：把 SIB2 及以后映射到系统信息消息并给出周期与窗口。
7. 驻留决策依赖 SIB1：小区选择门限、PLMN 匹配都在其中。
8. Rel-17 起支持按需 SIB1（卫星场景），从「必然广播」变为「默认广播、可按需获取」。
