# Incremental Redundancy (IR)

## 符号与记号约定

本笔记的公式集中在两处：冗余版本起点 $k_0$ 的查表与手算，以及合并后有效码率 $R_n$ 的计量口径。下表登记全文使用的每一个数学符号，逐行给出它的含义、取值或范围、单位与来源，并注明可追溯的协议出处，后文出现时不再重复定义；运算符与下标语义见表后的约定。

运算符与下标语义需要先固定，否则公式中的符号会被误读成物理量。运算符方面，$\lfloor\cdot\rfloor$ 为向下取整，$\lceil\cdot\rceil$ 为向上取整，$\bmod$ 为取余（余数落在 0 至模数减 1），$\cdot$ 与并置都表示乘法。下标语义方面，$E_r$ 的下标 r 指第 r 个码块而非乘法，$k_0$ 的下标 0 是版本入口的固定记法而非变量取值，$rv_{id}$ 与 $rv_{idx}$ 是同一物理量在 NR 与 LTE 两代协议中的两套写法。三套长度不可混用：$N$ 是母码长度、$N_{\mathrm{cb}}$ 是缓存长度、$N_{ref}$ 是 LBRM 上限，关系为 $N_{\mathrm{cb}}=\min(N,N_{ref})$；码率不带单位，比特数一律以 bit 计。

增量冗余（Incremental Redundancy，IR）是长期演进（Long Term Evolution, LTE）与新型无线电（New Radio, NR）两代系统混合自动重传请求（Hybrid Automatic Repeat Request, HARQ）的标准重传模式：每次重传按冗余版本（Redundancy Version, RV）选取循环缓存中的不同起点，把此前未发送的校验位补进接收端的软缓存，使合并后的有效码率随互异覆盖比特数增加而下降。一句话本质：**IR 的增益来自同一段缓存地址上的两个可分别计量的量——新起点带来的覆盖扩张与重复覆盖带来的证据累加，前者的上限由缓存长度 $N_{\mathrm{cb}}$ 决定，后者的上限由传输次数决定。**

## 独立解释任务

任务目标：解释增量冗余如何在循环缓存上用不同的冗余版本起点逐次扩大覆盖范围，说明发送端每次的读取区间如何由 $k_0$ 与 $E_r$ 确定、接收端如何在同一地址上累加对数似然比、合并后的等效码率 $R_n$ 与单次传输的有效码率 $R$ 为何是两个不同的量，并给出 $Z_c=384$、基图 1、$N_{\mathrm{cb}}=12672$ 一组四个冗余版本的可复算数值例。在 LTE/NR 译码链路中的位置：IR 是 HARQ 软合并（soft combining）的一种实现方式，向下由解速率匹配按 $k_0$ 把本次 LLR 回填到正确地址，向上由 [[HARQ_Process_HARQ进程管理]] 的进程号与新数据指示（New Data Indicator, NDI）决定这批 LLR 是覆盖写还是增量写。

## 前置概念

本笔记要解释的对象是增量冗余（Incremental Redundancy, IR）本身：它规定重传不必重复初传的编码比特，而是按 $rv_{id}$ 从母码的另一段继续取数，使接收端累积的证据在码率与能量两个方向上同时增加。与它对照的是 Chase 合并（Chase Combining, CC）：每次重传发送与初传相同的编码比特，接收端只在相同地址上把新旧 LLR 相加，等效码率不变，增益全部来自能量，实现细节见 [[Chase_Combining_Chase合并]]。

两种方式共用的动作是软合并（soft combining）：把同一编码比特的多次含噪观测按 LLR 相加，等价于把多次独立观测的证据集中到一次译码上，也因此要求接收端知道每个 LLR 属于母码的哪个位置，协议背景见 [[HARQ_混合自动重传请求]]，似然比的取值语义见 [[LLR_对数似然比]]。承载这些累加值的是软缓存（Soft Buffer）：接收端按编码比特的地址为每个位置保存一个 $\Lambda$，容量由 $N_{IR}$（LTE）或 $N_{ref}$（NR）限定，地址规则与发送端的循环缓存完全一致，详见 [[Soft_Buffer_软缓存]]。

发送端的地址空间是循环缓存（Circular Buffer）：编码器输出的码字按系统位在前、校验位在后的顺序写入长度为 $N_{\mathrm{cb}}$ 的线性地址，读取从 $k_0$ 起递增、越过上界后按模 $N_{\mathrm{cb}}$ 回到 0，详见 [[Circular_Buffer_循环缓存]]。冗余版本（Redundancy Version, RV）是决定 $k_0$ 的那个离散参数，它只有 0、1、2、3 四个取值，与第几次重传没有固定对应，详见 [[RV_冗余版本]]。最后一个对象是有效码率（effective code rate）：单次传输按 $R=K/E_r$ 计，描述一个码块被发得多薄；把多次传输的互异比特合并计数后得到的量记作 $R_n$，两者分母不同，不能混用。

## 起源与演进

(1) **起点：重传的两种可选做法。** 一次传输未能译出时，接收端已持有若干编码比特的含噪观测，重传面临的第一个问题是发什么：重复已有比特可以提高同一位置的观测次数，发送新比特可以扩大码字覆盖。Chase 合并选前者，IR 选后者，而两者的接收端动作可以是同一套按地址累加的机制，这也是两代协议能共用软缓存结构的原因。

(2) **LTE：三段式缓存上的线性起点。** LTE 的 Turbo 编码输出系统位与两路校验位，经子块交织后拼成长度为 $K_w=3K_{\Pi}$ 的循环缓存，$N_{\mathrm{cb}}$ 再按软缓存份额 $\lfloor N_{IR}/C\rfloor$ 截断。起点按 $k_0=R_{subblock}\left(2\left\lceil N_{\mathrm{cb}}/(8R_{subblock})\right\rceil rv_{idx}+2\right)$ 计算，四个起点随 $rv_{idx}$ 线性分布，RV=0 的起点不是 0 而是 $2R_{subblock}$。

(3) **NR：单段式缓存上的查表起点。** NR 的 LDPC 编码输出 $N=66Z_c$（基图 1）或 $N=50Z_c$（基图 2）个比特，最前面 $2Z_c$ 个系统位不写入缓存序列。起点改为按 $rv_{id}$ 与基图查 Table 5.4.2.1-2，四个起点都是 $Z_c$ 的整数倍，且都随 $N_{\mathrm{cb}}$ 缩放；LBRM 生效时 $N_{\mathrm{cb}}=\min(N,N_{ref})$，缓存上界被压到 $N_{ref}$，四个起点的间距随之缩短。

(4) **序列惯例与协议边界。** LTE 调度器常用 $[0,2,1,3]$、NR 常用 $[0,2,3,1]$，这是工程惯例而非协议强制的 HARQ 重传顺序：HARQ 重传的 RV 由调度下行控制信息逐次指示，接收端不能假设顺序。协议只在 PDSCH 的多次传输时机（聚合或重复发送）上把序列固定为 $0,2,3,1$ 循环（TS 38.214 §5.1.2.1 的 Table 5.1.2.1-2），因此"常见序列"与"协议规定序列"必须分开表述。

(5) **两个增益来源被分开计量。** 覆盖率提高带来的编码增益与重复覆盖带来的能量增益在协议里没有单独字段，它们完全由 $k_0$、$E_r$、$N_{\mathrm{cb}}$ 三者的取值组合决定；这也解释了为什么调度器只调整 RV 序列就能改变重传的增益结构，而不需要新增信令。

演进脉络给出的是机制来源，下面把它固定成可计算的量与一组可逐行核对的数值。

## 科学定义

### 合并规则与两种重传的差别

第 $n$ 次传输从起点 $k_0$ 起连续读取 $E_r$ 个地址，越过上界后按模 $N_{\mathrm{cb}}$ 回到 0，因此它覆盖的地址集合 $S_n$ 是一个长度 $E_r$ 的模区间。接收端按三条规则处理这批 LLR：本次覆盖到的地址把新的 $\Lambda$ 与此前保存的值相加，两次观测按独立观测处理；本次未覆盖的地址保持旧值不变；从未被任何一次传输覆盖过的地址取值未知，其 $\Lambda$ 置零并保留未知标记，不能按比特 0 处理。把前 $n$ 次覆盖集合取并集后计数得到 $M_n$，合并后的等效码率即

$$R_n=\frac{K}{M_n}$$

分母 $M_n$ 计的是互异地址数而不是发送比特数，这一口径把 IR 与 Chase 合并区分开。同 RV 重传与不同 RV 重传的差别就在这三条规则里：同一 RV 的多次重传只把相同地址上的 $\Lambda$ 相加，$M_n$ 不变、$R_n$ 不变，增益全部是能量；不同 RV 的重传把此前未写入的地址补进覆盖集合，$M_n$ 增大、$R_n$ 下降，增益是能量与编码两部分之和。

### 起点计算与两代公式

NR 的起点由冗余版本与基图共同决定，基图 1 的四个起点为 $k_0=0$、$\lfloor17N_{\mathrm{cb}}/(66Z_c)\rfloor Z_c$、$\lfloor33N_{\mathrm{cb}}/(66Z_c)\rfloor Z_c$、$\lfloor56N_{\mathrm{cb}}/(66Z_c)\rfloor Z_c$，依次对应 $rv_{id}=0,1,2,3$；基图 2 把分母换成 $50Z_c$、三个系数换成 13、25、43。LTE 的起点由一条闭式给出：

$$k_0=R_{subblock}\left(2\left\lceil\frac{N_{\mathrm{cb}}}{8R_{subblock}}\right\rceil rv_{idx}+2\right)$$

两代公式的共同点是 $k_0$ 只由冗余版本与基图决定（NR 的查表还用到 $N_{\mathrm{cb}}$ 与 $Z_c$），与 $E_r$ 无关：$E_r$ 只决定从该起点向后读多远，不改变起点位置。这一口径与 [[Circular_Buffer_循环缓存]] 一致：该笔记的符号表把 $k_0$ 记为本次读取的起始地址，并注明它由冗余版本与基图决定（NR 查 Table 5.4.2.1-2，LTE 由 $R_{subblock}$ 与 $N_{\mathrm{cb}}$ 算出）；三参数分工表把 $E_r$ 单列为本次输出的比特数，注明它由 $G$ 与码块数分配得到、与缓存长度无关；若两处表述出现冲突，以 TS 38.212 §5.4.2.1 的 bit selection 为准，其本地抽取件在 `3GPP_Rel19/processed/TS_38.212_38212-j30/full.md:1872`（起点按 $rv_{id}$ 与基图查表）与 `full.md:1892-1910`（Table 5.4.2.1-2 的四个起点）。

### 手算数值例

取 $Z_c=384$、基图 1、LBRM 生效且 $N_{ref}=12672$（$=33Z_c$）。码块信息比特数取基图 1 的码块上限 $K_{cb}=8448$ bit，即 $K=22Z_c$；初传目标码率 $3/4$，故每次传输的速率匹配输出长度 $E_r=K/(3/4)=11264$ bit。该码块长度恰为 $22Z_c$，码块分段没有补 filler，缓存中没有 NULL 位置，地址推进次数等于输出比特数。各量按下表顺序算出，后一步依赖前一步：

| 步骤 | 计算式 | 结果 |
|:---|:---|:---|
| 母码长度 | $N=66Z_c=66\times384$ | 25344 |
| 缓存长度 | $N_{\mathrm{cb}}=\min(N,N_{ref})=\min(25344,12672)$ | 12672（$=33Z_c$） |
| RV=0 起点 | $k_0=0$ | 0 |
| RV=1 起点 | $k_0=\lfloor17N_{\mathrm{cb}}/(66Z_c)\rfloor Z_c=\lfloor17\times12672/25344\rfloor\times384=\lfloor8.5\rfloor\times384$ | 3072（$=8Z_c$） |
| RV=2 起点 | $k_0=\lfloor33N_{\mathrm{cb}}/(66Z_c)\rfloor Z_c=\lfloor16.5\rfloor\times384$ | 6144（$=16Z_c$） |
| RV=3 起点 | $k_0=\lfloor56N_{\mathrm{cb}}/(66Z_c)\rfloor Z_c=\lfloor28\rfloor\times384$ | 10752（$=28Z_c$） |

|:---|:---|:---|:---|:---|:---|:---|
| 1 | 0 | 0 | $[0,11264)$ | 11264 | 11264 | 0.750 |
| 2 | 1 | 3072 | $[3072,12672)$ 与 $[0,1664)$ | 1408 | 12672 | 0.667 |
| 3 | 2 | 6144 | $[6144,12672)$ 与 $[0,4736)$ | 0 | 12672 | 0.667 |
| 4 | 3 | 10752 | $[10752,12672)$ 与 $[0,9344)$ | 0 | 12672 | 0.667 |

四个起点把地址轴切成四段读取：第一段从 0 读到 11264，是初传的全部输出；第二次从 3072 读到 12672 再回绕到 1664，新增的只有 11264 至 12672 这 1408 个地址，其余 9856 个地址与初传重复；第三、四次的区间全部落在已被覆盖的地址上，新增为零。四次合计发送 $4E_r=45056$ bit，其中重复写入 32384 bit，互异覆盖恰为整个缓存 $N_{\mathrm{cb}}=12672$ bit。

由此得到两个不同的码率序列。单次传输的有效码率四次都等于 $K/E_r=0.75$，它只由该次的 $E_r$ 决定；合并后的等效码率分别为 $8448/11264=0.75$、$8448/12672=2/3$、$2/3$、$2/3$，编码增益在第二次之后就耗尽，第三、四次只剩能量增益。这不是参数选取造成的特例，而是 LBRM 的直接后果：缓存只保留 $1.5K$ 个地址，$R_n$ 的下限就是 $K/N_{\mathrm{cb}}=2/3$。

把 LBRM 关闭后对照即可看出下限的来源。此时 $N_{\mathrm{cb}}=N=25344$，四个起点变为 0、6528、12672、21504，同一 $E_r=11264$ 下四次的累计覆盖为 11264、17792、23936、25344 bit，$R_n$ 依次为 0.75、0.475、0.353、$1/3$，最终落在母码码率 $K/N=1/3$ 上。同一组 RV 与同一个 $E_r$，两种缓存上界给出两个不同的码率下限，这就是"IR 的编码增益上限由 $N_{\mathrm{cb}}$ 而非母码长度决定"的定量含义。

## 直观模型

把四次传输放在同一条地址轴上：地址从 0 到 12671，每次读取是长度 11264 的一段，起点分别是 0、3072、6144、10752。第一段覆盖前 11264 个地址；第二段从 3072 开始，越过上界后从 0 续到 1664；第三段从 6144 开始，回绕后覆盖 0 至 4736；第四段从 10752 开始，回绕后覆盖 0 至 9344。四段的并集覆盖全部 12672 个地址，缺口只有第一段末尾的 1408 个地址，由第二段补上，第三、四段不产生新地址。

软缓存在同一坐标轴上按地址累加，每个地址保存一个 $\Lambda$，写入一次即完成首次覆盖，再次覆盖则相加。把四段的覆盖次数逐地址数出来，地址轴被分成 8 个区段，观测次数在 3 次与 4 次之间交替：$[0,1664)$ 4 次，$[1664,3072)$ 3 次，$[3072,4736)$ 4 次，$[4736,6144)$ 3 次，$[6144,9344)$ 4 次，$[9344,10752)$ 3 次，$[10752,11264)$ 4 次，$[11264,12672)$ 3 次；八段长度乘观测次数求和为 45056，与四次发送的比特总数一致。这说明合并后的等效码率由有多少地址被覆盖决定，而每个地址上的证据强度由被覆盖几次决定，两者互相独立：前者的上限是 $N_{\mathrm{cb}}$，后者只随传输次数增长。

## 常见误解

| 误解 | 正确理解 |
|:---|:---|
| IR 只是把同一段编码比特再发一遍 | 发送相同编码比特的是 Chase 合并；IR 每次按不同的 $rv_{id}$ 取另一段，覆盖集合随之扩大。 |
| RV 越大越可靠 | RV 只是地址起点，不表示可靠度等级；RV=3 的起点在 $56/66$ 处，回绕后覆盖的常常是已被覆盖过的地址，可靠度取决于 $M_n$ 与每个地址的观测次数。 |
| 合并一定提升码率 | 等效码率只在 $M_n$ 增大时下降；$M_n$ 已达到 $N_{\mathrm{cb}}$ 后继续合并只增加每个地址的观测次数，$R_n$ 不变。 |
| 每次重传的有效码率依次降低 | 单次传输的有效码率 $R=K/E_r$ 只由该次的 $E_r$ 决定，四次可以完全相同；依次降低的是合并后的 $R_n$。 |
| RV 的顺序固定为 0、1、2、3 | HARQ 重传的 RV 由调度下行控制信息逐次指示，LTE 常用 $[0,2,1,3]$、NR 常用 $[0,2,3,1]$；只有 PDSCH 的多次传输时机按 TS 38.214 Table 5.1.2.1-2 固定为 $0,2,3,1$ 循环。 |
| 新 RV 的区间一定与已发区间不重叠 | 只要 $E_r$ 与起点间距不匹配就会重叠：本笔记数值例中第二至四次传输的新增比特分别为 1408、0、0。 |
| 没有收到的地址按比特 0 处理 | 未覆盖地址的取值未知，$\Lambda$ 置零并保留未知标记；按比特 0 处理等于向译码器注入虚假证据。 |
| IR 只适用于 LTE 的 Turbo 码 | NR 的 LDPC 码用同一机制：$k_0$ 由 TS 38.212 Table 5.4.2.1-2 按 $rv_{id}$ 与基图给出，$N_{\mathrm{cb}}$ 由 LBRM 截断。 |
| 四次传输后的等效码率是 $K/(4E_r)$ | 该式把重复覆盖也算作新增比特；等效码率按互异覆盖比特数计，本笔记数值例为 $K/N_{\mathrm{cb}}=2/3$，而 $K/(4E_r)$ 仅 0.1875，没有物理意义。 |

这些误解多半来自把单次码率、合并码率与观测次数三个量混为一谈，下面按边界情形逐项分界。

## 边界情形

第一处边界是缓存上界小于母码长度时的起点缩放。起点按 $N_{\mathrm{cb}}$ 而非 $N$ 计算，本笔记数值例中若误按 $N=25344$ 算 RV=2，会得到 12672，恰好等于缓存上界，第一个比特落回地址 0，接收端的写回地址随之整体错位，表现为该码块的循环冗余校验持续失败。这一错误不会引起解调失败，输出比特数也仍然正确，只能靠两端对同一组参数重算来发现。

第二处边界是 $E_r>N_{\mathrm{cb}}$。此时单次传输内部就发生回绕，第一次传输的 $M_n$ 就直接等于 $N_{\mathrm{cb}}$，单次有效码率已等于 $K/N_{\mathrm{cb}}$；此后换任何 RV 都只是在已覆盖地址上增加观测次数，$R_n$ 不再变化。相邻两次传输的区间重叠也属同类情形，只是重叠发生在传输之间而非单次传输内部，判据同样是 $M_n$ 是否还能增长。

第三处边界是 $E_r=0$。码块组指示（Code Block Group Indicator, CBG）未调度某个码块时，该码块本次不读取任何地址，也不产生 LLR，$M_n$ 与 $R_n$ 都保持不变，该码块只能依赖此前传输留在软缓存中的值（TS 38.212 §5.4.2.1、TS 38.214 §5.1.7）。此时本次传输既不写入新证据，也不写入零值，覆盖集合与合并码率都保持上一次的状态。

第四处边界是缓存中存在 filler 或 NULL 位置。NULL 位置只推进扫描地址、不产生输出比特，因此覆盖集合要按地址计而不是按比特序号计，$E_r$ 与 $N_{\mathrm{cb}}$ 相等也不等于整轮覆盖；判覆盖是否完整只能比较 $M_n$ 与 $N_{\mathrm{cb}}$。

第五处边界是新数据指示（New Data Indicator, NDI）翻转。NDI 翻转表示新的传输块，接收端清空该进程的软缓存，等价于把 $M_n$ 重置为 0，此时即使 RV 与上一次相同也不能合并；NDI 不翻转而同 RV 的重传只在同一批地址上累加 $\Lambda$。RV 相同本身不构成合并依据，是否合并由进程号与 NDI 共同决定（[[HARQ_Process_HARQ进程管理]]）。

## 关键要点

1. IR 每次重传按不同 $rv_{id}$ 从循环缓存取另一段，接收端按地址把新 LLR 与旧值相加；发送相同比特的是 Chase 合并。
2. 起点 $k_0$ 由冗余版本与基图决定（NR 的查表还用到 $N_{\mathrm{cb}}$ 与 $Z_c$），与 $E_r$ 无关；$E_r$ 只决定从该起点读多远。
3. 合并后的等效码率是 $R_n=K/M_n$，分母是互异覆盖地址数；单次传输的有效码率是 $R=K/E_r$，分母是本次发送比特数，两者不同。
4. $Z_c=384$、基图 1、$N_{\mathrm{cb}}=12672$ 时，四个起点为 0、3072、6144、10752，即 $0$、$8Z_c$、$16Z_c$、$28Z_c$。
5. 同一组参数下 $E_r=11264$ 的四次传输覆盖区间为 $[0,11264)$、$[3072,12672)$ 与 $[0,1664)$、$[6144,12672)$ 与 $[0,4736)$、$[10752,12672)$ 与 $[0,9344)$，新增互异比特依次为 11264、1408、0、0。
6. 合并后的等效码率依次为 0.75、$2/3$、$2/3$、$2/3$；LBRM 生效时编码增益的码率下限是 $K/N_{\mathrm{cb}}=2/3$，关闭 LBRM 时降到母码码率 $1/3$。
7. 起点按 $N_{\mathrm{cb}}$ 缩放，误按母码长度 $N$ 计算会让写回地址整体错位；$E_r>N_{\mathrm{cb}}$ 时首次传输就覆盖满缓存，后续换 RV 只增加能量。
8. $M_n$ 达到 $N_{\mathrm{cb}}$ 后继续合并不会降低 $R_n$，只增加每个地址的观测次数；因此"合并一定提升码率"与"RV 越大越可靠"都不成立。
9. RV 序列是工程惯例，HARQ 重传按调度指示逐次确定；协议只在 PDSCH 的多次传输时机上固定 $0,2,3,1$ 循环（TS 38.214 Table 5.1.2.1-2）。
