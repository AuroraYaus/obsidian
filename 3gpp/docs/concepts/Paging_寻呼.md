# Paging 寻呼

寻呼是网络在 UE 空闲态（RRC_IDLE）或非激活态（RRC_INACTIVE）主动"找到"UE 的广播机制：网络在预先约定的寻呼时机（PO，Paging Occasion）发送以 P-RNTI（寻呼无线网络临时标识，Paging Radio Network Temporary Identifier）加扰 CRC 的 DCI 与寻呼消息，被点名的 UE 醒来接入网络。寻呼没有 HARQ（混合自动重传请求，Hybrid Automatic Repeat Request）确认——"重传"指同一寻呼消息的重复发送，而非纠错重传。一句话本质：**寻呼是"广播找人"——没有"收到请回答"，重要的事多喊几遍**。

## 独立解释任务

任务目标：解释寻呼时机（PO/PF）的计算、寻呼消息的收发流程、"寻呼无 HARQ、靠重复发送提高到达率"的关键语义，以及 PEI 节能预告，并与 PDCCH 盲检、随机接入衔接。

## 起源与演进

寻呼回答的问题是：空闲态的 UE 不持续监听数据信道，网络怎么找到它？答案是一套双方预先约定的广播机制——UE 按 DRX 周期在自己的寻呼帧（PF）内的寻呼时机（PO）醒来监听 PDCCH，PO 由 UE 标识（5G-S-TMSI）哈希分散，不同 UE 的监听时点错开。寻呼的 DCI 用 P-RNTI 加扰 CRC 标识"这是寻呼"，随后的 PDSCH 携带被寻呼 UE 的标识列表。最容易被误解的语义是"重传"：寻呼是广播式（一对多）发送，没有针对单个 UE 的 ACK/NACK 反馈，因此不存在 HARQ 重传——提高到达率的手段是同一消息在多个 PO 重复发送（覆盖增强）。演进方向是省电：Rel-17 的寻呼早期指示（PEI，38.213 §10.4A）在 PO 之前先发预告比特，UE 不必每个 PO 都完整醒来。被寻呼的 UE 通过随机接入回到连接态——这是寻呼与 T16.6 的衔接点。

## 科学定义

UE 按 DRX（非连续接收，Discontinuous Reception）周期在寻呼帧（PF，Paging Frame）内的某个 PO 监听 PDCCH：若 DCI 的 CRC 用 P-RNTI 解扰成功，UE 继续接收对应的 PDSCH 寻呼消息，其中包含被寻呼 UE 的标识列表。PO 由 UE 标识（5G-S-TMSI）哈希到资源，使同一网络下不同 UE 的监听时点分散。寻呼消息（PCCH 逻辑信道）经 PDSCH 广播发送，不针对单个 UE 反馈 ACK/NACK。

## 直观模型

寻呼像校园广播找人：喇叭按课间铃声（PO）定时响起，喊出名字（UE 标识）；被喊到的人去门卫（随机接入）报到，没被喊到的人继续做自己的事。广播没有"收到请回答"环节——重要的事会多喊几遍（重复发送）。

## 常见误解

| 误解 | 正确理解 |
|:---|:---|
| 寻呼支持 HARQ 重传 | 寻呼是广播式发送，无 ACK/NACK 反馈；"重传"指同一消息在多个 PO 重复发送，属覆盖增强手段 |
| 寻呼只在空闲态使用 | RRC_INACTIVE 态的 UE 同样监听寻呼 |
| PO 对所有 UE 相同 | PO 按 UE 标识哈希分散，不同 UE 的监听时点不同 |
| PEI 是寻呼消息本身 | PEI（寻呼早期指示，Paging Early Indication）是 PO 之前的"预告"比特，用于减少误唤醒、进一步省电 |

## 关键要点

1. 寻呼 = 网络在空闲/非激活态"喊醒"UE 的广播机制，触发随机接入回到连接态。
2. PO/PF 由 DRX 周期与 UE 标识哈希决定，不同 UE 监听时点分散。
3. P-RNTI 加扰的 DCI 是寻呼"信号旗"，PDSCH 里是被寻呼 UE 标识列表。
4. 无 HARQ 反馈："重传"= 同一消息在多个 PO 重复发送，属覆盖增强手段。
5. PEI（寻呼早期指示）是 PO 之前的预告，减少误唤醒、进一步省电。
6. RRC_INACTIVE 态的 UE 同样监听寻呼。
