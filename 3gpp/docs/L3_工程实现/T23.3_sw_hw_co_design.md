# T23.3 软硬件协同：固件调度、加速器接口与接收链任务编排

## 本节学习目标

T23.1/T23.2 讲了后端的时序与功耗——本节收官：**软硬件协同**——接收链/译码器在"固件（软件）调度 + 硬件加速器"的架构下如何工作。软硬件划分的核心：**控制面软、数据面硬**——调度/配置/中断由固件（CPU 上的软件）负责，重计算（译码/均衡/软解调）由硬件加速器负责，两者经寄存器/DMA（直接存储器访问，Direct Memory Access）/中断接口协作。

接收链的任务编排是软硬件协同的典型：每包数据经"同步 → 估计 → 均衡 → 软解调 → 译码"五级流水（T22 系列）——固件按调度表启动各级、硬件流水执行、中断回报完成。**流水线利用率取决于负载均衡**（numpy 验证：不均衡 42% → 均衡拆分 69%）。功耗管理（T23.2 的模式选择）也由固件按负载决策——**软硬件协同是系统的"总指挥"**。

学完本节后，应能做到：

- 说出软硬件划分原则（控制面软、数据面硬）与固件/加速器的职责分工。
- 说出硬件加速器接口（寄存器/DMA/中断）与接收链任务调度的流程。
- 完成接收链流水线调度仿真（不均衡 vs 均衡的利用率对比，numpy 验证）。
- 把 T23 系列（时序/功耗/协同）整合为后端实现的完整画像。

## 软硬件划分

### 划分原则

| 面 | 归属 | 职责 | 理由 |
|:---|:---|:---|:---|
| 控制面 | 固件（CPU） | 调度/配置/中断/错误处理 | 灵活（可改）、低频（开销小） |
| 数据面 | 硬件加速器 | 译码/均衡/软解调/估计 | 高性能（并行）、固定（不可改） |

**划分的语义**：控制面是"决策"（怎么做、何时做）、数据面是"执行"（重计算）——**决策要灵活（软件）、执行要快（硬件）**。边界按频率与灵活性定：高频重计算进硬件、低频策略进软件。

### 接收链的划分

| 子系统 | 归属 | 说明 |
|:---|:---|:---|
| 同步/估计 | 硬件（加速器）+ 固件（环路参数） | 重计算硬件、配置软件 |
| 均衡 | 硬件 | 矩阵运算（T22.2） |
| 软解调 | 硬件 | LLR 并行（T22.3） |
| 译码 | 硬件（T17-T20） | 迭代译码 |
| 调度/功耗 | 固件 | 任务编排 + 模式选择（T23.2） |

## 加速器接口与任务调度

### 接口三件套

| 接口 | 机制 | 用途 |
|:---|:---|:---|
| 寄存器 | 配置（T19.6 的寄存器映射） | 参数下发（资源/MCS/模式） |
| DMA（直接存储器访问，Direct Memory Access） | 数据搬运 | 输入输出（LLR/符号） |
| 中断 | 完成/错误回报 | 固件感知任务完成 |

**接口语义**：固件写寄存器配置任务 → DMA 搬数据 → 硬件执行 → 中断回报——**一个任务的完整生命周期**（T19.6 的配置流程 + DMA + 中断的闭环）。

### 接收链任务调度

```mermaid
flowchart LR
    A["固件：调度表"] --> B["启动同步/估计"]
    B --> C["启动均衡"]
    C --> D["启动软解调"]
    D --> E["启动译码"]
    E -->|"中断"| F["固件：回报/下一任务"]
```

**调度语义**：五级流水（T22 系列）按调度表逐级启动——每级完成发中断、固件启动下一级（或硬件流水线自动推进）。**流水线利用率取决于负载均衡**（各级处理时间接近则利用率高）。

### numpy 验证的数值走读

numpy 验证实现接收链流水线调度：5 级（sync 20/est 30/eq 25/demap 15/decode 80 us）、100 任务——不均衡流水线（decode 是其他级 2-5 倍）：加速 2.1x、利用率 42%（短级大量空闲）；均衡拆分（decode 80 → 40+40 两级）：加速 4.1x、利用率 69%。**"瓶颈级决定吞吐、负载均衡决定利用率"**——软硬件协同的调度优化方向：均衡各级负载（拆瓶颈/合并短级）。

## 软硬件协同调试

### 调试方法（T20 衔接）

| 方法 | 机制 | 适用 |
|:---|:---|:---|
| 寄存器转储 | 读配置/状态 | 配置错误 |
| 数据抓取 | DMA 数据采样 | 数据流错误 |
| 软硬对照 | 固件模型 vs 硬件结果 | 一致性验证（T20.6 的 bit-exact 衔接） |

**调试语义**：软硬件边界（接口）是错误高发区——寄存器位宽不一致、DMA 地址错、中断丢失——**协同调试先验接口、再验数据**。

### 与功耗管理的联动（T23.2）

固件按负载选功耗模式（高性能/均衡/低功耗）——**调度信息即功耗决策输入**：任务多 → 高性能模式；任务少 → 低功耗模式。软硬件协同把 T23.2 的模式选择落地（负载监测在固件、DVFS 配置经寄存器）。

### 生活类比：餐厅后厨

软硬件协同像餐厅后厨：厨师长（固件）排单（调度）、切配（DMA 备料）、炒锅（硬件加速器）猛火快炒（重计算）、出菜响铃（中断）。**切配慢（负载不均衡）则炒锅闲置**（利用率低）——厨师长按菜品调整分工（负载均衡）；客人少时关几个灶（功耗模式）。

## 示范例题

### 例题 1：划分决策

信道估计的环路参数调整（慢）与矩阵运算（快）：各归哪面？

**求解**：环路参数调整 → 固件（低频策略）；矩阵运算 → 硬件（高频重计算）。

### 例题 2：任务生命周期

一个译码任务的完整生命周期（固件视角）？

**求解**：写寄存器（配置）→ DMA 搬 LLR → 硬件译码 → 中断回报 → 固件读结果/下一任务。

### 例题 3：利用率

decode 80 us 是其他级的 3 倍：负载均衡怎么做？

**求解**：decode 拆两级（40+40）——节拍从 80 降到 40、利用率提升（numpy：42% → 69%）。

## 引导练习（带提示）

### 练习 1：划分原则

"控制面软、数据面硬"的理由？

**提示**：灵活 vs 性能。（答案：控制低频需灵活（软件可改）；数据高频需性能（硬件并行）。）

### 练习 2：接口作用

DMA 与中断在任务生命周期中的角色？

**提示**：搬运与回报。（答案：DMA 搬输入输出、中断回报完成——固件的"手"与"眼"。）

### 练习 3：均衡方向

流水线利用率低的两个优化方向？

**提示**：瓶颈与短级。（答案：拆瓶颈级（decode 80→40+40）、合并短级（demap 15 并入相邻）——均衡各级时间。）

## 常见误解

| 误解 | 正确理解 |
|:---|:---|
| 硬件越多越好 | 硬件固化（不可改）——控制面需软件灵活性 |
| 接口只是细节 | 接口（寄存器/DMA/中断）是错误高发区——协同调试先验接口 |
| 流水线自动高效 | 利用率依赖负载均衡——不均衡则短级闲置（numpy 42%） |
| 功耗管理与协同无关 | 固件按负载选模式——调度信息即功耗决策输入 |

## 常见错误

| 错误 | 正确理解 |
|:---|:---|
| 把所有逻辑进硬件 | 高频重计算进硬件、低频策略进软件——按频率/灵活性划分 |
| 忽略中断丢失 | 中断是回报通道——丢失则任务悬挂（需超时/轮询兜底） |
| 只优化瓶颈不考虑均衡 | 瓶颈决定吞吐、均衡决定利用率——两者都要 |
| 无负载感知的功耗 | 模式选择需负载信息（固件调度提供） |

## 内嵌 numpy 验证

下列断言先实跑通过再写入本节，输出与断言一致（流水线调度不均衡 vs 均衡）：

```python
import numpy as np

N_TASK = 100

# 阶段 1：不均衡流水线（decode 80us 是其他级 2-5 倍）
stage_time = {'sync': 20, 'est': 30, 'eq': 25, 'demap': 15, 'decode': 80}
t_serial = sum(stage_time.values()) * N_TASK
t_pipe1 = sum(stage_time.values()) + (N_TASK - 1) * max(stage_time.values())
util1 = sum(stage_time.values()) * N_TASK / (t_pipe1 * len(stage_time))
speedup1 = t_serial / t_pipe1
assert util1 < 0.5                 # 不均衡：利用率低
assert max(stage_time.values()) == stage_time['decode']

# 阶段 2：负载均衡（decode 拆 2 级 40+40）——节拍降、利用率升
stage2 = {'sync': 20, 'est': 30, 'eq': 25, 'demap': 15, 'dec1': 40, 'dec2': 40}
t_pipe2 = sum(stage2.values()) + (N_TASK - 1) * max(stage2.values())
util2 = sum(stage2.values()) * N_TASK / (t_pipe2 * len(stage2))
speedup2 = t_serial / t_pipe2
assert util2 > util1                 # 均衡后利用率提升
assert speedup2 > speedup1           # 加速比提升

print(f"T23.3_OK unbalanced: speedup={speedup1:.1f}x util={util1*100:.0f}% "
      f"-> balanced: speedup={speedup2:.1f}x util={util2*100:.0f}% "
      f"(decode split 80->40+40)")
```

输出：

```text
T23.3_OK unbalanced: speedup=2.1x util=42% -> balanced: speedup=4.1x util=69% (decode split 80->40+40)
```

## 小结

软硬件协同按"控制面软、数据面硬"划分：固件调度任务/选功耗模式、硬件执行重计算、接口（寄存器/DMA/中断）协作。接收链五级流水（T22 系列）的利用率依赖负载均衡（numpy：不均衡 42% → 均衡拆分 69%）；协同调试先验接口再验数据（T20 衔接）。
