# T18.4 NR Polar 定点模型计划：CA-SCL 的整数路径度量与状态规格
## 本节学习目标

本节规划NRPolar的 C/C++ 定点译码器模型。这里的重点不是重新发明 Polar（极化码，Polar Code）编码规则，而是把 [[T10.4_Polar_SC_decoding|T10.4]]、[[T10.5_Polar_SCL_decoding|T10.5]]、[[T10.6_CRC_aided_SCL_control_reliability|T10.6]] 和 [[T17.4_NR_Polar_float_sim_plan|T17.4]] 已经讲过的逐次消除（Successive Cancellation, SC）、逐次消除列表（Successive Cancellation List, SCL）和循环冗余校验辅助 SCL（CRC-aided Successive Cancellation List, CA-SCL）变成可审计的整数模型。模型必须说明对数似然比的输入位宽、$f/g$ 函数的定点近似、部分和（partial sum）的 1 bit 存储、路径度量（Path Metric, PM）的位宽和饱和、列表剪枝后的 path state remap，以及 CRC（循环冗余校验，Cyclic Redundancy Check）/无线网络临时标识（Radio Network Temporary Identifier, RNTI）选择器如何防止无效控制信息输出。


- 为 NR Polar rate recovery 后的 LLR（对数似然比，Log-Likelihood Ratio）、$f/g$ 中间 LLR、PM、partial sum、candidate path 和 CRC/RNTI pass mask 分配位宽、缩放、饱和和 trace 字段。
- 说明3GPP TS 38.212 规定 Polar construction、CRC、rate matching、上行控制信息和下行控制信息链路，但不规定接收机内部的 list size、PM 公式、sorter 或定点位宽。
- 写出定点 $f/g$ 函数、PM 增量、PM 归一化/饱和、`2L -> L` sorter、path id remap 和 CA-SCL final selector 的执行路径。
- 设计 C/C++ descriptor、config、buffer、trace 和 bit-exact（比特精确，bit-exact） checkpoint，让 Python fixed reference、C/C++ fixed model 和后续寄存器传输级/专用集成电路scoreboard 对齐。
- 解释为什么 PM 最小路径不能绕过 CRC/RNTI，为什么 PM 饱和后必须有稳定 tie-break，为什么剪枝时必须同步复制 LLR state、partial sum、PM 和 CRC state。

如果只记住一句话：NR Polar 定点模型的核心不是把浮点 LLR 改成整数，而是把“树节点 LLR、partial sum、path state、PM、sort/prune、CRC/RNTI final selector”绑成同一条 bit-exact 证据链。

## Polar 定点模型的理论底座

Polar code 的名称来自 channel polarization，也就是“信道极化”。Arikan 在 2009 年提出这种构造时，核心思想不是给每个比特位置同等保护，而是通过递归变换把一组普通信道变成一批更可靠的位置和一批更不可靠的位置。发送端把信息放在可靠位置，把不可靠位置冻结成已知 0；接收端再按同一套可靠性顺序恢复信息位。这解释了为什么 NR Polar 讲义总是同时出现 information bit、frozen bit、reliability sequence 和 rate matching：它们共同决定“哪些位置值得相信、哪些位置必须当作已知约束”。

从零基础角度看，SC 是一条路径的顺序判决：译码器先看第 0 个叶子，再看第 1 个叶子，每一步都把前面已经判出的 bit 当作后续计算条件。SCL 是把“某一步拿不准”的情况保留下来：遇到 information bit 时，路径可以分成取 0 和取 1 两个候选；列表大小 $L$ 限制最多保留多少条候选。CA-SCL 又在最后加上 CRC/RNTI 过滤：软信息看起来最像的路径，如果 CRC 或 RNTI 不通过，也不能当成有效控制信息输出。

定点化要解决的问题是：软件浮点模型里的 LLR、PM、排序比较和 CRC 状态，在 C/C++、RTL 和 ASIC 中不能无限精度保存。每个数都要落到有限位宽里，超出范围就会裁剪或饱和。工程后果很直接：如果 $f/g$ 节点 LLR 饱和太早，路径排序会变；如果 PM 位宽太窄，不同候选会被压成相同 PM；如果剪枝后 path state remap 不完整，后续 partial sum 或 CRC state 会贴到错误路径上。T18.4 因此把算法讲义中的“会算”推进到工程讲义中的“可复现、可定位、可 bit-exact 对比”。

Polar SC/SCL 译码可以看成一棵二叉树上的软信息传播。输入是 rate recovery 后长度为 $N$ 的 LLR 向量；树内部反复用 $f$ 函数把左右子节点 LLR 合成左侧估计，用 $g$ 函数在已知左侧 partial sum 后估计右侧；到叶子时，frozen bit 强制为 0，information bit 在 SCL 中分裂为 0/1 两条候选路径。

定点模型有六个核心对象：

| 对象 | 定义 | 定点风险 |
|:---|:---|:---|
| rate-recovered LLR | codeword-order 的输入软信息。 | punctured/shortened/repetition 语义错会污染整个树。 |
| $f/g$ LLR | 树节点中间软信息。 | min-sum 近似、符号、饱和和 guard bit 错会改变路径排序。 |
| partial sum | 子树硬编码后的 1 bit GF(2) 状态。 | 与叶子 bit 数组混用会让右子树 $g$ 输入错误。 |
| path state | 每条候选路径的 LLR state、partial sum、bits、PM、CRC state。 | prune 后只复制 bits 会导致路径内容与 PM/CRC 脱节。 |
| PM | 候选路径与 LLR 证据不一致的累计惩罚。 | 位宽不足或饱和后无稳定 tie-break 会导致 replay 不复现。 |
| CRC/RNTI pass mask | final selector 的合法候选集合。 | PM 最小但 CRC/RNTI fail 的路径被误输出。 |

小型数值例子：某个 information bit 的 LLR 为 $+5$。按照本项目约定，正 LLR 表示 bit=0 更可信。候选 bit 取 0 时，PM 增量应很小；候选 bit 取 1 时，PM 增量接近 5。若当前路径旧 PM 为 1019，PM 位宽只允许最大 1023，则取 1 的候选会饱和到 1023；如果另一条候选原本也是 1023，两个候选在排序器看来并列。这时 sorter 如果没有稳定 tie-break，同一个输入向量在 Python、C/C++ 和 RTL 中可能选择不同 path id。

手算例子：设左、右子节点 LLR 分别为 $a=+3$、$b=-2$。min-sum 近似的 $f$ 函数输出

$$
f_{\mathrm{MS}}(+3,-2)=\operatorname{sign}(+3)\operatorname{sign}(-2)\min(3,2)=-2.
$$

这个结果回答的问题是“左侧组合 bit 更像 0 还是 1”。负值表示更像 1。若已经判出的左侧 partial sum 为 $\beta=1$，右侧 $g$ 函数输出

$$
g(+3,-2,1)=-2-(+3)=-5.
$$

这个推导说明符号、partial sum 和加减法位宽为什么必须一起验证：只要 $\beta$ 贴错路径，右侧 LLR 就可能从 $b-a$ 变成 $b+a$，后续所有 PM 和 CRC 候选都会偏离。定点模型的每个 trace 字段，本质上都是为了把这种偏离定位到具体 bit、stage、path 和算子。

常见误解是把 PM 当成“错误概率本身”。更准确的定义是：PM 是路径与当前 LLR 证据不一致程度的累积度量，符号约定、缩放和近似都会影响它的数值范围。另一个误解是把 partial sum 当成 payload bit 缓存；它的来源是 Polar 递归变换后的中间硬判决状态，接收端 $g$ 函数用它决定加还是减。工程后果是，PM、partial sum、CRC state 和 path id 必须作为同一个 path state 一起复制、重映射和验证，不能只检查最后 payload 是否一致。

## LLR、f 函数与 g 函数定点化

SC/SCL 的输入 LLR 已经由 rate recovery 放回 codeword order。输入量化为：

$$
L^{(q)}_i=\operatorname{sat}_{W,F}\left(\operatorname{round}(sL_i)\right),
\tag{1}
$$

其中 $W$ 是总位宽，$F$ 是小数位，$s=2^F$。punctured 位置应量化为 0；shortened 位置应量化为强正值；repeated 位置先合并再饱和。

精确 SC 的 $f$ 函数可写为：

$$
f(a,b)=2\tanh^{-1}\left(\tanh\frac{a}{2}\tanh\frac{b}{2}\right).
\tag{2}
$$

定点 CA-SCL 常用 min-sum 近似：

$$
f_{\mathrm{MS}}(a,b)=\operatorname{sign}(a)\operatorname{sign}(b)\min(|a|,|b|).
\tag{3}
$$

$g$ 函数为：

$$
g(a,b,\beta)=b+(1-2\beta)a,\qquad \beta\in\{0,1\}.
\tag{4}
$$

式 (4) 是 partial sum 的高风险点。若 $\beta=0$，$g=b+a$；若 $\beta=1$，$g=b-a$。定点实现必须先把 $a$ 扩展到内部宽度，再执行加减和饱和，不能在窄位宽下先溢出。

建议字段：

| 字段 | 说明 |
|:---|:---|
| `polar.fg_llr_width/frac/min/max` | $f/g$ 节点内部 LLR 格式。 |
| `polar.f_func_policy` | `exact_lut`、`min_sum` 或 `scaled_min_sum`。 |
| `polar.g_guard_bits` | $b\pm a$ 的内部保护位。 |
| `polar.llr_init_policy` | punctured/shortened/repeated 的整数初始化规则。 |
| `polar.fg_sat_count` | $f/g$ 节点饱和次数。 |

## Partial Sum 与 Path State

partial sum 不是“已经判出的 bit 原样缓存”。它是子树硬编码后回传给父节点或兄弟节点的 1 bit GF(2) 状态。对一个二比特节点，若叶子判决为 $\hat{u}_0,\hat{u}_1$，回传 partial sum 可写为：

$$
\beta_0=\hat{u}_0\oplus\hat{u}_1,\qquad \beta_1=\hat{u}_1.
\tag{5}
$$

其中 $\oplus$ 是 GF(2) 异或。SCL 中每条路径都有自己的 partial sum state。剪枝时如果只复制 `path_bits`，但没有复制或重映射 `partial_sum`，后续 $g$ 函数会读到别的路径的 $\beta$，表现为 PM trace 从某个 stage 开始整体偏离。

两种实现策略都可以接受，但必须写入配置：

| 策略 | 含义 | 风险 |
|:---|:---|:---|
| `deep_copy` | prune 后复制 survivor 的 LLR state、partial sum、PM、CRC state。 | 简单但带宽大。 |
| `lazy_copy` | 使用 parent pointer、reference count 或 copy-on-write。 | 地址和生命周期复杂，path id remap 必须可 trace。 |

bit-exact trace 至少保存 `old_path_id`、`new_path_id`、`parent_path_id`、`partial_sum_addr`、`partial_sum_value` 和 `copy_policy`。

## 路径度量、饱和与排序剪枝

本项目沿用 [[T10.5_Polar_SCL_decoding|T10.5]]/[[T10.6_CRC_aided_SCL_control_reliability|T10.6]] 的约定：PM 越小越好。精确 LLR 域 PM 增量可写为：

$$
\Delta PM(b,L)=\ln\left(1+\exp\left(-(1-2b)L\right)\right).
\tag{6}
$$

硬件友好近似为：

$$
\Delta PM_{\mathrm{approx}}(b,L)=
\begin{cases}
0, & b=\mathbf{1}[L<0],\\
|L|, & b\ne\mathbf{1}[L<0].
\end{cases}
\tag{7}
$$

PM 更新为：

$$
PM_{\mathrm{new}}=
\operatorname{sat}\left(
PM_{\mathrm{old}}+\Delta PM
\right).
\tag{8}
$$

如果 PM 接近上限，多个候选可能饱和成同一个值。此时 sorter 必须使用稳定 tie-break，例如：

$$
\mathrm{key}(p)=\left(PM(p),\ path\_id(p)\right),
\tag{9}
$$

先比较 PM，再比较 path id。这样 Python fixed、C/C++ fixed 和 RTL 即使出现 PM 并列，也会保留同一组 survivor。

`2L -> L` sorter 的 trace 至少包括：

| 字段 | 含义 |
|:---|:---|
| `candidate_path_id` | 分裂后候选 path id。 |
| `parent_path_id` | 分裂前父路径。 |
| `candidate_bit` | 当前 information bit 取值。 |
| `pm_before/pm_increment/pm_after` | PM 更新三元组。 |
| `pm_sat` | 是否发生 PM 饱和。 |
| `sort_key` | PM 和 tie-break 字段。 |
| `survivor_rank` | 剪枝后排名；被剪路径写 `dropped`。 |
| `path_remap` | old path id 到 new path id。 |

## CRC/RNTI 辅助选择

CA-SCL 的 final selector 不是选择全体候选中的最小 PM，而是先构造通过集合：

$$
\mathcal{P}_{\mathrm{pass}}=
\{p\mid \mathrm{CRC}(p)=0\ \text{and}\ \mathrm{RNTI}(p)=\mathrm{match}\}.
\tag{10}
$$

若通过集合非空：

$$
p^\star=\arg\min_{p\in\mathcal{P}_{\mathrm{pass}}}PM(p).
\tag{11}
$$

若通过集合为空，输出 `decode_fail`，可保留 PM 最小路径用于调试，但不能提交为有效 UCI/DCI。C/C++ trace 必须保存 `crc_pass_vec`、`rnti_match_vec`、`selected_path_id`、`selected_pm`、`valid` 和 `fail_reason`。

## RTL/ASIC 映射

T18.4 的定点模型会直接变成 [[T19.3_NR_Polar_RTL_microarchitecture|T19.3]] NR Polar RTL 微架构的前置规格。

| C/C++ 对象 | RTL/ASIC 对象 | 风险 |
|:---|:---|:---|
| `input_llr/node_llr` | LLR RAM、tree traversal datapath。 | $f/g$ 饱和、符号扩展、stage 地址错。 |
| `partial_sum` | partial sum memory 或 beta network。 | path remap 后读到错误 beta。 |
| `path_metric` | PM accumulator、normalizer、saturating adder。 | PM 饱和和 tie-break 不稳定。 |
| `path_parent/path_remap` | path copy network、lazy-copy table。 | survivor bits、LLR state、CRC state 不一致。 |
| `sort_order` | `2L -> L` sorter 或 partial sorter。 | 比较宽度不足，PM 并列无稳定顺序。 |
| `crc_state/pass_mask` | 多路径 CRC/RNTI checker。 | CRC 结果贴错 path id。 |
| `selected_path` | final selector 和 output valid。 | fail 路径被误提交。 |

RTL 可以选择流水、并行 path、lazy copy 或 partial sorter；但只要它声明兼容某个 `fixed_requirement_id`，就必须在 [[T18.6_bit_exact_regression_harness|T18.6]]/T15 中通过同一组 bit-exact 检查点。

## 常见错误

| 错误 | 后果 | 修正 |
|:---|:---|:---|
| $g$ 函数 partial bit 取反 | 右子树 LLR 整体符号错。 | 固定 $a,b,\beta$ 的 directed test。 |
| partial sum 与 leaf bits 共用错误地址 | N=4 可能通过，深树错位。 | 独立 dump `partial_sum_addr/value`。 |
| prune 后只复制 bits | PM、CRC 或 LLR state 贴到错误路径。 | trace `path_remap` 和 `parent_path_id`。 |
| PM 饱和无稳定 tie-break | replay 不复现，RTL/C 选择不同 survivor。 | 固定 `stable_pm_then_path_id`。 |
| CRC/RNTI fail 路径参与 final compare | 无效 DCI/UCI 被输出。 | selector 先用 pass mask 过滤。 |
| 把 reliability sequence 当实现参数 | 不同实现 mask 不一致。 | 记录 TS 38.212 table hash 和 info/frozen hash。 |
| punctured/shortened LLR 混用 | 特定 $E/N$ case 高信噪比失败。 | 对照 [[T10.7_NR_Polar_rate_recovery|T10.7]] 的 LLR 初始化规则。 |

## 自测题

1. 为什么 TS 38.212 可以规定 information/frozen mask 来源，却不规定 `path_metric_width=12`？
2. $g(a,b,\beta)$ 中 $\beta=1$ 时为什么是 $b-a$？
3. SCL prune 时为什么不能只复制 path bits？
4. PM 饱和后为什么还需要稳定 tie-break？
5. CA-SCL 为什么不能输出 PM 最小但 CRC/RNTI fail 的路径？
6. T18.4 最少应保存哪七类 bit-exact checkpoint？

## 自测题参考答案

1. TS 38.212 规定 Polar construction、CRC、rate matching 和控制信息链路；接收机内部 PM 位宽是实现选择，只要能按协议恢复、译码和校验。
2. $g(a,b,\beta)=b+(1-2\beta)a$。当 $\beta=1$ 时，$1-2\beta=-1$，所以是 $b-a$；这来自右子树在已知左侧 partial sum 后的条件 LLR。
3. 因为每条 path 还绑定 LLR state、partial sum、PM、CRC state 和 RNTI state。只复制 bits 会让后续 $g$、PM 或 CRC checker 使用错误路径状态。
4. PM 饱和后多个候选可能数值相等。若 tie-break 不固定，Python/C/RTL 会保留不同 survivor，导致 replay 不复现。
5. CRC/RNTI fail 说明候选不满足控制信息检错或归属边界。PM 只是软信息一致性度量，不能覆盖协议有效性检查。
6. rate recovery LLR、$f/g$ LLR、partial sum、candidate PM、sort/prune order、CRC/RNTI pass mask、selected path。工程上还应保存 path remap、PM saturation counter 和 failure replay command。
