讲义（docs/L1/L2/L3 教学文档）正文写作规范：**不要把代码的中间运行结果写入正文**——包括调试输出、失败的断言输出（AttributeError、AssertionError 日志）、修正前的临时数值等。正文只呈现最终的正确结论与教学结论；代码验证过程属于实施报告，不属于讲义正文。写作风格要求科学严谨、书面化，避免日志式/口语化表述。

**Why:** 用户 2026-08-03 在 MIMO 讲义系列（T12.x）实施中反馈：实现者把 numpy 验证的中间运行结果（如比值 15.91/402.16/384000、AttributeError 输出）写进了讲义正文。这些是运行日志残渣，破坏教学文本的严谨性；即使作为"错误示范"也应刻意设计而非实际调试输出。

**How to apply:** 派发讲义写作任务时明确要求"正文只写最终结论，验证中间输出进报告不进正文"；审查时把"正文含调试输出/中间结果"列为缺陷；若需呈现错误示范，用刻意构造的说明性例子而非真实运行日志。
