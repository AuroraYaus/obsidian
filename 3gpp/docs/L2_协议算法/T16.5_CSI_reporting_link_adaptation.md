# T16.5 NR CSI 报告链路

## 本节学习目标

M16 系列讲调度。[[T16.1_scheduler_HARQ_process|T16.1]] 里，调度器（MAC（媒体接入控制，Medium Access Control）层的资源裁判）做"资源 + MCS（调制与编码方案，Modulation and Coding Scheme）+ 进程"三元组决策时，有一条输入被一句话带过："从 SRS（探测参考信号，Sounding Reference Signal）/CSI 得到每 RB 的 SINR（信干噪比，Signal-to-Interference-plus-Noise Ratio）"。本节把这句话展开成一条完整的**CSI（信道状态信息，Channel State Information，见 [[CSI_SINR]]）报告链路**：CSI-RS（信道状态信息参考信号，Channel State Information Reference Signal）测量 → CQI（信道质量指示，Channel Quality Indicator）/PMI（预编码矩阵指示，Precoding Matrix Indicator）/RI（秩指示，Rank Indicator）计算 → 上报 → 调度器使用。链路自适应（Link Adaptation）的闭环就建立在这条链路上——信道好就传得快、信道差就传得稳，知识库已有口径见 [[Link_Adaptation_链路自适应与CQI]] 概念笔记。

协议的三个锚点构成这条链路的骨架：TS 38.214 §5.2 定义 CSI 报告的框架（报告设置、资源设置、触发激活、CQI 表与计算准则），TS 38.211 §7.4.1.5 定义被测量的 CSI-RS（[[CSI_RS_信道状态信息参考信号]]）的时频结构与序列，TS 38.331 定义 RRC（无线资源控制，Radio Resource Control）侧的配置信息元素（CSI-ResourceConfig、NZP-CSI-RS-Resource、CSI-ReportConfig）。三份协议各管一段：38.211 管"信号长什么样"，38.214 管"UE（用户设备，User Equipment）怎么算怎么报"，38.331 管"基站怎么配"。

本节从调度器的视角切入：调度器需要的不是 SINR 数值本身，而是"以这个信道能支持多快的传输"——CQI/PMI/RI 就是把信道质量翻译成调度参数的三级翻译官。理解这条链路，就理解了物理层与 MAC 层耦合最紧的闭环（T16.1 的调度决策、T9.0 的 MCS 表、T14.3 的 HARQ 反馈都在这个环上）。

学完本节后，应能做到：

- 说出 CSI 报告闭环的五个环节（配置 → 测量 → 折算 → 上报 → 使用），并为每个环节指出协议章节锚点。
- 说出 CQI/PMI/RI 三个报告量的含义、量化粒度（4-bit CQI 索引、码本枚举索引、1-8 层秩）与计算依赖链（TS 38.214 §5.2.1.4）。
- 复现 4-bit CQI 表（表 5.2.2.1-2）的关键行，完成 SINR → CQI → MCS 的手算并说明效率与码率的关系。
- 说出 CSI-RS 资源配置的三个关键参数（端口数、密度、NZP/ZP 类型）以及 38.331 的三层配置链（CSI-ResourceConfig → NZP-CSI-RS-ResourceSet → NZP-CSI-RS-Resource）。
- 区分三种上报方式（周期/半持续/非周期）的触发机制，并按表 5.2.1.4-1 判断一种"上报方式 × CSI-RS 配置"组合是否合法。
- 解释 CSI 参考资源（§5.2.2.5）的时频定义与"无有效下行时隙则丢弃报告"规则，说明它解决什么一致性问题。
- 说明 CSI 如何成为 T16.1 调度器的输入、outer loop（外环校准）如何用 ACK/NACK 修正 CQI 误差，以及与 T2.11、T12.5 的衔接。
- 区分协议强制（UE 必须按 §5.2 计算与上报）与接收机自由度（SINR 测量与折算模型属于 UE 实现）。

## CSI 报告闭环的引入缘由：调度器缺一块"信道质量仪表盘"

### 它解决的问题：速率选择必须知道信道

回到 T16.1 的调度决策函数：调度器在每个时隙决定给每个被调度的 UE 多少资源、什么 MCS。决策的输入有三类——缓冲队列长度 $q_u$、HARQ（混合自动重传请求，Hybrid Automatic Repeat Request）进程状态 $h_u$、信道质量 $c_u$。前两类在基站侧可见：队列在 MAC 层的数据缓存里，进程状态在 MAC 层的进程状态机里。唯独信道质量 $c_u$ 是基站"看不见"的：下行信道从基站天线出发，穿过无线环境到达 UE 接收机，基站自己没有下行接收机，无法直接测量自己发出的信号经历了什么。

这就是 CSI 报告链路存在的根本原因：**UE 是下行信道的唯一观测者，基站必须让 UE 把观测结果报上来**。如果没有这条反馈，调度器只能盲目地按最保守的 MCS 发送（信道再好的 UE 也只敢用 QPSK（正交相移键控，Quadrature Phase Shift Keying）低码率），频谱效率被浪费到极致；或者盲目激进，导致 BLER（误块率，Block Error Rate）失控、重传风暴。链路自适应的全部收益——让传输速率跟着信道走——都建立在"信道质量能被量化并送回调度器"这一前提上。

### 直观模型：定期体检与医生开方

CSI 报告链路像"定期体检 + 医生开药方"。CSI-RS 是体检设备：基站把已知的测量信号发下去，UE 用这台"设备"检测自己的身体状况（信道质量）。体检报告（CSI 上报）包含三项指标：

- CQI（信道质量指示，Channel Quality Indicator）是"我现在的胃口能吃掉多少"——可支持的数据速率；
- PMI（预编码矩阵指示，Precoding Matrix Indicator）是"我适合吃什么方向的药"——期望的预编码方式；
- RI（秩指示，Rank Indicator）是"我一次能吸收几路营养"——可支持的并行传输层数。

医生（调度器）拿到体检报告后开处方（MCS 与资源分配）。体检设备坏了（CSI-RS 没收到或测量失败），报告缺失，医生只能按最保守的剂量开药（低 MCS），病人（吞吐）受损但不会出事故——这正是协议在"无有效测量时丢弃报告"上的设计取向。

### 最小手算模型：一次完整的闭环

下面是一个最小的闭环场景，全部数字可以手算。它把"配置 → 测量 → 折算 → 上报 → 使用"五步走通，后文每一节会展开其中一步：

(1) 配置。gNB（5G 基站，gNodeB）通过 RRC 配置一个 1 端口 NZP（非零功率，Non-Zero-Power）CSI-RS，密度 1 RE（资源元素，Resource Element）/PRB（物理资源块，Physical Resource Block）/端口，周期 10 slot，偏移 2 slot（38.331 NZP-CSI-RS-Resource 的 periodicityAndOffset）。

(2) 测量。UE 在 slot n 收到该 CSI-RS，经信道估计与均衡（T2.11 的 post-eq SINR）测得 SINR = 6 dB。

(3) 折算。UE 按 §5.2.2.1 的准则选"BLER 不超过 10% 的最高 CQI 索引"。教学模型把 SINR 折算为可承载效率（后文式 (6)）：6 dB 对应约 1.70 bit/RE，查表 5.2.2.1-2 得 CQI 7（16QAM（正交幅度调制，Quadrature Amplitude Modulation）、码率 378/1024、效率 1.4766）——CQI 8 的效率 1.9141 超过可承载值，不可行。

(4) 上报。UE 在 PUCCH（物理上行控制信道，Physical Uplink Control Channel）上按周期（10 slot）上报 CQI = 7。PUCCH 是上行控制信道，承载 CSI 与 HARQ 反馈（[[PUCCH_上行控制信道与UCI]]）。

(5) 使用。调度器收到 CQI 7，查 MCS 表（T9.0）选 16QAM 对应的 MCS 行，分配 RB 后经 DCI 下发，PDSCH（物理下行共享信道，Physical Downlink Shared Channel）按新 MCS 传输。UE 译码后回 ACK/NACK（确认应答/否认应答，Acknowledgement/Negative Acknowledgement）；连续 NACK 时调度器下调折算偏置（outer loop），认为 UE 的 CQI 报乐观了。

一次闭环的全部算术只有一次对数（SINR → 效率）、一次查表（效率 → CQI）、一次查表（CQI → MCS）。真实系统多出的只是端口数、子带数、UE 数与触发方式的规模。

### 正式定义：CSI 报告链路的分层结构

把链路的结构写成配置对象的关系。TS 38.214 §5.2.1 规定：UE 由高层配置 $N \geq 1$ 个 CSI-ReportConfig（报告设置）与 $M \geq 1$ 个 CSI-ResourceConfig（资源设置），以及触发状态列表（CSI-AperiodicTriggerStateList、CSI-SemiPersistentOnPUSCH-TriggerStateList）。三者分工：

| 配置对象 | 38.331 信息元素 | 回答的问题 |
|:---|:---|:---|
| 报告设置 | CSI-ReportConfig | 报什么（reportQuantity）、怎么报（reportConfigType、reportFreqConfiguration） |
| 资源设置 | CSI-ResourceConfig | 测什么（NZP CSI-RS 资源集、CSI-IM 干扰资源集） |
| 触发状态 | CSI-AperiodicTriggerStateList 等 | 何时报（非周期码点映射、半持续激活） |

关联方式：CSI-ReportConfig 通过字段 resourcesForChannelMeasurement 指向 CSI-ResourceConfig（38.331 §6.3.2，本地 `TS_38.331_38331-j20/content.md` L41217）；非周期触发状态通过 CSI-AperiodicTriggerStateList 把 DCI 的 CSI request 码点映射到报告配置（§5.2.1.5.1）。一条链路的完整描述 = "报告设置 + 资源设置 + 触发方式"三元组。

### 三点误解辨析

| 误解 | 正确理解 |
|:---|:---|
| 下行 CSI 是基站测量的 | CSI-RS 由基站发送、UE 测量，UE 上报测量结果；上行对应方向是 SRS（探测参考信号，Sounding Reference Signal）——UE 发、基站测 |
| CSI 上报就是报 SINR 数值 | 上报的是量化索引（CQI/PMI/RI），SINR 到索引的折算由 UE 实现决定，协议只给准则 |
| 一次上报定终身 | 信道时变，周期/非周期上报持续跟踪；outer loop 用 ACK/NACK 持续校准折算偏置 |

### 接收端后果：上报是 UE 的义务，也是 UE 的自由度

协议规定 UE 必须按 §5.2 计算并上报 CSI——否则调度器失去下行信道信息，整个链路自适应闭环断裂。但"如何从接收信号估计信道并算出 SINR""如何把 SINR 折算成 CQI"是 UE 实现：协议只给"选满足 BLER 目标的最髙 CQI 索引"这一准则（§5.2.2.1），不给具体的折算公式或接收机算法。这个"协议强制 vs 接收机自由度"的边界是本节反复出现的主题，也是理解 CSI 报告与译码链路关系的关键：**CSI 计算是接收机里唯一直接喂给发送端的功能模块，其余模块（均衡、译码）都只服务于本机接收。**

## CSI-RS：测量信道状态的"尺子"（TS 38.211 §7.4.1.5 精读）

### CSI-RS 在参考信号体系中的分工

CSI-RS（信道状态信息参考信号，Channel State Information Reference Signal）是下行测量参考信号（[[CSI_RS_信道状态信息参考信号]]）：基站发送已知序列，UE 测量它得到下行信道状态。它与 DMRS（解调参考信号，Demodulation Reference Signal）的分工是：DMRS 与 PDSCH 数据同传、UE 专用，服务于"这包数据怎么解"；CSI-RS 独立发送、可多用户共用，服务于"下次传输怎么配"。TS 38.214 §5.1.6.1 列出 CSI-RS 的五种用途：时频跟踪（TRS）、CSI 计算、L1-RSRP 计算、L1-SINR 计算、移动性——本节只展开 CSI 计算这一路，波束与跟踪用途留给 T16.2 与 TRS 主题。

### 时频结构与配置参数

TS 38.211 §7.4.1.5 定义两类 CSI-RS：

- **NZP-CSI-RS**：非零功率 CSI-RS，实际发送的测量信号，序列按 §7.4.1.5.2 生成、按 §7.4.1.5.3 映射到 RE；
- **ZP-CSI-RS**：零功率（Zero-Power）CSI-RS，不发送能量，只"占位"——UE 假设这些 RE 不用于 PDSCH 传输（§7.4.1.5.1），作用是为其他信号/相邻小区配置做速率匹配对齐。

NZP-CSI-RS 的资源配置由 38.331 的 CSI-RS-ResourceMapping 给出（本地 `TS_38.331_38331-j20/content.md` L42227），关键参数：

| 参数 | 协议取值 | 教学含义 |
|:---|:---|:---|
| nrofPorts（端口数） | p1/p2/p4/p8/p12/p16/p24/p32，即 1/2/4/8/12/16/24/32 | 一根天线端口一路测量；端口数决定可支撑的 MIMO（多输入多输出，Multiple-Input Multiple-Output）层数与码本规模 |
| density（密度） | dot5（0.5）/one（1）/three（3）RE/PRB/端口 | 每 PRB 每端口放几个 RE；密度高测量准但开销大 |
| cdm-Type | noCDM / fd-CDM2 / cdm4-FD2-TD2 / cdm8-FD2-TD4 | 端口在时频上的正交复用方式（CDM（码分复用，Code Division Multiplexing）组大小 1/2/4/8） |
| firstOFDMSymbolInTimeDomain | 0-13 | 时域起始符号，由表 7.4.1.5.3-1 按端口数约束可选位置 |
| frequencyDomainAllocation | 位图（row1 4 位 / row2 12 位 / row4 3 位 / other 6 位） | 频域 RE 位置，指示 CDM 组内的子载波偏移 |
| freqBand | CSI-FrequencyOccupation | 占用 PRB 范围（起始位置 + 数量） |

端口编号规则（§7.4.1.5.3）：CSI-RS 天线端口为 $p = 3000 + p'$，与 PDSCH 的 DMRS 端口 1000 系列、上行 SRS 端口区分开。协议还明确 UE 不期望 CSI-RS 与 DMRS 落在同一 RE（"The UE is not expected to receive CSI-RS and DM-RS on the same resource elements"）。除 1/2/4/8/12/16/24/32 端口外，Rel-19 还允许聚合出 48/64/128 端口（§7.4.1.5.3，表 7.4.1.5.3-6）——用于增强型 Type II 码本，本节不展开。

NZP-CSI-RS-Resource（38.331，本地 L48941）还携带功率与序列参数：powerControlOffset（-8..15，PDSCH EPRE（每资源元素能量，Energy Per Resource Element）相对 CSI-RS EPRE 的偏移）、powerControlOffsetSS（db-3/db0/db3/db6，相对 SS/PBCH 块的偏移）、scramblingID（扰码 ID，即序列公式的 $n_{\text{ID}}$）、periodicityAndOffset（周期与偏移，周期/半持续必配）、qcl-InfoPeriodicCSI-RS（周期资源关联的 TCI 状态）。

### 序列生成（§7.4.1.5.2）

CSI-RS 序列是 Gold 伪随机序列，生成器在每个 OFDM 符号起始处用下式初始化：

$$
c_{\text{init}} = 2^{10}\left(N_{\text{symb}}^{\text{slot}} n_{s,f}^{\mu} + l + 1\right)\left(2n_{\text{ID}} + 1\right) + n_{\text{ID}} \bmod 2^{31}
\tag{1}
$$

其中 $n_{s,f}^{\mu}$ 是帧内时隙号、$l$ 是 OFDM 符号号、$n_{\text{ID}}$ 是 scramblingID。这个公式回答的问题是"CSI-RS 序列怎么保证不互相干扰"：序列随（时隙、符号、扰码 ID）三者变化，不同小区配不同 $n_{\text{ID}}$ 得到的序列互不相关——干扰被随机化而非固定叠加。UE 端用同一个 $n_{\text{ID}}$ 本地重建参考序列，与接收信号做相关，就能把信道响应"抠"出来（T2.11 的信道估计环节）。

### 资源映射与发送时隙（§7.4.1.5.3）

序列映射到 RE 的位置由资源映射参数（端口数、CDM 类型、频域位图、时域起始符号）共同确定，映射公式为 $a_{k,l}^{(p,\mu)} = \beta_{\text{CSI-RS}} w_f(k') w_t(l') r_{l,n_{s,f}^{\mu}}(m')$（§7.4.1.5.3，$w_f/w_t$ 是 CDM 扩频序列，$\beta_{\text{CSI-RS}}$ 由 powerControlOffset 确定）。教学层不需要展开全部下标运算，关键是两个结论：

(1) 一个 CSI-RS 资源占用的 RE 集合是"频域位图 × 时域符号 × 端口"的确定性函数，UE 与基站按同一张表（表 7.4.1.5.3-1）得到一致的位置——配置一致是测量的前提。

(2) 周期/半持续 CSI-RS 在满足下式的时隙发送：

$$
N_{\text{slot}}^{\text{frame},\mu} n_f + n_{s,f}^{\mu} - T_{\text{offset}} \bmod T_{\text{CSI-RS}} = 0
\tag{2}
$$

$T_{\text{CSI-RS}}$ 是周期（slot 数）、$T_{\text{offset}}$ 是偏移，来自 periodicityAndOffset。式 (2) 与后文周期上报的式 (3) 形式相同——测量与上报各自独立地"周期 + 偏移"节拍，两条节拍链共同决定链路自适应的时效性。UE 还假设同一 CSI-RS 资源内的端口彼此 QCL（准共址，Quasi-Co-Location）于 Type A、Type D（适用时）与平均增益（§7.4.1.5.3 末句）——QCL 概念在 T16.2 波束管理中展开。

### 生活类比：体检设备的"标定"

CSI-RS 配置参数像体检设备的标定：端口数是"同时测几项指标"（心率、血压、血氧……），密度是"每项指标测几次取平均"（测 3 次比测 1 次准，但抽血多），CDM 是"几台设备共用一个采样窗口但用不同编码区分"（正交复用），周期是"多久体检一次"。标定决定了测量的精度与开销的平衡——这正是 CSI-RS 密度/端口数参数存在的意义。

### RRC 配置链：38.331 的三层结构

配置链共三层（全部在 38.331 §6.3.2，本地 `TS_38.331_38331-j20/content.md`）：

1. **CSI-ResourceConfig**（L41995）：csi-ResourceConfigId、csi-RS-ResourceSetList（CHOICE：nzp-CSI-RS-SSB 或 csi-IM-ResourceSetList）、bwp-Id、resourceType {aperiodic, semiPersistent, periodic}；
2. **NZP-CSI-RS-ResourceSet**：一组 NZP-CSI-RS-ResourceId 的列表，可配 repetition（波束重复测量）、trs-Info（跟踪用途）；
3. **NZP-CSI-RS-Resource**（L48941）：nzp-CSI-RS-ResourceId、resourceMapping（即 CSI-RS-ResourceMapping）、powerControlOffset、powerControlOffsetSS、scramblingID、periodicityAndOffset、qcl-InfoPeriodicCSI-RS。

报告设置 CSI-ReportConfig 通过 resourcesForChannelMeasurement 指向第 1 层的 CSI-ResourceConfig（L41217）——"报告设置 → 资源设置"的关联是整条链路的配置骨架。一个教学配置实例：

| CSI-ReportConfig | reportConfigType | periodic |

## 上报配置框架（TS 38.214 §5.2.1 精读）

### Reporting Setting 与 Resource Setting

§5.2.1 给出框架：UE 配置 $N \geq 1$ 个 CSI-ReportConfig 与 $M \geq 1$ 个 CSI-ResourceConfig，以及触发状态列表。§5.2.1.1 规定每个报告设置关联单个下行 BWP（带宽部分，Bandwidth Part）（由 CSI-ResourceConfig 中的 BWP-Id 给出），并包含：报告频带、码本配置（含码本子集限制）、时域行为（reportConfigType ∈ {aperiodic, semiPersistentOnPUCCH, semiPersistentOnPUSCH, periodic}）、频域粒度（reportFreqConfiguration：cqi-FormatIndicator 取 widebandCQI/subbandCQI、pmi-FormatIndicator、csi-ReportingBand 位图）、测量时域约束（timeRestrictionForChannelMeasurements / timeRestrictionForInterferenceMeasurements）。§5.2.1.2 规定每个资源设置包含 $S \geq 1$ 个资源集，资源集引用 NZP CSI-RS 资源集、SS/PBCH 块集或 CSI-IM（信道状态信息干扰测量，CSI-Interference Measurement）资源集；资源集的时域行为 resourceType ∈ {aperiodic, periodic, semi-persistent}。

§5.2.1.4.1 进一步规定资源设置的数量与分工：一个报告设置可链接 1-3 个资源设置——第 1 个（resourcesForChannelMeasurement）用于信道测量；第 2 个（csi-IM-ResourcesForInterference 或 nzp-CSI-RS-ResourcesForInterference）用于干扰测量；第 3 个用于 NZP CSI-RS 干扰测量。信道测量与干扰测量分离的意义：CQI 的"信"与"干"分开测，调度器才能分别优化（干扰抑制、协作调度），而不是只能得到一个混合的 SINR。

### 上报量与依赖链（§5.2.1.4）

上报量由 reportQuantity 决定（§5.2.1.4.2 给出取值列表）：'none'、'cri-RI-PMI-CQI'、'cri-RI-i1'、'cri-RI-i1-CQI'、'cri-RI-CQI'、'cri-RSRP'、'cri-SINR'、'ssb-Index-RSRP'、'cri-RI-LI-PMI-CQI' 等。当上报 CRI/RI/PMI/CQI 组合时，参数之间有严格的条件依赖（§5.2.1.4 原文）：

- LI（层指示，Layer Indicator）以已报的 CQI、PMI、RI 与 CRI 为条件计算；
- CQI 以已报的 PMI、RI 与 CRI 为条件计算；
- PMI 以已报的 RI 与 CRI 为条件计算；
- RI 以已报的 CRI（CSI-RS 资源指示，CSI-RS Resource Indicator）为条件计算。

依赖链写成箭头是：

$$
\text{CRI} \to \text{RI} \to \text{PMI} \to \text{CQI} \to \text{LI}
\tag{3}
$$

这条链的意义：**CQI 不是"裸信道质量"，而是"在指定资源（CRI）、指定层数（RI）、指定预编码（PMI）假设下的可支持速率"**。调度器必须按"先选资源、再定层数、再选预编码、最后读速率"的次序解读报告——这也解释了为什么 §5.2.1.4 把 CRI 作为整条链的根：资源没选对，后面所有假设都不成立。

### 三种上报方式（§5.2.1.4 与表 5.2.1.4-1）

§5.2.1.4 规定报告配置可以是 aperiodic（用 PUSCH（物理上行共享信道，Physical Uplink Shared Channel））、periodic（用 PUCCH）或 semi-persistent（用 PUCCH，以及 DCI 激活的 PUSCH）；CSI-RS 资源同样可以是周期、半持续或非周期。表 5.2.1.4-1 给出"上报方式 × CSI-RS 配置"的支持矩阵（复现，本地 `tables/table_0023.csv`）：

| CSI-RS 配置 | 周期上报 | 半持续上报 | 非周期上报 |
|:---|:---|:---|:---|
| 周期 CSI-RS | 无动态触发/激活 | PUCCH：激活命令；PUSCH：DCI 触发 | DCI 触发，可子选择 |
| 半持续 CSI-RS | 不支持 | PUCCH：激活命令；PUSCH：DCI 触发 | DCI 触发，可子选择 |
| 非周期 CSI-RS | 不支持 | 不支持 | DCI 触发，可子选择 |

矩阵的工程含义：周期上报开销最小但最"钝"（固定节拍），非周期上报最灵活但依赖 DCI 触发开销；非周期 CSI-RS 只能配非周期上报——"一次性测量配一次性报告"，避免为单次测量维持固定节拍。

周期上报的发送时隙公式（§5.2.1.4）：上报在满足

$$
N_{\text{slot}}^{\text{frame},\mu} n_f + n_{s,f}^{\mu} - T_{\text{offset}} \bmod T_{\text{CSI}} = 0
\tag{4}
$$

的时隙发送，$T_{\text{CSI}}$ 与 $T_{\text{offset}}$ 由 reportSlotConfig 配置（周期单位是 slot，$\mu$ 是上行 BWP 的子载波间隔配置）。式 (4) 与 CSI-RS 发送的式 (2) 同构——两条节拍链（测量节拍、上报节拍）分别独立配置。

### 触发与激活机制（§5.2.1.5）

三种方式的触发/激活分属三个机制：

- **非周期**（§5.2.1.5.1）：由 DCI 的 CSI request 字段触发。全 0 码点 = 不请求 CSI；非零码点按 CSI-AperiodicTriggerStateList 中触发状态的顺序映射（码点 1 → 第一个触发状态，§5.2.1.5.1）。触发状态数超过字段码点数时，先由 MAC CE 子选择指示（38.321 §6.1.3.13）把子集映射到码点。非周期 CSI-RS 的触发偏移 aperiodicTriggeringOffset 取值 {0,1,...,16,24} slot（$\mu_{\text{CSI-RS}} \leq 3$ 时；$\mu = 5/6$ 时取 {0,4,...,64,96}），CSI-RS 在触发 DCI 所在时隙之后 X slot 发送；UE 每 slot 每小区最多接收一个非零 CSI request 字段的 DCI（防止多 DCI 竞争同一测量/上报资源）。跨载波场景下发送时隙还受 ca-SlotOffset 修正，原文公式在抽取中截断，未核验。
- **半持续**（§5.2.1.5.2）：PUSCH 上的半持续报告由 SP-CSI-RNTI（半持续 CSI 无线网络临时标识，Semi-Persistent CSI Radio Network Temporary Identifier）加扰的 DCI 激活（CSI request 字段选择触发状态，码点 0 → 第一个触发状态）；PUCCH 上的半持续报告由激活命令（MAC CE，38.321 §6.1.3.16）激活。激活/去激活 DCI 必须通过特殊字段校验（表 5.2.1.5.2-1/-2），校验失败按 CRC 不匹配处理——防误激活。
- **周期**（§5.2.1.1）：无动态触发，纯 RRC 配置周期与偏移，UE 按式 (4) 的节拍自动上报。

### CSI 处理时延与处理单元（§5.2.1.6）

§5.2.1.6 规定 UE 用参数 simultaneousCSI-ReportsPerCC 指示每个载波同时支持的 CSI 计算数，对应 CSI 处理单元（CSI Processing Unit, CPU）：每个 CSI 报告按报告量类型占用若干 CPU、持续若干符号（如 'cri-RI-PMI-CQI' 类型按端口数与码本类型占用 CPU；纯 L1-RSRP 类报告占用 1 CPU）；CPU 不足时 UE 无需更新低优先级报告（优先级规则见 §5.2.5）。对工程的意义：**CSI 计算不是免费的**——高端口数、Type II 码本的报告占用大量处理单元，接收机 DSP 必须把 CSI 计算与 PDSCH 译码放进同一个处理预算里排程。本节对 CPU 占用规则只做定性介绍，逐条公式未展开（未核验：各报告量的精确 CPU 占用函数）。

## CQI、PMI、RI：三个报告量的含义与量化粒度（§5.2.2 精读）

### CQI：4-bit 索引与 BLER 目标

CQI 是 4-bit 索引（0-15），每个索引对应一组"调制阶数 + 目标码率 + 效率"（§5.2.2.1，表 5.2.2.1-2/-3/-4/-5 四张表可选）。UE 的折算准则（§5.2.2.1 原文）：在 CSI 参考资源上，选满足"单个 PDSCH 传输块（Transport Block, TB）以该 CQI 索引对应的调制、目标码率与 TBS（传输块大小，Transport Block Size）传输时，传输块错误概率不超过 0.1"的最高 CQI 索引；若 cqi-Table 配 table3（表 5.2.2.1-4），阈值收紧为 0.00001——面向 URLLC（超可靠低时延通信，Ultra-Reliable and Low-Latency Communication）类低 BLER 需求。

复现表 5.2.2.1-2（4-bit CQI Table，QPSK/16QAM/64QAM，本地 `tables/table_0032.csv` 全 16 行）：

|---:|---:|---:|---:|
| 0 | out of range | — | — |
| 1 | QPSK | 78 | 0.1523 |
| 2 | QPSK | 120 | 0.2344 |
| 3 | QPSK | 193 | 0.3770 |
| 4 | QPSK | 308 | 0.6016 |
| 5 | QPSK | 449 | 0.8770 |
| 6 | QPSK | 602 | 1.1758 |

表内效率 = 调制阶数 × 码率 / 1024（自洽关系）：

$$
\text{efficiency} = Q_m \times \frac{R}{1024}
\tag{5}
$$

如 CQI 9：$4 \times 616 / 1024 = 2.4063$。表 5.2.2.1-3 在 64QAM 之上加入 256QAM 行（CQI 12-15 用 256QAM），表 5.2.2.1-5 再加 1024QAM（Rel-17 的 table4-r17）——高调制阶数是高频谱效率的"加速挡"，只有 SINR 足够高才可行。CQI 的量化粒度：4 bit 只有 16 级，却覆盖约 0.15 到 5.55 bit/RE、约 36 倍的效率动态范围——用"效率"而非"SINR 数值"上报，把接收机实现差异（同一 SINR 下不同接收机性能不同）留在 UE 侧，协议只要求"按我的准则选最高可行索引"。

### 子带差分 CQI（§5.2.2.1）

宽带 CQI 用一个索引覆盖整个 CSI 上报频带；子带 CQI 每个子带一个。子带大小按 BWP 带宽查表 5.2.1.4-2（24-72 PRB → 4/8 PRB；73-144 PRB → 8/16 PRB；145-275 PRB → 16/32 PRB，本地 `tables/table_0024.csv`）。为节省上报开销，子带 CQI 默认报 2-bit 差分值（§5.2.2.1）：

$$
\text{Offset level}(s) = \text{sub-band CQI index}(s) - \text{wideband CQI index}
\tag{6}
$$

表 5.2.2.1-1 把 2-bit 值映射到偏移电平（本地 `tables/table_0031.csv`）：值 0 → 电平 0、值 1 → 电平 +1、值 2 → 电平 ≥ +2、值 3 → 电平 ≤ -1。即差分 CQI 只能表达"子带比宽带好一点（+1）、好很多（≥ +2）、持平（0）或更差（≤ -1）"——频选调度需要的"哪个子带好"信息压缩在 2 bit 里。若配置 cqi-BitsPerSubband，则每子带报 4-bit 绝对 CQI（开销大但更精细）。

### PMI：预编码矩阵指示

PMI 是码本索引（§5.2.2.2）：UE 从预编码码本中选一个矩阵 $W$，使接收端在 RI 层数假设下信号质量最好，并把 $W$ 的索引报给基站，基站按此预编码 PDSCH。Type I Single-Panel 码本：2 端口时 PMI 对应表 5.2.2.2.1-1 的码本索引（端口 3000-3001）；4/8/12/16/24/32 端口时 PMI 对应三个码本索引的组合（§5.2.2.2.1，$i_1/i_2/i_3$ 的结构与端口布局 $N_1/N_2$ 相关）；码本覆盖 1-8 层（表 5.2.2.2.1-5 至 -12）。PMI 的量化粒度是码本枚举索引——码本越大、预编码越精细，上报开销也越大（Type II 码本的 PMI 可达几十 bit，本节不展开；Type II 码本结构与预编码原理见 [[Precoding_预编码]]）。码本索引的精确组合规则依赖协议表 5.2.2.2.1-2/-3/-4 的逐表展开，本节未逐表复现（未核验：$i_1/i_2/i_3$ 与 $N_1/N_2$ 的完整映射关系）。

### RI：秩指示

RI 是 UE 建议的传输层数（空间复用流数），范围 1-8（Type I 码本）。RI 依赖 CRI（式 (3) 的链首）。这里的"秩"来自矩阵秩：MIMO（多入多出，Multiple-Input Multiple-Output）信道矩阵 $H$ 的秩刻画"能撑起几路并行数据流"——秩高说明信道空间选择性好、可多层复用，秩低说明空间强相关、只适合单层。RI 决定 TBS 计算中的层数：速率随层数倍增（两层比一层快一倍），因此 RI 直接影响吞吐，也影响 CQI 的口径（CQI 是"按 RI 层数假设下的每层可支持速率"）。

三件套的教学实例：

| 量 | 取值 | 含义 |
|:---|:---|:---|
| RI | 2 | 建议 2 层空间复用 |
| PMI | 码本索引（如 Type I 2 端口索引 1） | 期望预编码矩阵 $W$ |
| CQI | 9（16QAM, 616/1024, 2.4063） | 按 RI=2 与 PMI 假设折算的每层可支持速率 |

## 从测量到上报：CSI 参考资源与 UE 计算假设（§5.2.2.5 精读）

### CSI 参考资源的定义

CSI 参考资源（CSI reference resource）是 CQI/PMI/RI 计算时 UE 假设的"虚拟 PDSCH 传输"的时频占位（§5.2.2.5）：

- 频域：CSI 所对应的下行 PRB 组（即 CSI 上报频带）；
- 时域：单个下行时隙 $n - n_{\text{CSI\_ref}}$，其中 $n$ 是上报所在的上行时隙，$n_{\text{CSI\_ref}}$ 是满足"有效下行时隙"条件的最小值，且周期/半持续上报、单 CSI-RS/SSB 资源配置时 $n_{\text{CSI\_ref}} \geq 4 \cdot 2^{\mu_{\text{DL}}}$（§5.2.2.5；多资源配置与 128 端口 typeI-SinglePanel-r19 能力 2 场景的下限取值不同，原文公式符号在抽取中缺失，未核验）。

有效下行时隙（§5.2.2.5）定义为：至少包含一个高层配置的下行或灵活符号；且不落在该 UE 配置的测量间隙（measurement gap）内。**若无有效下行时隙，CSI 上报被丢弃**（"CSI reporting is omitted"）。

这个定义解决"测量基准不一致"问题：UE 和基站必须对"这个 CQI 说的是哪个时隙、哪段频带的信道"达成一致。如果 UE 按 slot 100 的信道报 CQI，基站却按 slot 120 的信道选 MCS，速率必然错配。参考资源把 CQI 的"时戳"钉死在协议层。

### UE 计算假设（§5.2.2.5.1）

计算 CQI（以及配置时的 PMI/RI）时，UE 必须假设一个标准的 PDSCH 传输（§5.2.2.5.1 原文要点）：

- 前 2 个 OFDM 符号被控制信令占用；
- PDSCH 与 DMRS 符号数为 12；
- 使用与 PDSCH 接收相同的子载波间隔与 CP（循环前缀，Cyclic Prefix）长度；
- 带宽 = 对应 CQI 报告的配置带宽；
- 无 PSS（主同步信号，Primary Synchronization Signal）/SSS（辅同步信号，Secondary Synchronization Signal）/PBCH（物理广播信道，Physical Broadcast Channel）占用的 RE；
- RV（冗余版本，Redundancy Version）= 0；
- 无 NZP CSI-RS 与 ZP CSI-RS 占用的 RE；
- 前端 DMRS 符号数与附加 DMRS 符号数按高层配置（maxLength、dmrs-AdditionalPosition）；
- PRB bundling 大小为 2 PRB；
- PDSCH 用最多 8 层传输，层信号与 CSI-RS 端口信号通过 $y = W x$ 关联（$W$ 为 PMI 对应的预编码矩阵，PDSCH 端口 1000 系列 ↔ CSI-RS 端口 3000 系列，§5.2.2.5.1）：

$$
\mathbf{y}(i) = \mathbf{W}(i)\, \mathbf{x}(i), \qquad \mathbf{x}(i) = \left[x^{(0)}(i),\, \ldots,\, x^{(\nu-1)}(i)\right]^{T}
\tag{7}
$$

这些假设的意义：**CQI 是"在给定假设下的可支持速率"**。假设越接近真实调度配置，CQI 越准；同时假设把所有 UE 的接收机实现差异排除在外——UE 不能因为"我的接收机有 16 根天线、性能比协议假设好"就报一个虚高的 CQI。这是"协议强制 vs 接收机自由度"边界最具体的落点之一：**上报内容（CQI 值）是协议强制的，但把它折算出来的接收机能力被协议用一个标准假设"冻结"了。**

### 时域约束（§5.2.2.1 与 §5.2.2.5）

timeRestrictionForChannelMeasurements = Configured 时，UE 只能用 CSI 参考资源之前最近一次的 NZP CSI-RS 场合做信道测量（§5.2.2.1）；= notConfigured 时可用参考资源之前的全部场合（无限制观测区间）。时域约束控制 CSI 的时效性：快速移动的 UE 信道变化快，需要"只看最新"（时间限制）；低速 UE 可以跨场合平均以降低测量噪声。§5.2.2.5 还规定：报告配置变更、小区激活、BWP 切换或半持续激活后，UE 只有在参考资源之前至少收到一次 CSI-RS 传输场合后才会上报，否则丢弃——防止"没有测量就报数"。

## 与调度器、链路自适应的衔接：CSI 是 T16.1 的输入

### 教学图：CSI 报告闭环全流程

下图为 CSI 报告闭环的完整信号流（Mermaid 教学重建，节点一律使用引号形式）：

```mermaid

```

图中从 H 到 I 到 J 到 D 的回路是链路自适应的"自校准"层：CQI 折算误差不会无限累积，而是被真实传输结果（ACK/NACK）持续修正。调度器在 F 处消费 CSI，在 G 处产出 T16.1 的调度决策，DCI（T14.2）下发，descriptor（T9.0）重建——CSI 报告链路是这条调度链的"测量输入端"。

### 调度器如何使用 CSI

T16.1 的调度决策输入 $c_u$ 在本节补全来源：

| T16.1 的输入 | 本节来源 | 使用机制 |
|:---|:---|:---|
| 每 RB SINR | CQI 上报（经折算） | CQI → MCS 表行（T9.0）→ $Q_m$ 与码率 |
| 层数假设 | RI 上报 | RI → TBS 计算中的层数 → 吞吐倍增 |
| 预编码假设 | PMI 上报 | PMI → PDSCH 预编码 → 波束/层成形 |
| 频选信息 | 子带 CQI / CRI | 好子带配高 MCS（频选调度） |
| 波束信息 | CRI / L1-RSRP（T16.2） | 波束选择与切换 |

MCS 选择链（T16.1 出现过）现在可以补全成完整闭环：

$$
\text{CSI-RS 测量} \to \text{SINR（T2.11）} \to \text{CQI 折算（\$5.2.2.1）} \to \text{上报} \to \text{CQI} \to \text{MCS 映射（T9.0）} \to \text{DCI（T14.2）} \to \text{PDSCH 传输} \to \text{ACK/NACK（T14.3）} \to \text{outer loop 校准}
\tag{8}
$$

注意式 (8) 的"折算-映射"分界：CQI → MCS 的映射用的是协议定义的 MCS 表（T9.0 的 Table 5.1.3.1-x），而 SINR → CQI 的折算由 UE 实现——两端在 CQI 这个"交换点"上对接，这正是 CQI 索引存在的工程意义：它让 UE 实现与基站调度器只共享一张 4-bit 表，不共享任何接收机细节。

### outer loop：ACK/NACK 校准 CQI 误差

CQI 是 UE 的预测，测量误差、信道时变、干扰波动都会让它偏乐观或偏悲观。基站侧 outer loop 用真实传输结果校准（[[Link_Adaptation_链路自适应与CQI]] 的 outer loop 一节）：连续 NACK → 认为 UE 报乐观了，下调 SINR 折算偏置（选更低的 CQI 对应行）；连续 ACK → 认为偏悲观，上调偏置——把实际 BLER 拉回目标值（10%）。**outer loop 不在 38.214 §5.2 里**：协议只提供 ACK/NACK 反馈路径（T14.3）与 CQI 计算准则，偏置的步长、收敛策略都是基站实现。这是"协议机制 vs 实现算法"边界在本节的又一落点。

### 与 T2.11、T12.5 的关系

- **T2.11（OFDM 均衡与 CSI）**：CSI-RS 接收后走与 PDSCH 相同的均衡链路（信道估计 $H_{\text{eff}}$ → MMSE 均衡 → post-eq SINR）。[[CSI_SINR]] 概念笔记记录了 CSI 加权（$\text{LLR}_{\text{out}} = \text{LLR}_{\text{in}} \times \text{CSI}$，LLR（对数似然比，Log-Likelihood Ratio））——T2.11 的 SINR 就是本节 CQI 折算的输入。两条链路（数据解调与 CSI 测量）共用信道估计模块，但用途不同：一个服务"这包数据怎么解"，一个服务"下次传输怎么配"。
- **T12.5（信道估计与 LLR 可靠度）**：T12.5 讲信道估计误差 $\sigma^2$ 如何影响译码 LLR 可靠度；同样的估计误差影响 CSI-RS 上的 SINR 测量精度，进而影响 CQI 准确度与 MCS 选择。估计误差在两个链路上是同源问题，而协议给 CSI-RS 配了密度参数（0.5/1/3）作为"精度-开销"旋钮：密度高（如 TRS 用 3 RE/PRB）估计准但开销大，密度低（0.5）省开销但只适合慢变信道。

### 内嵌 numpy 验证：CQI 选择规则与子带差分量化

下列断言先实跑通过再写入本节（输出与断言一致）。它用表 5.2.2.1-2 的真实数据实现两条协议规则：一是 §5.2.2.1 的"选 BLER 目标下最高 CQI 索引"（教学模型用"表效率 ≤ 可承载效率"的保守近似），二是 §5.2.2.1 的子带差分 2-bit 量化（表 5.2.2.1-1）：

```python
import numpy as np

# TS 38.214 Rel-19 Table 5.2.2.1-2（4-bit CQI Table，QPSK/16QAM/64QAM）
# 列: (CQI index, 调制阶数 Qm, code rate x1024, efficiency)
cqi_table = np.array([
    (0, 0, 0, 0.0),
    (1, 2, 78, 0.1523), (2, 2, 120, 0.2344), (3, 2, 193, 0.3770),
    (4, 2, 308, 0.6016), (5, 2, 449, 0.8770), (6, 2, 602, 1.1758),
    (7, 4, 378, 1.4766), (8, 4, 490, 1.9141), (9, 4, 616, 2.4063),
    (10, 6, 466, 2.7305), (11, 6, 567, 3.3223), (12, 6, 666, 3.9023),
    (13, 6, 772, 4.5234), (14, 6, 873, 5.1152), (15, 6, 948, 5.5547),
], dtype=float)

def sinr_to_efficiency(sinr_db):
    """教学模型：每 RB SINR（dB）-> 每 RE 可承载比特上限。
    香农容量公式留 2.5 dB 实现余量（beta 因子）贴近真实编码损耗。"""
    beta = 10 ** (-2.5 / 10)
    return np.log2(1 + beta * 10 ** (sinr_db / 10))

def select_cqi(sinr_db):
    """协议规则（38.214 5.2.2.1）：选 BLER<=10% 的最高 CQI 索引。
    教学模型用表效率 <= 可承载效率的保守近似实现该规则。"""
    eff = sinr_to_efficiency(sinr_db)
    feasible = cqi_table[:, 3] <= eff
    idx = int(np.flatnonzero(feasible)[-1])
    return idx, eff

sinr_values = np.array([-2, 2, 6, 10, 14, 18, 22, 26])
cqi_sel = np.array([select_cqi(s)[0] for s in sinr_values])
mod_sel = cqi_table[cqi_sel, 1].astype(int)
rate_sel = cqi_table[cqi_sel, 2].astype(int)
eff_sel = cqi_table[cqi_sel, 3]

# 断言 1：CQI 随 SINR 单调不减（最高索引规则的推论）
assert np.all(np.diff(cqi_sel) >= 0), "CQI must be monotonic in SINR"
# 断言 2：SINR 26 dB 必须落在 64QAM 行（索引 >= 10）
assert cqi_sel[-1] >= 10, "high SINR must reach 64QAM"
# 断言 3：SINR -2 dB 只能落在 QPSK 低码率（索引 <= 4）
assert cqi_sel[0] <= 4, "low SINR must stay in QPSK"
# 断言 4：表自洽——效率 == 调制阶数 x 码率 / 1024（式 5）
assert np.allclose(mod_sel * rate_sel / 1024.0, eff_sel, atol=0.001)
# 断言 5：子带差分 CQI 2-bit 量化（表 5.2.2.1-1：0->0, 1->+1, 2->>=+2, 3-><=-1）
subband = np.array([6, 8, 9, 10])     # 4 个子带各自独立的 CQI
wideband = 8
def quantize(d):
    if d >= 2: return 2
    if d == 1: return 1
    if d == 0: return 0
    return 3
delta = subband - wideband
q = np.array([quantize(d) for d in delta])
assert np.all(np.isin(q, [0, 1, 2, 3])), "2-bit levels must be in 0..3"

print("sinr_dB   =", sinr_values)
print("cqi_sel   =", cqi_sel, " mod =", mod_sel, " rate=", rate_sel)
print("eff_sel   =", np.round(eff_sel, 4))
print("subband CQI =", subband, " wideband =", wideband)
print("delta       =", delta, " -> 2-bit levels =", q)
print("T16.5_OK all 5 assertions passed")
```

输出（实跑结果）：

```text
sinr_dB   = [-2  2  6 10 14 18 22 26]
cqi_sel   = [ 3  5  7  9 12 14 15 15]  mod = [2 2 4 4 6 6 6 6]  rate= [193 449 378 616 666 873 948 948]
eff_sel   = [0.377  0.877  1.4766 2.4063 3.9023 5.1152 5.5547 5.5547]
subband CQI = [ 6  8  9 10]  wideband = 8
delta       = [-2  0  1  2]  -> 2-bit levels = [3 0 1 2]
T16.5_OK all 5 assertions passed
```

数值走读：SINR 从 -2 dB 到 26 dB，CQI 从 3 单调升到 15（断言 1），调制阶数从 QPSK 依次切换到 16QAM、64QAM（断言 2/3）；26 dB 时效率 5.5547 bit/RE 封顶（CQI 15）——教学模型里再高的 SINR 也只能报 15，这与协议"4-bit 表只有 16 级"的量化上限一致。子带差分例子里，子带 CQI 6/8/9/10 相对宽带 8 的偏移 -2/0/+1/+2 被压成 2-bit 值 3/0/1/2——"好很多"与"持平"各占一个码点，这就是 2-bit 差分的精度边界。

## 示范例题

### 例题 1：CQI 表自洽性验证

表 5.2.2.1-2 中 CQI 12 行的 efficiency 是多少？验证它与调制阶数、码率的关系。

**求解**：CQI 12 = 64QAM、码率 666/1024。调制阶数 $Q_m = 6$，按式 (5)：$6 \times 666 / 1024 = 3996 / 1024 = 3.9023$，与表值一致。工程语义：每 RE 携带 3.90 bit 数据——64QAM 每符号 6 bit 的 65% 是有效信息，其余是编码冗余（对抗信道噪声）。

### 例题 2：SINR → CQI 选择

教学模型下，SINR = 6 dB 的每 RB 信道应报哪个 CQI 索引？

**求解**：可承载效率 $\text{eff} = \log_2(1 + 10^{-2.5/10} \times 10^{6/10}) = \log_2(1 + 0.5623 \times 3.981) = \log_2 3.238 \approx 1.695$ bit/RE。查表 5.2.2.1-2：CQI 7 效率 1.4766 ≤ 1.695 可行，CQI 8 效率 1.9141 > 1.695 不可行，故选最高的可行索引 CQI 7（16QAM、378/1024）。与 numpy 验证中 SINR 6 dB → CQI 7 一致。

### 例题 3：子带差分 CQI 编码

宽带 CQI = 8，四个子带的 CQI 为 6、8、9、10。按表 5.2.2.1-1 写出 2-bit 差分值。

**求解**：差分偏移 = 子带 CQI − 宽带 CQI = -2、0、+1、+2。映射：-2 → 值 3（≤ -1）、0 → 值 0、+1 → 值 1、+2 → 值 2（≥ +2）。编码序列 3, 0, 1, 2——与 numpy 验证输出一致。

## 独立习题（附参考答案）

### 习题 1：256QAM 表

表 5.2.2.1-3（含 256QAM）中 CQI 13 的调制方式、码率与效率是什么？

**参考答案**：256QAM、码率 797/1024、效率 6.2266（$8 \times 797 / 1024 = 6.2266$）。

### 习题 2：CSI 参考资源时域

周期上报、$\mu_{\text{DL}} = 1$（子载波间隔 30 kHz）时，$n_{\text{CSI\_ref}}$ 的最小取值是多少 slot？

**参考答案**：$n_{\text{CSI\_ref}} \geq 4 \cdot 2^{\mu_{\text{DL}}} = 4 \times 2 = 8$ slot——参考资源至少在上报时隙前 8 个 slot，且必须是有效下行时隙。

### 习题 3：调度器解读

UE 上报 RI = 1、PMI 索引 0、CQI 7。调度器能得到哪些信息？

**参考答案**：RI = 1 表示建议单层传输（不用空间复用）；PMI 索引 0 表示期望的预编码矩阵（2 端口 Type I 码本的第一项）；CQI 7 表示在该层数/预编码假设下，每 RE 约 1.48 bit 的可支持速率（16QAM、378/1024）——调度器据此选 MCS 行与资源量，并可用子带 CQI 做频选。

## 资料与协议边界

本节内容横跨"协议机制"与"UE 实现"两个层面，分三层说明边界：

- **协议规定（机制层）**：CSI-RS 的时频结构与端口/密度/CDM 参数（TS 38.211 §7.4.1.5，含序列初始化式 (1) 与发送时隙式 (2)）；报告/资源设置的配置框架与上报量依赖链（TS 38.214 §5.2.1/§5.2.1.4）；三种上报方式的触发/激活机制（§5.2.1.5，表 5.2.1.4-1 的组合矩阵）；CQI 表与"最高索引 + BLER 目标"准则（§5.2.2.1，表 5.2.2.1-1/-2/-3）；CSI 参考资源与 UE 计算假设（§5.2.2.5/§5.2.2.5.1）；38.331 的 CSI-ResourceConfig/NZP-CSI-RS-ResourceSet/NZP-CSI-RS-Resource/CSI-ReportConfig 字段结构。
- **协议不规定（实现域）**：SINR 的具体测量方法（均衡/插值算法，T2.11/T12.5 给出的是教学模型而非协议要求）；SINR → CQI 的折算公式（协议只给准则，本节教学模型用香农近似式 (6)）；outer loop 的偏置步长与收敛策略；调度器把 CQI 映射到哪个具体 MCS 行（MCS 表本身是协议定义的，选行策略是调度器实现）；UE 是否用满 CSI 处理单元预算（§5.2.1.6 只给上限规则）。
- **接收端义务（执行层）**：按配置接收 CSI-RS 并完成测量；按 §5.2.2.1 准则折算 CQI（在 §5.2.2.5.1 的标准假设下）；按触发/激活机制按时上报；满足 §5.2.1.6 的处理时延与 CPU 约束；在无有效下行时隙或测量不足时丢弃报告（§5.2.2.5）。

上述边界对整条 CSI 链路同样成立：**协议规定"报什么、何时报、怎么算合格"，UE 决定"怎么测、怎么折算"，基站决定"怎么用"**——三句话概括本节协议观。

## 小结

CSI 报告链路把"UE 观测到的下行信道质量"翻译成"调度器可用的传输参数"：CSI-RS（38.211 §7.4.1.5）提供测量信号，UE 按 §5.2.2.1 的准则把 SINR 折算成 CQI/PMI/RI（4-bit 效率索引、码本索引、1-8 层秩，依赖链 CRI → RI → PMI → CQI），经 PUCCH/PUSCH 按三种方式（周期/半持续/非周期，表 5.2.1.4-1）上报，调度器（T16.1）把 CQI 映射成 MCS 与资源，outer loop 用 ACK/NACK 校准折算误差。CSI 参考资源（§5.2.2.5）把"这个 CQI 说的是哪个时隙的信道"钉死在协议层，UE 计算假设（§5.2.2.5.1）把接收机实现差异排除在 CQI 之外。

回到本节开头的问题：T16.1 调度器的那句"从 SRS/CSI 得到每 RB 的 SINR"，现在有了完整的机制支撑——SINR 的测量输入来自 T2.11 的均衡链路，其精度受 T12.5 的估计误差影响，其折算受 §5.2.2.1 的准则约束，其上报受 §5.2.1 的框架管理，其使用在 T16.1 的决策函数里。持久理解：**链路自适应不是一条"测了就报、报了就用"的开环，而是一条带自校准的闭环；环上的每个环节都由协议定义机制、由实现定义算法。**

下一篇指向 T16.2 波束管理：本节反复提到的 QCL、CRI 与 L1-RSRP 上报在波束场景下的完整展开（波束扫射、波束报告、失败恢复），CSI-RS 将从"测量信道质量"的角色扩展到"测量空间方向"。
