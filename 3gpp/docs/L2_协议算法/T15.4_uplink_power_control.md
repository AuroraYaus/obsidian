# T15.4 上行功率控制：开环补偿、闭环微调与功率余量

## 本节学习目标

T15.5 波形深化与 T15.2/T15.3 讲了上行"怎么发、何时发、发什么"——本节回答最后一个维度：**用多大功率发**。上行功率控制（Power Control）的目标是让每个 UE 的到达功率"恰到好处"：太小基站收不到（覆盖失败），太大浪费电池并干扰邻区（远近效应）。与下行不同（下行由基站统一功率管理），上行每个 UE 独立发射，功率必须逐 UE 闭环调节。

功控分两层：**开环（open-loop）**按路损补偿粗略定功率（UE 测下行路损 PL（路径损耗，Path Loss），按 $P_0 + \alpha \cdot PL$ 补偿），**闭环（closed-loop）**用 TPC（发射功率控制命令，Transmit Power Control Command）命令逐次微调（基站按实际接收 SINR（信干噪比，Signal-to-Interference-plus-Noise Ratio）发 ±dB 命令，UE 累计）。第三块拼图是 **PHR（功率余量报告，Power Headroom Report）**——UE 把"还能加多少功率"报告给调度器，调度器据此决定资源分配。三者构成上行链路"功率维度"的完整闭环。

功控公式（TS 38.213 §7）是本节的核心：PUSCH（物理上行共享信道，Physical Uplink Shared Channel）/PUCCH（物理上行控制信道，Physical Uplink Control Channel）/SRS（探测参考信号，Sounding Reference Signal）/PRACH（物理随机接入信道，Physical Random Access Channel）各有独立参数集，公式结构同源（目标功率 + 路损补偿 + 格式项 + 闭环项）。本节以 PUSCH 为主线（§7.1），PUCCH/SRS 对照（§7.2/§7.3），TPC 与 PHR 讲机制（§7 + 38.321 §5.4.6）。

学完本节后，应能做到：

- 说出上行功控的必要性（远近效应、电池、干扰控制）与下行功率管理的差异。
- 写出 PUSCH 功控公式（38.213 §7.1.1）并逐项解释 P0/α/PL/带宽项/ΔTF/f 的来源与语义，完成数值计算（含 P_CMAX 限幅）。
- 解释开环与闭环的分工（粗对齐 vs 细校正），说出 α 的部分补偿（α<1）在干扰受限场景的意义。
- 说出 TPC 命令的 DCI 携带方式（T14.2 字段衔接）、累计机制（f 项）与两个闭环进程（l=0/1）的选择。
- 说出 PHR 的触发条件、内容与调度器的用途（余量 → 资源决策）。
- 对照 PUCCH/SRS 功控的差异（无带宽项、独立参数集）。
- 把功控放进全链路：SRS 测量（T15.3）→ 调度决策 → TPC（T14.2 DCI）→ 功率调整 → PHR 反馈的闭环。

## 最小手算模型：一次 PHR 上报到功率调整的完整闭环

**本节主角解决什么问题**：功控的三段式（开环定基线、闭环微调、PHR 报余量）单独看都是"一条规则"，合起来才是一个闭环。本节给一个最小数值模型，回答一个贯穿性问题：**一次 PHR 上报之后，功率到底怎么变**——余量如何被量化、调度器如何把它翻译成资源决策或 TPC 命令、UE 的发射功率又如何随之更新，以及这个循环再来一轮时会怎样。模型只用加减与一次对数，全部数值可以手算复核。

### 历史来源：从 CDMA 的远近效应到 NR 的三段式

上行功控不是 NR 的新发明。它的雏形来自码分多址（Code Division Multiple Access, CDMA）时代的远近效应（Near-Far Effect）斗争：CDMA 是干扰受限系统，近处 UE 的高功率会淹没远处 UE 的信号，因此快速精确的功控是 CDMA 的容量生命线——这就是"到达功率对齐"这一目标的历史来源。

NR 沿用"开环 + 闭环"的基本结构，并加入两块新拼图：带宽项（保证每 RB 功率密度恒定，功率随带宽自适应）与 PHR（把功率信息翻译给调度器）。理解这段历史的意义在于：功控的目标从来不是"让 UE 发射功率均匀"，而是"让到达功率均匀"——发射功率只是路损的反函数。这个反函数的两个组成部分（路损补偿与反馈修正）各自对应一个测量来源，缺一不可。NR 的三段式还多了一层跨层含义：开环与闭环在物理层，PHR 在媒体接入控制（Medium Access Control, MAC）层——功控从来不是纯物理层机制（见「资料与协议边界」的接收端义务）。

### 白话直觉：空调恒温器

功控像空调恒温器：设定温度是目标接收功率 $P_0$，室外温度是路损，压缩机档位是发射功率。开环按"室外多热"先粗定一个档位（解决"量级对不对"的问题）；闭环靠室内温度回差逐次微调档位（解决"偏差怎么消"的问题）；PHR 是空调向主人报告的"还能再升几档"（解决"还剩多少空间"的问题）——主人（调度器）据此决定要不要让空调多干活（加带宽、加 MCS），而不是让空调自己瞎猜。

三段各自解决一个独立的问题，任何一段缺席闭环都会断：没有开环，冷启动功率全靠猜，收敛太慢；没有闭环，开环的残余误差永远残留；没有 PHR，调度器不知道功率空间还剩多少，资源决策变成盲拍。这个直觉模型的另一个要点是：**PHR 是"汇报"不是"申请"**——空调只报余量，升不升档由主人决定；对应到协议，UE 只报数值，加不加资源由调度器决定。恒温器模型还提示了收敛的节奏感：室内温度不会一步到位，功控功率也一样——这正是 TPC 逐次微调而非一步到位的直观来源。

### 手算例子：从 PHR 上报到功率调整的一次闭环

参数：$P_0 = -95$ dBm、$\alpha = 0.8$、$PL = 100$ dB、$M_{\text{RB}} = 2$、$\mu = 0$、$\Delta_{\text{TF}} = 0$、$f = 0$、$P_{\text{CMAX}} = 23$ dBm。路损由 UE 测下行参考信号得到（参考信号发射功率已知，接收功率实测，两者相减即 $PL$）。所有 dB 运算均为对数值的加减，没有乘法与幂运算——对数域正是功率控制选择 dB 单位的原因。逐步演算：

1. 带宽项：$10\log_{10}(2^0 \times 2) = 3.01$ dB。
2. 开环功率：$-95 + 3.01 + 0.8 \times 100 = -11.99$ dBm。注意 $\alpha = 0.8$ 是部分补偿——100 dB 路损只补 80 dB，少发的 20 dB 换来对邻区更小的干扰。
3. 功率余量：$PH = 23 - (-11.99) = 34.99$ dB。UE 上报 PHR = 34.99 dB，含义是"我还有约 35 dB 的功率可加"。
4. 调度器读余量：余量大 → 有功率换吞吐的空间 → 把 $M_{\text{RB}}$ 从 2 加到 4（带宽翻倍）→ 新带宽项 $6.02$ dB → 发射功率变为 $-95 + 6.02 + 80 = -8.98$ dBm。
5. 基站测接收 SINR 仍比目标低 1 dB → 下发 TPC = +1 dB → $f$ 从 0 累计到 1 → 发射功率变为 $-8.98 + 1 = -7.98$ dBm。
6. 新余量：$23 - (-7.98) = 30.98$ dB。随后 UE 移动到 $PL = 110$ dB 的位置：开环项增加 $0.8 \times 10 = 8$ dB，功率变为 $-95 + 6.02 + 88 + 1 = 0.02$ dBm，余量收窄到 $22.98$ dB——PHR 数值下降本身就是"覆盖余量在收窄"的信号，调度器据此停止加带宽、甚至下调调制与编码方案（Modulation and Coding Scheme, MCS）。
7. 负余量分支：若 $PL = 130$ dB，开环项 $0.8 \times 130 = 104$ dB，目标功率 $-95 + 6.02 + 104 + 1 = 16.02$ dBm 仍低于 $P_{\text{CMAX}}$，余量只剩 $6.98$ dB；若目标功率超过 $P_{\text{CMAX}}$，公式中的 min 截断生效，UE 以 $P_{\text{CMAX}}$ 发射，PHR 上报负值——这是"功率受限"的正式信号，也是调度器降速的最后依据。

把功率轨迹汇总成表：

| 阶段 | 发射功率 | 余量 PH | 语义 |
|:---|:---:|:---:|:---:|
| 初始（$M_{\text{RB}}=2$，$f=0$） | $-11.99$ dBm | $34.99$ dB | 上报 PHR |
| 带宽翻倍后 | $-8.98$ dBm | $31.98$ dB | 余量换吞吐 |
| TPC $+1$ dB 后 | $-7.98$ dBm | $30.98$ dB | 闭环微调 |
| 移动到 $PL=110$ dB | $0.02$ dBm | $22.98$ dB | 余量收窄信号 |

再跑一轮：调度器看到余量收窄，不再加带宽；基站测 SINR 又低 0.5 dB，再发 TPC = +1 dB → $f$ 累计到 2 → 功率 $0.02 + 1 = 1.02$ dBm → 新余量 $23 - 1.02 = 21.98$ dB，作为下一次 PHR 的上报值。第三轮：若 $PL$ 稳定、SINR 达标，TPC 发 0 dB，$f$ 保持 2，功率停在 1.02 dBm，余量停在 21.98 dB——闭环进入稳态后，PHR 的变化只随 $PL$ 与资源分配而变。这个最小数值例子只用了加减与一次对数，就把"上报 → 决策 → 调整 → 新余量"的完整闭环走了三轮：PHR 是输入，资源与 TPC 是决策，发射功率与新的余量是输出，下一轮循环从新的 PHR 开始。

### 三段的输入输出与更新时机

手算例子走通了闭环，把它拆回三段，可以看到每段的输入、输出与更新时机：

| 段 | 输入 | 输出 | 更新时机 |
|:---|:---|:---|:---|
| 开环 | $P_0$、$\alpha$、$PL$、$M_{\text{RB}}$（测量 + 配置） | 基线功率 | 每次传输前（$PL$ 变化即变） |
| 闭环 | TPC 命令（反馈） | 累计项 $f$ | 每收到一次 TPC |
| PHR | 当前发射功率、$P_{\text{CMAX}}$ | 余量数值 | 满足触发条件时 |

这张表的要点在"更新时机"列：开环随测量即时更新（快但粗），闭环随命令逐次更新（慢但准），PHR 按事件更新（触发条件见 TS 38.321 §5.4.6）。三段的时间尺度不同，正是它们必须互补的原因——用快的段兜底、用准的段校正、用事件化的段报告。三者更新时机错开，也正是它们能并行存在而不互相覆盖的原因。

### 开环误差与闭环校正的数值对比

开环的弱点是可以量化的：设 UE 的路损估计比真实值小 3 dB（测量误差），$\alpha = 0.8$ 时开环功率少发 $0.8 \times 3 = 2.4$ dB，到达功率也低 2.4 dB——误差按 $\alpha$ 缩放后直达接收端。闭环的作用是把这份误差逐次买回来：基站测出 SINR 低约 2.4 dB，按 +1 dB 步长发三次 TPC（或 +3 dB 一次），$f$ 累计 +2.4 dB 后误差归零。

数值对照：开环单独使用，稳态误差 = 测量误差 × $\alpha$（本例 2.4 dB）；开环 + 闭环，稳态误差由 TPC 步长决定（本例 ≤1 dB）；闭环单独使用，初始功率全靠猜，收敛次数 = 初始偏差 / 步长（偏差 20 dB 要 20 次 +1 dB 或 7 次 +3 dB，期间的接收质量没有保障）。这就是"开环给起点、闭环给精度"的数值含义：**单靠任何一段都不是闭环，合起来才收敛得快又准**。

### 正式定义

功率余量报告（Power Headroom Report, PHR）是 UE 按媒体接入控制（Medium Access Control, MAC）层触发条件（TS 38.321 §5.4.6）上报的报告，Type 1 余量定义为最大发射功率与当前发射功率之差：

$$
PH_{\text{Type 1}} = P_{\text{CMAX}} - P_{\text{PUSCH}}
$$

语义是"还能加多少功率"——它是调度器的调度空间度量，不是 UE 的功率请求。名称中的"余量"正是指这个差值。Type 2 余量（PUCCH 与 PUSCH 联合）用同样的差值定义，只是功率口径换成联合功率——本节的闭环模型以 Type 1 为口径。

开环与闭环的语义可以形式化地拆开：开环项 = 目标功率 + 带宽项 + 路损补偿，只依赖测量与配置、不含任何反馈；闭环项 $f(i)$ = 历次 TPC 命令的累计，只依赖反馈历史、不含任何测量。两者相加再经 $P_{\text{CMAX}}$ 截断，即为发射功率——完整公式与逐项解读见下文「PUSCH 功控公式」一节。

### 常见误解

| 误解 | 正确理解 |
|:---|:---|
| PHR 是 UE 的功率请求 | PHR 是报告不是请求——UE 只报余量，加不加资源由调度器决定 |
| 余量为负说明 UE 违规发射 | 负余量表示目标功率已超 $P_{\text{CMAX}}$ 被截断，是覆盖受限信号 |
| 余量 = 最大功率 − 到达功率 | 余量用发射功率计算（$P_{\text{CMAX}} - P_{\text{PUSCH}}$），到达功率还要再扣路损 |
| PHR 大说明信号质量好 | 余量大只说明功率空间大（如近点 UE 功率低），与信道质量无直接关系 |
| 开环项算出来就是最终功率 | 开环只是基线，还要叠加闭环累计项并经过 $P_{\text{CMAX}}$ 截断 |
| 负余量是故障信号 | 负余量是覆盖受限的常规信号——PHR 正是为把它报告给调度器而设计 |
| 开环功率越准越好，闭环可有可无 | 开环再准也有残差（测量误差 × α），闭环是残差唯一的消除手段 |
| TPC 命令值就是功率值 | TPC 是增量（δ），要累加进 $f$ 项才生效——命令值 ≠ 功率值 |

（本表针对闭环数值模型的建模口径；协议行为层面的误解见下文「常见误解」表，两表互补。）

### 接收端后果

- 基站侧到达功率对齐 → 各 UE 接收 SINR 均衡 → 调度公平与小区容量双收；功率受限 UE 的到达功率低于目标 → 其上行 MCS 必须压低，这是链路自适应的上行镜像。
- 闭环收敛代价：TPC 一次 ±1 或 +3 dB，收敛要数次调度——期间接收 SINR 波动直接影响上行译码的误块率（Block Error Rate, BLER）。
- UE 侧：功放长期满功率 → 发热与电池寿命下降；PHR 长期为零 → UE 处于覆盖边缘的硬件信号。
- 调度侧：余量大时加资源、余量小时降资源——PHR 是调度器"功率视图"的唯一输入，其上报时延直接限制调度反应速度。
- 网络侧：TPC 的步长选择（±1 或 +3 dB）与 SINR 门限是调度器参数——协议只规定命令格式，不规定生成策略（见「资料与协议边界」）。
- 数值一致性视角：本节的每个中间值都能独立重算（带宽项、余量、累计项互不依赖），手算自查比一次性套公式更容易发现单位或符号错误。
- 收敛口径：余量与 SINR 的换算以稳态为假设，TPC 过调（功率振荡）期间 PHR 会跟着波动——调度器对 PHR 的解读应带平滑窗口。
- 调度联动口径：PHR 上报与调度决策之间存在时延（上报 → MAC 处理 → 调度），闭环模型把这段时延视为零——真实系统的收敛轮数要加上这段往返。
- 工程后果：功控把"功率预算"变成调度器可读的数值——余量是预算、TPC 是支出、PHR 是对账单，三者闭环才谈得上"恰到好处的到达功率"。

### 本节的定位

本节是功控的数值底座：后文「PUSCH 功控公式」给出完整公式与逐项解读，「开环与闭环」给出两层分工的协议细节，「TPC 与 PHR」给出执行与报告的机制——本节的闭环例子是这三节的共同数值锚点。后文「示范例题」与「独立习题」的全部数值，也都可以在本节的闭环模型上重算复核。

## 功控的必要性

### 远近效应与干扰控制

| 问题 | 描述 | 功控的解法 |
|:---|:---|:---|
| 远近效应 | 近处 UE 功率过大淹没远处 UE 的信号 | 每个 UE 按路损补偿（到达功率相等） |
| 邻区干扰 | 小区边缘 UE 高功率发射干扰邻区 | 部分补偿（α<1）减少边缘功率 |
| 电池 | 过高功率浪费 UE 电量 | 只发"够用"的功率 |
| 覆盖 | 功率过低基站收不到 | 路损补偿保证到达功率 ≥ 目标 |

**核心指标是"到达功率"而非"发射功率"**：功控的目标是让基站看到的每个 UE 的信号强度接近目标值（目标接收功率 P0），而不是让 UE 都发一样大。到达功率 = 发射功率 - 路损，所以发射功率必须按路损反补偿。

### 与下行功率管理的差异

| 维度 | 下行 | 上行 |
|:---|:---|:---|
| 发射方 | 基站（统一管理） | 每个 UE（独立决策） |
| 功率分配 | 总功率按用户/信道分配 | 每 UE 按公式计算 |
| 反馈 | 无需（基站自己控制） | 需要（TPC 闭环） |
| 干扰控制 | 调度器统一协调 | 功控 + 调度联合 |

下行没有"开环功控"——基站知道自己的功率分配；上行每个 UE 不知道邻区干扰水平，必须靠"测量路损（开环）+ 接收反馈（闭环）"组合。**功控是上行链路区别于下行的最大机制差异之一**（T7.5/T15.5 的对照主线）。

### 生活类比：对讲机音量调节

功控像对讲机音量调节：开环是"按距离估算音量"（离得远就喊大声——P0+α·PL），闭环是"对方说大点/小点"（TPC 命令——现场反馈校正），PHR 是"我还能再大声多少"（余量报告——让调度员知道我还有多少余量可分配）。三者配合让通话质量刚好够用，又不吵到隔壁会议室（邻区干扰）。

## PUSCH 功控公式（38.213 §7.1.1）

### 完整公式

PUSCH 发射功率（dBm）：

$$
P_{\text{PUSCH}}(i) = \min \Big\{ P_{\text{CMAX}},\, P_0 + 10\log_{10}(2^{\mu} \cdot M_{\text{RB}}) + \alpha \cdot PL + \Delta_{\text{TF}} + f(i) \Big\}
\tag{1}
$$

（教学简化：省略载波/服务小区/BWP 索引与多面板项；§7.1.1 的完整式含 TCI 状态索引。）

### 逐项解读

| 项 | 含义 | 来源 | 教学要点 |
|:---|:---|:---|:---|
| $P_{\text{CMAX}}$ | 最大发射功率 | UE 能力/功放限制 | 公式的"天花板"——超限截断 |
| $P_0$ | 目标接收功率基准 | RRC 配置（含 P0_Nominal + P0_UE） | 开环的"基线" |
| $10\log_{10}(2^{\mu} M_{\text{RB}})$ | 带宽项 | 调度分配（RB 数 × SCS 因子） | 带宽越大功率越大（功率密度恒定） |
| $\alpha \cdot PL$ | 路损补偿 | α 配置（0-1）+ UE 测 PL | 补偿系数可调（部分补偿省干扰） |
| $\Delta_{\text{TF}}$ | 传输格式补偿 | 按 MCS（调制与编码方案，Modulation and Coding Scheme）与重复数查表 | 高码率/大重复需更多功率 |
| $f(i)$ | 闭环累计项 | TPC 命令累加 | 闭环的"执行器" |

### 带宽项的教学意义

$10\log_{10}(2^{\mu} M_{\text{RB}})$：RB 数 ×2 → 功率 +3 dB（带宽翻倍、每 RB 功率密度不变）——**功控公式保证"每 RB 功率密度"恒定**，调度器分配带宽不影响覆盖判决。SCS 因子 $2^{\mu}$ 的物理含义：子载波间隔翻倍 → 符号时间减半 → 相同功率密度下带宽等效加倍（30 kHz 相对 15 kHz 的 RB 带宽 ×2）。

### 数值实例

P0=-90 dBm、α=1、PL=100 dB、M_RB=4、μ=0、ΔTF=0、f=0、P_CMAX=23 dBm：

1. 带宽项 = $10\log_{10}(1 \times 4) = 6.02$ dB；
2. 开环功率 = -90 + 6.02 + 100 = 16.02 dBm（< P_CMAX，不截断）；
3. 到达功率 = 16.02 - 100 = -83.98 dBm = P0 + 带宽项——**目标接收功率加带宽项**（numpy 验证的数值走读）。

## 开环与闭环：两层分工

### 开环：路损补偿

开环项 = $P_0 + 10\log_{10}(2^{\mu}M_{\text{RB}}) + \alpha \cdot PL$。UE 自己完成：测下行参考信号（SSB/CSI-RS（信道状态信息参考信号，Channel State Information Reference Signal）的 RSRP（参考信号接收功率，Reference Signal Received Power））→ 已知参考信号发射功率 → 路损 = 发射功率 - 接收功率。**开环是"无反馈的粗对齐"**——路损测量有误差、干扰未知，只保证量级正确。

### 闭环：TPC 微调

闭环项 $f(i)$ 由 TPC 命令累加：

$$
f(i) = f(i-1) + \delta_{\text{TPC}}(i)
\tag{2}
$$

| TPC 命令值（2 bit 字段映射例） | 功率调整 |
|:---|:---|
| 00 | -1 dB |
| 01 | 0 dB |
| 10 | +1 dB |
| 11 | +3 dB |

基站按实际接收 SINR 与目标的差发命令（SINR 低于目标 → 加功率）——**闭环是"有反馈的细校正"**，把开环的残余误差逐次修正。两种闭环进程（adjustment state l=0/1）可同时配置，DCI 字段按配置选一个使用（多进程支持不同信道类型独立校正）。

### 部分补偿（α<1）的意义

| α | 行为 | 场景 |
|:---|:---|:---|
| 1（全补偿） | 到达功率与路损无关（完美对齐） | 噪声受限场景（覆盖优先） |
| <1（部分补偿） | 远处 UE 发射功率增长放缓 | 干扰受限场景（边缘 UE 少干扰邻区） |

**α=1 不是永远最优**：干扰受限的小区（边缘 UE 互相干扰），全补偿让边缘 UE 功率冲高、干扰加剧——部分补偿牺牲边缘覆盖换取系统容量（概念笔记的常见误解表已列）。

## PUCCH 与 SRS 功控：同源异参

### PUCCH 功控（§7.2）

$$
P_{\text{PUCCH}} = \min \Big\{ P_{\text{CMAX}},\, P_0 + \alpha \cdot PL + \Delta_{\text{FMT}} + g(i) \Big\}
\tag{3}
$$

差异对照（vs PUSCH）：

| 差异 | PUCCH | PUSCH |
|:---|:---|:---|
| 带宽项 | 无（PUCCH 固定 PRB 数，功率不随带宽变） | 有（10log₁₀(2^μ·M_RB)） |
| 格式项 | Δ_FMT（按 format 0-4 查表，T14.3 衔接） | Δ_TF（按 MCS/重复） |
| 闭环项 | $g(i)$（独立累计） | $f(i)$ |

**PUCCH 无带宽项的语义**：PUCCH 的控制资源（PRB/符号）由配置固定，不需要"带宽越大功率越大"的自适应——功率密度由 format 决定（format 3/4 长格式功率低些）。

### SRS 功控（§7.3）

SRS 功控公式与 PUSCH 同构（含带宽项），但参数集独立（`srs-PowerControl` 配置的 P0_SRS/α_SRS）且闭环项独立（$q_s$(i)）。**SRS 功率与 PUSCH 功率解耦的意义**：SRS 是探测信号，需要稳定的功率密度让基站准确测量信道——若随 PUSCH 联动，调度变化会污染测量。

### PRACH 功控（§7.4）

Msg1 前导功率 = P0_PRACH + PL + 功率爬升（ramping）——随机接入没有闭环（还没建立调度），用开环 + 重试爬升（每次失败 +2 dB 重试，T15.2 衔接）。**PRACH 功控是"纯开环 + 试探"**——接入阶段的功率策略。

## TPC 与 PHR：闭环的执行与报告

### TPC 的 DCI 携带（T14.2 衔接）

| 携带渠道 | 字段 | 作用对象 |
|:---|:---|:---|
| DCI 0_0/0_1（调度本 UE） | TPC command for scheduled PUSCH（2 bit） | 本 UE 的 PUSCH 闭环 |
| DCI 0_0/0_1（调度本 UE） | TPC command for PUCCH（2 bit） | 本 UE 的 PUCCH 闭环 |
| DCI 2_2（组公共） | 每块 2 bit TPC | 一组 UE 的 PUCCH/PUSCH（T14.2 的 2_2 格式） |
| DCI 2_3（组公共） | 每块 2 bit TPC | 一组 UE 的 SRS |

**TPC 的两类携带方式**：随调度 DCI（给被调度的 UE）与组公共 DCI（批量给一组 UE，省开销）——T14.2 的 2_2/2_3 格式在此落地。UE 按 DCI 类型与配置把 TPC 值累加进对应的闭环项（f/g/q）。

### PHR 的内容与触发（38.321 §5.4.6）

| 维度 | 内容 |
|:---|:---|
| 报告内容 | 功率余量 = P_CMAX - 当前发射功率（Type 1：PUSCH 实际功率；Type 2：PUCCH/PUSCH 联合） |
| 触发条件 | 周期性（配置周期）、路径损耗变化超门限、激活/去激活、功率受限切换等 |
| 接收方 | MAC（媒体接入控制，Medium Access Control）层处理 → 调度器 |
| 用途 | 调度器判断"还能给 UE 加多少资源"——余量大 → 加大 MCS/带宽；余量小/负 → 覆盖受限信号 |

**PHR 的调度语义**：功率余量是"调度空间"的度量——余量充足说明 UE 有功率可换吞吐（加大资源）；余量不足说明 UE 已到功率极限（覆盖受限，只能降速或换波束）。PHR 把物理层的功率信息翻译成 MAC 层的调度输入——**功控与调度的接口就在 PHR**。

## 功控进程与功率降级

### 闭环进程（adjustment state）

PUSCH 的闭环项 f 支持两个进程（l=0/1），DCI 的字段位宽与选择由配置决定：

| 进程 | 用途 | 配置 |
|:---|:---|:---|
| l=0 | 默认进程（单进程时唯一） | 默认启用 |
| l=1 | 第二进程（双闭环） | 配置 twoPUSCH-PC-AdjustmentStates 启用 |

双进程的用途：不同信道/场景用不同闭环（如数据与反馈分别校正、多波束独立校正）——每个进程有独立累计值，TPC 命令按 DCI 指示的目标进程更新。

### 功率受限时的降级行为（power scaling）

多个上行信道同时发射（PUSCH + PUCCH + SRS）且总功率超 P_CMAX 时，UE 按协议优先级降级（38.213 §7.5）：

1. PUCCH（含 HARQ-ACK（混合自动重传请求确认，Hybrid Automatic Repeat Request Acknowledgment））优先级最高——控制信息不可牺牲；
2. PUSCH 带 UCI 次之；
3. PUSCH 无 UCI 再次；
4. SRS 最低（探测可延迟）。

**降级是"功率预算下的优先级分配"**——与控制信令优先级（T14.3）一致的功率镜像：控制永远优先于数据，数据优先于探测。

## 接收端视角：功控的测量与反馈回路

### 基站侧的处理链

```mermaid
flowchart LR
    A["接收 PUSCH"] --> B["SINR 估计"]
    B --> C["与目标 SINR 比较"]
    C -->|"差 > 门限"| D["生成 TPC 命令"]
    D --> E["装入 DCI（2 bit）"]
    E --> F["发送"]
classDef default fill:#F7F9FC,stroke:#C9D4DF,color:#17212F;
```

1. 基站估计每个 UE 的接收 SINR（数据/导频联合估计）；
2. 与目标 SINR（按 MCS 与 BLER（误块率，Block Error Rate）目标设定）比较；
3. 差值超过门限 → 生成 TPC 命令（+1/+3 或 -1 dB）→ 装入下次调度的 DCI；
4. UE 收到后更新闭环项——**一次调度一个 TPC，收敛时间约数次调度**。

### 功控与 SRS 的联动

SRS（T15.3）在功控回路里的角色：**路损估计的辅助源**（下行 RSRP 为主）与**功控效果的验证**（基站从 SRS 看到调整后的信道功率）。此外 SRS 的功率密度稳定是信道测量准确的前提——SRS 功控独立（§7.3）保证测量不被 PUSCH 功率波动污染。

## 示范例题

### 例题 1：PUSCH 功率计算

P0=-90、α=1、PL=100 dB、M_RB=4、μ=0、ΔTF=0、f=0、P_CMAX=23：

**求解**（公式 (1)）：
1. 带宽项 = 10log₁₀(4) = 6.02 dB；
2. P = -90 + 6.02 + 100 + 0 + 0 = 16.02 dBm；
3. 16.02 < 23 ✓ 不限幅；
4. 到达功率 = 16.02 - 100 = -83.98 dBm。

### 例题 2：限幅场景

P0=-20、α=1、PL=60（近处 UE）、M_RB=4：功率超限吗？

**求解**：P = -20 + 6.02 + 60 = 46.02 dBm > 23 → **限幅到 23 dBm**。物理含义：UE 的功放天花板限制了发射功率——近处 UE 本可以小功率，但配置的目标功率过高（P0 配置错误或目标 SINR 过高）时会触及天花板（功率受限状态，PHR 将报告余量 0）。

### 例题 3：远近效应数值

UE-A（PL=100）与 UE-B（PL=120），α=1、P0=-90、M_RB=4：两者到达功率？

**求解**：A：-90+6.02+100-100 = -83.98 dBm；B：-90+6.02+120-120 = -83.98 dBm——**到达功率相等**（全补偿的理想结果）。实际中 B 的功率 36.02 dBm > P_CMAX 会被截断（覆盖受限），这正是 PHR 报告"余量不足"的场景。

## 引导练习（带提示）

### 练习 1：带宽项计算

M_RB 从 4 增到 8（μ=0），功率增加多少？

**提示**：10log₁₀(8/4)。（答案：+3.01 dB——带宽翻倍、功率密度不变。）

### 练习 2：α 的选择

噪声受限（小区边缘无强干扰）与干扰受限（边缘互相干扰）场景的 α 倾向？

**提示**：α=1 保证到达功率；α<1 减少边缘发射。（答案：噪声受限 α=1；干扰受限 α<1。）

### 练习 3：TPC 累计

f 从 0 起，收到 TPC 序列 [+1, +3, -1, 0]：f 最终值？

**提示**：逐次累加。（答案：f = 3 dB。）

## 独立习题（附参考答案）

### 习题 1：PUSCH 功率

P0=-95、α=0.8、PL=110、M_RB=2、μ=1、ΔTF=1、f=-2、P_CMAX=23：P 是多少？

**参考答案**：带宽项 = 10log₁₀(2¹×2) = 6.02；P = -95 + 6.02 + 88 + 1 - 2 = -1.98 dBm（< 23，不限幅）。

### 习题 2：限幅判断

同参数但 PL=90：P 是多少？

**参考答案**：P = -95 + 6.02 + 72 + 1 - 2 = -17.98 dBm——仍远低于 P_CMAX（α=0.8 部分补偿让功率随 PL 下降而下降）。

### 习题 3：远近效应

α=0.6 时，PL=100 与 PL=120 的到达功率差多少？

**参考答案**：发射差 = 0.6×(120-100) = 12 dB，到达功率差 = 12 - 20 = -8 dB——远处 UE 到达功率低 8 dB（部分补偿的代价：边缘覆盖下降，换来干扰减少）。

## 常见误解

| 误解 | 正确理解 |
|:---|:---|
| 上行功控和下行一样 | 下行固定功率+调度控制；上行开环+闭环两层（UE 独立决策） |
| 功控只在物理层 | TPC 在 DCI（物理层），PHR 在 MAC 层（38.321）——跨层机制 |
| α=1 一定最好 | 干扰受限场景部分补偿（α<1）更优 |
| PHR 越大越好 | 余量大说明可加资源；长期满功率说明覆盖边缘 |
| 功控只调发射功率 | 功控目标是到达功率（发射-路损）——路损测量是开环的核心 |
| 闭环能完全替代开环 | 闭环收敛慢（TPC 逐次微调），开环提供快速基线——两层缺一不可 |
| 功率受限时全部等比例降 | 按优先级降级（控制>数据>探测）——控制信息不可牺牲 |
| PHR 是调度器才用的 | UE 也用它自检覆盖（余量长期为 0 说明在覆盖边缘） |
| TPC 一步到位 | TPC 逐次微调（±1/+3 dB），收敛需数次调度——开环先粗对齐 |
| 上行功率与下行无关 | 开环的路损测量来自下行参考信号（RSRP）——上下行在功控上耦合 |
| 闭环进程越多越好 | 双进程有配置与信令开销——默认单进程，按场景启用第二进程 |

## 常见错误

| 错误 | 正确理解 |
|:---|:---|
| 忘记 P_CMAX 限幅 | 公式有 min{P_CMAX, ·}——功率受限是常态（PHR 的触发场景） |
| 把到达功率当发射功率 | 到达 = 发射 - 路损——远近效应的正确理解 |
| 混淆 f/g/q 闭环项 | PUSCH 用 f、PUCCH 用 g、SRS 用 q——独立累计 |
| 认为 TPC 只有随路 DCI | 组公共 DCI 2_2/2_3 批量携带 TPC（省开销） |
| 忽略 ΔTF 项 | MCS 高/重复多时 ΔTF 显著（高码率需更多功率） |
| 把 PHR 当物理层信号 | PHR 是 MAC 层报告（38.321 §5.4.6）——跨层机制 |
| 忽略功率受限的常态性 | P_CMAX 截断是常态（覆盖边缘），PHR 就是为它设计的 |

## 内嵌 numpy 验证

下列断言先实跑通过再写入本节，输出与断言一致（功控计算 + 限幅 + 远近效应）：

```python
import numpy as np

def pusch_power(P0, alpha, PL, M_RB, mu, delta_tf, f, P_CMAX):
    """P_PUSCH = min{P_CMAX, P0 + 10log10(2^mu*M_RB) + alpha*PL + delta_tf + f} [dBm]"""
    bw = 10*np.log10(2**mu * M_RB)
    p = P0 + bw + alpha*PL + delta_tf + f
    return min(p, P_CMAX), p

# (1) 基础例：P0=-90, alpha=1, PL=100, M_RB=4
p1, p1_raw = pusch_power(-90, 1.0, 100, 4, 0, 0.0, 0.0, 23)
assert abs(p1 - (-90 + 10*np.log10(4) + 100)) < 1e-9
assert abs(p1 - 16.02) < 0.01

# (2) 限幅：P0=-20、PL=60 时 raw=46 > P_CMAX=23 -> 截断
p2, p2_raw = pusch_power(-20, 1.0, 60, 4, 0, 0.0, 0.0, 23)
assert p2 == 23 and p2_raw > 23

# (3) 远近效应（未限幅 raw）：alpha=1 全补偿 -> 到达功率相等
_, near_raw = pusch_power(-90, 1.0, 100, 4, 0, 0.0, 0.0, 100)
_, far_raw = pusch_power(-90, 1.0, 120, 4, 0, 0.0, 0.0, 100)
assert abs((near_raw - 100) - (far_raw - 120)) < 1e-9

# (4) 闭环叠加：f=+3 dB
p_open, _ = pusch_power(-90, 1.0, 100, 4, 0, 0.0, 0.0, 23)
p_closed, _ = pusch_power(-90, 1.0, 100, 4, 0, 0.0, 3.0, 23)
assert abs(p_closed - p_open - 3.0) < 1e-9

# (5) 部分补偿：alpha=0.6 功率低于 alpha=1
p_a1, _ = pusch_power(-90, 1.0, 110, 4, 0, 0.0, 0.0, 23)
p_a06, _ = pusch_power(-90, 0.6, 110, 4, 0, 0.0, 0.0, 23)
assert p_a06 < p_a1

print(f"T15.4_OK p_open={p1:.2f}dBm p_cmax_clip={p2:.2f}dBm "
      f"near_arr={near_raw-100:.2f} far_arr={far_raw-120:.2f} "
      f"closed_delta={p_closed-p_open:.2f}dB alpha06={p_a06:.2f}dBm < alpha1={p_a1:.2f}dBm")
```


## 本节与前序知识的接线图

功控站在四条线的交汇点：**测量线**（T15.3 SRS 与下行 RSRP 提供路损/信道信息）、**执行线**（T14.2 的 TPC 字段是闭环命令的载体）、**格式线**（T14.3 的 PUCCH format 决定 Δ_FMT）、**接入线**（T15.2 的 Msg3 用开环功率起步，功控从接入时刻开始）。向后接线：**调度线**（PHR 报告给调度器决定资源——Scheduler 概念笔记）、**对照线**（T15.5 的 DL/UL 功控差异收束）。

### 功控与调度的联合视角

功控与调度（Scheduler 概念笔记）在三个层面联动：PHR 决定"能加多少资源"（调度空间）、TPC 反映"目标 SINR 是否达到"（调度质量）、功率受限的 UE 需要调度器降速或换资源（调度策略）。**功控不是孤立的物理层机制——它是调度器的"功率视图"**，PHR 是这两层之间的翻译器。

## 资料与协议边界

## 小结

上行功控用"开环补偿 + 闭环微调 + PHR 报告"三段式解决"发多大功率"的问题：开环按路损补偿定基线（P0 + α·PL），闭环用 TPC 累计修正（f 项），PHR 把余量反馈给调度器。公式（38.213 §7.1）逐项对应物理量——P_CMAX 天花板、带宽项保持功率密度、ΔTF 按格式补偿。PUCCH/SRS/PRACH 各有独立参数集（同源异参），TPC 经随路 DCI 或组公共 DCI 携带。

本节的三个衔接：**T15.3**（SRS 是功控效果的测量与验证）、**T14.2**（TPC 字段的 DCI 载体）、**T14.3**（PUCCH 功控的 format 关联）。下一节 T15.5 是阶段 3 的收官：**NR 上下行差异专篇**——把 T7.5 的 LTE 对照升级为 NR 全维度系统对照，M14/M15 两个批次的知识在此收束。

## 本节在阶段 3 中的位置

阶段 3 推进到收束：波形（T15.5 深化）→ T15.2（接入）→ T15.3（探测）→ T15.4（功控）。功控是"调度闭环"的执行侧：SRS 给测量（T15.3）、TPC 给执行（T14.2 的 DCI）、PHR 给反馈（MAC 层）——**功率维度把物理层（公式/测量）与 MAC 层（调度/报告）串成了闭环**。它也是上行链路"功率-资源-速率"三角的最后一块：功率受限时调度器降速（PHR 的语义），这正是链路自适应（Link_Adaptation 概念笔记）的上行镜像。
