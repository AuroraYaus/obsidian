# T8.0 TS 38.212 Chapter 5 接收侧地图
## 本节学习目标

本节精读 3GPP TS 38.212 Rel-19 `38212-j30` 第 5 章，把它从“发送端信道编码流程”翻译成“NR 接收端译码流程”。第 5 章是 NR 信道编码总过程：循环冗余校验、code block segmentation、channel coding、rate matching 和 code block concatenation 都在这里给出通用规则，后续上行共享信道、下行共享信道、上行控制信息、下行控制信息等章节再调用这些规则。

学完本节后，应能做到：

- 解释 TS 38.212 Chapter 5 各节在接收端分别变成什么模块。
- 区分 LDPC（低密度奇偶校验码，Low-Density Parity-Check Code）、Polar（极化码，Polar Code）和 small block lengths 三类分支，避免把 small block 普通化为 Polar CA-SCL（CRC 辅助连续消除列表译码，CRC-Aided Successive Cancellation List）或 LDPC。
- 把 [[T3.1_LTE_NR_CRC_families|T3.1]]/[[T3.4_NR_LDPC_segmentation_rules|T3.4]]/[[T3.5_NR_Polar_segmentation_crc|T3.5]]/T8/T9/T10/T11 回链到 Chapter 5 的具体位置。
- 说明哪些内容是协议强制比特序列规则，哪些是接收端等价逆流程，哪些是实现策略。

## 前置知识检查

| 前置项 | 本节要求 |
|:---|:---|
| CRC（循环冗余校验，Cyclic Redundancy Check） | 知道 CRC 是 error detection，接收端检查余数或等价 syndrome。 |
| TB（传输块，Transport Block）/CB（码块，Code Block） | 知道 TB 可能被分段成 CB，CB 可能有 CB CRC 和 filler。 |
| LDPC | 知道 NR 数据业务使用 LDPC（低密度奇偶校验码，Low-Density Parity-Check Code），具体矩阵由 BG（基图，Base Graph）、Zc 和 shift table 决定。 |
| Polar | 知道 NR 控制信息可能使用 Polar（极化码，Polar Code），SCL（连续消除列表译码，Successive Cancellation List）/CA-SCL 是接收端实现算法。 |
| Rate recovery | 知道发送端 rate matching 在接收端要反向恢复 LLR（对数似然比，Log-Likelihood Ratio）位置。 |

如果这些还不熟，先抓住一句话：TS 38.212 Chapter 5 不是一个 decoder 算法列表，而是规定“哪些比特如何被加 CRC、分块、编码、速率匹配和拼接”；接收端必须实现等价逆过程。

## Chapter 5 的协议前因后果

TS 38.212 Chapter 5 位于信道编码分册的通用过程。它前面不负责调度资源，也不负责物理信道的 RE（资源元素，Resource Element）映射；它后面由 UL-SCH（上行共享信道，Uplink Shared Channel）、DL-SCH（下行共享信道，Downlink Shared Channel）、UCI（上行控制信息，Uplink Control Information）、DCI（下行控制信息，Downlink Control Information）等具体章节调用。读它时要把因果链分清：

```text
调度和高层配置给出 A、Qm、R、TBS、RV、HARQ/CBG/context
  -> TS 38.212 具体信道章节确定 payload 和 CRC 调用方式
  -> Chapter 5 通用过程生成编码比特序列
  -> TS 38.211 物理映射和调制承载这些比特
```

接收端逆向：

```text
均衡/解调得到 LLR
  -> 反映射和 rate recovery
  -> 选择 LDPC/Polar/small-block decoder
  -> 检查 CRC
  -> 去 CB 边界和 filler
  -> 输出 TB 或控制信息
```

因此，Chapter 5 是译码器结构的核心证据源，但不是完整 descriptor 的唯一来源。`Qm`、目标码率、TBS（传输块大小，Transport Block Size）、RV（冗余版本，Redundancy Version）和 CBG（码块组，Code Block Group）仍需要 TS 38.214；HARQ（混合自动重传请求，Hybrid Automatic Repeat Request）生命周期还需要 MAC（媒体接入控制层，Medium Access Control）/RRC（无线资源控制，Radio Resource Control）上下文。

## §5.1 CRC 接收侧地图

TS 38.212 §5.1 给出通用 CRC 计算规则。接收端使用它时，要先知道当前调用者是谁：

| 调用者 | CRC 角色 | 接收端检查 |
|:---|:---|:---|
| UL-SCH/DL-SCH TB CRC | 整个 TB 的最终交付边界。 | 所有 CB 去 CRC/filler 并拼接后，检查 TB CRC。 |
| LDPC CB CRC | 分段时对每个 CB 附加的局部检错。 | 有 CB CRC 时逐 CB 检查；无 CB CRC 时不能伪造该层状态。 |
| Polar UCI CRC | 控制信息检错，也辅助 CA-SCL 路径筛选。 | 候选路径按 CRC 过滤，再选 path metric。 |
| DCI CRC/RNTI（无线网络临时标识，Radio Network Temporary Identifier） | DCI 盲检和归属边界。 | 不只是 CRC pass，还要处理 RNTI context。 |

接收端日志至少要记录 `crc_scope`、`crc_len`、`crc_poly_id`、`input_bit_count`、`pass_fail` 和 `context_hash`。如果只写 `crc_fail`，后续无法判断是 TB CRC、CB CRC 还是 Polar final selector 失败。

## §5.2 分段和 CB CRC 接收侧地图

§5.2 分成 Polar coding 和 LDPC coding 两条子分支。二者都叫 code block segmentation，但对象不同。

| 子节 | 适用对象 | 接收端 descriptor | 后续章节 |
|:---|:---|:---|:---|
| §5.2.1 Polar coding | UCI/DCI 等 Polar 控制信息 | `A/K/E/N`、CRC length、interleaver flag、frozen/information set context | [[T3.5_NR_Polar_segmentation_crc|T3.5]]、[[T10.1_NR_Polar_decoder_chain_overview|T10.1]]-[[T10.8_NR_Polar_decoder_edge_cases|T10.8]] |
| §5.2.2 LDPC coding | UL-SCH/DL-SCH/PCH 数据链路 | `A/B/C/L/K'/K/Zc/BG/filler/CB CRC present` | [[T3.4_NR_LDPC_segmentation_rules|T3.4]]、[[T8.1_NR_LDPC_decoder_chain_overview|T8.1]]-[[T8.8_NR_LDPC_decoder_numeric_walkthrough|T8.8]]、[[T9.1_NR_LDPC_rate_recovery_overview|T9.1]]-[[T9.6_NR_LDPC_decoder_edge_cases|T9.6]] |

接收端不要把 LDPC 的 filler 规则套到 Polar，也不要把 Polar 的 frozen bit 套到 LDPC。它们都在 Chapter 5，但属于不同编码家族。

### LDPC 小型教学例子

若 TB 加 CRC 后长度 $B$ 超过 LDPC 最大 code block size，§5.2.2 会产生 $C>1$ 个 CB，并给每个 CB 加 24 bit CB CRC。接收端就必须：

1. 按 descriptor 切出每个 CB 的 LLR。
2. 对每个 CB 做 LDPC 译码。
3. 去 filler。
4. 若 `cb_crc_present=true`，检查 CB CRC。
5. 按 CB index 拼回 TB candidate。
6. 检查 TB CRC。

如果第 4 步被跳过或被错误执行，最终 TB CRC 失败时很难定位是哪一个 CB 的问题。

### Polar 小型教学例子

若 UCI payload 进入 Polar 分支，§5.2.1 会决定 CRC 和 segmentation 入口，§5.3.1 再决定 Polar coding。接收端要把 payload、CRC 和 frozen mask 视为一个整体。CA-SCL 输出多条候选路径时，CRC 是最终选择的一部分，不是事后日志。

## §5.3 Channel Coding 接收侧地图

TS 38.212 §5.3 有三个关键分支。

| 分支 | 协议证据 | 接收端实现 | 不适用边界 |
|:---|:---|:---|:---|
| Polar coding | `content.md:815-943`，Table 5.3.1.1-1，Table 5.3.1.2-1 | SC/SCL/CA-SCL，frozen mask，reliability sequence，path metric，CRC selector | 不用于 NR 数据 TB 的 LDPC CB。 |
| LDPC coding | `content.md:945-989`，Table 5.3.2-1/2/3 | BG/Zc/QC parity-check matrix，BP（置信传播，Belief Propagation）/Min-Sum/layered schedule | 不用于 DCI 或普通 UCI Polar 分支。 |
| Small block lengths | `content.md:991-1017`，Table 5.3.3.1-1/5.3.3.2-1/5.3.3.3-1 | 小负载 block coding 逆处理或查表式判决 | 不是 Polar CA-SCL 的普通小码长模式，也不是 LDPC。 |

§5.3 先给 coding scheme 表，再给三类编码。[[T10.8_NR_Polar_decoder_edge_cases|T10.8]] 特别需要这里的边界：small block lengths 是协议独立分支。不能因为它也处理短控制信息，就把它写成“Polar list size 很小”。

## §5.4 Rate Matching 接收侧地图

发送端 rate matching 决定哪些编码比特被发送、顺序如何、是否重复。接收端 rate recovery 必须按相反语义处理 LLR。

| 操作 | 发送端含义 | 接收端 LLR 状态 |
|:---|:---|:---|
| puncturing | 某些母码位置不发送。 | 这些位置没有证据，初始化为 $0$。 |
| shortening | 某些位置被强约束为已知值。 | 用强可靠 LLR 或专门 mask 表示，不等同普通未知。 |
| repetition | 同一母码位置多次发送。 | 相同位置 LLR 累加，并按定点策略饱和。 |
| bit interleaving | 改变编码比特到调制 bit-channel 的对应关系。 | 先反交织，再放回 decoder 输入。 |
| circular buffer RV | 不同 redundancy version 选择不同起点和区域。 | 按 RV 起点恢复地址，并与 soft buffer 合并。 |

LDPC 的 §5.4.2 明确使用 circular buffer、$N_{\mathrm{cb}}$、$E$、RV 起点 $k_0$ 和 bit interleaving。Polar 的 §5.4.1 也有 sub-block interleaving、bit selection 和 coded-bit interleaving，但地址空间和初始化规则不同。[[T11.2_LTE_NR_rate_matching_comparison|T11.2]] 会做横向比较。

## §5.5 Code Block Concatenation 接收侧地图

发送端 concatenation 把每个 CB 的 rate matching 输出拼成一个连续序列。接收端要反过来切分。最小调试字段如下：

| 字段 | 为什么需要 |
|:---|:---|
| `C` | 一共有多少个 CB。 |
| `E_r` | 第 r 个 CB 本次接收多少个 LLR。 |
| `cb_index` | 拼接和重组顺序。 |
| `cbg_id` / `scheduled` | CBG 部分重传场景下哪些 CB 本次真的有新观测。 |
| `tb_epoch` | 防止旧 TB 的 soft buffer 与新 TB 混合。 |

如果 `E_r` 切分错，后续 LDPC 或 Polar core 可能依然运行，但 LLR 已经错位。最终表现常常是所有 CRC 都失败，且 syndrome 行为没有稳定规律。

## 最小接收端流程

```python
def nr_chapter5_receive(task, llr_stream):
    blocks = split_by_code_block(llr_stream, task.E_per_cb)
    decoded_blocks = []
    for r, llr in enumerate(blocks):
        if task.family == "LDPC":
            mother_llr = ldpc_rate_recover(llr, task.ldpc[r])
            cb_bits = ldpc_decode(mother_llr, task.ldpc[r])
            cb_payload = remove_ldpc_filler_and_optional_cb_crc(cb_bits, task.ldpc[r])
        elif task.family == "POLAR":
            polar_llr = polar_rate_recover(llr, task.polar)
            cb_payload = polar_ca_scl_decode_and_select(polar_llr, task.polar)
        elif task.family == "SMALL_BLOCK":
            cb_payload = small_block_decode(llr, task.small_block)
        else:
            raise ValueError("unknown coding family")
        decoded_blocks.append(cb_payload)
    return check_final_crc_and_deliver(decoded_blocks, task.final_crc)
```

这个伪代码省略了软缓存、HARQ、CBG 和定点饱和，但它保留了 Chapter 5 的核心分支：不要把所有对象都送进同一个 decoder。

## 常见错误

| 错误 | 后果 | 定位方法 |
|:---|:---|:---|
| 把 small block 当 Polar CA-SCL | 使用不存在的 frozen mask 或 CRC selector，输出语义错。 | 检查 TS 38.212 §5.3.3 是否被误路由。 |
| 把 CB CRC 当必然存在 | 单 CB 或未分段场景日志出现假 pass/fail。 | descriptor 增加 `cb_crc_present`。 |
| LDPC 和 Polar rate recovery 混用 | LLR 地址和初始化规则错。 | 对比 §5.4.1 与 §5.4.2 的对象。 |
| 只记录 `crc_fail` | 无法区分 TB、CB、UCI、DCI/RNTI 失败。 | 日志加入 `crc_scope` 和 `context_type`。 |
| 把 TS 38.214 字段写成 TS 38.212 算法字段 | descriptor 来源混乱。 | 字段表分协议编码、调度、MAC/RRC、实现策略。 |

## 自测题

1. TS 38.212 §5.3.3 small block lengths 为什么不能简单归入 Polar？
2. §5.4 的 puncturing 在接收端为什么不是“删除一个位置”？
3. 如果所有 CB CRC 通过但 TB CRC 失败，优先怀疑哪些对象？
4. 为什么 Chapter 5 不能单独给出完整 HARQ soft buffer descriptor？

## 自测题参考答案

1. §5.3.3 有独立的 small block encoding 表和 basis sequence 规则，不使用 Polar frozen set、SC/SCL path metric 或 CA-SCL final selector。
2. decoder 输入仍需要母码位置。punctured 位置没有观测，应初始化为中性 LLR 或由 mask 表示，而不是让后续地址整体左移。
3. 优先怀疑 CB 拼接顺序、filler 删除、TB CRC 输入边界、多 codeword/TB 上下文或错误的 payload 截取。
4. HARQ process、RV 调度、CBG、NDI（新数据指示，New Data Indicator）和高层 soft buffer 生命周期还来自 TS 38.214、MAC 和 RRC，Chapter 5 只给编码和 rate matching 的通用规则。
