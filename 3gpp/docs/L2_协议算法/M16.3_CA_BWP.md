# M16.3 载波聚合与 BWP：多载波调度与带宽自适应

## 本节学习目标

M16.1 讲了单载波的调度与 HARQ（混合自动重传请求，Hybrid Automatic Repeat Request），M16.2 讲了空间维度（波束）。本节讲调度的**多载波与带宽维度**：载波聚合（CA，Carrier Aggregation）把多个载波（CC，分量载波，Component Carrier）聚合给一个 UE——吞吐成倍；BWP（带宽部分，Bandwidth Part）在单载波内划分带宽子集——带宽自适应（大带宽能力 UE 用小带宽省电）。

CA 的调度语义：每个 CC 独立调度（每 CC 独立 HARQ 进程与 k1），DCI 的载波指示字段（CIF）实现跨载波调度（T14.2 衔接）；BWP 的调度语义：DCI 的 BWP 指示字段切换活动 BWP（T14.2 衔接），切换改变带宽、功率密度与调度粒度。**CA 是"多载波并行"，BWP 是"单载波内伸缩"**——两者都是"调度资源的组织方式"的扩展。

学完本节后，应能做到：

- 说出 CA 的结构（PCell/SCell、CC 数上限）与动机（吞吐聚合），并完成多 CC HARQ 时序仿真。
- 说出跨载波调度机制（CIF 字段，T14.2 衔接）与每 CC 独立 HARQ 的语义。
- 说出 BWP 的概念（带宽子集、活动 BWP、BWP 切换）与省电动机，完成带宽/功率换算。
- 说出 BWP 切换对调度的影响（DCI 的 BWP 指示字段）与休眠（DRX 衔接）。

## 载波聚合：多载波并行

### 结构与动机

| 要素 | 内容 |
|:---|:---|
| PCell（主小区） | 主载波（承载 RRC/安全/随机接入） |
| SCell（辅小区） | 聚合的辅载波（数据为主，可激活/去激活） |
| CC 数 | 最多 16 个（Rel-15 起） |
| 动机 | 多载波并行 → 吞吐聚合（带宽扩展） |

**CA 的语义**：一个 UE 同时使用多个 CC——每个 CC 独立调度（独立 DCI、独立 HARQ 进程、独立 k1）。PCell 承担控制面（接入/配置），SCell 补充数据面。

### 跨载波调度（CIF）

| 调度方式 | PDCCH 位置 | 调度目标 | CIF 字段 |
|:---|:---|:---|:---|
| 同载波调度 | CC i 的 PDCCH | CC i 的 PDSCH/PUSCH（物理上行共享信道，Physical Uplink Shared Channel） | 无/0 |
| 跨载波调度 | 调度载波的 PDCCH | 目标 CC 的 PDSCH/PUSCH | 3 位（CIF 指示目标 CC） |

**跨载波调度的语义**：一个 CC 的 PDCCH 可以调度另一个 CC 的数据——CIF（载波指示字段，Carrier Indicator Field）告诉 UE"这条 DCI 调度哪个 CC"（T14.2 的 0/3 位字段）。省 PDCCH 资源（一个 CC 管多个 CC 的调度）但增加 DCI 尺寸。

### 多载波 HARQ（numpy 验证的数值走读）

每 CC 独立 HARQ 状态机：numpy 验证实现 3 CC（PCell + 2 SCell），每 CC 8 进程、独立 k1（4/5/6）——60 slot 轮转调度，每 CC 进程覆盖完整、反馈时隙 = 传输时隙 + k1（CC 相关）。**每 CC 的 k1 独立**：不同 CC 的反馈时序不同（各 CC 帧结构/时延独立）——接收端按 CC 分别管理软缓存与反馈。

## BWP：带宽自适应

### BWP 概念

| 要素 | 内容 |
|:---|:---|
| BWP | 载波内的一组连续 PRB（带宽子集） |
| 活动 BWP | 当前使用的 BWP（每 CC 一个活动 BWP） |
| BWP 切换 | DCI 的 BWP 指示字段切换活动 BWP（T14.2 衔接） |

**BWP 的动机**：UE 能力（射频带宽）可能小于载波带宽——大带宽载波（100 MHz）给能力受限 UE 分配一个小子集（20 MHz）；且小带宽省电（射频前端带宽越小功耗越低）。

### 带宽与功率换算（numpy 验证的数值走读）

| 换算 | 数值 |
|:---|:---|
| 100 MHz / 30 kHz → PRB 数 | 273（协议值，含保护带） |
| 20 MHz / 30 kHz → PRB 数 | 51 |
| 带宽比 | 5:1 |
| 功率密度相同时的功率比 | 10log₁₀(5) ≈ 7 dB |

**BWP 切换的语义**：从 100 MHz 切到 20 MHz——PRB 273 → 51，相同功率密度下功耗降 7 dB（功放预算，T15.4 衔接）。**带宽自适应 = 功耗自适应**：数据少时用小 BWP 省电（DRX 衔接），数据多时切大 BWP 提吞吐。

### BWP 休眠与省电

| 机制 | 内容 |
|:---|:---|
| BWP 切换 | 大 BWP ↔ 小 BWP（按业务动态切换） |
| BWP 休眠（dormancy） | SCell 的 BWP 进入休眠（停止监听 PDCCH）——省电 |
| 与 DRX 衔接 | DRX 关断接收 + 小 BWP 降低功耗——联合省电 |

**BWP 的调度影响**：切换后调度解释基准变化（频域资源分配位宽、MCS 表、功控带宽项全部按新 BWP 重解释）——T14.2 的 BWP 指示字段正是切换的通道，T15.4 的带宽项随 BWP 变化。

### 生活类比：多车道高速公路

CA 像多条平行高速公路（每个 CC 一条路）：车辆（数据）可以同时在多条路上跑（并行调度），每条路有独立的收费站（HARQ 进程）；BWP 像一条路上的"可变车道"：车少时只开几条车道（小 BWP 省电），车多时全开（大 BWP 提吞吐）——切换车道由调度中心（DCI 指示）决定。

## 与 M16.1 的衔接：调度语义扩展

| 维度 | 单载波（M16.1） | 多载波（CA） | 带宽（BWP） |
|:---|:---|:---|:---|
| 资源 | RBG/VRB（单 CC） | 每 CC 独立 RBG/VRB | 活动 BWP 内的 RBG/VRB |
| HARQ | 8 进程 | 每 CC 8 进程 | 不改变（同 CC） |
| k1 | 单一 | 每 CC 独立 | 不改变 |
| DCI 字段 | FDRA/MCS/进程 | + CIF（跨载波） | + BWP 指示 |

**调度的三维扩展**：M16.1（时频）→ M16.2（空间波束）→ 本节（多载波 + 带宽）——调度的完整维度在 M16 系列里收齐。

## 示范例题

### 例题 1：跨载波调度

CC 0 的 PDCCH 调度 CC 2 的 PDSCH：CIF 字段值？

**求解**：CIF = 2（指示目标 CC）——UE 按 CIF 解析调度目标，PDSCH 在 CC 2 上接收。

### 例题 2：BWP 切换

100 MHz 载波，UE 从 273 PRB 的 BWP 切到 51 PRB：PRB 数与功耗变化？

**求解**：273 → 51 PRB；带宽比 5:1 → 相同功率密度下功耗降 10log₁₀(5) ≈ 7 dB。

### 例题 3：多 CC 反馈

CC 0/1/2 的 k1 分别为 4/5/6：slot 10 在 CC 1 的传输何时反馈？

**求解**：10 + 5 = slot 15 反馈——每 CC 独立时序。

## 引导练习（带提示）

### 练习 1：PCell 的角色

PCell 与 SCell 的分工？

**提示**：控制面 vs 数据面。（答案：PCell 承载 RRC/安全/随机接入；SCell 补充数据。）

### 练习 2：跨载波调度的代价

跨载波调度的优点与代价？

**提示**：PDCCH 资源 vs DCI 尺寸。（答案：省 PDCCH（一 CC 管多 CC）；代价 CIF 增加 DCI 尺寸 3 位。）

### 练习 3：BWP 切换的时机

什么场景切小 BWP？

**提示**：业务量 vs 功耗。（答案：数据少/待机时切小 BWP 省电（射频带宽功耗）；数据多切大 BWP 提吞吐。）

## 独立习题（附参考答案）

### 习题 1：CC 数

Rel-15 起的最大 CC 数？

**参考答案**：16 个（每 UE）——吞吐聚合的扩展空间。

### 习题 2：CIF 位宽

跨载波调度时 CIF 位宽与可指示 CC 数的关系？

**参考答案**：3 位 → 最多 8 个目标 CC（含自身）。

### 习题 3：BWP 与功率

50 MHz → 10 MHz BWP 切换的功耗变化？

**参考答案**：带宽比 5:1 → 10log₁₀(5) ≈ 7 dB 功耗下降（相同功率密度）。

## 常见误解

| 误解 | 正确理解 |
|:---|:---|
| CA 增加单 CC 带宽 | CA 聚合多个 CC——每 CC 带宽不变，吞吐聚合 |
| 所有 CC 用同一 k1 | 每 CC 独立 k1（帧结构/时延独立） |
| BWP 是负载均衡 | BWP 是带宽子集（能力适配 + 省电）——不是多用户分配 |
| CIF 与 BWP 指示相同 | CIF 选 CC、BWP 指示选活动 BWP——不同字段不同语义 |

## 常见错误

| 错误 | 正确理解 |
|:---|:---|
| 混淆 PCell/SCell | PCell 控制面（接入/配置）、SCell 数据面（可激活/去激活） |
| 忽略跨载波调度的 CIF | 无 CIF 时 PDCCH 只调度本 CC——跨载波必须有 CIF |
| 认为 BWP 切换瞬时无开销 | 切换需重配置接收链（带宽/采样率）——有切换时延 |
| 忘记每 CC 独立 HARQ | 每 CC 8 进程独立软缓存（多载波 × 进程数 = 总软缓存） |

## 内嵌 numpy 验证

下列断言先实跑通过再写入本节，输出与断言一致（多 CC HARQ + BWP 带宽换算）：

```python
import numpy as np

rng = np.random.default_rng(13)

# (1) 多 CC HARQ：每 CC 独立进程与 k1
N_CC = 3
N_PROC_PER_CC = 8
k1 = {cc: 4 + cc for cc in range(N_CC)}   # 每 CC 独立 k1（4/5/6）
n_slots = 60
acks = {cc: [] for cc in range(N_CC)}
for s in range(n_slots):
    cc = s % N_CC
    p = (s // N_CC) % N_PROC_PER_CC
    ok = rng.random() < 0.8
    acks[cc].append((p, s, ok))

# 断言：每 CC 进程轮转覆盖全部 8 进程
for cc in range(N_CC):
    procs = [x[0] for x in acks[cc]]
    assert len(set(procs)) == N_PROC_PER_CC
# 反馈时隙 = 传输时隙 + k1（CC 相关）
fb = {cc: [(s, s + k1[cc], ok) for (p, s, ok) in acks[cc]] for cc in range(N_CC)}
assert all(f[1] >= f[0] for cc in range(N_CC) for f in fb[cc])

# (2) BWP 带宽与功率（协议值：100MHz/30kHz -> 273 PRB，20MHz -> 51 PRB）
prb1, prb2 = 273, 51
power_reduction_db = 10*np.log10(100/20)
assert prb1 == 273 and prb2 == 51
assert abs(power_reduction_db - 6.99) < 0.01

print(f"M16.3_OK cc_harq: 3CC independent k1={[k1[c] for c in range(N_CC)]} "
      f"procs_per_cc={N_PROC_PER_CC} | bwp: {prb1}PRB->{prb2}PRB "
      f"power_reduction={power_reduction_db:.1f}dB")
```

输出：

```text
M16.3_OK cc_harq: 3CC independent k1=[4, 5, 6] procs_per_cc=8 | bwp: 273PRB->51PRB power_reduction=7.0dB
```

## 小结

CA 用多 CC 并行调度提升吞吐（每 CC 独立 HARQ 与 k1，CIF 实现跨载波调度），BWP 用带宽子集实现能力适配与省电（切换改变 PRB 数与功耗，273→51 PRB 降 7 dB）。调度的三维扩展在 M16 系列收齐：M16.1 时频、M16.2 空间、本节多载波 + 带宽。

下一节 M16.4 是本系列收官：**MAC（媒体接入控制，Medium Access Control）层映射**——把逻辑信道 → 传输信道 → 物理信道的映射与 MAC PDU 结构讲清，收束调度/控制/数据的协议全景。

## 本节在 M16 系列中的位置

M16 系列推进到第三站：M16.1（调度/HARQ）→ M16.2（波束）→ M16.3（CA/BWP，本节）→ M16.4（MAC 映射收官）。本节的 CA/BWP 是"调度资源组织"的扩展——M16.4 将把资源组织放进 MAC（媒体接入控制，Medium Access Control）层的完整信道映射。
