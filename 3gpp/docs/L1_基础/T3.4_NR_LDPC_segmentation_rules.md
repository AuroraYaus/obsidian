# T3.4 NR LDPC 分段规则：基图、提升大小、码块 CRC 与填充位
## 本节学习目标

T3.3 已经精读了 LTE Turbo的码块分段。本节切换到 NR 数据链路采用的低密度奇偶校验码。LDPC 的名字来自它的校验矩阵：矩阵中绝大多数位置为 0，只有少数位置为 1。工程上，这种稀疏性让译码器可以在变量节点和校验节点之间迭代传递软信息，而不是每次处理一个密集的大矩阵。

本节只关注 LDPC 译码前必须恢复的协议结构：传输块经过传输块循环冗余校验以后，如何被 TS 38.212 分成一个或多个码块，每个 CB 是否附加 CB CRC，如何选择基图、提升大小和填充位。真正的置信传播、Min-Sum 和层化译码调度会在 T8 展开；但如果本节的分段参数错了，后面的 LDPC 译码器即使算法正确，也会在错误的矩阵尺寸和错误的软信息边界上运行。


- 解释 NR 数据链路中 BG1/BG2、$K_{\mathrm{cb}}$、$C$、$L$、$B'$、$K'$、$K_b$、$Z_c$、$K$ 和 $F$ 的含义。
- 读懂 TS 38.212 §6.2.2/§7.2.2 的 LDPC base graph selection 与 §5.2.2 分段之间的前后关系。
- 解释 Table 5.3.2-1 的 lifting size set、Table 5.3.2-2/3 的移位系数表如何影响接收端 LDPC 矩阵尺寸。
- 用一个 BG1 例子和一个 BG2 例子手算码块数量、提升大小和填充位数量。
- 说明接收端在速率恢复、LDPC 译码、CB CRC、filler 删除和 TB CRC 之间应保存哪些描述符。

## NR LDPC 分段的协议链路

NR 的用户数据主要通过 UL-SCH 和 DL-SCH 传输。TS 38.212 对上下行数据链路给出相似的调用顺序：

```text
MAC 交付 TB
  -> TB CRC attachment
  -> LDPC base graph selection
  -> Code block segmentation and code block CRC attachment
  -> 每个 CB individually LDPC encoded
  -> Rate matching
  -> Code block concatenation
```

接收端反向处理：

```text
解调与均衡得到 LLR
  -> 按 HARQ/RV/Qm 做 LDPC 速率恢复（rate recovery）和软合并
  -> 按 CB 描述符切出每个码块的软信息
  -> 用 BG、$Z_c$（提升大小，见下文符号表）和 set index 构造 LDPC 校验矩阵结构
  -> LDPC 迭代译码
  -> 去掉 filler 和 CB CRC，执行 CB CRC 检查
  -> 按 CB 编号拼回 TB CRC 后序列
  -> 执行 TB CRC 检查
```

这里的混合自动重传请求、冗余版本（Redundancy Version, RV）和调制阶数 $Q_m$ 会在 T9 详细展开。本节只强调一个事实：速率恢复和 LDPC 译码都需要同一组分段描述符。如果发送端使用 BG1、提升大小 $Z_c=240$、$C=2$，接收端却按 BG2 或别的 $Z_c$ 建矩阵，译码图的节点数量、软信息位置和 CRC 边界都会错。

## 基图选择的因果关系

LDPC base graph 可以理解为“校验矩阵骨架”。NR 使用两套基图：

| 基图 | 协议矩阵规模 | 典型适用直觉 | 编码后长度形式 |
|:---|:---|:---|:---|
| BG1 | 46 行、68 列 | 较大净荷（payload）或较高码率的数据块 | $N=66Z_c$ |
| BG2 | 42 行、52 列 | 较小净荷（payload）或较低码率的数据块 | $N=50Z_c$ |

矩阵列数看起来是 68 或 52，但 TS 38.212 的 LDPC 编码输出长度分别是 $66Z_c$ 和 $50Z_c$。原因是 NR LDPC 的前 $2Z_c$ 个系统位置在编码输出序列中被打孔处理，后续速率匹配章节会继续精读。对接收端来说，这意味着 速率恢复（rate recovery）不能只按“基矩阵总列数乘 $Z_c$”理解输出软信息长度。

UL-SCH 的 §6.2.2 和 DL-SCH 的 §7.2.2 使用同一套 base graph selection 条件。设 $A$ 为 净荷大小（payload size），$R$ 为由调制与编码方案等过程指示的目标编码率，则：

$$
\text{use BG2 if } A \le 292
\tag{1}
$$

或：

$$
\text{use BG2 if } A \le 3824 \text{ and } R \le 0.67
\tag{2}
$$

或：

$$
\text{use BG2 if } R \le 0.25
\tag{3}
$$

否则使用 BG1：

$$
\text{otherwise use BG1}
\tag{4}
$$

这些条件的工程含义是：很短的块、较低码率的块和低码率覆盖场景更适合 BG2；较大块或较高码率数据链路通常使用 BG1。接收端不能只从 TB 长度猜基图，必须按调度得到的 $A$ 和 $R$ 走同一套选择逻辑。

## 分段符号与工程对象

| 符号 | 含义 | 接收端保存原因 |
|:---|:---|:---|
| $A$ | TB 净荷大小（payload size），不含 TB CRC | base graph selection 使用。 |
| $B$ | 进入 §5.2.2 分段的长度，通常是 TB CRC 附加后的长度 | 计算 CB 数量和分段输入。 |
| $K_{\mathrm{cb}}$ | 单个 LDPC CB 的最大允许输入长度 | 判断是否需要分段。 |
| $L$ | 每个 CB 追加的 CRC 长度 | $C>1$ 时为 24，决定 CB 局部验收。 |
| $C$ | CB 数量 | 决定并行 LDPC 译码任务数量。 |
| $B'$ | 计入 CB CRC 后需要分配的总长度 | 用于计算每个 CB 的目标长度。 |
| $K'$ | 每个 CB 在追加 lifting filler 前的长度 | 数据和 CB CRC 的边界。 |
| $K_b$ | 选择 $Z_c$ 时使用的基准列数 | BG2 小块时可为 6、8、9、10。 |
| $Z_c$ | lifting size，提升大小 | 决定实际矩阵扩展尺寸和硬件并行颗粒。 |
| $K$ | 送入 LDPC 编码器/译码器的 CB 长度 | BG1 为 $22Z_c$，BG2 为 $10Z_c$。 |
| $F$ | 每个 CB 末尾的 filler 数量 | 接收端译码后必须忽略，不交给 TB 重组。 |

这里最容易混淆的是 $K_b$ 和 $K$。$K_b$ 用来选择一个不过大的 $Z_c$；真正进入 LDPC 编码输入长度的 $K$ 在 BG1 中是 $22Z_c$，在 BG2 中是 $10Z_c$。因此 BG2 小块可能用 $K_b=6$、8 或 9 来选 $Z_c$，但实际 $K$ 仍然是 $10Z_c$。

## 分段尺寸公式

BG1 和 BG2 的最大码块大小不同：

$$
K_{\mathrm{cb}} =
\begin{cases}
8448, & \text{BG1}\\
3840, & \text{BG2}
\end{cases}
\tag{5}
$$

如果 $B \le K_{\mathrm{cb}}$，不需要分段，也不追加 CB CRC：

$$
C=1,\quad L=0,\quad B'=B
\tag{6}
$$

如果 $B>K_{\mathrm{cb}}$，需要分段，每个 CB 追加 24 bit 的 CRC：

$$
L=24
\tag{7}
$$

码块数量为：

$$
C=\left\lceil \frac{B}{K_{\mathrm{cb}}-L}\right\rceil
\tag{8}
$$

计入 CB CRC 后的总长度为：

$$
B'=B+C L
\tag{9}
$$

每个 CB 在 lifting filler 前的长度为：

$$
K'=\frac{B'}{C}
\tag{10}
$$

式 (10) 是协议写法。工程实现中应对合法传输块大小、调度参数和分段结果做一致性断言：若 $B'$ 不能被 $C$ 整除，不能悄悄改成另一套非协议行为，而要追查上游传输块大小、CRC 或分段输入是否已经错位。

BG1 的 $K_b$ 固定为：

$$
K_b=22
\tag{11}
$$

BG2 的 $K_b$ 由 $B$ 决定：

$$
K_b =
\begin{cases}
10, & B>640\\
9, & 560 < B \le 640\\
8, & 192 < B \le 560\\
6, & B \le 192
\end{cases}
\tag{12}
$$

接着在 Table 5.3.2-1 的所有 lifting size 集合中寻找最小 $Z_c$，使得：

$$
K_b Z_c \ge K'
\tag{13}
$$

选到 $Z_c$ 后，实际 LDPC 输入长度为：

$$
K =
\begin{cases}
22 Z_c, & \text{BG1}\\
10 Z_c, & \text{BG2}
\end{cases}
\tag{14}
$$

每个 CB 末尾的 filler 数量为：

$$
F=K-K'
\tag{15}
$$

与 LTE Turbo 分段不同，NR LDPC 本节讨论的 filler 是追加在每个 CB 的 $K'$ 之后、$K$ 之前的 `<NULL>` 区间。接收端译码后不能把这些 filler 当成有效净荷或 CRC 位。

## 基图移位表复现

Table 5.3.2-2 和 Table 5.3.2-3 不是普通“参数表”，而是 NR LDPC 校验矩阵的骨架。表中每一行列出一个非零基图位置 $(i,j)$，并给出 8 个 set index 下的移位系数 $V_{i,j}$。未出现在表中的基图位置视为 0。

对于某个非零位置 $(i,j)$，选定 $Z_c$ 和 $i_{\mathrm{LS}}$ 后，循环右移量为：

$$
P_{i,j}=V_{i,j}^{(i_{\mathrm{LS}})} \bmod Z_c
\tag{16}
$$

基本节图表中的 1 被替换为一个 $Z_c \times Z_c$ 的循环置换矩阵：

$$
I_{P_{i,j}}=\text{identity matrix circularly shifted right by } P_{i,j}
\tag{17}
$$

基本节图表中的 0 被替换为同尺寸全 0 矩阵。这样得到完整 LDPC 奇偶校验矩阵 $H$。

## 比特填入与 filler 位置

分段输出的第 $r$ 个 CB 记为：

$$
c_{r,0},c_{r,1},\ldots,c_{r,K-1}
\tag{18}
$$

每个 CB 的前 $K'-L$ 个位置来自分段输入序列：

$$
c_{r,k}=b_s,\quad 0 \le k < K'-L
\tag{19}
$$

若 $C>1$，对该 CB 的前 $K'-L$ 个比特计算 CB CRC，并把 CRC 放到：

$$
K'-L \le k < K'
\tag{20}
$$

最后，filler 放到：

$$
K' \le k < K
\tag{21}
$$

式 (21) 是接收端实现的重点。NR LDPC 的 filler 在每个 CB 的尾部，不是 T3.3 中 LTE Turbo 分段那种第一个 CB 开头的 filler。译码器输入端可以把这些位置当作已知 0 参与编码一致性，速率恢复和重组时则必须把 `<NULL>` 位置排除，不能把它们交给 CRC 或 TB 重组。

## 手算例子一：BG1 两个码块

设 base graph selection 已经选择 BG1，分段输入长度为：

$$
B=10000
\tag{22}
$$

BG1 的最大码块大小为：

$$
K_{\mathrm{cb}}=8448
\tag{23}
$$

因为 $B>K_{\mathrm{cb}}$，需要分段：

$$
L=24,\quad C=\left\lceil\frac{10000}{8448-24}\right\rceil=2
\tag{24}
$$

计入两个 CB CRC 后：

$$
B'=10000+2\times 24=10048
\tag{25}
$$

每个 CB 的 $K'$ 为：

$$
K'=\frac{10048}{2}=5024
\tag{26}
$$

BG1 有 $K_b=22$，所以需要找最小 $Z_c$ 使：

$$
22Z_c \ge 5024
\tag{27}
$$

从 Table 5.3.2-1 查得 $Z_c=224$ 不够，因为 $22\times224=4928$；$Z_c=240$ 满足，因为：

$$
22\times240=5280
\tag{28}
$$

因此：

$$
Z_c=240,\quad i_{\mathrm{LS}}=7,\quad K=5280,\quad F=5280-5024=256
\tag{29}
$$

接收端得到的描述符应包含：

| 字段 | 值 |
|:---|---:|
| BG | 1 |
| $C$ | 2 |
| $L$ | 24 |
| $K'$ | 5024 |
| $Z_c$ | 240 |
| $i_{\mathrm{LS}}$ | 7 |
| $K$ | 5280 |
| $F$ | 256 |
| 每个 CB 的 净荷位数 | 5000 |
| 每个 CB 的 CB CRC 位数 | 24 |
| 每个 CB 尾部 filler 位数 | 256 |

这里每个 CB 的净荷位数是 $K'-L=5000$，两个 CB 合计正好恢复 $B=10000$ 个输入位。译码后每个 CB 要先丢弃尾部 256 个 filler，再检查 24 bit CB CRC，最后把两个 5000 bit payload 片段按 CB 编号顺序拼接。

### NR LDPC 与 LTE Turbo 的 filler 位置对比

接收端删除 filler 的位置在 LTE 和 NR 中完全不同，不能混用：

| | LTE Turbo（T3.3） | NR LDPC（本节） |
|:---|:---|:---|
| **filler 放在哪个 CB** | 只放在第 0 个 CB（`c_{0,k} = <NULL>`） | 每个 CB 都可能带 filler（只要 $K>K'$） |
| **filler 在 CB 内的位置** | CB0 的**开头**（前 $F$ 个位置） | 每个 CB 的**尾部**（$K'$ 之后、$K$ 之前） |
| **filler 后面是什么** | 真实的 TB 数据比特 | （filler 在尾部，后面就是 CB 边界了） |
| **接收端删除时机** | 所有 CB 译码并拼接后，删除拼接序列的**开头** $F$ 个位置 | 每个 CB 独立译码后，先丢弃该 CB **尾部**的 filler，再各自检查 CB CRC |
| **出错后果** | 把 CB0 开头的 filler 当数据 → TB 整体位序偏移 | 把尾部 filler 当数据送入 CB CRC → 该 CB 局部 CRC 失败 |
| **协议来源** | TS 36.212 §5.1.2 | TS 38.212 §5.2.2 |

核心原因来自两类编码器的结构差异。LTE Turbo 分段需要在 $K_+$ 和 $K_-$ 两种长度之间分配 CB，filler 只是补齐差额，所以一个 TB 只产生一批 filler，全放在第一个 CB 开头。NR LDPC 分段先计算统一的 $K'$，再为每个 CB 各自选 $Z_c$ 得到 $K$，$K-K'$ 的差额作为该 CB 的尾部 filler——因此每个 CB 都有自己的一份 filler。

错误的删除位置会导致严重后果。如果接收端用 LTE 逻辑处理 NR LDPC 的 CB（"拼接后删开头"），实际尾部 filler 会被当成净荷送入 TB CRC，位序错乱；如果反过来用 NR 逻辑处理 LTE（"每个 CB 删尾部"），CB1 的真实数据会被误删。

## 手算例子二：BG2 单码块

设 base graph selection 选择 BG2，分段输入长度为：

$$
B=1024
\tag{30}
$$

BG2 的最大码块大小为：

$$
K_{\mathrm{cb}}=3840
\tag{31}
$$

因为 $B \le K_{\mathrm{cb}}$，不需要分段：

$$
C=1,\quad L=0,\quad B'=1024,\quad K'=1024
\tag{32}
$$

BG2 的 $K_b$ 由 $B$ 决定。因为 $B>640$：

$$
K_b=10
\tag{33}
$$

需要找最小 $Z_c$ 使：

$$
10Z_c \ge 1024
\tag{34}
$$

Table 5.3.2-1 中 $Z_c=104$ 满足，且比 112、120、128 等更小：

$$
Z_c=104,\quad i_{\mathrm{LS}}=6,\quad K=10\times104=1040
\tag{35}
$$

因此：

$$
F=1040-1024=16
\tag{36}
$$

这个例子没有 CB CRC，因为 $C=1$。接收端译码后只需忽略尾部 16 个 filler，再把前 1024 个比特交给后续 TB CRC 检查。

## 接收端流程

NR LDPC 接收端的分段描述符生成不在译码迭代内部，但它决定译码迭代的所有尺寸。

```text
输入：A, B, target code rate R, uplink/downlink channel context
输出：每个 CB 的 LDPC descriptor

1. 按 TS 38.212 §6.2.2 或 §7.2.2 选择 BG：
   - 满足 BG2 条件则 BG=2，否则 BG=1。
2. 按 BG 设置 Kcb：
   - BG1: Kcb=8448
   - BG2: Kcb=3840
3. 按 B 和 Kcb 计算 C、L、B'。
4. 计算 K'=B'/C，并检查整除关系。
5. 按 BG 和 B 计算 Kb。
6. 从 Table 5.3.2-1 选择最小 Zc，使 Kb*Zc >= K'。
7. 得到 Zc 所属 set index iLS。
8. 计算 K 和 F。
9. 对每个 r=0..C-1 创建 descriptor：
   - BG, Zc, iLS
   - K, K', F, L
   - 净荷偏移（payload offset）
   - CB CRC present flag
   - rate recovery buffer range（速率恢复缓冲区范围）
10. 速率恢复后，按 descriptor 调用 LDPC 译码器。
```

注意第 9 步中的 `净荷偏移（payload offset）` 必须按 CB 编号递增。不能按 CB 译码完成时间拼接，也不能因为多个 CB 尺寸相同就丢掉编号。

## 伪代码

```python
from math import ceil

LIFTING_SETS = {
    0: [2, 4, 8, 16, 32, 64, 128, 256],
    1: [3, 6, 12, 24, 48, 96, 192, 384],
    2: [5, 10, 20, 40, 80, 160, 320],
    3: [7, 14, 28, 56, 112, 224],
    4: [9, 18, 36, 72, 144, 288],
    5: [11, 22, 44, 88, 176, 352],
    6: [13, 26, 52, 104, 208],
    7: [15, 30, 60, 120, 240],
}


def select_bg(A: int, R: float) -> int:
    if A <= 292:
        return 2
    if A <= 3824 and R <= 0.67:
        return 2
    if R <= 0.25:
        return 2
    return 1


def select_kb(bg: int, B: int) -> int:
    if bg == 1:
        return 22
    if B > 640:
        return 10
    if B > 560:
        return 9
    if B > 192:
        return 8
    return 6


def select_zc(kb: int, k_prime: int) -> tuple[int, int]:
    candidates = []
    for set_index, values in LIFTING_SETS.items():
        for zc in values:
            if kb * zc >= k_prime:
                candidates.append((zc, set_index))
    if not candidates:
        raise ValueError("no legal Zc")
    return min(candidates)


def ldpc_segmentation_descriptor(A: int, B: int, R: float) -> dict:
    bg = select_bg(A, R)
    k_cb = 8448 if bg == 1 else 3840
    if B <= k_cb:
        C, L, Bp = 1, 0, B
    else:
        L = 24
        C = ceil(B / (k_cb - L))
        Bp = B + C * L
    if Bp % C:
        raise ValueError("B' must be divisible by C for this protocol descriptor")
    k_prime = Bp // C
    kb = select_kb(bg, B)
    zc, i_ls = select_zc(kb, k_prime)
    K = (22 if bg == 1 else 10) * zc
    F = K - k_prime
    return {
        "BG": bg,
        "C": C,
        "L": L,
        "B_prime": Bp,
        "K_prime": k_prime,
        "K_b": kb,
        "Z_c": zc,
        "i_LS": i_ls,
        "K": K,
        "F": F,
    }


print(ldpc_segmentation_descriptor(A=9976, B=10000, R=0.5))
print(ldpc_segmentation_descriptor(A=1000, B=1024, R=0.5))
```

预期输出为：

```text
{'BG': 1, 'C': 2, 'L': 24, 'B_prime': 10048, 'K_prime': 5024, 'K_b': 22, 'Z_c': 240, 'i_LS': 7, 'K': 5280, 'F': 256}
{'BG': 2, 'C': 1, 'L': 0, 'B_prime': 1024, 'K_prime': 1024, 'K_b': 10, 'Z_c': 104, 'i_LS': 6, 'K': 1040, 'F': 16}
```

这段代码不是完整 PHY 参考模型。它只覆盖本节讲的分段描述符；真实链路还需要 TB CRC 生成、多项式细节、LDPC 编码、速率匹配、解速率匹配、软合并和 CRC 检查。

## 浮点仿真方案

本节的浮点仿真不追求完整块错误率曲线，而是验证分段描述符与后续译码接口的一致性。

| 仿真项 | 方法 | 通过条件 |
|:---|:---|:---|
| BG 选择覆盖 | 枚举 $A$ 和 $R$ 的边界：$A=292$、293、3824、3825，$R=0.25$、0.67 附近 | BG1/BG2 与式 (1)-(4) 一致。 |
| $Z_c$ 选择 | 对 $K'$ 枚举 Table 5.3.2-1 附近边界 | 总能选择最小满足 $K_bZ_c\ge K'$ 的 $Z_c$。 |
| filler 位置 | 构造已知比特序列，按 descriptor 填入 CB | 净荷（payload）、CB CRC、filler 三段边界逐位正确。 |
| 矩阵尺寸 | 根据 BG 和 $Z_c$ 生成矩阵尺寸 | BG1 为 $46Z_c \times 68Z_c$，BG2 为 $42Z_c \times 52Z_c$。 |

## 定点化策略

分段本身主要是整数控制逻辑，但它会决定后续定点资源规模。

| 对象 | 定点关注点 | 工程建议 |
|:---|:---|:---|
| $Z_c$ | 控制并行粒度、地址步长和循环移位模数 | 用枚举编码保存合法 $Z_c$，不要让任意整数进入硬件。 |
| $K$、$N$ | 决定 LLR SRAM、消息 SRAM 和输出缓存长度 | 预先生成 descriptor，避免译码核心动态做复杂除法。 |
| $F$ | 决定哪些位置是 `<NULL>` | 用 mask 或边界计数器控制，不要把 filler LLR 当普通信道观测。 |
| 移位系数 | $P_{i,j}=V_{i,j}\bmod Z_c$ | 配置阶段预计算，译码迭代中只读移位量。 |

LLR 的定点位宽、饱和和归一化参数不在本节定论。T2.16 已给出软信息量化预览，T18.3 会把 NR LDPC 定点消息位宽系统化。

## 硬件实现映射

本节对寄存器传输级和专用集成电路的影响集中在 descriptor 生成和矩阵访问。

| 模块 | 输入 | 输出 | 关键风险 |
|:---|:---|:---|:---|
| BG selector | $A$、$R$、UL/DL 模式 | BG1/BG2 | 边界条件比较错误导致全链路矩阵错误。 |

## 常见错误

| 错误 | 后果 | 修正 |
|:---|:---|:---|
| 把 BG2 的 $K_b$ 当成实际 $K/Z_c$ | 小块 BG2 的 $K$ 算小，矩阵列数和 filler 都错 | 记住 $K_b$ 只用于选 $Z_c$，BG2 实际 $K=10Z_c$。 |
| 用 LTE 的短块/长块顺序套 NR | CB 重组边界错误 | NR LDPC 使用每个 CB 相同 $K'$，再追加每个 CB 的尾部 filler。 |
| 忽略 $i_{\mathrm{LS}}$ | 查错 Table 5.3.2-2/3 的移位列 | 从选中的 $Z_c$ 反查 set index。 |
| 把 filler 交给 TB CRC | TB CRC 假失败 | 译码后先删除 `<NULL>` 区间，再处理 CB/TB CRC。 |
| 只按 $B$ 选择 BG | 低码率大块可能应走 BG2 | BG 选择必须同时看 $A$ 和 $R$。 |
| 没有检查 $B'/C$ | 后续 净荷偏移（payload offset） 隐性错位 | descriptor 生成阶段加入整除断言和输入追踪。 |

## 工程思考题

1. 为什么 BG2 小块使用 $K_b=6/8/9$ 选择 $Z_c$，但实际 $K$ 仍然是 $10Z_c$？
2. 若 $Z_c=240$，为什么接收端还必须知道它属于 set index 7？
3. NR LDPC filler 与 LTE Turbo filler 的位置差异会如何影响接收端重组？
4. 对于同一个 $B$，如果接收端 BG 选择错了，最先暴露问题的通常是矩阵尺寸、syndrome 还是 CRC？
5. 为什么本节不直接给出完整 BLER 性能结论？

## 工程思考题参考答案

1. $K_b$ 是选择提升大小的辅助参数，用来避免短块 BG2 选到过大的 $Z_c$。实际 LDPC 输入长度仍按 BG2 的系统列数 $10Z_c$ 计算，因此 $K_b$ 不能替代 $K/Z_c$。
2. Table 5.3.2-2/3 的移位系数按 set index 分列。相同基图位置在不同 set index 下的 $V_{i,j}$ 不同；只知道 $Z_c$ 数值而不知道 set index，就无法正确查移位列。
3. LTE Turbo 的 filler 位于第一个 CB 开头；NR LDPC 的 lifting filler 位于每个 CB 的 $K'$ 到 $K-1$ 尾部区间。接收端删除 filler 的位置不同，错误套用会导致 净荷偏移（payload offset） 和 CRC 输入错位。
4. 通常矩阵尺寸和速率恢复长度会先错，随后 syndrome 和 CRC 都会失败。若实现没有尺寸断言，可能表现为 LDPC 迭代不收敛或 CB CRC 全失败。
5. BLER 需要真实编码、调制、信道、解调、速率恢复和 LDPC 译码算法。本节只讲分段和矩阵描述符，不能替代完整链路仿真。

4. $Z_c$ 的 set index 用来查哪两张表？
5. NR LDPC 的 filler 放在每个 CB 的哪个区间？
