# 文档与代码注释规则总纲（项目根级规则）

> CLAUDE.md 第 3 条引用的项目根级规则文件。覆盖：代码注释（DOXYGEN）、讲义文档规范、概念笔记规范、SVG 与图片资产、术语与同步。**代码可读性优先于功能正确性；教学可读性优先于一切。**

## 一、DOXYGEN 注释细则（代码红线）

所有 Python 脚本、Shell 脚本、配置文件中的函数/类/任务入口必须使用完整的 DOXYGEN 风格注释。

### 1.1 Python 文件头

```python
#!/usr/bin/env python3
"""
@file    <文件名>
@brief   <一句话功能>
@date    YYYY-MM-DD
@note    <可选：设计说明/教训来源>
"""
```

### 1.2 Python 函数

```python
def func(param1, param2) -> type:
    """@brief <一句话>
    @param param1 <说明>
    @param param2 <说明>
    @return <返回说明>
    @note  <可选>
    @throws <可选：异常情形>"""
```

### 1.3 Python 脚本入口（main）

```python
def main() -> int:
    """@brief <一句话>
    @usage python3 <script> <args>
    @args  <参数说明>
    @env   <依赖环境>
    @exit_code 0 = 成功，1 = 失败"""
```

### 1.4 Shell 脚本

```bash
#!/usr/bin/env bash
# @file    <文件名>
# @brief   <一句话功能>
# @date    YYYY-MM-DD
# @usage   bash <script> <args>
# @exit_code 0 = 成功，非 0 = 失败
```

### 1.5 配置/JSON/YAML 文件

顶层注释（或 README 引用处）说明：文件用途、关键字段语义、与代码的对应关系。结构体/枚举字段必须逐项注释。

### 1.6 注释规范

- `@throws`：注明触发条件与异常类型（非默认异常才写）
- `@note`：**教学知识库惯例——记录"为什么这样设计"与教训来源**（如 SVG 审计教训、数值口径约定）
- 中英混排：说明性文字用中文，标识符/命令保持英文
- 内嵌教学代码块（讲义正文中的 numpy 示例）不强制完整 DOXYGEN 头，但必须有教学注释（见 §二.4）

### 2.2 结构模板

`# <编号> <中文标题>` → `## 本节学习目标`（叙事 intro + 6-8 条可检验 bullets，动词开头）→ `## 前置知识检查`（表格 `| 前置项 | 本节需要达到的程度 |`）→ 内容章节（LaTeX `\tag{}` 编号公式、表格、生活类比、数值实例）→ 例题（示范/引导/独立，附参考答案）→ `## 资料与协议边界`（**必选**，2026-08-14 升格：协议规定什么 / 不规定什么（实现域）/ 接收端义务边界，呼应 Rule 7/19）→ `## 小结`（收束 + 与持久理解呼应 + 指向下一篇）。

**自测题为可选章节**（2026-08-14 裁定）：示范/引导/独立习题 3+3+3 已覆盖检验职能，重复设自测题有凑字数之嫌；审计工具不再把自测题列为必检章节。旧讲义既有自测题章节保留不动。

**例题数量上限（用户确立，强制）**：示范例题、引导练习、独立习题**每类不超过 3 个，全篇习题总数不超过 9 个**。习题是检验手段不是篇幅填充——禁止用习题凑行数；话题深度不足以支撑 500 行时，与相关课题**合并**而非注水（教训：2026-08-13 T14.3-T15.5 八篇习题 13-20 个/篇凑行数，用户纠正；T14.1 基准仅 2 个示范例题）。

### 2.3 写作规范（用户确立，强制）

- **正文不得包含代码中间运行结果**：不贴报错文本、不展示修正前调试数值、不写"原稿崩溃→修正"过程叙述；内嵌代码必须是最终正确版本，正文只呈现正确结论（教训：2026-08-03 MIMO 系列）
- **概念首现必须讲解**：即使存在概念笔记，任何概念（含先修概念）首次出现必须给出名称+定义+一句解释，再 `[[wikilink]]` 指向笔记深入；第 2+ 次可裸用（教训：2026-08-04 PS 系列）
- **手算数值实例必须与 numpy 独立重算一致**（教训：T12.4 手算实例 s0↔s1 系统性互换）
- 标题口语化禁止（Rule 16）；英文术语首现"中文（English）"（Rule 10）；LaTeX 必须可渲染（Rule 20）
- **禁止生活类比（2026-11-10 用户纠错固化）**：正文与概念笔记一律使用书面表述，禁止"蛋糕/盘子/跑道/好比/像一…"等生活比喻与拟物化措辞。Rule 8 要求的零基础直觉必须由**结构化描述、可数数值实例或协议处理流程**承担，不得由比喻承担；比喻看似降低门槛，实际额外引入一套未定义的语义，对零基础读者是第二重负担（教训：E_Value_G_Value 首段用"总预算/分账/蛋糕/盘子/撤盘/一口"解释 G 与 $E_r$，用户判定"第一段都不明白"）
- 每篇 ≥500 行（下限参考，内容充实即可；上限不限——内容与主题允许可远超 500；话题深度不足时合并而非注水，2026-08-13 用户裁定）；≥1 个教学图；1 个内嵌 numpy 验证（实跑断言通过）

### 2.4 内嵌代码块

- numpy 验证代码：先本地实跑确认正确，再写入讲义；输出与断言一致
- 教学注释风格（不强制 DOXYGEN 头；抽为 `sim/` 正式脚本时补完整 DOXYGEN）

## 三、概念笔记规范（docs/concepts/）

- 命名：`English_中文.md`；标题 `# English 中文`（空格分隔）
- **节标题必须书面语**（2026-11-05 用户纠错固化）：叙事节用「起源与演进」等书面标题，禁「来龙去脉」类口语标题（呼应 Rule 16 标题口语化禁止；2026-11-05 六篇样板曾误用已全库改正，含 T21.3 正文一处）
- 六段式模板（按序）：`## 独立解释任务`（首行"任务目标：…"）→ `## 科学定义` → `## 直观模型` → `## 常见误解`（表格 `| 误解 | 正确理解 |`）→ `## 协议锚点`（TS/TR 小节号 + 本地 `3GPP_Rel19/processed/` 锚点；非标准项标注"非 3GPP 标准"）→ `## 图谱关联`（含 `[[概念图谱入口]]` + 上下游，末行"关系语义：…"）
- **`## 直观模型` 的内容口径（2026-11-10 用户纠错固化）**：该节承担的是"关系的结构化呈现"，不是生活比喻的容器。写法限三种——两级/多层结构分解（总量–切片、标量–向量）、地址空间或坐标系描述（起点、长度、上界、回绕）、约束清单（步长约束、余数归属、置零不缩量）。节标题沿用模板固定名，内容不得出现拟物化叙事。
- **增厚口径（2026-11-05 全库 116 篇增厚定稿；2026-11-10 修订类比项）**：开头定位段含「一句话本质」（本质 + 加粗）；「独立解释任务」之后可加 `## 前置概念`（见下一条），再加 `## 起源与演进`（(1)(2)(3) 分步编号 + 每步小标题点题 + 数值实例 + LTE/NR 两代对照）；「图谱关联」之前加 `## 关键要点`（≥5 条，`1. 2. 3.` 列表写法）。数学基础类（GF2/dB/傅里叶等非协议概念）豁免起源与演进、只补本质句与关键要点。四维丰富度（展开更深/直觉更具体/叙述更连贯/覆盖面更全）与去重纪律（不逐篇复制同一表述与数值例，重复处指向直观模型）不变；有协议族分布节（问答命中时随 queries 一并补）的笔记按五层职责表 + 联系链写。
- **术语解释三重义务（2026-11-10 用户纠错固化，强制）**：概念密集的笔记必须在三处同时承担解释义务，缺一即视为不可读——
  (1) **前置概念节**：首段就出现多个他域术语时，在「独立解释任务」之后加 `## 前置概念`，每个对象 1-3 句书面定义 + 中文（English, ABBR）首现 + wikilink，并交代它在本笔记中承担的角色；
  (2) **符号与记号约定（2026-11-10 用户加严，强制）**：在**标题之后、任何数学片段之前**写 `## 符号与记号约定`，逐个列出全文用到的每个数学符号（表格列：符号 / 读法 / 含义与取值），并说明运算符与记号惯例（$\lfloor\cdot\rfloor$、$\bmod$、$\min$、$\sum$、上下标语义、撇号表示净量、同一量的两套记号如 $N_L$ 与 $\nu$、易混长度 $N$ / $N_{cb}$ / $N_{ref}$）。**判据是「首次使用之前」而非「文中有解释」**——定位段、一句话本质里出现的符号同样受此约束。检查工具 `tools/audit_symbol_table.py` 必须报 `SYMBOL_TABLE_AUDIT_OK`；原来的 `## 科学定义` 首个子节 `### 记号约定` 不再使用，其内容并入文首该节；
  (2b) **符号须标协议锚点（2026-11-10 用户两次加严，强制）**：符号表每个符号都必须能追到出处——表格增列「协议锚点」，按三类填写：协议量写**规范号 + 条款**（如 `TS 38.212 §5.4.2.1`、`TS 38.211 Table 5.3.2-1`）；派生量写「**由 TS xx.xxx §x.x 导出**」——只写「由 §x.x 导出」不合格，必须带规范号；非协议量写「非 3GPP 标准」或「实现域」。锚点可写在符号行本身，也可写在独立的「符号与协议出处」表里。检查工具 `tools/audit_symbol_anchor.py` 必须报 `SYMBOL_ANCHOR_AUDIT_OK`（它只认含 `TS xx.xxx` 的行、或明确标注非标准/实现域的行）。
  (2c) **「含义与取值」列（2026-11-10 用户两次加严）**：该列不能只写符号名的同义重复，必须写清四件事——①含义（这个量在链路上的角色）②取值或范围③单位④来源（由哪个量算出、由哪层配置、协议固定常量）。**四项内容压成一句连贯书面语，禁止写成「含义：…；取值：…；单位：…；来源：…」这类标签前缀式**（用户明确要求去掉「含义：」等标签）。例：`一个传输块本次可用的编码比特总数，是编码之后的比特预算；常规下行共享信道上取 $N_{RE}Q_mN_L$，数值例 8000；单位为 bit；定义见 TS 38.212 §5.4.2.1。`
：符号表每个符号都必须能追到出处——表格增列「协议锚点」，按三类填写：协议量写条款（如 `TS 38.212 §5.4.2.1`、`Table 5.3.2-1`）；派生量写「由 §x.x 导出」（如 $X,q,R_{rem}$）；非协议量（$\sigma^2$、LLR、判决门限等）写「非 3GPP 标准」或「实现域」。锚点可写在符号行本身，也可写在独立的「符号与协议出处」表里，两种写法等价。检查工具 `tools/audit_symbol_anchor.py` 必须报 `SYMBOL_ANCHOR_AUDIT_OK`；
  (3) **首现就地解释**：任何术语、符号、缩写在其首次出现处给出解释性定语或括注，禁止"先裸用、后文再定义"；符号表需含"物理意义与取值来源"列，不能只给符号名与出处。
- **禁止提纲化分层（2026-11-10 用户确立，强制）**：概念笔记必须是连贯的书面论述，不是条目堆叠。
  1. `## 前置概念` 内**不使用 `###` 小标题**，改为连续段落：每个对象自成一个句子或短句组，定义随句给出，wikilink 嵌在句中；
  2. `## 科学定义` 内三级标题**不超过 3 个**，`## 直观模型` 内**不使用 `###`**（合并为 1-2 段连贯论述），其余内容用过渡句连接成段；能用一句话讲清的事实不得拆成单行项目符号；
  3. 列表仅用于并列的参数清单（如符号表、边界情形枚举），且每一项须是完整句，不是短语残片；
  4. 小节之间必须有过渡句——承接上一节的结论、指出下一节要解决的问题，禁止用标题硬切；
  5. 保留项：`## 符号与记号约定` 表格、图注与图例、`## 常见误解` 表格——它们是检索与校验所需，不属于"分层"。
  6. 判据：把一篇笔记读给不熟悉该主题的人听，若只能听到"标题—要点—标题—要点"，即为不合格；应有可复述的因果链与递进关系。
- frontmatter：`type: definition` + aliases + tags（含 `3gpp`/`concepts`）+ source_spec + `queries`（问答命中计数，整数默认 1）

## 四、SVG 与图片资产

- **生成后强制验证**（CLAUDE.md 第 4 条三步）：(1) Y 坐标扫描（间距 ≥8px）(2) 边界间距检查（`tools/audit_svg_layout.py` R1-R11：文字宿主/越界/重叠/箭头落点/**边界间距 ≥8px**/**部分重叠禁止**/free 文字重叠/箭头三角/曲线贴字/circle 贴边）(3) PNG 预览（cairosvg）

- **概念笔记图资产（2026-08-17 确立）**：概念笔记配图存 `docs/concepts/assets/`，命名 `<概念名>_<主题>.svg`（如 `Preemption_Indication_bitmap.svg`）；概念笔记无 T 编号，命名用概念名前缀保证"图 ↔ 笔记"可追溯，台账登记归属同讲义资产

- SVG 文件由脚本生成时：脚本路径登记台账；SVG 内容内嵌文字同时随目录改名更新（sed 覆盖 svg 内嵌说明）

### 4.1 PlantUML 资产（2026-08-07 绘图政策）

- **适用场景**：特别大型图（完整解码链路全景、超大流程/时序/状态/结构图等手绘成本过高的场景）；其余复杂图一律手绘 SVG，简单流程/结构图用 Mermaid。**禁止新写 Python 绘图脚本**（存量已归档 `tools/archive_python_drawing/`，git 可恢复）。
- **源码保存**：` ```plantuml ` 代码块嵌入讲义，或资产 `T<编号>_<主题>.puml` 存入对应层 `assets/`
- **渲染与嵌入**：`java -jar ~/.local/bin/plantuml.jar -tsvg <源>` 渲染产物（SVG/PNG）嵌入正文，命名 `T<编号>_<主题>.svg`；渲染产物与源文件都登记 `docs/audits/image_asset_inventory.md`
