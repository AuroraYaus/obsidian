# 文档与代码注释规则总纲（项目根级规则）

> CLAUDE.md 第 3 条引用的项目根级规则文件。覆盖：代码注释（DOXYGEN）、讲义文档规范、概念笔记规范、SVG 与图片资产、术语与同步。**代码可读性优先于功能正确性；教学可读性优先于一切。**

## 一、DOXYGEN 注释细则（代码红线）

所有 Python 脚本、Shell 脚本、配置文件中的函数/类/任务入口必须使用完整的 DOXYGEN 风格注释。

### 1.1 Python 文件头

```python
#!/usr/bin/env python3
"""
@file    <文件名>
@brief   <一句话功能>
@date    YYYY-MM-DD
@note    <可选：设计说明/教训来源>
"""
```

### 1.2 Python 函数

```python
def func(param1, param2) -> type:
    """@brief <一句话>
    @param param1 <说明>
    @param param2 <说明>
    @return <返回说明>
    @note  <可选>
    @throws <可选：异常情形>"""
```

### 1.3 Python 脚本入口（main）

```python
def main() -> int:
    """@brief <一句话>
    @usage python3 <script> <args>
    @args  <参数说明>
    @env   <依赖环境>
    @exit_code 0 = 成功，1 = 失败"""
```

### 1.4 Shell 脚本

```bash
#!/usr/bin/env bash
# @file    <文件名>
# @brief   <一句话功能>
# @date    YYYY-MM-DD
# @usage   bash <script> <args>
# @exit_code 0 = 成功，非 0 = 失败
```

### 1.5 配置/JSON/YAML 文件

顶层注释（或 README 引用处）说明：文件用途、关键字段语义、与代码的对应关系。结构体/枚举字段必须逐项注释。

### 1.6 注释规范

- `@throws`：注明触发条件与异常类型（非默认异常才写）
- `@note`：**教学知识库惯例——记录"为什么这样设计"与教训来源**（如 SVG 审计教训、数值口径约定）
- 中英混排：说明性文字用中文，标识符/命令保持英文
- 内嵌教学代码块（讲义正文中的 numpy 示例）不强制完整 DOXYGEN 头，但必须有教学注释（见 §二.4）

## 二、讲义文档规范（docs/L*）

### 2.1 frontmatter

```yaml
---
type: algorithm          # algorithm | definition | spec
aliases:
  - <编号> <英文标题>
tags:
  - 3gpp
  - docs
  - l<层>                # l0/l1/l2/l3
  - lesson
source_spec: "docs/L<层>_<语义名>/<文件名>.md"
---
```

### 2.2 结构模板

`# <编号> <中文标题>` → `## 本节学习目标`（叙事 intro + 6-8 条可检验 bullets，动词开头）→ `## 前置知识检查`（表格 `| 前置项 | 本节需要达到的程度 |`）→ 内容章节（LaTeX `\tag{}` 编号公式、表格、生活类比、数值实例）→ 例题（示范/引导/独立，附参考答案）→ `## 小结`（收束 + 与持久理解呼应 + 指向下一篇）。

**例题数量上限（用户确立，强制）**：示范例题、引导练习、独立习题**每类不超过 3 个，全篇习题总数不超过 9 个**。习题是检验手段不是篇幅填充——禁止用习题凑行数；话题深度不足以支撑 500 行时，与相关课题**合并**而非注水（教训：2026-08-13 T14.3-T15.5 八篇习题 13-20 个/篇凑行数，用户纠正；T14.1 基准仅 2 个示范例题）。

### 2.3 写作规范（用户确立，强制）

- **正文不得包含代码中间运行结果**：不贴报错文本、不展示修正前调试数值、不写"原稿崩溃→修正"过程叙述；内嵌代码必须是最终正确版本，正文只呈现正确结论（教训：2026-08-03 MIMO 系列）
- **概念首现必须讲解**：即使存在概念笔记，任何概念（含先修概念）首次出现必须给出名称+定义+一句解释，再 `[[wikilink]]` 指向笔记深入；第 2+ 次可裸用（教训：2026-08-04 PS 系列）
- **手算数值实例必须与 numpy 独立重算一致**（教训：T12.4 手算实例 s0↔s1 系统性互换）
- 标题口语化禁止（Rule 16）；英文术语首现"中文（English）"（Rule 10）；LaTeX 必须可渲染（Rule 20）；每篇至少 1 个生活类比（Rule 8）
- 每篇 ≥500 行（下限参考，内容充实即可；上限不限——内容与主题允许可远超 500；话题深度不足时合并而非注水，2026-08-13 用户裁定）；≥1 个教学图；1 个内嵌 numpy 验证（实跑断言通过）

### 2.4 内嵌代码块

- numpy 验证代码：先本地实跑确认正确，再写入讲义；输出与断言一致
- 教学注释风格（不强制 DOXYGEN 头；抽为 `sim/` 正式脚本时补完整 DOXYGEN）

## 三、概念笔记规范（docs/concepts/）

- 命名：`English_中文.md`；标题 `# English 中文`（空格分隔）
- 六段式模板（按序）：`## 独立解释任务`（首行"任务目标：…"）→ `## 科学定义` → `## 直观模型` → `## 常见误解`（表格 `| 误解 | 正确理解 |`）→ `## 协议锚点`（TS/TR 小节号 + 本地 `3GPP_Rel19/processed/` 锚点；非标准项标注"非 3GPP 标准"）→ `## 图谱关联`（含 `[[概念图谱入口]]` + 上下游，末行"关系语义：…"）
- frontmatter：`type: definition` + aliases + tags（含 `3gpp`/`concepts`）+ source_spec

## 四、SVG 与图片资产

- **生成后强制验证**（CLAUDE.md 第 4 条三步）：① Y 坐标扫描（间距 ≥8px）② 边界间距检查（`tools/audit_svg_layout.py` R1-R7：文字宿主/越界/重叠/箭头落点/**边界间距 ≥8px**/**部分重叠禁止**）③ PNG 预览（cairosvg）
- 资产命名：`T<编号>_<英文主题>.svg`，与讲义编号对应（讲义重编号时资产同步重命名）
- 图片资产登记台账：`docs/audits/image_asset_inventory.md` + migration 台账
- SVG 文件由脚本生成时：脚本路径登记台账；SVG 内容内嵌文字同时随目录改名更新（sed 覆盖 svg 内嵌说明）

### 4.1 PlantUML 资产（2026-08-07 绘图政策）

- **适用场景**：特别大型图（完整解码链路全景、超大流程/时序/状态/结构图等手绘成本过高的场景）；其余复杂图一律手绘 SVG，简单流程/结构图用 Mermaid。**禁止新写 Python 绘图脚本**（存量已归档 `tools/archive_python_drawing/`，git 可恢复）。
- **源码保存**：` ```plantuml ` 代码块嵌入讲义，或资产 `T<编号>_<主题>.puml` 存入对应层 `assets/`
- **渲染与嵌入**：`java -jar ~/.local/bin/plantuml.jar -tsvg <源>` 渲染产物（SVG/PNG）嵌入正文，命名 `T<编号>_<主题>.svg`；渲染产物与源文件都登记 `docs/audits/image_asset_inventory.md`
- **强制验证**：新增/修改后 `bash tools/audit_plantuml_syntax.sh`（真实渲染全库扫描）；工具缺失（java / plantuml.jar）显式声明验证缺口，不得默认通过
- **新增资产查重**：任何新图（SVG/PlantUML/协议截图）嵌入前先查台账是否已有同源资产（教训：2026-08-07 T3.3 与 T3.2 重复生成 Table 5.1.3-3 截图）

- SVG 审查：R1-R7 全过（审计工具输出 `SVG_LAYOUT_AUDIT_PASS`）
- 术语审查：新术语登记 L0 总表（同步清单第 1/2/6 条）
